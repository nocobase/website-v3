# 编写应用开发专题

每篇功能专题对应一个可运行的示例 App。文档介绍相关 API 的用法，App 展示这些用法的实际效果，让读者能够操作、查看代码，并迁移到自己的应用。

## 适用范围

- 用于 `doc/content/core/developing-apps/` 和 `doc/content/zh-CN/core/developing-apps/` 下的功能专题，包括子目录中的页面、路由、数据、接口、权限等指南。
- 概览、项目结构等说明性文章不强制配独立 App。入门教程、框架参考和插件使用指南按各自规范编写。
- 通用表达、文章目的与导航沿用 [write-docs](../write-docs/SKILL.md)；出现读者提示词时使用 [write-doc-prompts](../write-doc-prompts/SKILL.md)，不要求每篇增加 Agent 章节。
- 新写或整体重组专题时落实本规范。局部纠错、修改标题或链接只处理当前范围；审阅时列出覆盖缺口，不自动重建示例或迁移其他文章。

## 一篇专题对应一个 App

为每篇功能专题维护一个独立可运行的示例 App，两种语言共用该 App。优先用客户、商品、订单或库存等熟悉的业务场景承载相关用法，尽量避免任务管理、项目管理示例，以免与 Studio 的任务、项目混淆。具体选题遵循下文的仓库约定。

文档介绍的有效用法都要在该 App 中实现。不同用法可以放在不同页面、功能入口或明确的演示状态中；不要只完成最基础的一种，把其余用法留成无法体验的代码片段。已有实现符合要求时继续完善，不为采用本规范更换业务场景。

示例只实现展示本篇能力所需的范围。UI、路由等专题可以使用固定演示数据和内存状态，明确保存是否持久化、刷新或重启后如何复原；不要求补成完整业务系统。权限、持久化等能力属于本篇主题时，必须接入并验证相应的真实机制，不能用界面或模拟响应代替。

- 有界面的示例提供可发现的入口和必要的演示数据。没有菜单入口的详情、弹窗或受限页面，要说明从哪里打开、使用什么角色，以及直接访问地址。
- 服务端、后台任务和 CLI 等能力提供可执行的接口请求、命令或触发操作，以及能观察的响应、数据变化、日志或文件结果，不强制为它们增加管理页面。
- 多种替代配置可以使用独立路由、测试或明确的配置切换展示。说明切换与复原方式，避免读者只能靠手工拼接片段猜测完整配置。
- 不支持的配置用明确标注的反例和隔离测试说明，不放进正常启动路径。涉及权限、数据或状态的关键失败场景也要能复现。

示例项目的存放、英文界面与数据、截图、固定提交链接和 README 要求遵循 [AGENTS.md 的示例项目约定](../../../AGENTS.md#documentation-example-projects)。实现发生在 `nocobase/docs-examples-v3`，先读取该仓库及目标应用自己的指引；本文档 Skill 不替代应用开发规范。

## 确认 API 和用法覆盖

先明确本篇要讲的公开 API、版本及职责，再核对对应版本的导出、类型、实现和测试。区分框架 API、默认模板行为、插件提供的能力和示例自行实现的逻辑；源码分支与发布版本不一致时记录差异，不把分支的新能力写成旧版本已支持。

正文聚焦 NocoBase 特有的应用约定、接入方式及与通用方案的差异。React、shadcn 等通用知识链接对应官方文档，保留理解当前用法必需的上下文。

同一 API 或交互出现在多个专题时，核对受影响的示例、代码片段和说明，确保相同条件下的行为一致；版本或场景导致差异时说明条件。主要专题负责详细解释，其他专题保留必要接入并链接过去。修正共享用法不意味着迁移无关示例。

围绕这些内容检查覆盖：

- 最小可用方式，包括导入、注册或调用位置、必要配置和依赖。
- 有实际意义的不同用法，如参数形式、嵌套、组合、继承、覆盖和返回值处理。
- 影响使用结果的默认值、约束、权限与生命周期，以及容易遇到的失败情况。

每种介绍的用法都给出具体示例，不能只列字段名和类型。“覆盖用法”不要求穷举所有参数组合，也不需要复制底层库的完整参考；超出本篇主题的共享能力链接到相应专题。

在示例 README 中维护“文档用法 → App 操作入口或执行命令 → 源码文件 → 截图或执行结果 → 预期结果与验证”的对应关系。用它检查缺漏，不必把整份开发检查表搬进文章。

## 文章组织

按文章的主要目的和读者查找具体用法的需要组织，使用自然的、默认不编号的标题。下面是内容职责，不要求所有文章复制同一组标题或小节数量。

### 按用法展开

以具体用途或 API 方法组织正文，从基本用法逐步展开相关变体。每种用法让读者能找到：

- 适用场景，以及与前一种用法有关的差异。
- 经核实的代码示例、所在文件和必要的调用上下文。
- 关键参数、返回值、默认行为和影响结果的限制。
- 在示例 App 中怎样操作，以及应该看到什么结果。
- “查看源码”入口，指向固定提交下对应的文件或目录。

这些信息按需要写成连贯说明，不必每次重复五个小标题。正文保留关键代码，完整实现链接到文件；省略导入、组件或数据准备时明确说明，示例 App 中必须有对应的完整实现。

已有持续维护、地址稳定且可访问的在线示例时，在相应用法旁提供“在线体验”链接，直达对应 demo 页面，并说明必要的角色和后续操作。尚未部署在线示例时，提供源码链接即可。

每种有界面用法的 demo 都必须提供对应的实际运行截图，放在该用法的代码、操作说明和预期结果附近，直接展示该用法的效果。一个 demo 可以覆盖相关用法；同一界面状态已展示时，可明确链接到已有截图所在小节，避免重复插图；不同的弹窗、抽屉、权限或交互状态仍分别展示。截图使用英文界面，中英文文档共用。无界面用法提供执行输出或数据变化等结果示例。截图不能替代可操作示例和行为验证。

例如，路由专题讲到动态参数、嵌套页面、弹窗、抽屉、导航分组和权限差异时，每项都应有代码及 App 中可体验的对应场景，而不是只在文末附一个普通列表 App。

### 配置、边界与验证

共用配置和易错点集中解释一次，少见限制可以放在速查或常见问题中；具体用法必需的条件仍放在该示例附近。配置表用来方便查阅，不能代替用法示例。

给出读者验证正常流程和关键边界的方法、命令与预期结果。测试通过数量、执行日志及作者的环境与检查结果记录放在示例 README 或 PR 中；正文保留影响读者运行和判断结果的前提与验证范围。运行命令和共同验证步骤不必在每节重复。不强行添加“下一步”、重复总结或与专题无关的导航。

### 示例源码与运行

用法指南先介绍具体用法，完整 App 的源码、安装和启动集中放在文末“示例源码与运行”，开头可简短介绍示例并提供入口。需要读者跟做的教程则在操作前交代运行准备。

提供对应 App 的固定提交源码和启动入口，交代真正影响运行的版本、前提、工作目录和命令；较长的通用准备步骤链接到对应指南或示例 README。示例采用的数据库、服务或部署方式要与必要条件区分。

## 验证与交付

实现或更新示例时，按其 README 从准备、启动到实际操作验证对应场景，并执行示例仓库要求的检查。对权限、持久化、关闭与返回、加载或提交失败等本篇涉及的关键行为，使用能检验该行为的测试或操作；构建成功和截图不能单独证明这些结果。

在示例 README 或 PR 中记录实际使用的依赖版本、源码提交、运行环境、已执行的检查和未验证项。区分源码审阅、预期行为和实际运行结果，不把已有验证记录写成本次重新验证。仅修改文字时，按改动范围检查文档和相关引用即可；已有示例缺失或无法运行时如实列出缺口。

交付前确认：

- 本篇介绍的用法均能对应到示例中的实现和观察方式，代码片段、截图或执行结果、说明与实际行为一致。
- 中文和英文的 API、示例、源码链接、版本及验证范围一致；修改示例行为时同步受影响的截图和说明。
- 内容、菜单、链接和锚点保持一致，文档检查按仓库 [AGENTS.md](../../../AGENTS.md) 执行。
- 报告清楚本次修改了哪些文档或示例，以及实际完成的文档检查和应用验证。
