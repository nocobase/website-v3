---
title: ビルド成果物の管理
---

## アプリパッケージ、バージョン、成果物

`package.json.name` がアプリパッケージを識別します。バージョンは変更不可の配布単位、成果物はアップロードするアーカイブです。1 パッケージに複数バージョンを持て、1 バージョンから複数インスタンスを作れます。

開発プロジェクトを作る `sub-app` テンプレートと、配置するビルド済みバージョンは別です。

## 成果物をアップロードして公開する

子アプリで実行します。

```bash
pnpm nocobase deploy artifact upload --build --yes
```

初回はパッケージも作成します。画面を使う場合は `pnpm build --tar` で `storage/exports/dist.tar.gz` を生成し、Main の **System settings → Deployment management → Build artifacts** で **Upload build artifact** を選択します。名前、バージョン、検証結果を確認して送信します。

公開だけではインスタンスは作成・更新されません。変更したコードは新しいバージョンにし、旧成果物を削除して同じ番号で置き換えないでください。

## ビルド情報と設定項目を確認する

バージョン詳細で OS、CPU、libc、Node.js、DB ドライバー、SSO 依存関係、設定例、変数宣言を確認します。これらの宣言が作成フォームに反映されます。

不足するドライバーやプラグインは子アプリに追加・登録して再ビルドします。インスタンス設定の変更では依存パッケージを追加できません。DB、アップロード、秘密情報、インスタンスの `config.yml` は成果物に含めません。

## 同じバージョンから複数インスタンスを作る

バージョンやパッケージの追加メニューで **Create application instance** を選び、別々の ID、名前、ノード、DB、設定を指定します。SSO 資格情報もインスタンスごとに発行されます。

同じコードを再ビルドせず繰り返し配置できます。手順は[アプリインスタンスの管理](management.md)を参照してください。

## 関連するインスタンスを確認する

パッケージの **Application instances** タブで配置状況を確認し、詳細で実際のバージョンを照合します。更新可能の表示は更新完了を意味しません。実行状態と操作記録で判断します。

## バージョンを非推奨・復元・削除する

追加メニューから古い版を非推奨にできます。実行中のインスタンスは停止しません。復元すると再び利用できます。

削除前に参照を確認します。CLI では `artifact delete 0.0.1 --confirm-delete 0.0.1 --yes` のように対象を再指定します。実際の番号に置き換え、不要と確認してから実行してください。サーバーの参照・状態チェックは引き続き適用されます。成果物削除はインスタンス削除の代わりにはなりません。
