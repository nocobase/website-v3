---
title: 独立してデプロイされた子アプリを接続する
description: 子アプリの既存のデプロイを維持したまま、メインアプリのワークベンチに接続し、シングルサインオンとユーザーのアクセス権を設定します。
---

子アプリが独自のサーバーですでに稼働している場合は、デプロイパッケージのアップロードやホスト型インスタンスの作成をせずに、メインアプリに接続できます。メインアプリはワークベンチの入口とシングルサインオンを提供し、子アプリのデプロイ、アップグレード、バックアップは引き続きそのアプリの担当者が管理します。

ログイン設定が自動的に提供されるホスト型インスタンスとは異なり、独立してデプロイされた子アプリでは、登録後に担当者が SSO 設定を自身のプロジェクトと実行環境に適用する必要があります。

## メインアプリに子アプリを登録する

完全な管理権限を持つアカウントで、メインアプリの **Application instances → Connected applications** を開き、**アプリを接続**（Connect application）をクリックします。

1. アプリ名を入力します。
2. アプリの種類に **Independent NocoBase 3** を選択します。
3. `https://crm.example.com/` など、アプリの完全なアクセス URL を入力します。`/crm/` 配下にデプロイされている場合は、そのパスも含めてください。クエリパラメーターは含めません。
4. ログイン方法に **Platform sign-in** を選択し、保存します。

![独立したアプリの名前、アクセス URL、ログイン方法を登録する](/assets/core/multi-app/external-connect.png)

メインアプリと子アプリには、アクセス可能な HTTPS の URL を使用してください。管理されたローカル環境や内部ネットワークで HTTP を使う場合は、先にメインアプリで[対象のオリジンを許可](environments.md#デプロイ環境を追加する)します。

ワークベンチへの入口だけが必要で、シングルサインオンが不要な場合は、Web アプリとリンク方式を選択できます。ユーザーは引き続き、元のサイトのアカウントでログインします。OIDC に対応するサードパーティのアプリでは、Web アプリとシングルサインオンを選び、そのアプリが指定する正確なコールバック URL を入力してください。

## 子アプリにシングルサインオンを設定する

登録が完了しても、子アプリのログイン連携が完了したわけではありません。接続したアプリの詳細を開き、ログイン連携の領域で **Copy setup instructions** を選択し、その子アプリを担当する開発者または信頼できる Agent に渡してください。

子アプリのプロジェクトディレクトリで Agent のセッションを開き、セットアップ手順と、既存ユーザーや業務権限をどう維持するかを伝えます。Agent は、プラットフォーム経由のログイン、業務ロール、アプリ切り替えの入口を組み込む必要があります。準備はホスト型アプリと同じです。[子アプリのデプロイパッケージを準備する](templates.md#子アプリのデプロイパッケージを準備する)のログイン連携の説明を参照してください。独立したアプリでは、その節のホスティング用パッケージをビルドする手順は不要です。

セットアップ手順の表示時にはシークレットがマスクされますが、コピーした内容にはシークレットの値がすべて含まれます。信頼できる相手にのみ渡し、Git や公開の会話には載せないでください。

手動で設定する場合は、セットアップ手順内の `serverEnvironment` を子アプリのサーバーの非公開環境設定に反映します。

| 設定 | 設定方法 |
| --- | --- |
| `PLATFORM_SSO_ISSUER`、`PLATFORM_SSO_APP_ID`、`PLATFORM_SSO_CLIENT_ID`、`PLATFORM_SSO_CLIENT_SECRET` | メインアプリがこのアプリ用に生成した値を使います。他のアプリの設定をコピーしないでください |
| `PLATFORM_URL` | 手順に記載されたメインアプリの入口を使います。`/main/` などのパスも含めてください |
| `APP_PUBLIC_ORIGIN`、`APP_BASE_PATH` | 登録した子アプリの URL と一致させます |

設定後、子アプリを再デプロイまたは再起動します。子アプリのサーバーからメインアプリのログインサービスにアクセスできる必要があります。ログインコールバックは、セットアップ手順内の `callbackUrl` と一致させてください。

既存の業務システムを接続する場合は、元のデータベース、ユーザー、業務権限を保持し、再初期化しないでください。プラットフォームのアカウントと既存のローカルアカウントは、メールアドレスが同じだけでは自動的に統合されません。既存のアカウントを使い続ける場合は、先に開発者がアカウントの関連付け方法を確認し、ローカル管理者のログインも残してください。

サードパーティの OIDC アプリには NocoBase のログインプラグインをインストールしません。そのアプリ自身のログイン設定に、セットアップ手順内の URL とクライアント認証情報を入力します。

## アクセス権を付与してログインを確認する

1. 接続したアプリの**アクセス権**（Access）でユーザーを追加し、閲覧または編集権限を選択します。アプリを登録しても、既存ユーザーに自動的にアクセス権が付与されることはありません。
2. アクセス権を付与したユーザーでメインアプリにログインし、ワークベンチで対象アプリをクリックします。パスワードの再入力なしで業務画面に進めることを確認してください。
3. 閲覧・編集操作が子アプリの業務権限に従っていることを確認します。続けて[アプリ切り替えメニュー](management.md#ワークベンチからアプリを開く切り替える)を開き、別のアプリへの移動とワークベンチへの復帰を確認してください。

メインアプリの管理者にも、別途そのアプリへのアクセス権が必要です。アクセス権のないアカウントでも検証し、メインアプリ経由でその子アプリにログインできないことを確認してください。

## アプリの接続情報を管理・無効化する

接続したアプリの詳細で、ユーザーのアクセス権を管理します。ユーザーのアクセスが不要になったら、そのアクセス権を取り消します。アプリ全体の接続が不要になった場合は、無効化します。

無効化すると、メインアプリに入口が表示されなくなり、プラットフォームの認証情報を使ったアクセスも許可されなくなります。ただし、外部サーバーの停止や業務データの削除は行われません。Web リンクへの直接アクセスは、常にリンク先のサイトが制御します。

既存の接続の URL と種類は、その場では変更できません。変更が必要な場合は、新しい接続とログイン設定を用意し、ユーザーが正常にアクセスできることを確認してから、古い入口を無効にしてください。既存アカウントの関連付けを直接上書きしたり、古いアプリのシークレットをコピーしたりしないでください。セットアップ手順を再生成しても、シークレットがローテーションされたことにはなりません。
