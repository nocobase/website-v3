---
title: アプリインスタンスの管理
---

## バージョンとノードを選んで作成する

**System settings → Deployment management → Application instances** の **Create instance**、または成果物バージョンの追加メニューから開始します。

パッケージ、バージョン、利用可能なノード、表示名、固有 ID を選び、DB、設定、初期管理者、プラットフォーム接続を設定します。ID はパスに使われ、`main` は予約されています。

必須項目と互換性を確認して送信します。承認対象なら承認後に進みます。操作完了と正常な実行状態を確認してから実際にアクセスします。

![バージョン、実行ノード、データベースを選び、作成前にアクセス URL を確認します。](/assets/core/multi-app/hd-create-instance.png)

## 状態を確認してアプリを開く

詳細に実際のバージョン、ノード、URL が表示されます。**Open application** で開き、保守操作は追加メニューから選びます。一般ユーザーはワークベンチを使います。

実行中はログインや業務機能の正常性を保証しません。初回、更新後、ログイン設定変更後は実際の画面を確認します。

![インスタンス一覧で実行状態と現在のバージョンを確認します。](/assets/core/multi-app/hd-application-instances.png)

## 初期管理者を保存する

生成された管理者は **View and save** で権限を持つ人が確認・保存します。保存済みと確認すると Main はパスワードを保持しなくなります。CLI では取得できません。

初期管理者は初期化時のみ作成されます。初期設定の変更で既存パスワードはリセットされません。以後は子アプリのアカウント回復機能を使います。

![生成された管理者の資格情報を保存してから確認します。画像ではパスワードを非表示にしています。](/assets/core/multi-app/hd-save-initial-admin.png)

## 名前と設定を変更する

追加メニューで変更する名前は表示名です。ID やアクセスパスは変わりません。

**Configuration** で生効値を確認・編集します。インストール後の DB 種類は変更できません。SSO 資格情報は Main が管理します。新しいドライバーやプラグインは対応した版を先に公開します。

変更内容とバックアップを確認して適用します。再起動が伴う場合は操作記録と実際の設定を確認してください。

![Configuration で実行条件と現在有効なインスタンス設定を確認します。](/assets/core/multi-app/hd-instance-configuration.png)

## 起動・停止・再起動する

追加メニューから実行し、完了後に状態を更新します。停止してもデータと入口設定は保持されます。再起動は接続を中断するため、利用状況を考慮します。

入口の無効化はアクセス制御、停止はプロセス制御です。

## バージョンを更新する

[新しいバージョンを公開](artifacts.md)してから更新を選びます。版、設定差分、変数、DB 要件を確認し、競合を解決してバックアップを確認します。

完了後に実際の版、ログイン、データ、主要操作を確認します。ダウングレードでは DB マイグレーションを戻せません。

## 承認を処理する

承認対象ノードでは、別の承認権限を持つ管理者が内容と影響を確認して承認・拒否します。申請者自身は承認できません。

ノード設定や状態が変わった場合は案内に従って再確認・再申請します。承認待ちは成功ではなく、承認回避のためにノードを変更してはいけません。

## 操作記録とログを確認する

インスタンスの **Deployment history** と全体の **Deployment records** で、操作の段階、エラー、デプロイログを確認します。**Logs** は実行中アプリの出力です。

調査にはインスタンス ID、操作 ID、時刻、エラーコードを記録します。保持期間やサイズ制限でログがない場合も、操作未実行とは限りません。

![Deployment records に各インスタンスの操作結果が集まります。](/assets/core/multi-app/hd-deployment-records.png)

![デプロイログで展開、起動、有効化、完了の各段階を確認します。](/assets/core/multi-app/hd-deployment-logs.png)

![実行ログでアプリの出力を確認し、問題を調べます。](/assets/core/multi-app/hd-runtime-logs.png)

## 失敗を調べて中断した操作を回復する

ノード、互換性、DB 接続、必須変数、コールバック設定など、実際の原因をログから確認します。原因を直して元の操作の再試行・回復を使います。

タイムアウトや結果不明では、まず元の記録を照会します。同名で再作成したり操作ファイルを消したりせず、現在状態と承認規則に従って回復します。CLI については[子アプリの開発とデプロイ](development.md#agent-と-ci-でデプロイする)を参照してください。

## 削除とデータ保持

対象 ID とバックアップを確認します。既定の削除は永続データを保持し、明示的な消去と追加確認を行った場合のみ対象データを削除します。保持は自動移行やワンクリック復旧を意味しません。

Main はアクセスを撤回してから実行リソースを除去します。失敗時は元の記録で確認します。外部接続アプリの稼働とデータは、元の運用者が管理します。
