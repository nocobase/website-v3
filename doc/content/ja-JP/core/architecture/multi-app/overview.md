## マルチアプリが適している場面

業務システムを個別に開発・リリース・運用しながら、共通の入口とアカウントで利用したい場合に使います。たとえば、顧客管理と在庫管理のデータやバージョンを分離し、メインアプリのワークベンチからアクセスできます。

同じアプリ内でページやナビゲーション、ユーザー向けの入口を分ける場合は、[マルチポータル](../multi-portal/create-app.md)を検討してください。マルチアプリでは、インスタンスごとのデータベースと運用が必要です。

> [!NOTE]
> このガイドは新しいマルチアプリのデプロイ管理を対象とします。利用する配布元に、互換性のある `multi-app`、`sub-app` テンプレートとプロジェクト用デプロイ CLI が公開されていることを確認してください。ソース候補の機能が公開パッケージに含まれるとは限りません。旧 Releases の設定・操作手順は適用できません。

## メインアプリ、子アプリ、アプリインスタンス

| 用語 | 役割 |
| --- | --- |
| メインアプリ（Main） | ワークベンチ、プラットフォームアカウント、SSO、デプロイ管理を提供 |
| 子アプリ | 独自のコード、依存関係、バージョンを持つ業務プロジェクト |
| アプリインスタンス | あるバージョンを配置した実体。個別の設定、データ、URL を持つ |

メインアプリを作成しても、子アプリは自動作成されません。同じ子アプリを複数のインスタンスとして配置できます。名前は表示用で、インスタンス ID は識別とアクセスパスに使われます。

## ビルド成果物、バージョン、実行ノード

子アプリをビルドするとデプロイアーカイブが生成され、アップロードによりアプリパッケージの変更不可のバージョンとして公開されます。実行ノードはデプロイ操作を実行し、インスタンスを動かします。

流れは **子アプリのプロジェクト → ビルド成果物 → 公開バージョン → 実行ノード上のインスタンス** です。公開だけではインスタンスの作成や更新は行われません。

現在は、同じマシン上で独立した App Host プロセスを起動するローカル実行ノードに対応しています。ノードは Main の設定で定義し、起動時に自動開始します。ノード画面は設定と状態の確認用です。リモートマシンの登録や Docker オーケストレーションは、この手順の対象外です。

## データ分離、SSO、業務権限

インスタンスごとに業務データ、設定、秘密情報、ファイルを管理します。同じデータベースサーバーを使う場合も、データベースまたは名前空間を分離してください。開発用データベースやアップロードファイル、インスタンスの秘密情報は成果物に含めません。

SSO は有効なプラットフォームユーザーの本人確認を行いますが、Main のロールを子アプリにコピーしません。Main の管理者も子アプリの管理者には自動でなりません。[SSO と業務権限](single-sign-on.md)を参照してください。

## Main とプラグインの役割

Main テンプレートはシェル、システム設定、プラグイン構成を提供します。Deployment は成果物、バージョン、ノード、インスタンス、デプロイ操作を担当します。Multi-app は管理画面、ワークベンチ、プラットフォーム接続を担当します。Identity Provider と子アプリの Platform SSO が統一ログインを提供します。

テンプレートでは必要な統合が済んでいます。既存アプリでは、そのアプリの構成に合わせた統合が必要です。ログイン URL のコピーだけでは完了しません。

## ワークベンチとデプロイ管理

一般ユーザーは **Workbench** からアプリを開きます。権限を持つ管理者は **System settings → Deployment management** を使います。

| 入口 | 操作 |
| --- | --- |
| Application instances | 作成、設定、更新、運用、既存アプリの接続 |
| Build artifacts | アーカイブのアップロードとバージョン管理 |
| Runtime nodes | 設定、利用可否、実行要件の確認 |
| Deployment records | 進捗、承認、ログの確認 |

デプロイ管理権限と子アプリの業務権限は別です。

## 前提条件

Node.js 24 以降、テンプレートに対応する pnpm、商用パッケージのダウンロード権限が必要です。Main には安定した URL、独立したデータベース、永続ストレージを用意します。実行ノードは成果物の OS、CPU、libc、Node.js 要件を満たす必要があります。

初回は[クイックスタート](quickstart.md)、既存システムには[既存アプリの接続](external-apps.md)を使ってください。
