## マルチアプリを使う場面

複数の業務システムでデータ、設定、リリースバージョンを個別に管理しながら、共通の入口とログイン体験を提供したい場合に、マルチアプリ構成を利用できます。

| 業務上の要件 | 利用方法 |
| --- | --- |
| 複数の店舗で同じ在庫管理機能を使い、データは店舗ごとに保存する | 店舗ごとに独立した在庫管理アプリを稼働させ、データと更新時期を個別に管理する |
| 顧客管理と購買管理を別々のチームが担当し、リリース時期も異なる | アプリを個別に開発・デプロイし、共通のワークベンチからアクセスする |
| 既存システムを稼働させたまま、共通の入口を追加する | システムをワークベンチに追加し、必要に応じてシングルサインオンを連携する。既存のデプロイ方法は維持する |
| 複数の入口で同じアプリ、データ、バージョンを共有する | アプリを分割せず、[マルチポータル](../multi-portal/create-app.md)を利用する |

プラットフォームは子アプリをデプロイ・管理できるほか、すでに独立して稼働しているシステムにも接続できます。アプリ間で業務データが自動的に共有されることはありません。データを交換する場合は、API と適切な権限を使って連携します。

## メインアプリと子アプリ

**メインアプリ**は、ワークベンチ、アプリ管理、シングルサインオンを提供します。ログインしたユーザーは、ワークベンチからアクセス権のあるアプリを開きます。

**子アプリ**は、顧客管理、在庫管理、経費管理などの業務を担います。子アプリごとに画面、データ、設定、業務権限を持ち、個別に開発・デプロイ・更新できます。

![現在のユーザーがアクセスできる顧客管理アプリと経費管理アプリを表示するワークベンチ](/assets/core/multi-app/workbench.png)

メインアプリはユーザーがどのアプリに入れるかを決め、子アプリは入った後に何ができるかを決めます。たとえば、在庫管理アプリへのアクセスを許可された従業員が在庫を調整できるかどうかは、そのアプリの業務権限で決まります。メインアプリの管理者が、自動的に子アプリの管理者になることはありません。

子アプリは独自のログイン方法を使うことも、メインアプリのシングルサインオンと連携することもできます。シングルサインオンは、ユーザーテーブル、業務データ、すべての権限を共有する仕組みではありません。

## 利用の前提条件

マルチアプリには、互換性のあるバージョンの商用プラグイン、有効な商用ライセンス、パッケージのダウンロード権限が必要です。プロジェクトテンプレートには商用プラグインの実装は含まれず、商用ライセンスも付与されません。

| プラグイン | 利用するアプリ | 提供する機能 |
| --- | --- | --- |
| `@nocobase/app-plugin-multi-app` | メインアプリ | アプリテンプレート、バージョン、インスタンス、外部アプリの入口の管理 |
| `@nocobase/app-plugin-identity-provider` | メインアプリ | プラットフォームの認証サービス、OIDC クライアント、メンバーのアクセス権管理 |
| `@nocobase/app-plugin-platform-sso` | 子アプリ | プラットフォーム経由のログイン、セッション確認、アプリの切り替え |

新規プロジェクトは[クイックスタート](quickstart.md)から始めてください。既存の NocoBase 3 アプリを利用する場合は、[独立してデプロイされた子アプリを接続する](external-apps.md)で接続方法を確認してください。
