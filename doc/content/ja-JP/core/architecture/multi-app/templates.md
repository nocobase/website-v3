---
title: アプリテンプレートを管理する
description: 子アプリをデプロイ可能なバージョンとしてパッケージ化し、メインアプリからホスト型インスタンスを作成するためのテンプレートを管理します。
---

アプリテンプレートには、子アプリのデプロイ可能なバージョンを保存します。たとえば、顧客管理アプリをテンプレートとしてアップロードすると、チームごとに顧客管理インスタンスを作成できます。各インスタンスは同じ業務機能を使いますが、データと設定は個別に保持します。

メインアプリの**アプリテンプレート**（Templates）では、テンプレートの最新バージョンとインスタンス数を確認できます。ここで扱うテンプレートは既存のアプリをデプロイするためのもので、ソースプロジェクトの作成時に選ぶ `default` プロジェクトテンプレートとは異なります。

![公開済みバージョンと各テンプレートを使うインスタンス数を表示するアプリテンプレート一覧](/assets/core/multi-app/template-list.png)

## 子アプリのデプロイパッケージを準備する

子アプリのプロジェクトで業務機能を開発し、正常に動作することを確認してから、パッケージ化してメインアプリに渡します。メインアプリで子アプリのソースコードを保持する必要はなく、それぞれ別の Git リポジトリで管理できます。

**シングルサインオンとアプリ切り替えの準備。** デプロイ時にメインアプリから自動的に提供される SSO 設定を使うには、子アプリ側にプラットフォーム経由のログイン機能が必要です。まだ連携していないプロジェクトでは、子アプリのディレクトリでプラグインを登録してください。

```bash
pnpm nocobase plugin register @nocobase/app-plugin-platform-sso --dry-run
pnpm nocobase plugin register @nocobase/app-plugin-platform-sso
```

登録後、プロジェクトに同期された `nocobase-app-plugin-platform-sso` Skill に従って、ログイン画面、業務権限、アプリ切り替えの入口を組み込みます。子アプリのディレクトリで Agent に依頼することもできます。

```prompt
この顧客管理アプリをメインアプリのシングルサインオンに対応させ、サイドバーにアプリの切り替えとワークベンチに戻る入口を追加してください。
閲覧専用ユーザーは顧客を閲覧でき、編集ユーザーは顧客情報を管理できるようにしてください。ただし、ユーザー管理やシステム設定の操作は許可しないでください。シングルサインオンが使えない場合にアクセスを復旧できるよう、ローカル管理者のログインは残してください。
```

ホスト型のデプロイでは、メインアプリがログイン用クライアントを自動登録し、インスタンスにログイン設定を提供します。クライアントシークレットをソースコードやデプロイパッケージに書き込む必要はありません。

**デプロイパッケージのビルド。** 子アプリのルートディレクトリで実行します。

```bash
pnpm build --tar
```

生成されるファイルは `storage/exports/dist.tar.gz` です。デプロイパッケージは、実際の実行環境の OS、CPU アーキテクチャ、libc、Node.js のバージョンに対応している必要があります。別のマシンに配布する場合は、[デプロイ用アーカイブのビルド](../../tutorials/deploy-with-app-installer.md#デプロイ用アーカイブをビルドする)に従って対象のパラメーターを指定してください。開発用データベース、アップロードファイル、インスタンスのシークレットを共通のデプロイパッケージに含めないでください。

## テンプレートを作成してデプロイパッケージをアップロードする

1. メインアプリで**アプリテンプレート**（Templates）を開き、**テンプレートを作成**（Create template）をクリックします。
2. 名前と説明を入力し、確認済みの[デプロイ環境](environments.md)を選択します。
3. 作成後にテンプレートの詳細を開き、右上の操作メニューから **Upload archive** を選択して、子アプリの `dist.tar.gz` をアップロードします。

![名前、説明、デプロイ環境を指定してアプリテンプレートを作成する](/assets/core/multi-app/template-create.png)

アップロード後、認識されたアプリのパッケージ名とバージョンを確認してください。アップロードはデプロイパッケージを保存するだけです。インスタンスを作成するには、バージョンを公開する必要があります。

## バージョンを公開・管理する

テンプレートの操作メニューで**バージョンを公開**（Publish version）を選択し、アップロード済みの成果物から公開するバージョンを選んで確定します。

![アップロード、バージョン公開、テンプレートの無効化を行う操作メニュー](/assets/core/multi-app/template-actions.png)

公開すると、**公開済みバージョン**（Published versions）に表示されます。バージョンを選択して、[ホスト型インスタンスを作成](management.md#インスタンスを作成してアクセス権を付与する)できます。

![公開済みバージョンから新しいアプリインスタンスを作成する](/assets/core/multi-app/template-versions.png)

業務機能を更新するときは、元の子アプリのプロジェクトでコードを変更し、`package.json` のバージョン番号を更新してから、再度ビルド、アップロード、公開を行います。アプリのパッケージ名は変えず、公開済みバージョンを上書きしないでください。

新しいバージョンを公開しても、既存インスタンスは変更されません。各インスタンスは元のバージョンを使い続けることも、管理者が[個別にアップグレード](management.md#インスタンスをアップグレードアーカイブ復元する)することもできます。

## 使用しなくなったテンプレートを無効にする

テンプレートの操作メニューで **Retire template** を選び、対象を確認して確定します。無効化後はバージョンの公開や新規インスタンスの作成ができなくなりますが、既存のインスタンスとデータが削除されたり、稼働が停止したりすることはありません。

特定の業務アプリを停止する場合は、テンプレートを無効にするのではなく、対象の[アプリインスタンス](management.md#設定を変更し稼働状態を管理する)を操作してください。
