title: ポータルへのアクセスと権限
metaDescription: インストール状態、ページアクセス、業務権限、管理者専用ディレクトリを区別します。
---

ポータルのインストールはアプリ内で稼働可能にする操作であり、ページ、データ、操作の権限をユーザーに付与しません。認証と権限はアプリの仕組みを使用し、別のユーザー管理は作りません。

## テンプレートの既定動作

| 入口・機能 | 既定の動作 |
| --- | --- |
| 管理者ホーム | ポータルのワークベンチ |
| 一般ユーザーのホーム | 標準アプリのホーム |
| ポータル管理と一覧 API | ログイン済みで `unrestricted` 権限を持つ管理者が必要 |
| 生成されたポータルホーム | `auth: 'required'`、`authz: 'unrestricted'` |
| 既定の切り替え UI と `PortalPage` | 管理者用の一覧を使用し、ユーザー別の許可済みポータル一覧ではない |

管理者はワークベンチからインストール済みポータルに入り、サイドバーで切り替えたりワークベンチに戻ったりできます。インストールだけで一般ユーザーにも同じ画面が提供されるわけではありません。ホームの `authz` だけ変更しても、既定の一覧 API は拒否されます。

## 業務ユーザーへの提供

在庫管理だけを使える担当者を例に、次の対応を行います。

1. 在庫ホームと業務ページにアクセス要件を宣言し、ルートの安定した識別子と翻訳名を保持します。
2. 在庫照会、入庫、出庫などの操作とデータ範囲を宣言し、サーバーで検証します。
3. 権限管理で業務ロールを設定し、ユーザー管理で明示的に選んだユーザーに割り当てます。
4. 一般ユーザー向けの入口、切り替え、利用可能状態の取得を実装し、管理者用の一覧 API をそのまま再利用しません。

現在のテンプレートには一般ユーザー用のポータル一覧はありません。提供する場合、認証と業務権限で保護した問い合わせをアプリに実装し、利用可能なポータルと必要な情報だけを返します。ホーム、切り替え UI、ページの状態確認も対応させます。全員に `unrestricted` を付与したり、管理 API の管理者チェックを緩めたりして回避しないでください。

ロール、ページ権限、データ範囲は[権限管理](../../using-plugins/authorization/permissions.md)、アプリへの組み込みは[認証と権限](../../developing-apps/authentication-and-permissions.md)を参照してください。

## サーバーで利用可能状態を確認

業務 API は認証と業務権限に加え、ポータルがインストール済みか確認します。

```ts
import { portalCenterServiceToken } from '@nocobase/app-plugin-multi-portal/server';

// Inside an authenticated and authorized request handler with access to app.
await app.container.resolve(portalCenterServiceToken).requireInstalled('inventory');
```

これはインストール状態だけを確認し、本人確認や業務権限の代わりにはなりません。業務データの読み書き前に実行してください。アンインストール済み、または利用不可のポータルには API を直接呼んでもアクセスできないようにします。

ボタンやメニューの非表示、ブラウザーのルート制御は、サーバー側のチェックを代替しません。

## 権限境界の検証

| シナリオ | 期待する結果 |
| --- | --- |
| 未ログインで業務 API を呼ぶ | 拒否 |
| ログイン済みだが在庫権限がない | 直接 URL や API でも在庫業務を利用できない |
| 在庫ロールだけを持つユーザー | 許可された入口のみ表示し、操作とデータ範囲が設定どおり |
| 業務ユーザーが管理 API を呼ぶ | 拒否。業務権限は管理権限を与えない |
| アンインストール後に業務 API を呼ぶ | インストール状態のチェックで拒否 |

一般アカウントで検証し、継承を含むすべての権限付与元を確認します。管理者権限や別のロールが問題を隠していないことを確かめてください。入口変更後はモバイルメニュー、直接リンク、セッション期限切れも確認します。
