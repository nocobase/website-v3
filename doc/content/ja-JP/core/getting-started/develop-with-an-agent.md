機能を開発するとき、業務上の判断を下すのはあなたです。何を作るか、設計で問題ないか、結果が使えるか。エージェントは NocoBase のスキルに従ってコードを書き、テストを実行し、自分の作業を確認します。

## 要件を伝える

アプリのルートでエージェントを開き、業務の言葉で 3 つのことを説明します。

- だれが使うか。
- 何をする必要があるか。
- どんなルールがあるか：だれが何をできるか、どのデータを変えてはならないか。

「フォロー記録を編集できるようにするかはまだ決めていません」のように、未決のことはそう伝えましょう。エージェントに推測させないでください。すでにある設計、API の取り決め、業務資料は共有します。ページのレイアウト、ファイルの場所、テストの手順を指定する必要はありません。

たとえば、[最初の機能を開発する](build-your-first-app.md) の顧客管理にフォロー記録を追加するには、次のようにします。

```prompt
顧客にフォロー記録を追加してください。連絡するたびに、営業担当者が日付、方法（電話、訪問、メール）、メモを記録します。
フォロー記録は顧客の詳細に新しい順で表示してください。
営業担当者は自分の顧客にだけフォローを追加できます。営業マネージャーはすべての記録を閲覧できます。閲覧専用ユーザーは閲覧だけができます。
既存の顧客に過去のフォロー記録を追加する必要はありません。
```

本番環境、実データ、アカウントにかかわる作業の場合は、環境と、エージェントに許可することを明示してください。

## 設計を確認する

作成・編集の流れや詳細のドロワーなど、新しいページや操作の流れを作る前に、エージェントは設計を示して確認を求めます。設計には次の内容が含まれます。

- ページの構成と主な操作。
- 設計のレビューで見つかった問題と、その対処方法。
- あなたの判断が必要な質問。

質問に答えて設計を確認すると、エージェントは開発を始めます。この確認の待ちを省くには、依頼に「確認を待たずに、一度に作業を完了してください」と添えます。エージェントは最終報告に設計を含めます。

列の追加や文言の変更などの小さな変更では、エージェントは設計を作らずに直接編集します。

## 結果を確認する

開発が終わると、エージェントはテストを実行し、ブラウザーで機能を確認してスクリーンショットを撮り、次の内容を含む報告をします。

- 変更内容：ページ、ルート、ファイル。
- 検証中に見つかった問題と、修正の結果。
- 主要なスクリーンショット。
- 未解決または未検証のことと、その理由。

検証にサインインが必要な場合、エージェントは自分でサインインするよう求めます。あなたのパスワードを入力することはありません。

まず報告の未検証の項目を確認し、次に関係するロールのアカウントでアプリの主な流れを試します。問題があれば、何をして、何が起き、何を期待していたかを説明します。

```prompt
閲覧専用ユーザーでサインインしていますが、顧客の詳細でフォロー記録を追加できてしまいます。
閲覧専用ユーザーは記録を閲覧できても、追加はできないようにしてください。
```

エージェントが従うテストと検証の方法については、[テスト](../developing-apps/testing-and-acceptance.md) を参照してください。

## 大きな要件を分割する

一度に扱う範囲が広すぎると、設計が長くなり、判断が積み重なり、レビューで問題を見つけにくくなります。次のいずれかに当てはまる場合は、作業を分割します。

- 新しい種類のデータがいくつも必要で、それぞれに独自のページとロールがある。
- このステップが終わったときに、人が何をできるようになるかを説明できない。
- 業務上の判断がいくつも未決のまま残っている。

業務の機能ごとに分割し、各ステップで使えるものを届けます。たとえば、顧客管理を本格的な CRM に拡張するなら、4 つのステップに分けられます。

1. **フォロー記録**：営業担当者が顧客との連絡を毎回記録する。
2. **商談**：1 人の顧客に複数の商談を持たせ、それぞれに金額と受注予定日を付ける。
3. **見積**：商談の見積を作成する。
4. **営業レポート**：受注を営業担当者別、月別に集計する。

各ステップは、できあがった時点で使い始められます。使っていて見つかった問題は、次のステップで対処できます。

要件をデータ、API、ページに分割しないでください。それはエージェントの実装の手順です。データベースのテーブルだけができても、アプリで試せるものは何もありません。

分割の仕方がわからない場合は、コードを書く前にエージェントに計画を依頼します。

```prompt
顧客管理を、フォロー記録、商談、見積、営業レポートを備えた本格的な CRM に拡張したいです。
まだコードは書かないでください。それぞれ使えるものを届けるステップに分割し、各ステップで私に決めてほしいことを一覧にしてください。
```

計画が合意できたら、順番に進めます。各ステップは、要件を伝える、設計を確認する、結果を確認するという同じ流れをたどります。最初のステップを依頼するときに全体の計画を共有しておくと、初期の設計の選択が後の機能の余地を残したものになります。

## プロジェクトの規約を保存する

今後の作業にも適用すべきルールに合意したら、エージェントにプロジェクトのガイダンスとして保存してもらいます。

```prompt
今後、日付の計算にはすべて会社のタイムゾーンを使ってください。これをプロジェクトのガイダンスに保存してください。
```

エージェントはルールを `.agents/rules/` に書き、`AGENTS.md` の索引に追加します。以降のセッションやほかの開発者も、それに従えるようになります。エージェントがアプリのフレームワークの構成を変更したときも、何をなぜ変えたかをこれらのルールに記録します。
