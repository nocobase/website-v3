NocoBase は、ユーザー、認証、権限、ファイル、通知、エージェントなど、アプリでよく使う機能のプラグインを提供しています。このセクションでは、各プラグインが何をするか、どう設定するか、そのページ、コンポーネント、API、サービス、スキルをアプリでどう使うかを説明します。

以下のトピックから、必要なプラグインを探してください。インストール、登録、更新、削除の共通の手順については [プラグインを管理する](../developing-apps/manage-plugins.md) を参照してください。

## 組み込みの前に

アプリの実際の登録と、インストールされたバージョンを確認します。インストールしただけでは、プラグインは有効になりません。一部のプラグインには、設定のファクトリーや、アプリが所有するデータ、ページ、権限も必要です。

各ガイドの `/client` や `/server` などのパスは、そのパッケージの公開のエクスポートを指します。ページと HTTP のパスはアプリのマウント先からの相対パスで、`/main` のアプリでは `/api/users` は `/main/api/users` になります。リクエスト、レスポンス、アクセスの完全な取り決めは、動作中のアプリの `/api/swagger/docs` または `/api/swagger` で確認してください。

## プラグインの使い方のガイドを読む

各プラグインのガイドは、次の 4 つの章で構成されています。

1. **機能**：解決する問題、提供するページ、コンポーネント、API、サービス、スキルと、アプリが担うこと。
2. **シナリオと例**：業務上のニーズ、コーディングエージェント向けの開発用のプロンプト、使い方の手順、完了の基準。
3. **主な仕組みと実装**：組み込みの領域、コードと設定の変更、画面の変化、重要な仕組み。
4. **AI 開発の制約と検証**：プラグイン固有の境界、よくある間違い、検収の要件。

開発用のプロンプトは、現在のアプリのディレクトリで作業するコーディングエージェント向けです。まず `AGENTS.md`、アプリのルール、インストールされたバージョンに同梱の関連するスキルを読ませてください。開発用のスキルがない場合は、公開のインターフェース、型、ドキュメントを使います。第 4 章は AI を活用した信頼できる組み込みを扱うもので、プラグイン自体に AI の機能があることを求めるものではありません。共通の流れについては [アプリの開発を続ける](../getting-started/develop-with-an-agent.md) と [テスト](../developing-apps/testing-and-acceptance.md) を参照してください。

プラグインが提供する機能の種類はさまざまです。テンプレート印刷は実装のガイダンスを提供します。ユーザー管理は管理用の API と招待のページを提供し、管理画面はアプリが所有します。ナレッジベースとアプリケーション基盤は登録できるページを提供します。ページ、データ、業務ロジックをだれが所有するかは、各ガイドで説明しています。

これらのガイドは、2026-10-28 に、メインリポジトリのリビジョン [`015404ecd`](https://github.com/nocobase/nocobase/tree/015404ecd0dbed33cc46831f73907329c577d375/packages/plugins) と、商用の承認プラグインの公開の取り決めをもとに、ソースと照合しています。[エージェント](agents-and-knowledge/agents.md) には、別に検証したアプリの基準、スクリーンショット、ソースのダウンロードがあります。インストールされたバージョンは異なる場合があります。検証の手順は、利用するアプリでのチェックを記述したもので、ガイドの執筆時にすべてのプラグインの組み込みを実行したことを示すものではありません。
