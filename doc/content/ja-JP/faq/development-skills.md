---
title: "開発のたびに Skill を指定する必要がありますか？自分の Skills と競合した場合は？"
---

通常は業務要件を伝えるだけでよく、毎回 Skill を手動指定する必要はありません。ただし、Coding Agent がスキルの検出に対応し、プロジェクト内のスキルを読み取れることが前提です。自動選択は保証されません。規約が守られていない場合は、プロジェクトの `AGENTS.md` と該当する Skill を読むよう明示し、実行記録を確認します。

V3 アプリでは、プロジェクト内の `nocobase-app-development` が主な開発の入口です。`nocobase-data-modeling` や `nocobase-ui-builder` などのノーコード基盤向けスキルを、V3 Core アプリにそのまま適用しないでください。現在のアプリテンプレートも、グローバルにインストールされた NocoBase 2 Skills を使わないよう指定しています。[最初のアプリを開発する](../getting-started/develop-your-first-app.md)を参照してください。

独自の Skills で業務ルール、デザイン規約、受け入れ基準を補足できます。競合した場合は、対応バージョンとタスク範囲を確認したうえで、使用する Agent の指示優先順位に従います。「NocoBase Skills が常に優先する」という全ツール共通の規則はありません。合意したチーム規約はプロジェクト独自の指針で管理し、依存関係から同期生成される Skills を直接変更しないようにします。

Studio ではグローバル、プロジェクト、リポジトリのスキルが組み合わされ、同名なら範囲がより具体的なものが優先されます。これは適用範囲の規則であり、異なるスキル間の矛盾を自動解決するものではありません。[Studio のスキル](../studio/project/skills.md)を参照してください。
