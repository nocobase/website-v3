## 製品と開発方法の違い

NocoBase 2 では、ノーコードのページ、テーブル定義、権限、ワークフローを主にプラットフォームの設定で管理します。NocoBase 3 Core アプリでは、ページ、API、業務ロジック、データベースマイグレーションをアプリのソースで管理します。Core はランタイム、基盤ライブラリ、プラグインを npm パッケージとして提供し、Skills がエージェントによる利用を支援します。

アプリのコードはエージェントでも人でも保守できます。コード変更はブランチ、レビュー、テスト、デプロイを経て届けます。ユーザーやロール割り当てなどの日常的な管理データは引き続きデータベースに保存し、アプリに組み込んだ管理ページで変更できるため、毎回コードを編集する必要はありません。基盤機能と業務開発の範囲は [Core が提供する機能](core-capabilities.md)を参照してください。

## AI Portal と Core アプリの違い

[AI Portal](https://nocode.docs.nocobase.com/ai-builder/ai-portal/) は、ノーコード基盤が提供するデータ、認証、権限、API を使って独自の画面を開発します。Portal プロジェクト自体は主にクライアントコードです。エージェントはプラットフォームのツールでテーブル作成や権限設定も行えます。

V3 Core アプリは、Core の基盤機能を再利用しながら、クライアント、サーバー API、業務サービス、マイグレーションを自社リポジトリで管理します。違いは AI がコードを書くかどうかだけでなく、アプリの構造とバックエンドの管理方法にあります。V3 は V2 のノーコードページやデータモデリング画面を引き継ぎません。テーブル構造の変更は[テーブル作成とデータ初期化](../core/developing-apps/data-models-and-migrations.md)を参照してください。

## 機能の対応関係

| NocoBase 2 | NocoBase 3 | 備考 |
| --- | --- | --- |
| ユーザー、ロール、権限 | 認証、ユーザー、認可の各プラグインに加え、既定のデータ範囲、共有ルール、制限ルールの 3 つのプラグイン | 既定のテンプレートには関連プラグインが登録されています。管理ページは必要に応じて組み込み、業務操作とデータ範囲を定義します |
| データソースとコレクション | データベースの基盤ライブラリとマイグレーション。外部データベースは 2 つ目の接続として接続します | SQLite、PostgreSQL、MySQL、SQL Server、Oracle に対応。Dameng、KingbaseES、OceanBase は商用版で対応します |
| ファイルマネージャー | ファイルプラグインとストレージの基盤ライブラリ | ローカルストレージ、S3 互換ストレージ、Alibaba Cloud OSS |
| ワークフロー | レコードのライフサイクル（基盤ライブラリ）と定期タスクプラグイン | プロセスの構造はコードで書き、ドラッグ＆ドロップのデザイナーはありません |
| 承認 | 承認プラグイン <span class="tag pro">商用版</span> | 多段階承認、全員承認、いずれか承認、承認者の追加、転送、差し戻し |
| 通知とアプリ内メッセージ | 通知、アプリ内メッセージ、通知チャネルの各プラグイン | アプリ内メッセージ、メール（SMTP、Resend）、Feishu と DingTalk のグループボット |
| メール管理 | メールプラグイン | 個人のメールボックスを連携し、メールの送受信と同期を行います |
| AI 従業員と AI ナレッジベース | Agents プラグインとナレッジベースプラグイン | 既定のテンプレートに依存関係が含まれます。利用時にプラグインと画面を組み込み、モデルやナレッジを設定します |
| 多言語化とテーマ | 多言語化プラグイン。テーマはテンプレートに含まれます | |
| API キー | API キープラグイン | 既定のテンプレートで有効 |
| テンプレート印刷 | テンプレート印刷のスキルパック | エージェント向けのガイダンスのみです。実装はエージェントがアプリ内で行います |
| グラフ、インポート・エクスポート、その他のブロック | エージェントがアプリ内で実装 | UI ライブラリがデータテーブルやダッシュボードなどのコンポーネントを提供します |
| 監査ログ | まだ提供されていません | **App foundation** の監査の項目には、プロバイダーがまだ検出されていないことが表示されます |
| LDAP、SAML、DingTalk、WeCom、Feishu、Slack などのサインイン方法 | 認証プラグイン | Better Auth を拡張し、提供元とプロトコルに応じて設定または開発します。アカウント対応とコールバックの検証が必要で、すべてが初期状態で使えるわけではありません |

アプリが使うプラグインの確認、登録、更新、削除については、[プラグインを管理する](../core/developing-apps/manage-plugins.md) を参照してください。

## NocoBase 2 の更新は続きますか？

はい。NocoBase 2 と NocoBase 3 は並行して保守されます。V3 の登場によって既存の V2 アプリを移行する必要はありません。方針は[公式パートナー情報](https://www.nocobase.com/partner/)、各バージョンの機能・改善・修正は [NocoBase 2 リリース履歴](https://nocode.nocobase.com/en/blog/timeline)を参照してください。アーキテクチャと開発方法が異なるため、すべての機能が両方で同時に提供されるという意味ではありません。

## NocoBase 3 を使うには NocoBase 2 のインストールも必要ですか？

いいえ。V3 Core アプリは独自のランタイム、データベース、基盤機能を持ち、V2 をインストールせずに開発・デプロイ・運用できます。

既存の V2 システムがある場合は、必要に応じて API などで新しいアプリと連携できます。これは任意のシステム連携であり、V3 の実行に必要な依存関係ではありません。認証、データ、権限の境界を明確にしてください。[既存システムとの連携](existing-systems.md)を参照してください。

## 既存アプリの移行

アプリの構造が異なるため、バージョン番号やイメージを変更するだけで V2 アプリを V3 Core アプリに更新することはできません。通常は元の業務要件に基づいてページ、API、データ構造、権限を再構築し、業務データをインポートします。

移行前にテーブルと関連、ロールとデータ範囲、ワークフロー、添付ファイル、外部連携を整理し、移行後にデータの対応関係と実際の業務操作を検証します。ノーコード設定、プラグイン設定、AI 従業員設定をそのまま再利用できるとは限りません。業務 AI は [AI アシスタントの追加](business-ai.md)、データの復元と移動は[バックアップ・復元・移行](backup-and-migration.md)を参照してください。

[Core のアップグレードガイド](../core/developing-apps/upgrade-nocobase-core.md)は、V3 アプリ内のフレームワーク依存関係とテンプレートを更新するためのものです。V2 から V3 への自動移行ツールではありません。
