NocoBase 3 は、従来のローコード／ノーコードプラットフォームと比べて、開発の進め方、デリバリーの速さ、実現できる範囲の上限、そしてシステムのあり方そのものが本質的に異なります。

## 開発スピードと拡張性の限界

- **開発スピード**：従来のローコードプラットフォームでは、人が画面ごとにパーツをドラッグ＆ドロップし、フィールドを設定し、数式やルールを組み合わせて検証する必要があるため、業務が複雑になるほど時間がかかります。NocoBase 3 では、コーディングエージェントが統一されたアプリケーション基盤の上で業務のソースコードを直接書き、さらに Studio を使えば複数の要件を 24 時間並行して進められるため、一般的な要件であれば数時間のうちに検収可能な状態で仕上がります。
- **拡張性の限界**：ローコードプラットフォームは用意されたコンポーネントやデータモデル、拡張仕様の枠内に制約されるため、複雑な業務ルール、独自の画面操作、既存システムとの深い連携が必要になると回避策を講じるか行き詰まりがちです。NocoBase 3 が生成するのは標準的な TypeScript・React・Node.js のソースコードであるため、既製コンポーネントによる機能の上限がなく、複雑な基幹業務システムも通常のソフトウェア開発と同じ品質で実装できます。

## コードの所有権と稼働方式

- **プラットフォームへのロックインがない**：ローコードプラットフォームで作ったアプリは専用の実行基盤や独自のメタデータ設定に依存するため、プラットフォームから切り離して独自に保守・移行するのが困難です。NocoBase 3 では業務のソースコードがそのまま自社の Git リポジトリに保存されるため、一般的な開発チームがいつでも人の手で引き継いで保守できます。詳しくは[AI が開発したアプリを人が引き継いで保守できますか？](human-maintenance.md)を参照してください。
- **リリース後の独立稼働**：NocoBase の業務アプリは自社のサーバーにデプロイされ、リリース後は独立して稼働します。日常の業務リクエストが Studio を経由することはありません。詳しくは[開発したアプリを独立してデプロイ・運用できますか？](independent-deployment.md)を参照してください。

## 日常の業務運用

従来のローコードプラットフォームで作られるのは、あくまで人が操作することを前提とした業務システムであり、データ入力や伝票の回覧、案件のフォローアップはすべて人が行う必要があります。

NocoBase 3 のアプリケーション基盤には、モデル接続、業務エージェントの実行基盤、AI ナレッジベースが標準で内蔵されています。システム稼働後は、業務エージェントが担当者の権限の範囲内で 24 時間自律的に日常業務を進め、重要な判断が必要な場面だけ根拠を添えて人に確認を求めます。詳しくは [NocoBase Solution](https://www.nocobase.com/ja-JP/solutions/) および[アプリに AI アシスタントを追加するには？従来の AI 従業員は使えますか？](business-ai.md)を参照してください。

以前 NocoBase 2 のノーコード機能を利用されており、2.x と 3.x の位置づけの違いや選定のポイントを知りたい場合は、[NocoBase 2 と NocoBase 3](from-v2.md) を参照してください。
