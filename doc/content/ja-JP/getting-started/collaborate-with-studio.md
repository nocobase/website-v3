1 つのコマンドで無料の Studio コミュニティ版と最初のプロジェクトを自分のコンピューターにインストールし、要件の提出、エージェントによる開発、チェック・レビュー、検収までを一通り体験します。

## 前提条件

- macOS、Linux、または Windows の WSL と Docker Desktop
- Compose v2 を含む Docker が起動していること
- Node.js 24、Git、curl
- インストールしてサインイン済みの Coding Agent が 1 つ以上あること（Claude Code、Codex、OpenCode、Pi など）

## ワンコマンドでインストールしてサインインする

ターミナルで次を実行します。

```bash
curl -fsSL https://get.nocobase.com/studio | sh -s -- --lang ja-JP
```

`--lang ja-JP` によりインストーラーと Studio が日本語になります。その他のオプションは[インストーラーのオプション](../studio/setup/install.md#インストーラーのオプション)を参照してください。

インストーラーはこのコンピューターに次を自動で用意します。

- Studio コミュニティ版（データは `~/.nocobase-studio/` に保存）
- プロジェクトリポジトリ用のローカル Git サーバー（Gitea）
- このコンピューターを[個人ランタイム](../studio/join/personal-runtime.md)として接続し、ここで Coding Agent がタスクを実行
- 最初のプロジェクト **My first project**（Core ベースの NocoBase 3 アプリを含み、テスト環境にデプロイ済み）

完了すると、Studio のアクセス先 URL とログインアカウントがターミナルに表示されます。`http://127.0.0.1:13000/main` を開き、表示されたアカウントとパスワードでサインインして（サインイン後に「個人設定 › アカウントとセキュリティ」でパスワードを変更できます）、最初のプロジェクトの会話へ進みます。

会話にはエージェントが作成した初期計画と、**開始** ボタン付きの提案タスクが表示されています。そのまま **開始** を押して試すことも、以下の手順で自分の要件を新しく出すこともできます。

## テスト環境のアプリを開く

会話にあるエージェントの最初の返信は、テスト環境のアドレスとアカウントから始まります（既定は `http://127.0.0.1:13000/my-first-project-staging/`）。

このアドレスを開いて返信内のアカウントでサインインすると、初期化された NocoBase 3 アプリを確認できます。10 分間アクセスがないと自動で停止し、次回アクセス時に再起動します。Studio の[マネージド環境](../studio/admin/environments.md)からも確認できます。

## 要件を提出して案を確認する

プロジェクト画面で「新規タスク」をクリックし、業務目標と確認方法を伝えます。例：

```prompt
仕入先ページを追加してください。名前、担当者、電話番号、取引ステータスを記録し、購買担当者が新規作成・編集・閲覧できるようにします。

完了後、仕入先を 1 件追加し、ステータスを一時停止に変更して、一覧でステータス別に絞り込めることを確認したいです。
```

エージェントは不明なルールを質問したうえで、タスクとして整理します。内容を確認して「実行開始」をクリックします（「手動入力」に切り替えて直接作成することもできます）。

![新規タスク作成時に会話で目的と業務ルールを補足する画面](https://static-docs.nocobase.com/studio-en-new-task-20261111-normal-2x.webp)

開始するとタスクは「進行中」になり、コーディネーターエージェントが設計・開発・テスト・レビューを割り振ります。既存の業務規定や項目定義がある場合は、タスクに添付するか[ナレッジベース](../studio/project/knowledge-base.md)に登録しておけます。

## 開発・チェック・レビューを追う

タスク上部には現在担当しているエージェント、ランタイム、次のステップが表示されます。「アクティビティ」に引き継ぎ・返信・レビュー結果が残り、「実行履歴」で詳細な実行内容を確認できます。

![現在の実行ステップと次の予定を示すタスク詳細画面](https://static-docs.nocobase.com/studio-en-req-now-20261111-normal-2x.webp)

実行エージェントは専用ブランチでコードを変更して PR を作成し、チェックとレビューの結果も同じタスクにひも付きます。チェック失敗やレビュー指摘があれば、コーディネーターエージェントが自動で修正と再検証を手配し、すべて通過してから検収に回します。詳しくは[チェックとレビュー](../studio/project/checks-and-review.md)を参照してください。

## 質問に回答して結果を検収する

業務判断が必要なときはタスクが「ブロック中」になり、「マイタスク › 対応待ち」の先頭に並びます。「あなたの対応が必要」カードで回答すると、コーディネーターエージェントが作業を再開します。

タスクが「検収待ち」になったら次を確認します。

1. 納品レポートを読み、変更内容、検証結果、未検証項目を確認する。
2. 「変更を見る」から PR を確認し、プレビューまたはテスト環境で業務シナリオを試す。
3. 問題なければ「マージ」をクリックし、対象ブランチとマージ方法を確認する。
4. 修正が必要な場合は「差し戻し」をクリックし、問題点と期待する結果を伝える。

![納品レポートと検収基準でタスク結果を確認する画面](https://static-docs.nocobase.com/studio-en-req-accept-20261111-normal-2x.webp)

タスクが「完了」になり既定ブランチへ反映されれば、今回の開発デリバリーは完了です。

## 変更をリリースして知識を蓄積する

コードのマージはそのまま本番公開ではありません。CI を接続したプロジェクトではマージ後にテスト環境へ自動反映され、責任者がリリース対象タスクを確認して本番デプロイ後に Studio へ本番バージョンを記録します。詳しくは[リリース管理](../studio/release/overview.md)を参照してください。

今回確定した業務ルールや設計方針は[プロジェクトメモリー](../studio/project/project-memory.md)に残し、原資料はナレッジベースへ保管することで、次の要件や担当者・エージェントの交代時にも文脈を引き継げます。

## 既存の Core アプリを接続する

[Core で最初のアプリを開発する](develop-your-first-app.md)でローカル作成したアプリをすでに Git リポジトリへプッシュしている場合、プロジェクトを作り直す必要はありません。ワンコマンドインストールで `nb-studio` も導入されているため、アプリディレクトリで Coding Agent に次のように伝えます。

```prompt
nb-studio を使って Studio に新しいプロジェクトを作成し、現在のリポジトリを初期化なしでひも付けてください。完了したらプロジェクトの URL を教えてください。
```

詳しい手順と PR プレビューの設定は[プロジェクトを Studio に取り込む](../guides/bring-into-studio.md)を参照してください。
