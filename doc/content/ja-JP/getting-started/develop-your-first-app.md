空のディレクトリから NocoBase アプリを作成し、Coding Agent と顧客管理機能を開発します。顧客、担当営業、次回フォロー日を記録し、ロールに応じて閲覧・操作範囲を制限します。完了すると、サインインして顧客データを操作しながら次の要件へ進めます。

## 環境を準備する

- Node.js 24 以降、pnpm 11（セットアップ手順は[開発環境を準備する](../guides/prepare-environment.md)を参照）。
- インストールしてサインイン済みのローカル Coding Agent が 1 つ以上あること（Claude Code、Codex、Cursor など）。
- Windows では WSL を使用します。以下のコマンドは Bash などの POSIX シェルで実行してください。

以下ではデータベースサーバーを別途用意せずに使える SQLite を利用します。他のデータベースを使う場合は[異なるデータベースでアプリを作成する](../core/developing-apps/database-configuration.md)を参照してください。

## アプリを作成して起動する

以下の 2 つの方法からどちらか 1 つを選び、完了後に[サインインする](#サインインする)へ進みます。

### 方法 1：Coding Agent で作成する（推奨）

アプリ作成用の Skill をグローバルにインストールし（初回のみ）、表示されたら使用する Coding Agent を選びます。

```bash
npx skills@latest add nocobase/skills-v3 --skill nocobase-create-app -g
```

Coding Agent をすでに開いている場合は、新しくインストールした Skill を読み込ませるため新しいセッションを開始してください。続いて空のディレクトリ（例：`my-app`）を作成して移動し、Coding Agent を開いて次を送ります。

```bash
mkdir my-app && cd my-app
```

```prompt
この空のディレクトリに、既定のテンプレートと SQLite を使うローカル開発用の NocoBase 3 アプリを作成してください。
起動できたら、アクセス先 URL と初回ログイン用のアカウントを教えてください。
```

Coding Agent がアプリの作成、設定生成、起動までを行い、完了後にアクセス先 URL とログインアカウントを案内します。

### 方法 2：手動でコマンドを実行して作成する

アプリを配置するディレクトリで次を実行すると、`my-app` ディレクトリが作成され依存パッケージがインストールされます。

```bash
PNPM_CONFIG_MINIMUM_RELEASE_AGE=0 pnpm create @nocobase/app@beta my-app --template-tag=beta
```

NocoBase 3 は現在 beta 版です。`PNPM_CONFIG_MINIMUM_RELEASE_AGE=0` は今回の実行に限り公開されたばかりのパッケージをインストールできるようにするための指定です。

ディレクトリへ移動し、設定を生成・確認してから起動します。

```bash
cd my-app
pnpm nocobase config init --dialect sqlite
pnpm nocobase config check
pnpm dev
```

- `config init` はローカル設定 `config.yml` とアプリ用キーを生成します。SQLite を使うため別途データベースの構築は不要です。`config.yml` は Git にはコミットしません。
- `config check` は起動時と同じ手順で設定を読み込み、問題があれば修正のヒントを表示します。
- `pnpm dev` は開発サーバーを起動し、ターミナルに `Local:` のアドレスを出力します。このターミナルを開いたままにしてください（閉じるとアプリが停止します）。

## サインインする

ブラウザーでアプリのアドレス（例：`http://127.0.0.1:13000/main/`）を開き、既定の管理者（ユーザー名 `nocobase`、パスワード `admin123`）でサインインします。

- **方法 1**：Coding Agent が案内したアドレスを使用します。
- **方法 2**：ターミナルに表示された `Local:` のアドレスを使用します。

末尾のアプリパス（`/main/` など）まで含めて開いてください。サインインするとホーム画面が表示され、標準機能と要件例を確認できます。

![作成直後のアプリのホーム画面。まだ業務機能は追加されていません。](/assets/core/tutorials/getting-started/home.png)

## 最初の業務要件を伝える

アプリのルートディレクトリ `my-app` で Coding Agent のセッションを開きます。方法 2 で手動起動した場合は、`pnpm dev` のターミナルはそのまま残し、別のターミナルで `my-app` に移動して Coding Agent を起動してください。

次の要件を送ります。

```prompt
顧客管理を作ってください。顧客には名前、連絡先、メモ、担当営業、次回フォロー日を持たせ、ステータスは見込み・対応中・成約済みにします。
顧客の作成・閲覧・編集・削除、名前での検索、ステータスでの絞り込みができるようにしてください。
営業マネージャーは全顧客を管理でき、営業担当者は自分の担当顧客のみ閲覧してステータスを更新でき、閲覧専用ユーザーは全顧客を閲覧できるが変更はできないようにしてください。
```

伝えるのは業務ルールだけです（何を記録し、何ができ、誰に許可するか）。ユーザー・権限管理、多言語文言、テスト、報告はプロジェクト同梱の Skill に従って Coding Agent が進めます。

実装に入る前に、Coding Agent が画面構成、主な操作、確認が必要な点をまとめた設計案を提示します。質問に答えて確認すると開発が始まります。

## 機能と権限を確認する

開発が終わると、Coding Agent はテストを実行してブラウザー上で項目ごとに確認・スクリーンショット撮影を行い、実装内容と未検証項目をまとめたレポートを返します。検証中にログインが必要な場合は、手動でのサインインを求められます。

アプリのアドレスを開くと、サイドバーに **Customers** が追加されています。顧客の登録、担当営業と次回フォロー日の設定、ステータス更新、検索・絞り込みを試せます。

![ステータス、担当営業、次回フォロー日、ページネーションを備えた顧客一覧。](/assets/core/tutorials/crm/customer-list-en.png)

ユーザー管理と権限管理も合わせて有効になります。次の手順で営業担当者の権限を確認します。

1. **System settings → Users** でユーザーを追加し、**Permission sets** で営業ロール（サンプルアプリでは `Sales rep`）を割り当てます。
2. 顧客を 1 件作成し、担当営業にこのユーザーを指定します。
3. このアカウントに切り替えてサインインします。自分が担当する顧客だけが表示され、ステータス変更はできる一方で詳細編集や削除はできないことを確認します。

続けて営業マネージャーと閲覧専用ユーザーでも確認します。マネージャーは全顧客を管理でき、閲覧専用ユーザーは閲覧のみ可能である必要があります。レポートに未検証項目がある場合は、次の機能へ進む前に確認しておきます。

## 改善して開発を続ける

期待どおりに動かない点や変えたい動作があれば、行った操作・見えた結果・期待する動作をそのまま Coding Agent に伝えます。

```prompt
営業ロールだけを割り当てたアカウントでサインインしても、他の担当者の顧客が見えてしまいます。
営業担当者は自分が担当する顧客だけを見られるようにしてください。
```

「顧客名をクリックしたらまず詳細画面を開き、そこから編集に進めるようにする」といった操作面の調整も直接依頼できます。

次に、同じアプリルートの Coding Agent セッションで顧客のフォロー記録を追加します。

```prompt
顧客にフォロー記録を追加してください。連絡するたびに、営業担当者が日付、方法（電話、訪問、メール）、メモを記録します。
フォロー記録は顧客の詳細に新しい順で表示してください。
営業担当者は自分の顧客にだけフォローを追加できます。営業マネージャーはすべての記録を閲覧できます。閲覧専用ユーザーは閲覧だけができます。
既存の顧客に過去のフォロー記録を追加する必要はありません。
```

設計を確認してから、営業担当、営業マネージャー、閲覧専用ユーザーでそれぞれ検証します。大きな要件はフォロー記録、商談、見積もり、売上レポートのように単独で使える単位に分けて、ひとつずつ検証しながら進めます。

継続して守りたいルールは「今後、日付はすべて会社のタイムゾーンで扱い、プロジェクト規約に保存してください」のように伝えます。規約は `.agents/rules/` に保存され、`AGENTS.md` から参照されます。
