1 つのコマンドで Studio コミュニティ版と最初のプロジェクトを自分のコンピューターにインストールし、最初のタスクをエージェントに任せます。

## 前提条件

- macOS、Linux、または Windows の WSL と Docker Desktop
- Compose v2 を含む Docker が起動していること
- Node.js 24、Git、curl
- インストールしてサインイン済みのコーディングツールが 1 つ以上あること：Claude Code、Codex、OpenCode、Pi など

## インストーラーを実行する

```bash
curl -fsSL https://get.nocobase.com/studio | sh -s -- --lang ja-JP
```

`--lang ja-JP` でインストーラーと Studio が日本語になります。ほかのオプションは[インストーラーのオプション](../studio/setup/install.md#インストーラーのオプション)を参照してください。

インストーラーは、このコンピューターに次のものを用意します。

- Studio コミュニティ版。データは `~/.nocobase-studio/` に保存されます
- Gitea。プロジェクトのリポジトリを置くローカルの Git サーバーです
- このコンピューターを[個人ランタイム](../studio/join/personal-runtime.md)として接続します。エージェントはここでタスクを実行します
- 最初のプロジェクト **My first project**。リポジトリに NocoBase 3 アプリがあり、テスト環境にデプロイ済みです

完了すると、Studio のアドレスとサインイン情報が表示されます。

## Studio にサインインする

Studio は `http://127.0.0.1:13000/main` で動いています。表示されたアドレスを開いて、ターミナルに表示されたメールアドレスとパスワードでサインインすると、最初のプロジェクトの会話が開きます。その後、**アカウント設定 › アカウントとセキュリティ** でパスワードを変更します。

会話には、エージェントがこのプロジェクト用にまとめた計画と、**開始** ボタンのある提案タスクがあります。

## テスト環境のアプリを開く

会話にあるエージェントの最初の返信は、テストアプリのアドレス `http://127.0.0.1:13000/my-first-project-staging/` とサインイン情報から始まります。アドレスを開き、返信にあるメールアドレスとパスワードでサインインすると、インストール時に作成された NocoBase 3 アプリにアクセスできます。アプリは 10 分間アクセスがないと停止し、次に開いたときに自動で起動します。

このテスト環境は、Studio の[ホスト環境](../studio/admin/environments.md)にも表示されます。

## 最初のタスクを開始する

提案タスクのカードで **開始** をクリックします。コーディネーターエージェントがタスクをこのコンピューター上のエージェントに渡して開発が始まり、モデルの利用枠を消費します。

進捗、変更、チェック結果はタスクに記録されます。[進捗を追う](../studio/use/follow-progress.md)を参照してください。開発とチェックが終わると、エージェントが PR を作成し、あなたが[検収](../studio/use/accept.md)します。
