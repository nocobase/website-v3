NocoBase 3 は、AI で業務システムを継続的に開発・運用するためのオープンソースプラットフォームです。エージェントがコードを書いて実行し、NocoBase が基盤とガバナンスを提供し、人が意思決定を行います。

## なぜ NocoBase なのか

バイブコーディングはソフトウェア開発を速くします。しかし業務システムは何年も使われ、機能の追加、プロセスの変更、担当者の引き継ぎが続きます。NocoBase はバイブコーディングにアプリケーション基盤、開発規約、ガバナンスを加えます。チームは引き続き Claude Code、Codex などのコーディングツールで開発できます。

### 信頼できる共通機能

AI がコードを書くとしても、権限、ワークフローエンジン、承認をゼロから設計するのは難しく、例外ケースも多く、保守の負担も大きくなります。

Core はすぐに使える共通機能を提供し、NocoBase がそれを継続的に保守・アップデートします。たとえば購買チームに仕入先管理システムが必要なら、エージェントは仕入先情報、発注書、承認ルールといった業務部分だけを書き、Core の権限と承認はそのまま使います。書いて検証すべきコードは大幅に減ります。

### 統一された開発規約

担当者やモデル、さらには会話が変わるたびに、AI はその場しのぎの実装をしがちです。同じシステムがいくつもの異なる書き方で作られ、どんどん保守しにくくなります。

Core は統一されたプロジェクト構成と開発規約を提供し、エージェントはパッケージに同梱された開発スキルに従ってコードを書きます。そのため、システムは統一されたアーキテクチャのもとで長期にわたって安定して進化します。

### チームの協働と経験の蓄積

チームは複数のプロジェクトとタスクを同時に抱え、誰もがターミナルや会話を行き来しています。エージェントから届く変更は増える一方です。すべてを確認しきれず、かといって任せきるのは危険に感じます。

Studio はひとつのエージェントチームを取りまとめて、多数のプロジェクトとタスクを同時に進め、進捗はひと目でわかります。人の介入が必要なときは、エージェントがレポート、チェックリスト、スクリーンショットを添えるので、人は根拠を手元に置いて判断できます。

要件の背景、業務資料、得られた教訓が、別々の PC の会話に散らばっています。担当者やエージェントが変わると、見つけるのが難しくなります。

Studio は方法と経験をスキル、ナレッジベース、プロジェクトメモリーに蓄積するので、新しい担当者やエージェントも前任者の続きから仕事を引き継げます。

### Core：オープンソースのアプリ基盤

**[Core](../core/index.md)** は、AI で業務システムを開発・運用するためのオープンソースのアプリケーション基盤です。業務システムに共通する機能と開発規約を提供します。

1 人または少人数のチームで、1 つまたは少数のアプリを開発する場合は、アプリのディレクトリで Claude Code、Codex などのコーディングツールを開き、エージェントと一緒に開発できます。テスト、レビュー、デプロイはチームが自分で取りまとめ、Core のデプロイツールと開発ガイドを使います。Core の利用に Studio のインストールは必要ありません。

### Studio：協働開発とガバナンス

**[Studio](../studio/index.md)** は、人とエージェントが協働開発するためのガバナンスプラットフォームです。Claude Code、Codex、OpenCode をひとつのエージェントチームにまとめます。

チームで多数のプロジェクトとタスクを同時に進める場合や、業務の専門家が直接要件を出して判断する場合は、Studio を使えます。コーディネーターエージェントが設計、開発、テスト、レビューを割り振ります。チェックとレビューを通過してから人が検収し、保護された環境へのデプロイには承認者の承認が必要です。

Studio は商用版で提供されます。

### Solution：すぐに使える業務アプリ

**Solution** は、Core 上に構築された、エージェントが動かす業務アプリのシリーズです。NocoCRM や NocoITAM などがあります。実務の大部分はエージェントが担い、人は重要な判断だけを行います。そのままインストールして使うことも、エージェントに自社の業務に合わせてカスタマイズさせることもできます。

## 開発から業務での利用へ

### 開発とリリース

仕入先管理システムなら、管理する仕入先情報、発注書の承認方法、役割ごとに閲覧・変更できるデータを決めます。エージェントは Core の上で画面、データ構造、業務ルールを実装し、アプリのコードは自社のリポジトリに保存されます。チームが業務フロー、権限、テスト結果を確認し、要件を満たしてからリリースすると、業務ユーザーがアプリを使えるようになります。

### 継続的な改修

稼働後、購買チームが仕入先の評価機能を必要としたり、発注書の承認ルールを変更したりすることがあります。引き続きエージェントと既存のアプリを改修し、既存データや業務フローへの影響を確認できます。

### 業務を担うエージェント

アプリが稼働すると、エージェントはアプリの中で業務も担えます。顧客の調査、メールの下書き、資産台帳の照合、サポートチケットの対応などです。こうした業務エージェントは Core の Agents プラグインで接続され、人と同じ権限を使います。判断が必要なときは、根拠を添えて担当者に引き渡します。Solution アプリにはすべて業務エージェントが組み込まれており、自社のアプリにも必要に応じて追加できます。

## すべてを自社で管理

### セルフホストと独立した稼働

Core、Solution、Studio はすべて自社サーバーで稼働し、コードとデータは自社のものです。業務アプリはリリース後、独立して稼働し、日常の業務リクエストが Studio を経由することはありません。

### モデルとエージェントを自由に選ぶ

モデルとエージェントは自由に選べ、特定ベンダーに縛られません。Claude Code、Codex などのコーディングツールと、さまざまなモデルに対応しています。
