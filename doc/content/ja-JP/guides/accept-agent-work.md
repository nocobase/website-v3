この章では、デバイスの申請に「希望日」を追加し、検収と差し戻しを一通り行います。

## 1. 要件を出す

```prompt
デバイスの申請に、任意の「希望日」を追加してください。今日より前の日付は選べず、一覧と詳細に表示します。すでに提出された申請は空のままにしてください。
```

## 2. 業務のシナリオを自分で動かす

Alice としてサインインし、**Device requests** を開きます。

![古い申請に 1970 年が表示され、新しい申請には余計な時刻が付いています](https://static-docs.nocobase.com/20261030-itam-lite-accept-needed-by-wrong.webp)

問題が 2 つあります。

- 「デバイスの申請と承認」と「ロールと権限」で提出した古い申請には希望日がないのに、`Jan 1, 1970, 7:30 AM` と表示される。
- 新しい申請には `Nov 6, 2026, 8:00 AM` と、日付のあとに時刻が表示される。

検収では、既存のデータを使い、各ロールの日常業務を一通り試します。シナリオが固まったら、エージェントにブラウザーテストにしてもらえます。[テストと検収](../core/developing-apps/testing-and-acceptance.md#ブラウザーテストと機能の検収) を参照してください。

## 3. 差し戻す

検収基準を満たしていない、古いデータの表示や扱いが間違っている、権限が間違っている、といった場合は差し戻します。再現手順と期待される結果を添えます。

```prompt
希望日の表示が間違っています。
1. Alice の Device requests で、日付のない古い申請に Jan 1, 1970, 7:30 AM と表示されます。「—」と表示されるべきです。
2. 11 月 6 日を指定した申請に Nov 6, 2026, 8:00 AM と表示されます。日付だけを表示すべきです。
一覧と詳細の両方を修正してください。修正したら、Alice として再確認し、スクリーンショットを添付してください。
```

エージェントは、日付だけを表示し、日付がない場合は「—」を表示するフォーマット関数を追加し、型を null 許容にしました。新しいテストは UTC、ロサンゼルス、上海の 3 つのタイムゾーンで通過します。もう一度確認します。

![古い申請には「—」が表示され、新しい申請には日付だけが表示されます](https://static-docs.nocobase.com/20261030-itam-lite-accept-needed-by-fixed.webp)

もう一度昨日の日付を選んで提出すると、日付フィールドの横に `Choose today or a later date.` と表示されます。Ben としてサインインすると、一覧に Alice の希望日が表示されます。

**完了の条件**：新しい申請の希望日が一覧と詳細に日付だけで表示され、古い申請には「—」が表示されること。今日より前の日付は提出できず、フィールドの横に表示されること。Ben がその日付を確認できること。すべてのテストが通過すること。
