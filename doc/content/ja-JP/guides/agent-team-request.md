[Studio に接続した CRM](bring-into-studio.md)を使います。営業は交渉中に見積を調整するため、価格の変更を説明しつつ、顧客に送付済みの内容を残す必要があります。この機能を Agent チームに依頼します。

## 見積バージョン比較の要望を伝える

**My sessions → New conversation** を開き、最初の送信前に入力欄の下で Agent と CRM プロジェクトを選びます。別のプロジェクトを扱う場合は新しい会話を作ります。共有実行環境を使う業務担当者は、自分の PC にコーディングツールを入れる必要はありません。

![新しい会話で Agent と CRM プロジェクトを選択します。](/assets/guides/studio/new-session.png)

```prompt
顧客から見積の修正を求められることが多いので、CRM で同じ見積のバージョンを比較したいです。商品、数量、単価、値引き、合計の変更と、誰がいつ変更したかを確認できるようにしてください。送付済みのバージョンは残し、後から上書きしないでください。まずルールを相談してから、合意した内容をタスクにしてください。
```

保存するタイミング、比較するバージョン、閲覧できる人を決めます。この演習では、提出済みバージョンを変更不可とし、調整時は新しい下書きを作ります。比較画面も顧客のアクセス範囲に従い、顧客を閲覧できない人は見積履歴も読めないものとします。ルールと受け入れ条件をタスクの説明に保存します。

**ステップの確認**：CRM に見積バージョン比較のタスクがあり、担当者、履歴保持、アクセス条件が明確です。

## 実行を開始し、進捗を確認する

タスクを確認して **Start** を押すと、調整役の Agent が設計、実装、テスト、レビューを手配します。状態は **Backlog** から **In progress** に変わります。上部の **Now** と次の予定、**Activity** の引き継ぎ、**Runs** の実行内容を確認します。

![プロジェクトのボードでタスクを状態別に確認できます。](/assets/guides/studio/issues-board.png)

追加の要望はタスクにコメントします。非公開の会話で決まった内容が、すべてのメンバーに自動共有されるわけではありません。重要な決定がタスクにも記録されたか確認してください。[進捗の確認](../studio/use/follow-progress.md)も参照できます。

## 業務上の質問に答える

例えば、履歴を持たない既存見積の扱いを Agent が質問することがあります。判断が必要なタスクは **Blocked** になる場合があります。担当者は **My issues** の **Needs you** を開き、回答します。

```prompt
既存見積の番号、明細、金額はそのまま最初の閲覧可能なバージョンとして残してください。過去の変更を推測して補わないでください。今回のリリース以降の変更から履歴を記録し、提出済みバージョンは編集不可にしてください。
```

決定が記録され、実行が再開されたことを確認します。実行環境やチェックの失敗で止まる場合もあるため、状態だけを変えず原因を解消します。[質問への回答](../studio/use/answer.md)を参照してください。

## チェックとレビューを確認する

**Code & previews** で PR のコミット、チェック結果、プレビューを確認します。調整役の Agent はプロジェクトの Skills に従って独立レビューを手配し、必須の修正を実装者に戻します。チェック元は設定によって CI または Agent 自身です。[チェックとレビュー](../studio/project/checks-and-review.md)を参照してください。

![CRM タスクの Code & previews で PR、チェック元、各チェックの結果を確認します。](/assets/guides/studio/issue-checks.png)

交付レポートでは既存見積の移行、金額計算、提出済みバージョンの保護、権限の検証根拠を読みます。テストの成功だけで業務上の受け入れを済ませないでください。

## 既存見積との互換性を確認してマージする

**In review** になったら、独立したテストアカウントでプレビューを確認します。

| 操作 | 期待する結果 |
| --- | --- |
| 更新前の見積を開く | 番号、顧客との関連、明細、金額が変わらず、初期バージョンを閲覧できる |
| 提出後に数量や値引きを変更する | 新しい下書きが作られ、提出済みバージョンは変わらない |
| 前後のバージョンを比較する | 商品の追加・削除、数量、単価、値引き、合計、変更者と時刻を照合できる |
| 商品カタログの価格を変える | 保存済み見積は変わらない |
| 顧客権限のない営業が履歴や API にアクセスする | 見積履歴を取得できない |

![demo の完了済み見積修訂タスクには業務背景、交付レポート、検証記録が残っています。](/assets/guides/studio/quote-task.png)

**Needs you → Merge** で対象ブランチとコミットを確認してマージします。問題があれば **Send back** を選び、操作、実際の結果、期待する結果を伝えます。関連 PR のマージ後にタスクが完了します。Git の権限とブランチ保護は引き続き適用されます。[受け入れ](../studio/use/accept.md)を参照してください。

**完了の条件**：比較機能が受け入れられてデフォルトブランチに入り、既存の顧客と見積も使えます。
