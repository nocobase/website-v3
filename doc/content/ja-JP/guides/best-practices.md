## Studio では、タスクを作成する前に要件を話し合う

いきなりタスクを作成して開始しないでください。まず **My sessions** でエージェントと要件を話し合います。何を作るか、ルールと境界、どう検収するか。それが固まってから、エージェントにタスクを作成・開始してもらいます。

タスクの開始前に要件が固まっていれば、エージェントチームからの質問も手戻りも減り、タスクの説明にはルールと検収基準がすべて残ります。

```prompt
<要件を 2、3 文で>
不明な点があれば先に質問してください。内容が固まったら、ルールと検収基準をタスクの説明に書いて、タスクを作成してください。
```

![My sessions で要件を説明すると、エージェントが実行できるタスクに分割します](https://static-docs.nocobase.com/20261029151954700.png)

## プロジェクトについて疑問があれば Studio に聞く

業務部門の同僚も開発者も、コードを読んだりだれかを探したりしなくても、プロジェクトの業務ロジックや機能の動作をエージェントに尋ねられます。プロジェクトやタスクのページで **Ask agent** をクリックすると、現在のページをコンテキストとしてセッションが始まります。

```prompt
デバイスの申請に資産管理者の承認が必要になるのはどんなときですか。承認されたあと、デバイスのステータスと使用者はどう変わりますか。
```

![プロジェクトページで Ask agent をクリックすると、現在のプロジェクトがコンテキストになります](https://static-docs.nocobase.com/20261030-studio-ask-agent.webp)

**My sessions** で直接尋ね、対象のプロジェクトを選ぶこともできます。

![My sessions で質問する](https://static-docs.nocobase.com/20261029151954700.png)

## ほかの部門にも、まずエージェントで要件を書いてもらう

総務や経理などの部門が要件を持ってきたときは、まず自分のエージェントで要件をまとめてもらいましょう。だれが使うか、何をするか、ルールは何か。ページを言葉で説明しにくい場合は、HTML のデモを添付してもらいます。

```prompt
IT 部門に要件を出したいです：<一文で>。まずいくつか質問してから、要件定義書にまとめ、主要なページを 1 ファイルの HTML デモにしてください。
```

受け取った開発者は、まずエージェントと設計書に照らして設計を更新してから、構築に取りかかります。
