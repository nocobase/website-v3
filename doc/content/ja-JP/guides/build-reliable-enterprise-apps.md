## はじめに

エージェントにバイブコーディングで業務システムを作らせると、最初のバージョンはたいていすぐにできあがりますが、その後こんな問題が出てきます。

1. 権限、ワークフロー、承認などの基盤機能をゼロから作る必要があり、信頼性が低かったり壊れやすかったりする。
2. モデル、担当者、会話が変わるたびに書き方が変わり、アーキテクチャが少しずつ制御できなくなる。
3. 多くのタスクが並行して進むと、エージェントからのメッセージや変更の確認に人が追いつかない。
4. 要件の背景、業務ルール、得られた教訓が会話に散らばり、担当者やエージェントが変わると失われる。

これらの問題に対処するため、NocoBase 3 は [NocoBase Core](https://www.nocobase.com/ja-JP/core/) と [NocoBase Studio](https://www.nocobase.com/ja-JP/studio/) を導入しました。これらを使えば、AI エージェントの時代に企業が自社のエンタープライズアプリをすばやく開発しつつ、上記の問題を解決できます。このチュートリアルでは IT 資産管理を例に、NocoBase 3 で信頼できるエンタープライズアプリを構築する方法を紹介します。

## Core：AI で業務システムを開発・運用するためのオープンソースの基盤

**共通機能を一から開発・検証する必要はありません。** ユーザーと権限、データとファイル、ワークフローと承認、メッセージ、AI とエージェントなど、20 以上の共通機能がすぐに使え、NocoBase が継続的に保守・アップデートします。機能の一覧は [NocoBase Core](../core/index.md#共通機能を再利用する) を参照してください。

**統一されたアーキテクチャと規約。** 新しいアプリには決まった構成があり、ページ、API、マイグレーション、テストにはそれぞれ置き場所があります。`AGENTS.md` とパッケージに同梱されたスキルが、業務コードの置き場所と、そのまま使う機能を示します。担当者、モデル、会話がだれでも、エージェントは同じ方法で開発します。[プロジェクト構成](../core/developing-apps/project-structure.md) を参照してください。

アプリがどの Core の機能を使っているかは、**System settings › App foundation** で確認できます。[App foundation](../core/using-plugins/application-support/foundation.md) を参照してください。

![App foundation：アプリが使っている Core の機能](https://static-docs.nocobase.com/20261030-itam-lite-ego-preview-foundation-2x.webp)

## Studio：人とエージェントが協働開発するためのガバナンスプラットフォーム

**エージェントチームが自律的に仕事を進めます。** Claude Code、Codex などのコーディングツールがエージェントチームとして Studio に加わります。コーディネーターエージェントが各エージェントの得意分野に応じて設計、開発、テスト、レビューを割り振り、複数のタスクがそれぞれ専用のブランチで同時に進みます。各タスクがどこまで進み、だれが担当し、次に何をするのかがひと目でわかります。

**重要な判断は人が下します。** 作業が人に届くのは、テストとレビューを通過してからです。人はレポート、スクリーンショット、プレビューを確認して、受け入れるか差し戻します。コードを書かない業務の専門家も、直接要件を出し、判断し、結果を検収できます。

**方法と経験がチームに残ります。** スキルには仕事の進め方、ナレッジベースには業務資料、プロジェクトメモリーにはエージェントが学んだことが蓄積されるので、次の担当者やエージェントが仕事を引き継げます。[Studio とは](../studio/intro/what-is-studio.md) を参照してください。

Core だけでも、完全なアプリを開発してリリースできます。チームで複数のプロジェクトを同時に進めるときや、業務部門の同僚に直接参加してもらいたいときに Studio を導入しましょう。

> [!NOTE] Studio のエディション
> Studio は NocoBase の Professional エディションと Enterprise エディションでのみ提供されます。[料金](https://www.nocobase.com/ja-JP/pricing/) を参照してください。

## チュートリアルの例：IT 資産管理

以下では ITAM と呼びます。会社は従業員にノート PC やモニターを貸与しており、各デバイスがどこにあり、だれが持ち、どんな状態かを把握する必要があります。また、デバイスの申請には承認が必要です。ロールは 3 つあります。

| ロール | システムで行うこと |
| --- | --- |
| 従業員 | 自分に割り当てられたデバイスを確認し、デバイスを申請する |
| IT サポート | デバイスの申請に対応し、デバイスの貸与と回収を行い、デバイスの状態を最新に保つ |
| 資産管理者 | デバイス台帳を管理し、申請を承認し、棚卸しを取りまとめる |

パート 1 では、デバイス台帳、デバイスの申請と承認、3 つのロールの権限を構築します。パート 2 では、エージェントチームにデバイスの棚卸しを構築させ、資産管理者に直接参加してもらいます。

チュートリアルのコードは [nocobase/docs-examples-v3](https://github.com/nocobase/docs-examples-v3/tree/main/apps/itam-lite) にあります。より本格的な IT 資産管理システムについては、[NocoITAM のオンラインデモ](https://solutions.nocobase.com/itam/) を参照してください。

## チュートリアルのロードマップ

### はじめに

1. [NocoBase 3 で信頼できるエンタープライズアプリを構築する](build-reliable-enterprise-apps.md)：このページ。
2. [開発環境を準備する](prepare-environment.md)：Node.js、pnpm、Git をインストールします。
3. [エージェントとモデルを選ぶ](choose-agent-and-model.md)：コーディングツールとモデルを選びます。

### パート 1：Core でアプリを構築する

4. [アプリを作成する](create-app.md)：エージェントにアプリを作成させ、起動してサインインし、最初のコミットを行います。
5. [まずシステム設計書を書く](write-a-design-doc.md)：ITAM で何をすべきかをエージェントと話し合い、設計書にまとめます。
6. [最初の機能：デバイス台帳](first-feature-devices.md)：デバイスの登録、検索、状態の追跡。
7. [デバイスの申請と承認](requests-and-approval.md)：従業員がデバイスを申請し、承認後にデバイスが貸与されます。
8. [ロールと権限](roles-and-permissions.md)：3 つのロールがそれぞれ何を見て何をできるか。
9. [エージェントの作業を検収する](accept-agent-work.md)：エージェントが引き渡したものを確認し、修正を依頼します。
10. [アプリをデプロイする](deploy.md)：アプリをサーバーにデプロイします。

### パート 2：チームで Studio を使う

11. [プロジェクトを Studio に取り込む](bring-into-studio.md)：ITAM のコードリポジトリを Studio のプロジェクトに接続します。
12. [要件をエージェントチームに任せる](agent-team-request.md)：エージェントチームにデバイスの棚卸しを構築させます。
13. [業務部門の同僚に参加してもらう](business-colleagues.md)：資産管理者を招待し、要件を出し、質問に答え、結果を検収してもらいます。
14. [方法と経験を蓄積する](capture-knowledge.md)：方法と業務知識をスキル、ナレッジベース、プロジェクトメモリーに残します。
15. [本番にリリースする](release.md)：テスト環境にデプロイし、リリースのタグを付けて、自社のサーバーにデプロイします。
