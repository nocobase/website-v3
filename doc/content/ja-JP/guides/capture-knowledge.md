ナレッジベースが有効な Studio プロジェクトと、記録したい業務ルールやチーム基準を用意します。ここでは CRM の見積バージョンと顧客引き継ぎのルールを例に、長く使う決定を整理して次の開発者や Agent が参照できるようにします。

| 保存先 | 保存するもの |
| --- | --- |
| Knowledge | 人が維持する業務ルール、制度、判断の背景 |
| Skills | 開発、検証、レビューの進め方 |
| Project memory | コードとともに維持する制約、修正された認識、経験 |

ここで扱う資料は Studio の開発協働用です。CRM 内の営業や業務 Agent が使う商品知識・顧客情報はアプリの機能であり、Studio に文書を追加するだけでは接続されません。

## CRM のルールと判断を Knowledge に保存する

CRM プロジェクトの **Knowledge** で業務ルールの文書を作り、確定した内容を記載します。

- 提出済み見積は変更不可とし、変更時は新しい下書きを作る。カタログ価格の変更で過去の金額は変えない。
- 既存見積の番号と内容を残し、過去の修訂履歴を推測で追加しない。
- 責任者が顧客を引き継ぎ、理由、操作人、日時を記録する。元のフォロー作成者と見積履歴は維持する。
- 元の担当者は担当に基づくアクセスを失う。協力には責任者の明示的な読み取り専用共有が必要。

適用範囲と関連タスクも記載します。値引き承認ルールがある場合は合意済みの制度を参照し、新しいしきい値を勝手に作りません。Morgan に対象文書の編集権限を与え、業務上の意味を維持してもらいます。[Knowledge](../studio/project/knowledge-base.md)を参照してください。

![CRM の Knowledge で受け入れ基準と文書の管理情報を確認できます。](/assets/guides/studio/knowledge.png)

CRM の会話で質問します。

```prompt
顧客の引き継ぎ後、元の担当者はまだ閲覧できますか？プロジェクトのナレッジに基づいて条件を説明し、参照元を示してください。
```

**ステップの確認**：回答が文書と一致し、根拠を確認できます。読めない場合は、依頼した人の資料へのアクセス権を確認します。

## CRM の開発・レビューチェックリストを作る

プロジェクトと交付レポートを読める Coding Agent に依頼します。

```prompt
今回の見積比較と顧客引き継ぎの経験を、今後 CRM を改善するときのチェックリストにまとめてください。顧客を閲覧・更新できる人、過去の見積の保持、引き継ぎ記録の 漏れがないこと を中心に、まず内容を見せてください。
```

単に「権限に注意」とせず、確認方法を書きます。

| 対象 | 確認方法 |
| --- | --- |
| 顧客と関連データ | 担当者、権限のない営業、責任者で画面と API を確認 |
| 提出済み見積 | 新しい下書きとカタログ価格を変え、旧内容・金額を照合 |
| 引き継ぎと共有 | 取り消し後のアクセスと読み取り専用共有の制限を確認 |
| 既存データの更新 | 更新前のサンプルを残し、関連、作成者、履歴を照合 |

確認後、**Skills** で作成します。`SKILL.md` の `name` を `crm-checklist` にし、`description` に CRM の開発・自己検証・レビューで使うことを書き、本文に確認方法を記載します。管理権限のある Agent に作成を手伝ってもらうこともできます。CRM の **Settings → Default skills** に追加し、必要ならリポジトリを限定します。形式と権限は [Skills](../studio/project/skills.md)を参照してください。

![Default skills でプロジェクトや対象リポジトリに Skill を割り当てます。](/assets/guides/studio/default-skills.png)

**ステップの確認**：`crm-checklist` が割り当てられ、その後の実行記録と交付レポートに実際のチェックが残っています。割り当てだけでは実施の証拠になりません。

## プロジェクト記憶を確認して蓄積する

**Memory** を開き、Agent が残した長期的な結論を確認します。例えば「旧見積の履歴を推測で補わない」「担当者の権限を取り消すときは独立した共有も確認する」といった内容です。

![プロジェクト記憶をリポジトリと種類で確認します。](/assets/guides/studio/memory.png)

記憶はリポジトリの `.nb-studio/memory/` に置かれ、タスクの PR とともにレビュー・マージされます。残すべき決定をタスクで伝え、Agent に記録を判断させます。レビュー時に重複、古い情報、誤りを削除します。秘密情報、顧客の個人情報、一時的な進捗は記憶に入れません。[プロジェクト記憶](../studio/project/project-memory.md)を参照してください。

**完了の条件**：ルールに出典があり、手順がプロジェクトに割り当てられ、経験がコードとともに残り、次のタスクでも同じ背景を参照できます。

更新を検証して本番に公開するには、[機能を公開して本番バージョンを記録](release.md)を参照してください。
