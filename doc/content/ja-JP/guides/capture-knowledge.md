廃棄の年数や、棚卸しの差異は人が確認する必要があることなど、Xu Ning（業務部門の同僚）が決めたルールは、今は 2 つのタスクのセッションとコメントに散らばっています。Studio はこれらを 3 つの場所に残します。

| | 入れるもの | 書く人 |
| --- | --- | --- |
| ナレッジベース | 業務の進め方：規程、ルール、重要な判断 | 人 |
| スキル | 仕事の進め方：開発規約、チェックリスト | 人 |
| プロジェクトメモリー | エージェントが修正されたやり方、はまった落とし穴 | エージェント |

## 1. 資産管理の規程をナレッジベースに入れる

**Development › Knowledge** を開き、itam-lite プロジェクトのスペースを選んで「資産管理規程」というフォルダーを作成し、既存の規程ファイルをアップロードするか、記事を作成します。

```markdown
# デバイスの申請、廃棄、棚卸しのルール

## 標準の機器
- 新入社員にはノート PC とモニターを 1 台ずつ貸与する。
- 標準を超える申請には、部門長がデバイスの申請に理由を書く必要があり、資産管理者が承認する。

## 廃棄のルール
- ノート PC は 4 年、モニターは 5 年たてば廃棄できる。それより前は、損傷を説明して写真を添付する。
- 従業員がまだ持っているデバイスは直接廃棄できない。先に返却する必要がある。
- 廃棄したデバイスは既定で台帳に表示せず、ステータスで絞り込むと表示できる。監査では、だれが申請し、だれが承認し、理由は何かを確認できる必要がある。

## 棚卸しのスケジュール
- 四半期ごとに場所単位で分けて棚卸しを行い、毎年 12 月に全数の棚卸しを行う。
- 棚卸しで見つかった差異で台帳を自動で更新しない。資産管理者が 1 件ずつ確認してから更新する。
```

コードからは読み取れないルールと判断だけを書きます。Xu Ning に直接管理してもらうには、このフォルダーの **Edit** 権限を Xu Ning に付与します。スペース、権限、エージェントの読み方については、[ナレッジベース](../studio/project/knowledge-base.md) を参照してください。

![ナレッジベース：左にスペースとフォルダー、右にドキュメント](https://static-docs.nocobase.com/20261028205037978.png)

**完了の目安**：セッションで「ノート PC は何年たてば廃棄できますか」と尋ねると、エージェントが 4 年と答え、この記事を引用していることを示すこと。

## 2. スキルを書く：ITAM のチェックリスト

結果を検収するたびに、異なるロールでサインインして、権限と、台帳の変更に記録が残るかを確認しています。これをスキルとして書けば、開発するエージェントとレビューするエージェントがそれに照らして確認します。

まずローカルのコーディングエージェントに下書きを作ってもらいます。

```prompt
itam-lite のコードと、デバイスの棚卸しとデバイスの廃棄のタスクの引き渡しレポートを読んで、itam-checklist というスキルの下書きを作ってください：このシステムへのすべての変更で確認すべき、権限と記録の要件です。このプロジェクト固有の規約だけを書いてください。
```

おおよそ次のような内容になります。

```markdown
---
name: itam-checklist
description: itam-lite で、デバイス、デバイスの申請、廃棄、棚卸しにかかわる変更を開発、セルフテスト、レビューするときに読む。このシステムで確認すべき権限と記録の要件を挙げる。
---

# ITAM チェックリスト

## 3 つのロールすべてで試す
- 従業員：自分に割り当てられたデバイスだけが見え、棚卸しと廃棄は見られない。
- IT サポート：デバイスの申請に対応し、棚卸しの確認結果を入力し、廃棄申請を出せるが、承認はできない。
- 資産管理者：デバイスの申請と廃棄を承認し、棚卸しを開始・終了し、棚卸しの差異を確認する。
- 検収シナリオごとに、影響を受けるロールのうち少なくとも 2 つでサインインし、引き渡しレポートにスクリーンショットを添付する。

## 台帳の変更には記録を残す
- デバイスのステータス、場所、使用者が変わったときは、だれがいつ変更し、どの申請によるものかを確認できなければならない。
- デバイスのレコードは決して直接削除しない。廃棄ではステータスを変更し、削除はしない。

## 業務ルールはナレッジベースで決まる
- 標準の機器、廃棄の年数、棚卸しのスケジュールは、ナレッジベースの「デバイスの申請、廃棄、棚卸しのルール」に従う。推測してハードコードしない。
```

内容がよければ、エージェントに Studio へ追加してもらいます。

```prompt
nb-studio を使って、itam-checklist を Studio のスキルとして作成し、itam-lite プロジェクトに適用してください。
```

その後、**Agent management › Skills** に表示され、itam-lite の **Project settings › Default skills** に一覧表示されます。

![スキルの一覧：組み込みスキルとチーム独自のスキル](https://static-docs.nocobase.com/20261028210018195.png)

スキルは、グローバル、プロジェクト、リポジトリの 3 つのレベルで適用できます。[スキル](../studio/project/skills.md) を参照してください。

![スキルの詳細でのグローバル適用と、新しいプロジェクトへの自動適用](https://static-docs.nocobase.com/20261028210517252.png)

![プロジェクト設定の Default skills](https://static-docs.nocobase.com/20261029152525192.png)

![既定のスキルは個々のリポジトリにも適用できます](https://static-docs.nocobase.com/20261029152621517.png)

**完了の目安**：次にデバイスにかかわるタスクで、レビューするエージェントがチェックリストに照らしてロールの権限と記録を確認し、引き渡しレポートに異なるロールのスクリーンショットがあること。

## 3. プロジェクトメモリーを見る

プロジェクトメモリーはエージェントが自分で書きます。リポジトリの `.nb-studio/memory/` に保存され、PR と一緒にコミット・レビューされ、Claude と Codex が同じものを読みます。**Development › Project memory** で確認できます。たとえば：

| 種類 | 例 |
| --- | --- |
| Feedback | 棚卸しの差異で台帳を自動では更新しない。資産管理者が確認してから更新する |
| Project | デバイスの廃棄ではレコードを削除せずステータスを変更する。監査で履歴が必要なため |
| Reference | 廃棄の年数と棚卸しのスケジュールは、ナレッジベースの「デバイスの申請、廃棄、棚卸しのルール」に従う |

![プロジェクトメモリー：プロジェクトとリポジトリごとに表示し、種類で絞り込めます](https://static-docs.nocobase.com/20261028205613068.png)

エージェントにルールを覚えてもらうには、タスクでエージェントに伝えます。[プロジェクトメモリー](../studio/project/project-memory.md) を参照してください。

**完了の目安**：資産管理の規程がナレッジベースに入り、`itam-checklist` が itam-lite に適用されていること。
