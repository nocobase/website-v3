営業担当者が顧客から受け取った要件資料を顧客レコードに添付すると、その顧客の閲覧権限を持つメンバーは顧客詳細から資料をプレビュー、ダウンロードできます。顧客詳細とアクセス権限を備えたアプリに添付機能を追加するか、[CRM の完成例](https://github.com/nocobase/doc-demo-crm/tree/main)で試してください。

## ファイルの保存先を選んで設定する

ファイル本体はローカルディレクトリまたは S3 バケットに保存できます。アプリは `local` や `s3` といったディスク名で保存先を識別します。各ファイルのレコードにはディスク名とオブジェクトキーが記録され、ダウンロードや削除に使われます。

### 非公開のローカルディレクトリを使う

CRM の完成例では、既定の `local` ディスクをそのまま使えます。[サーバー設定](https://github.com/nocobase/doc-demo-crm/blob/main/server/config/drive.ts)の `driver: 'fs'` はファイルシステムを、`location: paths.storage()` はアプリのストレージディレクトリを指定します。既定の場所はプロジェクト直下の `storage/` です。

新規環境でマウント済みのボリュームに保存する場合は、プロジェクト直下の `config.yml` に絶対パスを指定します。Web の公開ディレクトリの外に、アプリが読み書きできる永続ディレクトリを用意してください。複数のインスタンスで利用する場合は同じボリュームをそれぞれにマウントします。

```yaml
drive:
  default: local
  disks:
    local:
      driver: fs
      location: /srv/crm/files
      visibility: private
```

### S3 のバケット、リージョン、認証情報を設定する

パブリックアクセスをブロックした非公開バケットを用意し、アプリの実行主体に添付オブジェクトを読み書き・削除する権限を付与します。`config.yml` に実際のバケット名とリージョンを指定してください。この例ではバケットポリシーでアクセスを管理し、`supportsACL: false` を指定してアップロード時のオブジェクト ACL を省略します。

```yaml
drive:
  default: s3
  disks:
    s3:
      driver: s3
      bucket: your-crm-bucket
      region: us-east-1
      credentials: {}
      visibility: private
      supportsACL: false
```

`credentials: {}` の場合、AWS SDK はサーバーの実行環境から認証情報を取得します。アプリに IAM ロールを割り当てるか、デプロイ環境で `AWS_ACCESS_KEY_ID` と `AWS_SECRET_ACCESS_KEY` を設定します。一時キーを使う場合は `AWS_SESSION_TOKEN` も必要です。[AWS の認証情報の設定](https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/setting-credentials-node.html)

S3 互換サービスの場合は、同じ `s3` ブロックにサービスの `endpoint` を追加し、指定された署名リージョンを設定します。バケット名を URL のパスに含める形式（`https://host/bucket`）が必要であれば、`forcePathStyle: true` を指定します。

### 顧客の添付ファイルを保存するディスクを選ぶ

CRM の完成例では `drive.default` で新しい添付ファイルと新規発行する見積書の保存先を選びます。切り替え後も、以前のディスク名、ディレクトリまたはバケット、認証情報を維持してください。既存のファイルは移動せず、レコードに記録されたディスクから読み込まれます。自分のアプリでも、選択したディスク名を[添付ファイルのアップロードルート](https://github.com/nocobase/doc-demo-crm/blob/main/server/routes/customer-files.ts)に渡します。

設定を保存してアプリを再起動します。管理者として **System settings → System → File storage** を開き、対象ディスクを選んで **Check** を実行します。一時ファイルの書き込み、読み取り、削除が成功したら、**Data and files → Files and quotation documents** で添付ファイルの保存先を確認してください。バケットポリシーでプレフィックスごとに権限を付与している場合は、チェック用の `nocobase-check/` と添付ファイル用の `objects/` の両方で読み取り・書き込み・削除を許可してください。[ファイルストレージとドライバー](../../core/framework/file-storage.md)

## 顧客詳細で添付ファイルを使う

### アップロード制限と顧客のアクセス権限を設定する

自分のアプリに添付機能を追加するときは、開発 Agent に次のように依頼できます。完成例では次の節から操作を試せます。

```prompt
顧客詳細に「添付ファイル」タブを追加して、営業担当者が要件資料をアップロードできるようにしてください。1 回の保存で最大 10 ファイル、1 ファイルは 5 MB までにします。担当者と編集権限を持つ上長は追加と削除ができ、閲覧のみで共有された人はプレビューとダウンロードができます。

「保存」を押したときに資料を顧客に紐付けてください。顧客の引き継ぎや資料の削除後は、以前のリンクを開いても現在の権限が適用されるようにしてください。顧客に一度も紐付かず 24 時間以上経ったアップロードは、管理者が整理できるようにしてください。
```

プレビューとダウンロードはいずれもアプリを経由させ、リクエストごとに顧客へのアクセス権限を確認します。非公開ディレクトリやバケットはファイル本体の保存先です。[CRM のファイルサービス](https://github.com/nocobase/doc-demo-crm/blob/main/server/providers/customer-files.ts)

### 添付ファイルをアップロードして保存・プレビュー・ダウンロードする

1. 営業担当の Alex でログインし、Alex が担当する **Northstar Manufacturing → Attachments** を開きます。サンプルアカウントの設定は[ロール権限とデータ範囲制御](roles-and-permissions.md)を参照してください。
2. 確認しやすい要件を 1 件記入した `Customer requirements.txt` を用意します。**Add attachments** で選択し、アップロードが終わったら **Save** を押します。キャンセルすると選択は破棄されます。保存に失敗した場合は選択したまま再試行できます。
3. 一覧でファイル名、サイズ、アップロードしたユーザーを確認します。ファイル名をクリックしてプレビューを開き、**Download** で取得したファイルも元の内容と照合します。ローカルから S3 に切り替えた場合は、切り替え前に保存した資料もダウンロードして確認します。

## アクセス権限を確認し、期限を過ぎた一時ファイルを削除する

- 閲覧権限を持つ上長の Morgan と、閲覧のみで共有されたユーザーで同じ顧客を開きます。どちらもプレビューとダウンロードができます。追加と削除には編集権限が必要です。共有されていない営業担当の Taylor や未ログインのユーザーは、ダウンロードリンクを開いてもファイルを取得できません。
- ダウンロードリンクを控え、顧客を別の担当者に引き継ぎます。元の担当者が顧客へのアクセス権限を失うと、そのリンクからも取得できなくなります。添付を削除した後は、元のアップロード者も古いリンクでの取得や同じファイルの再関連付けができません。
- 管理者として **System settings → Data and files → Files and quotation documents** を開きます。アップロードから 24 時間を過ぎ、一度も顧客に紐付いていないファイルを選んで削除し、一覧を再読み込みします。保存済みの添付ファイルと発行済みの見積書は引き続きダウンロードできます。

## まとめと次のステップ

営業担当者は顧客詳細で資料を扱えるようになり、ダウンロードにも現在の担当・共有関係が反映されます。確定した見積から固定書式の DOCX を作成する手順は、[テンプレートから帳票ファイルを生成する](template-print.md)を参照してください。
