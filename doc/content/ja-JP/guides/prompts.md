山かっこの部分は自分の内容に置き換えてください。

## アプリを作成する

```prompt
現在のディレクトリに、データベースに SQLite を使う NocoBase 3 アプリを作成してください。起動したら、URL とサインイン用のアカウントを教えてください。
```

## 設計を話し合う

```prompt
<システム> を作りたいです。まだコードは書かずに、先に一緒に設計を固めてください。
<ロールと主な流れを 2、3 文で>
私が決める必要があることは、1 グループずつ質問してください。それぞれにあなたのおすすめも添えてください。
```

## 設計書を書く

```prompt
合意した設計を docs/design.md に書いてください：ロール、データ、流れ、ページ、権限、さらにステップごとの引き渡し計画と、各ステップの検収基準。
AGENTS.md に登録してください：業務上の変更の前には必ず読むこと。要件が設計を変える場合は、コードを変更する前に設計書を更新すること。
```

## 要件を出す

```prompt
<だれが使い、何をするか>
<ルール：だれが何をできるか、どのデータに触れてはならないか>
```

## 先に計画する

```prompt
まだコードは変更しないでください。この変更がどの部分にかかわるか、私が決める必要がある質問、どう検証するつもりかを一覧にしてください。
```

## 差し戻す

```prompt
<機能> に問題があります：<アカウント> で <手順> を行うと、<実際の結果> になります。<期待される結果> になるべきです。修正したら、同じアカウントで再確認し、スクリーンショットを添付してください。
```

## レビューする

別ベンダーのモデルでセッションを開きます。

```prompt
コミットされていない変更をレビューしてください。AGENTS.md の規約に照らして問題を探し、重要度順に一覧にしてください。コードは変更しないでください。
```

## 新しいセッションに引き継ぐ

```prompt
まず AGENTS.md、docs/design.md、最近のコミットを読んで、このアプリがどこまでできていて、何がまだ足りないかを教えてください。そのあとで次のことをしてください：<要件>。
```

## 規約をルールにする

```prompt
この規約を .agents/rules/<topic>.md に記録し、AGENTS.md の索引に登録して、いつ読むべきかを書いてください：
<規約>
```

## NocoBase Core をアップグレードする

```prompt
NocoBase を最新バージョンにアップグレードしてください。先にアップグレード計画を示し、私が確認してから変更してください。終わったら、すべてのテストを実行し、業務データがすべて残っていることを確認してください。
```

## デプロイする

```prompt
このアプリを Docker でサーバー <user>@<server address> のディレクトリ <path> にデプロイし、https://<domain>/<path>/ で公開してください。データベースは新しい空のものを使ってください。
コンテナを作り直しても失われないよう、設定とデータはデプロイ先のディレクトリに置いてください。管理者のパスワードは別途伝えます。コードやレポートには書かないでください。
デプロイ後、サインインしてレコードを 1 件作成し、コンテナを作り直して、データが残っていることを確認してください。最後に、HTTPS など、まだ設定されていないものを教えてください。
```

## ほかの部門からの要件

```prompt
開発チームに要件を出したいです：<一文で>。まずいくつか質問してから、要件定義書にまとめ、主要なページを 1 ファイルの HTML デモにしてください。
```
