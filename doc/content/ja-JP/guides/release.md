見積バージョン比較と顧客引き継ぎがマージされました。組み合わせた動作をテスト環境で確認し、同じ CRM リポジトリと業務データを引き継いで本番に公開します。

Studio の **Releases** には、PR を確認する **Preview**、マージ後を確認する **Staging**、Git tag と成果物を扱う **Release**、チームが確認した本番バージョンを記録する **Production** があります。Studio はプレビューとテストアプリをホストでき、本番へのデプロイは自社の環境で行います。

![CRM のリリース画面で四つの段階と未公開タスクの位置を確認します。](/assets/guides/studio/releases.png)

## テスト環境にデプロイして業務フローを確認する

CRM プロジェクトの **Releases → Staging → Deployment guide** を開きます。`crm-staging` などの独立したアプリ ID と、既存のテスト環境を指定します。

プロンプトをコピーしてローカルの Agent にビルドとアップロードを依頼するか、**Connect CI** でマージ後の自動更新を設定します。環境は[ホスト環境](../studio/admin/environments.md)、ビルドと報告は[チェックと CI](../studio/configure/checks.md)を参照してください。

![テスト環境への指引は Agent、CI、手動コマンドに対応します。](/assets/guides/studio/staging-guide.png)

実際に動いているコミットを確認します。Morgan が独立したテストデータで既存顧客と過去の見積を開き、新しい見積バージョンを比較し、顧客引き継ぎと新旧担当者の権限を確認します。承認、通知、メールを導入済みなら、それらも壊れていないか確認します。

**ステップの確認**：候補コミットで新旧のフローが動作し、不具合が修正済みか、公開対象から明示的に外されています。

## 公開待ちのタスクを確認する

**Pending release** は完了済みで本番に未交付のタスクを示します。**In staging** はテスト環境に入り、**Not deployed yet** はまだ入っていない状態です。見積比較と顧客引き継ぎが候補コミットに含まれるか確認し、**Done** だけでは判断しません。

依存する変更もまとめて確認します。必要なタスクが含まれなければテスト環境を更新して再確認し、未検証のデフォルトブランチ最新コミットをそのまま公開しないでください。

## バージョン系列を設定する

**Settings → Code repositories → Release lines** で `v*` などの tag パターンを設定します。既存のチーム規約があれば沿用し、複数のパターンを重複させません。[バージョンと公開](../studio/release/versions.md)を参照してください。

教材ソースの `lesson-N` は学習段階、`v1.1.0` などはアプリのリリースを表します。教材 tag の変更は本番更新ではありません。

## バージョンを公開する

**Release → How to publish** を開きます。

1. CRM リポジトリとバージョン系列を選びます。
2. 検証済みのテスト環境を選び、**Target commit** を照合します。
3. `v1.1.0` など未使用の tag を入力します。
4. **Included issues** と **Omitted issues** で範囲を確認します。
5. 生成されたコマンドをコピーし、自分の CRM リポジトリで tag を作って push します。

![公開パネルで対象コミット、含むタスク、含まないタスク、tag のコマンドを確認します。](/assets/guides/studio/publish.png)

Studio が tag を認識したら、デプロイ可能なアーカイブやイメージがあるか確認します。tag だけでは成果物にならず、CI や Agent のビルドとアップロードが必要です。また、バージョン公開だけでは本番に反映されません。

**ステップの確認**：検証済みコミットを指すバージョンに意図したタスクが入り、デプロイ成果物が利用可能です。

## 本番を更新し、実行バージョンを記録する

**Production → Deployment guide** で対象バージョンを選び、既存環境に合う **Docker** または **Installer** を使います。サーバーにアクセスできる Coding Agent に渡す場合は、既存の CRM を更新し、設定とデータを維持することを伝えます。

事前に DB と永続化ファイルをバックアップし、移行と復旧方法を確認します。更新後はログイン、旧顧客と過去の見積、比較、引き継ぎ権限を検証します。[本番への交付](../studio/project/release.md)を参照してください。戻す場合は、そのバージョンの互換性に応じてコードと DB をそれぞれ復旧します。

検証後、権限を持つプロジェクト責任者が実際のバージョンを記録します。記録はデプロイを実行せず、動作確認の代わりにもなりません。

**完了の条件**：本番と Studio の記録が一致し、Morgan が新機能を使え、既存データが残っています。その後のフィードバックも CRM のタスクにして、次の開発へ進みます。
