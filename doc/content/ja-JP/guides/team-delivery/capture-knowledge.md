業務ルールや過去の教訓が個別タスクに埋もれたままだと、担当者や Agent が代わるたびに同じ確認を繰り返したり既存の取り決めを壊したりしがちです。ここでは CRM で見積バージョンと顧客引き継ぎのルールが確定した想定（自分のプロジェクトでは直近で確定したルールに置き換えてください）を例に、Knowledge・Skills・プロジェクト記憶へ整理します。

開始前に、Studio に接続済みのプロジェクト（ナレッジ編集・スキル管理権限あり）と記録したい業務ルールを用意してください。3 つの保存先の役割分担は次のとおりです。

| 保存先 | 保存するもの |
| --- | --- |
| Knowledge | 人が維持する業務ルール、制度、判断の背景 |
| Skills | 開発、検証、レビューの進め方 |
| Project memory | Agent がタスク完了時に自動蓄積し、コードとともに維持する制約・つまずき・経験 |

ここで扱う資料は Studio の開発協働用であり、CRM アプリ内で営業が参照する業務ナレッジとは自動連携しません。

## CRM のルールと判断を Knowledge に保存する

CRM プロジェクトの **Knowledge** を開き、プロジェクトスペースに「CRM 業務ルール」の記事を作成して確定内容を保存し、権限設定から業務責任者 Morgan に編集権限を付与します（詳細は[Knowledge](../../studio/project/knowledge-base.md)）。

- 提出済み見積は変更不可とし、変更時は新しい下書きを作る。カタログ価格の変更で過去の金額は変えない。
- 既存見積の番号と内容を残し、過去の修訂履歴を推測で追加しない。
- 責任者が顧客を引き継ぎ、理由、操作人、日時を記録する。元のフォロー作成者と見積履歴は維持する。
- 元の担当者は担当に基づくアクセスを失う。協力には責任者の明示的な読み取り専用共有が必要。

![CRM の Knowledge で受け入れ基準と文書の管理情報を確認できます（画面はサンプルプロジェクトの例です）。](/assets/guides/studio/knowledge.png)

CRM プロジェクト画面の **Ask agent**（または CRM を紐付けた **My sessions**）で参照できるか確認します。

```prompt
顧客の引き継ぎ後、元の担当者はまだ閲覧できますか？プロジェクトのナレッジに基づいて条件を説明し、参照元を示してください。
```

**ステップの確認**：回答が文書と一致し参照元も示されます。読めない場合は、依頼者のナレッジ閲覧権限を確認してください。

## CRM の開発・レビューチェックリストを作る

CRM プロジェクトに紐付いた会話（または Studio 接続済みのローカル Coding Agent）で、まず下書きを作らせます。

```prompt
CRM の見積バージョンと顧客引き継ぎで得た知見を、今後 CRM を改善するときのチェックリストにまとめてください。顧客を閲覧・更新できる人、過去の見積の保持、引き継ぎ記録の漏れがないことを中心に、まず内容を見せてください。
```

単に「権限に注意」ではなく、具体的な確認方法を書きます。

| 対象 | 確認方法 |
| --- | --- |
| 顧客と関連データ | 担当者、権限のない営業、責任者で画面と API を確認 |
| 提出済み見積 | 新しい下書きとカタログ価格を変え、旧内容・金額を照合 |
| 引き継ぎと共有 | 取り消し後のアクセスと読み取り専用共有の制限を確認 |
| 既存データの更新 | 更新前のサンプルを残し、関連、作成者、履歴を照合 |

内容を確認したら、そのまま Agent にスキル作成と割り当てを依頼します。

```prompt
確認したチェックリストを、CRM の開発・自己検証・レビューで使う Studio スキル crm-checklist として作成し、CRM プロジェクトの既定スキルに割り当ててください。
```

左ナビゲーションの **Agent management › Skills** で手動作成し、プロジェクトの **Settings › Default skills** に追加・保存することもできます（形式と権限は[Skills](../../studio/project/skills.md)を参照）。

![Default skills でプロジェクトや対象リポジトリに Skill を割り当てます（画面はサンプルプロジェクトの例です）。](/assets/guides/studio/default-skills.png)

**ステップの確認**：CRM の既定スキルに `crm-checklist` が割り当てられ、その後の **Runs** と **引き渡しレポート** に実際の確認記録が残ります。割り当てだけでは実施の証拠になりません。

## Agent にプロジェクト記憶を自動蓄積させる

人が手動で管理する Knowledge とは異なり、プロジェクト記憶は 1 件ずつ手書きする必要がありません。Agent はタスクを完了する過程で、今後も役立つ経験——繰り返し起きるバグの原因、パフォーマンス上の注意点、指摘を受けて修正したやり方、コードからは読み取りにくい業務制約（例：「旧見積の履歴を推測で補わない」「担当者の権限を取り消すときは独立した共有も確認する」）、外部資料の参照先など——を自動でまとめ、作業ブランチの `.nb-studio/memory/` に項目ごとのファイルとして保存します。長期的な学びがない通常の変更では無理に記録せず、既存の記憶が最新コードと合わなくなった場合はタスク PR 内で自動更新または削除されます。

やり取りの中で確定したルールや教訓を確実に残したい場合は、タスクコメントで長期記憶するよう直接伝えることもできます。

記憶ファイルはタスク PR と一緒に提出・レビューされます。検収時に **View changes** で `.nb-studio/memory/` の追加・変更内容を確認し、誤記や古くなった項目、不要な記述を取り除いてください（秘密情報、個人情報、一時的な進捗は入れません）。**PR がマージされると**、CRM プロジェクトの **Memory** タブからリポジトリ別・種類別に項目と参照元コミットを確認できます（接続直後のプロジェクトで空でも正常です）。次回以降のタスクでは着手前に Agent が自動で記憶を読み込み、同じ落とし穴を繰り返さないようにします（詳細は[プロジェクト記憶](../../studio/project/project-memory.md)）。

![プロジェクト記憶をリポジトリと種類で確認します（画面はサンプルプロジェクトの例です）。](/assets/guides/studio/memory.png)

**完了の条件**：ルールに出典があり、チェックリストのスキルがプロジェクトに割り当てられ、タスクで自動蓄積・補足した経験がコード PR とともに保存されて次のタスクへ引き継がれます。

## まとめと次のステップ

業務ルール、開発・レビューチェックリスト、長期的な制約がそれぞれ適切な場所に整理されたことで、担当者や Agent が代わっても口頭での申し送りに頼らず共通の基準で進められるようになりました。

次は、リリース前に継続テストと課題追跡で品質を確認したい場合は[リリース品質を管理する](enterprise-management.md)へ進み、そのまま検証・公開へ進む場合は[本番にリリースする](release.md)をご覧ください。
