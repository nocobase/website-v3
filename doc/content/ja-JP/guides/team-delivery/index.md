Studio を使って複数人でアプリを開発・運用するチーム向けのシリーズです。既存の Core リポジトリを Studio に接続し、業務担当者が直接要件を伝え受け入れる方法、業務ルールをチーム資産として残す仕組み、そして安全にテスト・本番へリリースする手順を学びます。

## 事前準備

このシリーズを始める前に、次を確認してください。

- **Studio 環境とアカウント**：利用可能な Studio 作業環境、オンラインの実行環境、利用可能な Agent が必要です。未構築の場合は管理者が[インストールと設定](../../studio/setup/index.md)、[Git 連携](../../studio/setup/git.md)、[Agent 設定](../../studio/setup/agents.md)を完了し、招待を受けたメンバーは[プロジェクトに参加する](../../studio/join/index.md)からサインインします。
- **リポジトリとプロジェクト**：既存の NocoBase Core リポジトリがある場合は 1 本目から Studio に接続します。すでに接続済みのプロジェクトがあれば、必要な運用コースへ直接進めます。
- **メンバーアカウントと環境権限**：業務担当者との連携には業務担当者用アカウントとメンバー招待権限が必要です。リリース・保守には[チェックとプレビュー](../../studio/setup/ci.md)、[ホスト環境](../../studio/admin/environments.md)、リリース権限を用意します。

> [!NOTE]
> Studio を初めて使い、まず 1 件の要件の流れを体験したい場合は、[Studio で協働開発する](../../getting-started/collaborate-with-studio.md)からご覧ください。

## コース一覧

既存リポジトリを Studio に接続する場合は 1 本目から進めます。残りのコースは独立したチーム運用のテーマを扱っており、順番を問わず必要なものから取り組めます。

| コース | 完了時の状態 | 開始条件 |
| --- | --- | --- |
| [既存プロジェクトを Studio に接続する](../open-crm-project.md)（準備中） | 既存リポジトリを Studio に接続し、チェックと PR プレビューを整えてチーム開発を始められる。 | Studio 作業環境、対象リポジトリへのアクセス権、オンライン実行環境と Agent。 |
| [業務担当者が要件に直接関わる](../business-colleagues.md) | 業務担当者が Studio で直接要件を起票し、ルール確認とプレビューでの受け入れを行う。 | Studio プロジェクト、業務担当者のアカウント、メンバー招待権限。 |
| [業務ルールと開発経験を蓄積する](../capture-knowledge.md) | 確定した業務ルール、設計判断、レビュー項目をナレッジベースとプロジェクト記憶に整理する。 | ナレッジベースが使える Studio プロジェクトと、記録対象のルール・基準。 |
| [Studio で品質を管理する](../enterprise-management.md)（準備中） | 継続テスト、主要シナリオのチェック、課題追跡で並行開発の品質を管理する。 | Studio プロジェクト（詳細な設定はコース公開時に掲載）。 |
| [更新をリリースしてアプリを保守する](../release.md) | テスト環境で候補版を検証し、既存データを保ったまま本番環境へリリースする。 | Studio プロジェクト、候補コミット、テスト・本番環境、リリース権限。 |
