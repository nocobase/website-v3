description: "既存プロジェクトを Studio に接続し、業務担当者の要件参加、プロジェクト知識の蓄積、品質管理、テストと本番リリースを運用します。"
---

Studio を使って複数人でアプリを開発・運用するチーム向けのシリーズです。既存の Core リポジトリを Studio に接続し、業務担当者が直接要件を伝え受け入れる方法、業務ルールをチーム資産として残す仕組み、継続テストによる品質管理、そして安全にテスト・本番へリリースする手順を学びます。

## 事前準備

始める前に、次を確認してください。

- **Studio 作業環境**：サインイン可能で、オンラインの[ランタイム](../../studio/setup/shared-runtimes.md)と利用可能な [Agent](../../studio/setup/agents.md) があること。未構築の場合は管理者が[インストールと設定](../../studio/setup/index.md)と [Git 連携](../../studio/setup/git.md)を完了し、メンバーは[プロジェクトに参加する](../../studio/join/index.md)からサインインします。
- **リポジトリ**：既存の NocoBase Core リポジトリがある場合は 1 本目から接続します。試すだけなら [`nocobase/doc-demo-crm`](https://github.com/nocobase/doc-demo-crm) をフォークして使えます。接続済みプロジェクトがあれば、必要なコースへ直接進めます。
- **権限とエディション**：新規メンバー招待には管理者権限、リリースには[チェックとプレビュー](../../studio/setup/ci.md)と[ホスト環境](../../studio/admin/environments.md)が必要です。「リリース品質を管理する」は **Studio Enterprise Edition（EE）**、複数担当者の検収は**プロフェッショナル版・エンタープライズ版**が対象です。

> [!NOTE]
> Studio を初めて使い、まず 1 件の要件の流れを体験したい場合は、[Studio で開発を進める](../../getting-started/collaborate-with-studio.md)からご覧ください。

## コース一覧

既存リポジトリを Studio に接続する場合は 1 本目から進めます。残りのコースは独立したチーム運用のテーマを扱っており、順番を問わず必要なものから取り組めます。

| コース | 完了時の状態 | 開始条件 |
| --- | --- | --- |
| [既存プロジェクトを接続する](open-crm-project.md) | 既存リポジトリを Studio に接続し、チェックと PR プレビューを整えて最初の PR を通す。 | Studio 作業環境、対象リポジトリへのアクセス権、オンライン実行環境と Agent。 |
| [業務担当者と協働する](business-colleagues.md) | 業務担当者が Studio で直接要件を起票し、ルール確認とプレビューでの受け入れを行う。 | Studio プロジェクト、業務担当者のメールアドレスと招待権限。 |
| [知識と経験を蓄積する](capture-knowledge.md) | 確定した業務ルール、チェックリスト、経験をナレッジ・スキル・プロジェクト記憶へ残す。 | Studio プロジェクト（ナレッジ編集・スキル管理権限）と記録対象のルール。 |
| [リリース品質を管理する](enterprise-management.md) | 継続テスト、コアシナリオ確認、フォローアップで並行開発の品質を管理する。 | Studio Enterprise Edition（EE）、リポジトリ接続済みプロジェクト、有効なプロジェクト責任者、Agent とオンライン実行環境。 |
| [本番にリリースする](release.md) | テスト環境で候補版を検証し、既存データを保ったまま本番環境へリリースする。 | Studio プロジェクト、候補コミット、設定済みのテスト環境と自社の本番サーバー。 |
