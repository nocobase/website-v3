顧客、フォロー履歴、商談、見積を管理する CRM を、Studio で継続的に開発します。営業からの要望をタスクにまとめ、Agent チームが実装し、人が結果を受け入れます。既存のリポジトリ、設定、業務データを引き継ぎ、アプリを作り直す必要はありません。

以降の演習には[商談と見積](../../guides/opportunities-and-quotes.md)と[顧客のアクセス制御](../../guides/team-permissions.md)が必要です。未実装なら対応するレッスンを先に進め、回帰確認用に既存の顧客と見積を残してください。Studio のプロジェクトとタスクは開発を管理するもので、CRM 内の業務レコードとは別です。

[Studio demo](https://studio.demo.nocobase.com/main) で画面を確認できます。**CRM System** は協働の例ですが、変更を保存できません。演習には自分の Studio と CRM リポジトリを使い、画像のタスク番号やバージョン番号をそのまま使う必要はありません。

## Studio と Agent を準備する

[インストールの概要](../../studio/setup/index.md)に従い、[Git 接続](../../studio/setup/git.md)と [Agent](../../studio/setup/agents.md)を設定します。既存の Studio を使う場合は、対象リポジトリへのアクセス、オンラインの実行環境、調整と実装を担当できる Agent を確認します。

ライセンスとインストール用認証情報の条件はインストールガイドを参照してください。個人のログインや Git の認可はアカウントの所有者が行います。実行環境には CRM の依存関係をインストールしてテストできる環境と、利用する外部サービスの設定も必要です。

**ステップの確認**：Studio にログインでき、実行環境と Agent が利用可能で、Git 接続から CRM リポジトリにアクセスできます。

## 既存の CRM リポジトリを接続する

ローカルの CRM ディレクトリで、Studio に接続済みの Coding Agent に依頼します。

```prompt
Studio でチームと一緒に今の CRM を改善していきたいです。プロジェクト名は CRM にして、これまでの機能と情報を残してください。顧客、フォロー履歴、商談、見積を管理するプロジェクトだと説明に記載し、完了したらプロジェクトの URL を教えてください。
```

ローカルのツールが未接続なら、先に [Agent から Studio を使う](../../studio/join/local-agent.md)手順を進めます。**Projects → New project** で既存リポジトリを選ぶ方法もあります。[プロジェクト設定](../../studio/project/settings.md)を参照してください。

プロジェクトの **Settings → Code repositories** でリポジトリとデフォルトブランチを確認します。既存の `AGENTS.md`、開発 Skills、要件文書を残し、引き継ぐ Agent が業務ルールを読めるようにします。既存 CRM に新規アプリの初期化を実行しないでください。

![CRM のリポジトリ設定にはブランチ、チェック、バージョン系列、プレビューがまとまっています。](/assets/guides/studio/repositories.png)

**ステップの確認**：自分の CRM リポジトリと意図したブランチが接続され、既存のコードとデータが保たれています。

## チェックと PR プレビューを設定する

**Checks** の **Edit** からチェック元を選びます。

| チェック元 | 設定する内容 |
| --- | --- |
| Agent self-check | Agent がチェックを実行し、結果とプレビューを公開する |
| GitHub Actions | ワークフローと CI 用認証情報を設定する |
| External CI | 既存のパイプラインから結果とプレビューを公開する |

採用されるのは選択したチェック元の結果だけです。GitHub Actions では **Pull request** を選び、プレビュー環境を指定します。アプリがリポジトリ直下にある場合、**Directory** は `.` です。**Show prompt** で設定内容を取得し、ローカルの Agent に渡します。ネットワーク、認証情報、手動設定は[チェックとプレビューの設定](../../studio/setup/ci.md)を参照してください。

![Checks パネルでチェック元、トリガー、アプリのディレクトリ、プレビュー環境を設定します。](/assets/guides/studio/checks.png)

小さな変更で PR を作り、最新コミットに対するチェック結果を確認して **Code & previews** からプレビューを開きます。プレビューには独立したデータを使い、本番 DB を接続しません。ログイン、顧客と見積の表示、テスト用ロールのアクセス範囲を確認します。

**完了の条件**：Studio に自分の CRM リポジトリと正しいデフォルトブランチが接続され、既存のコードとデータが保たれ、実行環境と Agent が利用できます。PR の最新コミットに対するチェック結果と利用可能なプレビューがあり、担当者が顧客、見積、テスト用ロールのアクセス範囲を確認しています。

一般的な接続方法は、[既存プロジェクトを Studio に接続する](../../guides/open-crm-project.md)を参照してください。
