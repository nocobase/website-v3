## 製品と役割

| 用語 | 意味 |
| --- | --- |
| NocoBase Core | 業務システムを開発・運用するためのオープンソースの基盤。npm パッケージのセット |
| NocoBase Studio | 人がエージェントチームを率いてアプリを開発するワークスペース。商用版で提供 |
| NocoBase Solution | NocoBase 上に構築されたオープンソースの業務アプリのシリーズ。NocoCRM や NocoITAM など。個々のアプリは Solution アプリと呼ぶ |
| エージェント | AI の働き手の総称。コーディングツールとモデルの組み合わせで、たとえば「Claude · Opus 5.5」 |
| コーディングツール | Claude Code、Codex、OpenCode、Cursor など |
| 業務エージェント | アプリの中で、権限の範囲内で業務を担うエージェント。Agents プラグインで接続する。NocoBase 2 では「AI 従業員」と呼ばれていた |
| 開発エージェント | アプリのコードを書くエージェント。業務エージェントと区別する必要がある場合にだけ使う。それ以外では単にエージェントと呼ぶ |

## Core

| 用語 | 意味 |
| --- | --- |
| アプリ | NocoBase のテンプレートから作成したコードリポジトリ。デプロイすると業務システムになる。所有するのは自社 |
| テンプレート | アプリを作成するときの出発点。既定のテンプレートとサンプルのテンプレートがある |
| プラグイン | アプリに登録された `@nocobase/app-plugin-*` パッケージ。サーバー側の機能、ページ、UI コンポーネント、スキル、コマンドをもたらす |
| プラグインリスト | アプリ内でプラグインを登録する 3 つのファイル：`server/plugins.ts`、`client/plugins.ts`、`cli/plugins.ts` |
| 基盤ライブラリ | レコードのライフサイクルやデータベースなど、登録せずにアプリが直接使うパッケージ |
| UI ライブラリ | NocoBase が公開する業務コンポーネント。インストールするとアプリのソースにコピーされ、以降はアプリのものになる。個々の項目はコンポーネントまたはブロックと呼ぶ |
| スキル | エージェントに何かのやり方を教える指示書（`SKILL.md`）。パッケージに同梱されたスキルは、アプリの `.agents/skills/` に同期される |
| 機能 | Core が提供する機能の種類。**App foundation** の 13 のカテゴリーに分類される |
| システム設定 | アプリの管理用の入口：ユーザー管理、ロールと権限、ワークフロー管理、App foundation など |
| App foundation | 既定のテンプレートに付属するページ。アプリが使っている Core の機能と、それを提供するパッケージを表示する |
| レコードのライフサイクル | レコードの状態をそのレコード自身のフィールドに保存し、状態間の遷移をコードで宣言するもの。NocoBase 3 のワークフローはすべてこの上に構築される |
| ワークフローパラメーター | 承認者や金額のしきい値など、管理者が **Workflow management** で調整できる値 |
| 権限セット | ページ、操作、データ範囲の付与をまとめたもの。ロールまたは個人に割り当てる。画面では「ロール」と表示される |
| データ範囲 | 操作の対象になるレコードの範囲。たとえば「自分が担当する注文」 |
| マイグレーション | データベースの構造を変更するコードファイル。順番に実行され、実行済みのマイグレーションは編集しない |
| `config.yml` | アプリのデプロイ設定：データベース、ストレージ、シークレット、バックグラウンドジョブなど。コードリポジトリにはコミットしない |

## Studio

| 用語 | 意味 |
| --- | --- |
| タスク | Studio で引き渡す仕事の基本単位（英語の画面では issue）。「チケット」や「依頼票」とは呼ばない |
| タスク責任者 | タスクの結果に責任を持つ人。常に人である |
| コーディネーターエージェント | 仕事をステップに分け、割り振り、質問し、検収に引き渡す、唯一のシステムエージェント（画面上の名称は Lead Agent）。コードは書かない |
| 実行エージェント | コーディネーターエージェントが割り振ったステップを実行する、エージェントチームのエージェント |
| 自分のエージェント | Claude Code や Codex など、自分が使うコーディングツール。Studio に接続すると、My sessions であなたと要件を相談する |
| エージェントチーム | チームが有効にしたすべてのエージェント |
| ランタイム | `nocobase-runner` を実行するマシン。共有ランタイムと個人ランタイムがある |
| My issues、My sessions | 仕事を追う 2 つの入口：タスクごと、セッションごと |
| プロジェクトメモリー | エージェントが作業中に書き留めたこと。コードリポジトリに保存され、エージェントが自分で読み書きする |
| ナレッジベース | 人が作成・アップロードした資料。エージェントは読むだけ |
| 引き渡しレポート | タスクが In review に移るときに、コーディネーターエージェントが提出するもの |
| Backlog / In progress / Blocked / In review / Done / Cancelled | タスクの 6 つの固定のステータス。In review は、引き渡し済みでタスク責任者の検収を待っていることを意味する |

Studio の用語の全体は、Studio の [基本概念](../studio/intro/concepts.md) を参照してください。

## 表記のルール

- 画面上の名前、ボタン、メニューは、英語の画面の表記どおりに **太字** で書きます。パスは **A › B** の形で書きます。
- 日本語と英数字の間には半角スペースを入れます。
- コード内の名前（パッケージ名、ファイル名、コマンド）はコード書式で書き、必要な場合にだけ使います。
