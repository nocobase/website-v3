Core はアプリケーション基盤です。あらゆる業務システムに共通する共通機能と開発規約を提供し、エージェントはその上で各社固有のニーズに合わせて開発します。Studio は、人とエージェントが協働開発するためのガバナンスプラットフォームです。エージェントが仕事を分担して進め、人は進捗を把握して重要な判断を下します。NocoBase は、AI のソフトウェア開発能力を、信頼できる業務システムをリリースごとに届け続ける組織の力に変えます。

## なぜ NocoBase なのか

AI でコードはすぐに書けます。それでも、信頼できる業務システムをつくるのは簡単ではありません。チームはすでに AI による開発やバイブコーディングを取り入れ、最初のバージョンはすぐに形になります。しかし業務システムは何年も使われます。機能は追加され続け、プロセスは変わり続け、担当者も引き継がれていきます。そこで新たな課題が生まれます。

### プロジェクトのたびに基盤を作り直す

AI がコードを書くとしても、権限、ワークフローエンジン、承認をゼロから設計するのは難しく、例外ケースも多く、保守の負担も大きくなります。

Core はすぐに使える共通機能を提供し、NocoBase がそれを継続的に保守・アップデートします。たとえば購買チームに仕入先管理システムが必要なら、エージェントは仕入先情報、発注書、承認ルールといった業務部分だけを書き、Core の権限と承認はそのまま使います。書いて検証すべきコードは大幅に減ります。

### アーキテクチャが場当たり的に崩れていく

担当者やモデル、さらには会話が変わるたびに、AI はその場しのぎの実装をしがちです。同じシステムがいくつもの異なる書き方で作られ、どんどん保守しにくくなります。

Core は統一されたプロジェクト構成と開発規約を提供し、エージェントはパッケージに同梱された開発スキルに従ってコードを書きます。そのため、システムは統一されたアーキテクチャのもとで長期にわたって安定して進化します。

### 並行作業が増え、人の確認が追いつかない

チームは複数のプロジェクトとタスクを同時に抱え、誰もがターミナルや会話を行き来しています。エージェントから届く変更は増える一方です。すべてを確認しきれず、かといって任せきるのは危険に感じます。

Studio はひとつのエージェントチームを取りまとめて、多数のプロジェクトとタスクを同時に進め、進捗はひと目でわかります。人の介入が必要なときは、エージェントがレポート、チェックリスト、スクリーンショットを添えるので、人は根拠を手元に置いて判断できます。

### 知識やノウハウが蓄積・共有されない

要件の背景、業務資料、得られた教訓が、別々の PC の会話に散らばっています。担当者やエージェントが変わると、見つけるのが難しくなります。

Studio は方法と経験をスキル、ナレッジベース、プロジェクトメモリーに蓄積するので、新しい担当者やエージェントも前任者の続きから仕事を引き継げます。

- **[Core](../core/index.md)** は、AI で業務システムを開発・運用するためのオープンソースのアプリケーション基盤です。権限、ワークフロー、ファイルなどの共通機能がそろっているため、エージェントは統一されたアーキテクチャの上で、自社の業務固有の部分だけを開発します。
- **[Studio](../studio/index.md)** は、人とエージェントが協働開発するためのガバナンスプラットフォームです。Claude Code、Codex、OpenCode をひとつのエージェントチームにまとめ、タスクを自律的に進めます。進捗はひと目でわかり、重要な判断は人が下します。
- **Solution** は、Core 上に構築された、エージェントが動かす業務アプリのシリーズです。NocoCRM や NocoITAM などがあります。実務の大部分はエージェントが担い、人は重要な判断だけを行います。そのままインストールして使うことも、エージェントに自社の業務に合わせてカスタマイズさせることもできます。

## Core だけか、Studio も使うか

| | Core のみ | Studio を使う |
| --- | --- | --- |
| 誰が開発するか | アプリのディレクトリで Claude Code、Codex などのコーディングツールを開き、エージェントと一緒に開発します | チームのエージェントがエージェントチームを組み、コーディネーターエージェントが設計、開発、テスト、レビューを割り振ります |
| 向いているケース | 1 人または少人数のチームで、1 つまたは少数のアプリを開発する場合 | チームで多数のプロジェクトとタスクを同時に進め、業務の専門家が直接要件を出して判断する場合 |
| チェックとリリース | テスト、レビュー、デプロイはチームが自分で取りまとめます。Core のデプロイツールと開発ガイドを使います | チェックとレビューを通過してから人が検収し、保護された環境へのデプロイには承認者の承認が必要です |
| はじめ方 | [Core アプリを作成する](../core/getting-started/create-app.md) | [Studio とは](../studio/intro/what-is-studio.md) |

どちらの場合も、開発されるアプリは同じで、すべて Core の上に構築されます。

## 業務システムの中のエージェント

アプリが稼働すると、エージェントはアプリの中で業務も担えます。顧客の調査、メールの下書き、資産台帳の照合、サポートチケットの対応などです。こうした業務エージェントは Core の Agents プラグインで接続され、人と同じ権限を使います。判断が必要なときは、根拠を添えて担当者に引き渡します。Solution アプリにはすべて業務エージェントが組み込まれており、自社のアプリにも必要に応じて追加できます。

## セルフホスト

Core、Solution、Studio はすべて自社サーバーで稼働し、コードとデータは自社のものです。モデルとエージェントは自由に選べ、特定ベンダーに縛られません。Claude Code、Codex などのコーディングツールと、さまざまなモデルに対応しています。業務アプリはリリース後、独立して稼働し、日常の業務リクエストが Studio を経由することはありません。

## NocoBase とバイブコーディングの関係

バイブコーディングはソフトウェア開発を速くします。しかし、複雑な業務ロジック、多くの関係者、長年にわたる改修を伴うプロジェクトでは、AI が生成したコードだけでは足りません。信頼できるアプリケーション基盤、統一された開発規約、しっかりしたガバナンスも必要です。NocoBase はバイブコーディングに基盤とガバナンスを加えるもので、チームは引き続き Claude Code、Codex などのコーディングツールでコードを書きます。
