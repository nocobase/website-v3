CI によるアプリのデプロイ、スクリプトによるタスクの一括作成、ほかのシステムによるレポートの読み取りなど、人がブラウザーで操作しない場面では、API キーを使って Studio を呼び出します。キーには 2 種類あります。

| | 組織の API キー | 個人の API キー |
| --- | --- | --- |
| 管理する場所 | **Settings › API keys** | **Account settings › API keys** |
| だれとして動作するか | キー自身。だれにも属さないため、作成した人が離れても動作し続けます | あなた |
| できること | 選ばれたことだけ | あなたができることを、選ばれた範囲に絞ったもの。あなたが権限を失うと、キーも失います |
| 作成できる人 | Admin と Owner | すべてのメンバー（組織が個人のキーをオフにしていない場合） |
| 向いている用途 | CI と長期的な連携 | 自分のスクリプト |

## 組織のキーを作成する

1. **Settings › API keys** を開き、新しいキーを作成します。
2. 名前と説明を入力します。たとえば「GitHub Actions deployment」です。
3. 権限を選びます。**Start from a preset** から始めて調整することもできます。
   - **CI deployment**：リリースをアップロードしてデプロイします。一部のアプリに限定することもできます。
   - リリースをアップロードするがデプロイはしない CI 用のプリセット。自分でデプロイすべきでない CI 向けです。
   - **Read only**：あなたが読めるものをすべて読みます。
4. 有効期限を選びます。既定は 90 日で、**Never** も選べます。
5. 作成されたらキーをコピーします。表示されるのはこの一度だけで、あとから見ることはできません。

権限は、プロジェクト、タスク、エージェント、ランタイム、アプリ、デプロイ環境、ナレッジベース、レポートなどの領域ごとにまとめられ、それぞれに読み取り、書き込み、管理などのレベルがあります。一部は特定のプロジェクトやアプリに限定できます。付与できるのは自分が持っている権限だけで、持っていないレベルはグレー表示になります。

## キーにできないこと

権限がどれだけ広くても：

- キーは、キーの作成、ローテーション、取り消しができません。キーを管理できるのはサインインした人だけです。
- キーは、アプリの変更や削除、保護された環境への直接のデプロイができません。承認者が承認するデプロイをリクエストすることだけができます。
- 受信トレイ、通知、コードホストの接続、アカウント管理を支えるエンドポイントは、キーを受け付けません。

キーが何かを行った場所には、API キーであることを示す印とともにその名前が表示されます。

## ローテーション、無効化、削除

- **Rotate**：新しいキーは同じ名前、権限、有効期限を引き継ぎ、古いキーはすぐに使えなくなります。新しい値を CI のシークレット設定に入れてください。
- **Disable**：すぐに使えなくなります。必要に応じて再び有効にできます。
- **Delete**：キーを取り消します。キーが行ったことには、引き続きその名前が表示されます。

組織のキーにはすべて **History** があり、だれがいつ作成、名前の変更、権限の変更、ローテーション、無効化、削除を行ったかが記録されます。

## リポジトリの CI キー

リポジトリに CI を設定すると、Studio は「<repository> CI」という名前の組織のキーを作成します。キーには「Managed by <repository>」と表示され、権限はそのリポジトリのアプリに限定されます。有効期限のリマインダーとローテーションの方法については、[CI を接続する](../setup/ci.md) を参照してください。ここで無効化または削除すると CI はデプロイできなくなり、プロジェクトリーダーに通知されます。

## 個人のキーをオフにする

メンバーに自分のキーを作成させたくない場合は、**Settings › Roles** で該当するロールから「Create API keys of one’s own」を外します。既存のキーは引き続き表示・取り消しできます。
