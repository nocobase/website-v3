管理者は **Releases › Deploy environments** でデプロイ環境を管理します。環境ごとに独自のアプリのセットがあるため、ある環境を変更しても、別の環境のアプリには影響しません。

| 環境 | 作られ方 | 用途 |
| --- | --- | --- |
| Preview | Studio のインストール時に自動で作成 | 各 PR のプレビュー。検収の前に自分で変更を試します |
| Staging | 管理者が追加 | マージ後に自動でデプロイされ、リリース前にチームが試します |
| Production | 管理者が追加。Studio が自動で作成することはありません | 実際に使われる業務システム。デプロイには毎回承認が必要です |

## 2 つの実行モード

環境を追加するときは、最初に実行モードを選びます。あとから変更することはできません。

| 実行モード | アプリが動作する場所 | 向いている用途 |
| --- | --- | --- |
| In process | Studio のサーバー上。Docker は不要です。アプリは最初のアクセスで起動し、使われていないときは停止します | プレビュー |
| Docker | Studio のサーバー上の Docker。アプリごとに 1 つのコンテナで、互いに分離されます | ステージングと本番 |

Docker モードでは、デプロイ時にバージョンのダイジェストでイメージを取得し、先に新しいコンテナを起動して、ヘルスチェックを通過してからトラフィックを切り替えます。新しいバージョンが正常にならなければ、古いコンテナが引き続き応答し、デプロイは失敗します。ロールバックも同じ方法で以前のイメージをデプロイします。

Docker モードを使う前に、Studio の `config.yml` でオンにし（`releases.docker.enabled`）、Studio を実行するユーザーが Docker にアクセスできることを確認してください。

## 環境を追加する

1. **Releases › Deploy environments** を開き、**Add environment** をクリックして、実行モードを選びます。
2. 名前と環境 ID を入力します。たとえば「Staging」と `staging` です。環境 ID はアドレスに使われ、作成後は変更できません。
3. **Public URL pattern**：この環境のアプリを人が開く場所です。`{appId}` がアプリを表します。たとえば `https://apps.example.com/{appId}/` です。
4. Docker の場合は、CI がイメージをプッシュする **Registry** を選ぶか、アドレスと取得用の認証情報を入力して追加します。
5. 次のセクションで説明するポリシーを設定します。
6. 保存する前に **Test connection** をクリックし、接続できることを確認します。

アプリの設定では、環境に置けるアプリの最大数と、使われていないアプリが停止するまでの時間、休止するまでの時間を設定できます。停止したアプリはメモリを解放し、次のアクセスで再び起動します。休止したアプリは展開したファイルも削除され、設定とデータは保持されるため、次のアクセスでの準備に時間がかかります。

## 保護された環境と承認者

**Protected** をオンにすると、その環境へのすべてのデプロイ（人、エージェント、CI のだれが開始したものでも、ロールバックも含む）が、承認者を待つデプロイリクエストになります。承認するには、承認者がアプリ ID をもう一度入力します。

承認者には次の人を指定できます。

- プロジェクトリーダー：デプロイするアプリのリポジトリを持つプロジェクトのリーダー。
- 管理者：Owner と Admin。
- 特定の人。

承認者のだれか 1 人が承認すれば十分で、自分のリクエストを自分で承認することはできません。承認者を選んでいない場合は、管理者が判断します。承認者が行うことについては、[リリースの承認とロールバック](../project/release.md) を参照してください。

> [!WARNING] 先に本番をバックアップする
> Studio はデプロイの前にアプリのデータベースをバックアップしません。本番のデータベースは自分で定期的にバックアップしてください。

## プレビュー環境

プレビュー環境は Studio のインストール時に自動で作成されます。In process モードで動作し、保護されていません。既定では同時に最大 20 個のプレビューを動かし、プレビューは 10 分間アクセスがないと停止し、24 時間で休止します。

- CI で作成された PR プレビューは、初回のデプロイ時にサンプルデータを読み込み、初期管理者を生成します。自社の実データは含まれません。
- PR がマージまたはクローズされると、そのプレビューは自動で削除されます。
- プレビューに変数が足りない場合は、タスクページのプレビューエリアに足りないものが表示されます。環境を管理できる人は、プレビュー環境全体にその変数を設定でき、以降はすべてのプレビューで使われます。

PR の自動プレビューについては、[CI を接続する](../setup/ci.md) を参照してください。

本格的に使う場合は、Studio のアドレスを共有せずにプレビュー専用のドメインを使い、Studio の設定を読めない別のシステムユーザーでプレビューを実行します。[設定項目](../reference/config.md) を参照してください。

## 環境変数

デプロイされたアプリが読み取る変数は、環境（その環境のすべてのアプリ向け）または個々のアプリに設定できます。アプリ自身の変数が優先されます。シークレットは暗号化され、二度と表示されません。
