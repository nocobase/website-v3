---
title: チェックと CI
description: リポジトリの CI でアプリをビルドし、PR プレビューとテスト環境を Studio に配信します。
---

リポジトリごとに、変更を検証してプレビューを公開する方法を選びます。Studio は、コードプラットフォームの CI、外部の CI、エージェントのセルフチェックに対応しています。

## チェックの取得元

各リポジトリは、**Project settings › Code repositories › Checks** で選んだ取得元からの結果だけを受け付けます。

| 取得元 | 仕組み |
| --- | --- |
| コードプラットフォームの CI | GitHub Actions または GitLab CI がチェックを実行します。下記で生成する設定を使います |
| 外部の CI | 既存のパイプラインが、リポジトリの CI キーを使ってチェックを報告し、プレビューを公開します |
| エージェントのセルフチェック | エージェントがプロジェクトのスクリプト、README、AGENTS.md からチェックを判断し、各結果を `nb-studio check report` で報告して、PR プレビューをビルド・公開します |

エージェントのセルフチェックには CI ファイルは不要です。外部の CI の場合は、その取得元を選び、Studio に表示されるコマンドを使います。キーはパイプラインのシークレットストアに保存してください。取得元を切り替えると、Studio は以前の取得元からの報告を受け付けなくなります。

以下の手順では、コードプラットフォームの CI を扱います。

## 前提条件

- **CI から Studio に到達できる。** クラウドの CI は localhost やプライベートネットワークには到達できません。到達可能な HTTPS アドレスか、Studio にアクセスできるセルフホストの runner を使います。
- **対象の環境がある。** Studio にはプレビュー環境があります。管理者は [デプロイ環境](../admin/environments.md) でテスト環境を追加できます。
- **プロジェクトを管理できる。** CI キーを生成するにはこの権限が必要です。

プレビュー用とテスト用のアプリは、Studio のサブプロセスとして動作します。本番のイメージは別にビルドしてデプロイしてください。Studio は本番のデプロイをホストしません。[本番へのデプロイ](../project/release.md) を参照してください。

## 設定を生成する

1. プロジェクトの概要を開き、プレビュー用 CI の設定項目を選びます。**Settings › Code repositories** を開いて、リポジトリの **Checks** を選ぶこともできます。
2. チェックの取得元として、**GitHub Actions** などコードプラットフォームの CI を選びます。トリガーと環境を選びます。

   | トリガー | 用途 |
   | --- | --- |
   | Pull request | PR ごとにプレビューを作成し、PR がマージまたはクローズされると削除します |
   | Push to a branch | 選んだブランチの変更をテスト環境に配信します |
   | Tag | 一致するタグを選んだテスト環境に配信します。既定のパターンは `v*` です |

3. アプリのディレクトリと ID を入力します。アプリがリポジトリのルートにある場合は `.` を使います。
4. ローカルのコーディングエージェント用のプロンプトをコピーします。エージェントが CI ファイルを追加し、シークレットを保存して、PR を作成します。
5. 手動で設定する場合は、手動設定のセクションを展開します。CI キーを生成してコードプラットフォームに保存し、提供された CI ファイルをリポジトリに追加します。

1 つの設定が対象にするトリガーは 1 つです。PR プレビューとブランチのデプロイは、別々に設定してください。

GitHub では `.github/workflows/` 以下のワークフローと、Actions のシークレット `NB_STUDIO_API_KEY` を使います。GitLab では `.gitlab/` 以下のファイルを使い、`.gitlab-ci.yml` から読み込みます。Studio はこれらのファイルを自動ではコミットしません。

## CI を検証する

PR を作成し、CI が終わるのを待ちます。

1. **Settings › Code repositories › Build records** でビルドを確認します。
2. タスクの **Code and preview** タブを開き、結果とプレビューのリンクを確認します。
3. プレビューを開き、サインインしてアプリを使えることを確認します。

最初の報告を待っている設定は、まだ検証されていません。

## CI キーを保守する

CI キーは組織に属します。リポジトリではなく、コードプラットフォームの CI シークレットに保存してください。表示されるのは生成時だけです。

キーは 90 日で期限が切れます。Studio は期限の 14 日前、3 日前、当日に、プロジェクトリーダーと管理者にリマインダーを送ります。促されたら、保存済みの CI シークレットを置き換えてください。キーを無効化または削除すると、CI は Studio にデプロイできなくなります。

## プレビューを使う

PR プレビューはサンプルデータを使います。タスクを編集できるメンバーは、初期管理者の認証情報を確認できます。

プレビューが不要なタスクでは、プロパティで **No preview needed** をオンにします。エージェントが `no-preview` ラベルを付け、CI テンプレートはそれに従います。処理能力とスリープの設定については、[PR プレビュー](../release/previews.md) を参照してください。
