---
title: リポジトリのチェックと CI を設定する
description: "チェックの取得元、PR プレビュー、テスト環境への配信を設定します。"
---

**プロジェクト設定 › コードリポジトリ**で **Checks** と **Previews** を個別に設定します。同じ PR で GitHub Actions のチェック結果を使い、プレビューの公開をエージェントに任せることもできます。

![リポジトリのチェック取得元に GitHub Actions を選ぶ](https://static-docs.nocobase.com/studio-guide-en-checks-20261127-a6340eebb255.webp)

## エージェントのセルフチェック

新しいリポジトリではセルフチェックが既定です。エージェントはプロジェクトのチェックを実行し、`nb-studio check report` で結果を報告します。プレビューの公開も任せる場合は **Previews** で **Agent build** を選びます。

## コードプラットフォームの CI

GitHub Actions、GitLab CI、Gitea Actions を利用している場合は、**Checks** でコードホストを選んで保存します。Studio は関連する PR または MR から既存のチェック結果を取得します。

CI からプレビューも公開する場合は、次のように設定します。

1. **Previews** で **CI build** を選びます。
2. リポジトリの CI キーをパイプラインのシークレット `NB_STUDIO_API_KEY` に保存します。`NB_STUDIO_URL` には実行環境からアクセスできる Studio の URL を設定します。外部 CI のチェック報告とプレビュー公開には同じキーを使えます。
3. パネルの設定例に従って PR 用のビルドジョブを追加します。既存のパイプラインでは、表示されたビルドと公開のコマンドを組み込みます。保存後、PR で動作を確認します。

コードホストの CI を使う場合は、トリガー、対象環境、アプリのディレクトリ（リポジトリ直下は `.`）を選びます。PR はプレビューに、ブランチへのプッシュやタグは[テスト環境](../admin/environments.md)へのデプロイに使います。設定はトリガーごとに生成します。CI の実行機から Studio に接続できることを確認してください。

![CI build でリポジトリキーの設定とワークフローの選択肢を確認する](https://static-docs.nocobase.com/studio-guide-en-ci-build-20261127-a2f2cc4abfa1.webp)

## 外部 CI

**Checks** で **External CI** を選び、リポジトリの CI キーをパイプラインのシークレットに保存します。生成されたスクリプトで各チェックの状態とログ URL を送信します。プレビューも公開する場合は、**Previews** で **CI build** を選びます。

キーは生成時にだけ表示されます。リポジトリには保存しないでください。リポジトリの CI キーの有効期限は既定で 90 日です。期限の通知を受け取ったらキーを交換し、パイプラインの変数を更新します。

## ブランチルールを設定する

**Project settings › Code repositories › Branch rules** で設定します。

- 必須チェックの失敗時にコーディネーターエージェントを起動するか。
- チェック通過時に次のステップを開始するか。
- PR の競合時に修正を開始するか。
- どのチェックを参考情報とし、Studio の通常のマージを妨げないようにするか。

参考情報に指定していないチェックは必須です。コードプラットフォームのブランチ保護も適用されます。自動起動を無効にした場合は、タスクのコメントでコーディネーターエージェントに続行を依頼します。

## 接続を確認する

PR を作成したら、タスクの **Code & previews** でチェック結果を確認します。プレビュー公開後、リポジトリの **Previews** 行の **Build records** に公開済みのアプリと公開元が表示されます。

**Not reported yet** は、選択した取得元から結果が届いていない状態です。必須変数が不足している場合は、表示に従って環境またはアプリに設定します。プレビュー不要のタスクには **No preview needed** を指定できます。生成される CI テンプレートは `no-preview` ラベルを認識します。

結果とタスク進行の関係は[PR のチェックとコードレビュー](../project/checks-and-review.md)を参照してください。
