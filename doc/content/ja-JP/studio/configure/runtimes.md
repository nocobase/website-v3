---
title: ランタイム
description: チームのサーバーや仮想マシンに runner をインストールして Studio に接続します。そこにインストールされたコーディングツールがエージェントチームに加わり、全員のタスクを実行します。
---

ランタイムは、エージェントが作業するマシンです。共有ランタイムがあるからこそ、エージェントチームは 24 時間働き続けられます。接続には管理者の権限が必要です。自分のマシンを接続する場合は、[個人ランタイムを接続する](../join/personal-runtime.md) を参照してください。

## マシンを準備する

| 項目 | 要件 |
| --- | --- |
| オペレーティングシステム | macOS または Linux。Windows では WSL 上の Ubuntu で実行します |
| 基本ソフトウェア | Node.js 24 以降と Git。NocoBase のアプリテンプレートを使うプロジェクトでは pnpm も必要です。Node.js に同梱の corepack で有効にできます：`corepack enable` |
| コーディングツール | runner を実行するシステムユーザーで、Claude Code や Codex などを公式の方法でインストールしてサインインします。レビューを別ベンダーのモデルに回せるよう、2 つのベンダーのツールを用意してください |
| コードホストの CLI | エージェントが PR を作成するのに使います。GitHub では `gh`、GitLab では `glab` |
| ブラウザー | エージェントが画面を変更すると、引き渡しレポート用に動作中のアプリでスクリーンショットを撮ります。ランタイムで Chromium を実行できる必要があります。Linux では、システム依存関係と一緒にインストールします。たとえば `npx playwright install --with-deps chromium` です |
| ネットワークアクセス | マシンから Studio のアドレスに到達でき、各コーディングツールがそのモデルサービスに到達できること |

> [!NOTE] 専用の環境を使う
> コーディングツールと runner は、Studio から分離した専用のコンテナまたは仮想マシンにインストールすることをおすすめします。エージェントは、ランタイムのシステムユーザーがアクセスできるファイルを読み書きし、コマンドを実行できます。

## ランタイムを追加する

1. **Agent management › Runtimes** を開き、**Add runtime** をクリックします。
2. **Usage scope** で **Shared** を選びます。すべてのユーザーが開始したタスクを実行し、その変数とシークレットを受け取ります。
3. **Coding tools** で、このマシンで使いたいツールにチェックを入れます。チェックを入れたツールの作業だけがここに送られます。
4. **Max concurrent runs** は、マシンが同時に実行する作業の数で、既定は 3 です。マシンのリソースとモデルの利用枠に合わせて設定します。サブスクリプションで許可されるセッション数が少ないツールには、**Advanced: limits per coding tool** で個別の上限を設定します。
5. **Generate install command** をクリックし、マシンのオペレーティングシステムを選びます。

ツールと同時実行数は、あとからランタイムの詳細で変更できます。

::figure qs-add-runtime | 共有ランタイムを追加する

## マシンにインストールする

インストール方法は 2 つあり、どちらを使ってもかまいません。

**プロンプト。** ダイアログのプロンプト全体を、そのマシンのコーディングツール（Claude Code など）にコピーします。ツールは Node.js とコーディングツールを確認し、登録コマンドを実行し、runner をバックグラウンドサービスとしてインストールし、PATH、プロキシ、npm の権限などのよくある問題を解決して、最後に自分で行う必要があるサインインやネットワーク設定を教えてくれます。

**手動。** エージェントを実行するシステムユーザーで、ダイアログのコマンドをマシンで実行します。たとえば：

```bash
curl -fsSL https://studio.example.com/main/api/agents/dist/installScript | sh -s -- --runner --server https://studio.example.com/main --token <one-time credential>
```

このコマンドは、Studio から runner（`nocobase-runner`）と `nb-studio` CLI をダウンロードし、runner を登録して、サインイン後に自動で起動するよう設定します。マシンにすでに `nocobase-runner` がインストールされている場合は、代わりにダイアログの `nocobase-runner register` コマンドを使います。

**Windows。** 先に PowerShell で `wsl --install` を実行し、Windows を再起動します。続いて Ubuntu を開き、Linux 用のコマンドを実行します。Node.js とコーディングツールはすべて WSL 上の Ubuntu に入れます。WSL からインターネットに接続できない場合は、WSL のミラーモードのネットワークをオンにします。

プロンプトとコマンドには、一度だけ使える認証情報が含まれています。有効期限はダイアログに表示され、通常は数分以内です。期限が切れたら、新しく生成してください。プロンプトはそのマシンのコーディングツールにだけ渡し、ほかの人には絶対に渡さないでください。

## 接続を確認する

数秒以内に、ランタイムが一覧に **Online** として表示され、実行中の数（「Online 0/3」など）と、チェックを入れた各コーディングツールの状態が示されます。

| 状態 | 意味 | 対応 |
| --- | --- | --- |
| Signed in | 作業できる状態 | 不要 |
| Login required | インストールされているがサインインしていない | マシンで、runner を実行するシステムユーザーとしてツールにサインインし、詳細で **Detect again** をクリックします |
| Not installed | ツールが見つからない | インストールします。インストール済みなのにまだ表示される場合は、下のトラブルシューティングを参照してください |

**完了の目安**：ランタイムがオンラインで、使いたいコーディングツールに **Signed in** と表示されていること。このとき **Agent management › Agents** には、よく使われるモデルのエージェントが一覧表示され、ほかのモデルは **Add agent** で追加できます。次に、[エージェントを有効にします](../setup/agents.md)。

## ランタイムを管理する

一覧でランタイムをクリックすると、詳細が開きます。

- **General**：名前、最大同時実行数、使用範囲。
- **Tools**：各コーディングツールのオン・オフ、状態、利用枠、同時に実行できる数。オフにしたツールの作業はここに送られません。
- **Local policy**：マシンの所有者がそのマシンで許可している作業の種類。マシン自体で設定し、Studio は表示するだけです。
- **Variables from this machine**：マシンが実行に提供できる変数。名前だけが表示され、値はマシンに残ります。`nocobase-runner env set NAME` で設定します。
- **Workspaces** と **Runs**：このマシン上のタスクのディレクトリと、このマシンが行った実行。

runner は、エージェントが実行されていないときに自動でアップグレードします。すぐにアップグレードするには、マシンで `nocobase-runner update` を実行します。

ランタイムの使用をやめるときは、先に認証情報を取り消します。runner は次のリクエストで停止し、保持していた作業はキューに戻ります。取り消したあとで削除でき、実行履歴は保持されます。再び接続するには、もう一度追加します。

## トラブルシューティング

**ランタイムがオフラインと表示される。** 150 秒間 Studio に接続していない runner はオフラインと表示され、その作業はキューに戻ってほかのランタイムが引き受けます。マシンで `nocobase-runner status` を実行し、runner が動いていて、マシンから Studio のアドレスに到達できることを確認します。

**ツールをインストールしたのに、まだ Not installed と表示される。** バックグラウンドサービスの PATH にツールが含まれていません。`which claude` や `which codex` が動作するターミナルで `nocobase-runner service install` をもう一度実行し、サービスを再起動します。

**runner のダウンロードが失敗する。** プロキシが必要な場合は、ダウンロードとバックグラウンドサービスの両方に設定します。npm にグローバルインストールの権限がない場合は、`sudo npm install` ではなく、自分のユーザーが所有するインストール先ディレクトリか Node のバージョンマネージャーを使います。
