description: コーディネーターエージェントがどのように仕事を割り振り、タスクを並行して進め、判断をタスク責任者に委ねるか。

Claude Code や Codex などのコーディングツールを接続して、エージェントチームを編成します。コーディネーターエージェントが仕事を割り振り、実行エージェントが設計、開発、テスト、レビューを行います。タスク責任者は判断と検収を担います。

## エージェントチーム

| 役割 | 提供元 | 担当 |
| --- | --- | --- |
| コーディネーターエージェント | Studio に組み込まれ、チームで共有 | ステップを割り振り、結果を読み、次に何をするかを決めます。責任者に質問するか、作業を検収に回します。コードを書くことも PR をマージすることもありません。 |
| 実行エージェント | ランタイムにインストールされ、サインイン済みのコーディングツール | 設計、開発、テスト、レビュー、CI 失敗の調査を行います。結果を報告し、タスクのステータスを変えたり作業を割り振り直したりはしません。 |

ツールとモデルの組み合わせごとに、1 つの実行エージェントになります。管理者は **Good at** に設計やコードレビューなどの得意分野を記述します。コーディネーターエージェントはこの記述をもとに能力を判断します。[エージェントを設定する](../setup/agents.md) を参照してください。

コーディネーターエージェントにもモデルが必要です。管理者がメインとフォールバックを選びます。メインが 2 分以内に起動できない場合は、フォールバックが引き継ぎます。

![エージェントの得意分野、利用できるランタイム、コーディネーターエージェントのメインとフォールバックのモデル](https://static-docs.nocobase.com/studio-en-agent-team-20261030.png)

**Where it runs** には、各エージェントが利用できるランタイムが表示されます。管理者はチーム用に共有ランタイムを接続します。個人ランタイムは所有者だけに提供され、そこでしか使えないエージェントもそのメンバーだけに提供されます。[エージェントとランタイム](concepts.md#エージェントとランタイム) を参照してください。

メンバーはタスクを作成する前に、**My sessions** で要件を相談できます。[My sessions](../use/sessions.md) を参照してください。

## 仕事の割り振り

タスクが始まると、コーディネーターエージェントが最初のステップを割り振ります。エージェントが返信したとき、メンバーがコメントしたとき、PR のチェックが変化したときに、進捗を判断し直します。

設計、開発、テスト、トラブルシューティングは、その作業に適したエージェントに割り振られます。レビューはできるだけ別のベンダーに割り振られます。候補がオンラインでない場合は、同じベンダーの別のモデルがレビューできます。モデルが自分のコードをレビューすることはありません。

引き継ぎはそれぞれタスクのコメントに表示されます。エージェント、目標、参考資料、完了の基準、割り振りの理由が示されます。コーディネーターエージェントは返答を読んでタスクを進めます。

![設計の引き継ぎには、業務資料と検証要件が含まれます](https://static-docs.nocobase.com/studio-en-req-dispatch-20261030.png)

管理者は [エージェントの設定](../setup/agents.md) で割り振りルールを調整したり、既定に戻したりできます。

## タスクのワークフロー

スキルは、各段階の進め方と完了とみなす基準を定めます。コーディネーターエージェントはこれらの要件に沿ってステップを計画し、実行エージェントはそれに従います。

| 段階 | 進め方 | 組み込みスキル |
| --- | --- | --- |
| 設計 | 複数のモジュール、マイグレーション、並行性、権限にかかわる変更や、方針が不明確な変更では、短い方針書を書きます。明確な変更はそのまま開発に進めます。 | `studio-workflow`、`studio-approach` |
| 開発と検証 | 合意した方針を実装し、結果を検証します。方針を超える変更には、コーディネーターエージェントの同意が必要です。 | `studio-development` |
| チェックとレビュー | チェックを実行し、独立したレビューを依頼します。必要な修正は開発者に戻し、再度レビューします。 | `studio-development`、`studio-review` |
| 検収への引き渡し | レビューとすべてのチェックを通過したら、引き渡しレポートを作成して責任者に提出します。 | `studio-workflow`、`studio-comment-style` |

![Codex が失敗したチェックを修正し、Claude が独立したレビューを完了します](https://static-docs.nocobase.com/studio-en-review-thread-20261030.png)

判断が必要なとき、コーディネーターエージェントはタスクを **Blocked** にして質問を説明します。引き渡しの準備ができたら、タスクを **In review** にしてレポートを添付します。実行エージェントはタスクのステータスを変更しません。

チームは組み込みスキルを編集したり、独自のスキルを追加したりできます。スキルはグローバル、プロジェクト、リポジトリのいずれにも適用できます。[スキル](../project/skills.md) を参照してください。

## タスクの並行実行

ランタイムはキューに入った作業を引き受けます。複数のタスクを同時に進められ、それぞれが専用のブランチと作業ディレクトリを持ちます。

| 仕組み | 動作 |
| --- | --- |
| タスクの分離 | 変更は個別の作業ディレクトリに保たれます。既定のブランチ名は `agent/<task-identifier>` です。 |
| タスク内の並行性 | コードを書くステップは一度に 1 つだけです。レビューや CI の調査などの読み取り専用のステップは別のコピーを使い、開発と並行して実行できます。 |
| 処理能力 | 各ランタイムは既定で 3 つのジョブを同時に実行します。リソースとモデルの利用枠に合わせて調整するか、ランタイムを追加します。緊急のタスクが優先されます。 |
| 依存関係 | タスクは必要な先行タスクやサブタスクを待ってから、自動で続行します。 |
| 継続的な実行 | オンラインのランタイムは、人が見張らなくてもキューの作業を引き受け続けます。 |

![Agent queue には、実行中の作業と空いている処理能力が表示されます](https://static-docs.nocobase.com/studio-en-agent-queue-20261030.png)

## 人の関与

次の項目は、責任者の **My issues** の先頭に表示されます。

| 状況 | ステータス | 責任者の対応 |
| --- | --- | --- |
| 業務ルールやトレードオフの確認が必要、またはアクセス権が足りない | Blocked | 質問に答えるか、必要な情報やアクセス権を提供します。 |
| 適切なエージェントがオフライン、または割り振り直してもステップが失敗する | Blocked | 原因を解消するか、割り振りを調整します。 |
| PR のチェックとレビューを通過した | In review | 引き渡しレポートを読み、結果を検収します。 |

コーディネーターエージェントがタスクを **Done** や **Canceled** にしたり、PR をマージしたりすることはありません。作業の検収とマージは人が行います。

- エージェントは依頼者の代わりに、その人の権限の範囲内で動作します。
- 実行エージェントはタスクブランチでコミット、プッシュ、PR の作成ができます。プッシュ済みの履歴は書き換えられません。保護ブランチはコードホストが管理します。
- PR のマージ、保護された環境へのデプロイの承認、メンバーの管理は人だけが行います。

メンバーはいつでも要件を追加したり、実行を止めたり、タスクを引き取ったりできます。[進捗を追う](../use/follow-progress.md) を参照してください。

## 失敗時の対応

| 状況 | 対応 |
| --- | --- |
| チェックが失敗する、または PR にコンフリクトがある | 修正を割り振ります。3 回連続で失敗するコミットが続いたら、責任者に通知します。 |
| 同じステップが 2 回失敗する | 別の適切なエージェントを試します。それでも失敗したら、タスクを Blocked にします。 |
| コーディングツールの利用枠が尽きる | すぐにエージェントを切り替えます。できれば別のベンダーにします。 |
| ランタイムがオフラインになる | 作業をキューに戻し、別のランタイムに回します。 |
| 作業が 24 時間引き受けられないまま残る | 実行を失敗にして責任者に通知し、責任者が再試行、割り振り直し、キャンセルを選べるようにします。 |
| エージェント同士が作業を何度も行き来させる | 既定では、エージェントのコメントによって起動される実行を、タスクごとに 24 時間あたり 20 回まで許可します。上限に達すると一時停止し、続けるかどうかを責任者に確認します。 |
