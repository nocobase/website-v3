---
title: 個人ランタイムを接続する
description: 自分のマシンを個人ランタイムとして Studio に接続します。そのマシンでサインインしたコーディングツールとサブスクリプションを使い、あなたの代わりに行われる作業だけを実行します。
---

共有ランタイムは管理者が接続し、チーム全員の作業を実行します。個人ランタイムはメンバーが自分で接続し、あなたの代わりに行われる作業だけを実行します。あなたが責任者のタスクでコーディネーターエージェントが手配するすべてのステップと、**My sessions** でのチームのエージェントとの会話です。

接続するよくある理由は次のとおりです。

- 共有ランタイムが混んでいて、自分のタスクをもっと速く進めたい。
- チームにまだないコーディングツールやモデルにサインインしていて、まず自分のタスクで使いたい。
- 自分のタスクを、自分のサブスクリプションと利用枠で実行したい。

**My sessions** で自分のエージェントと対話するのは、別の種類の接続です。[自分の PC を接続する](connect-computer.md) を参照してください。

## 必要なもの

共有ランタイムと同じです。macOS または Linux（Windows では WSL 上の Ubuntu）、Node.js 24 以降と Git、使いたいコーディングツール（インストールしてサインイン済みのもの）、さらにコードホストの CLI と Chromium です。詳しくは [共有ランタイムを接続する](../setup/shared-runtimes.md#マシンを準備する) を参照してください。

> [!WARNING] runner はセキュリティ境界ではない
> このマシンでは、エージェントは runner を実行するシステムユーザーとして作業し、そのユーザーがアクセスできるすべてのもの（SSH キーなどの認証情報を含む）を読み書きできます。個人ランタイムでも、普段使いのアカウントではなく、専用のシステムユーザー、コンテナ、仮想マシンを使ってください。

## 追加する

1. **Agent management › Runtimes** を開き、**Add runtime** をクリックします。ダイアログに、ランタイムが個人用になることが表示されます。
2. このマシンで使いたいコーディングツールにチェックを入れ、マシンと利用枠に合わせて最大同時実行数を設定します。
3. **Generate install command** をクリックし、マシンのオペレーティングシステムを選びます。
4. **Prompt** をそのマシンのコーディングツールに渡してインストールを任せるか、**Manual** に切り替えて自分でコマンドを実行します。

コマンドには、一度だけ使える、数分で期限が切れる認証情報が含まれています。期限が切れたら新しく生成してください。インストールの詳細とトラブルシューティングについては、[共有ランタイムを接続する](../setup/shared-runtimes.md#マシンにインストールする) を参照してください。

## 接続を確認する

数秒以内に、ランタイムの一覧に **Personal** と **Online** として表示され、チェックを入れたコーディングツールに **Signed in** と表示されます。詳細を開くと、あなたが所有者であることがわかります。

このマシンが報告するモデルのエージェントをチームがすでに有効にしていれば、**Agent management › Agents** の **Where it runs** にあなたのマシンも数えられます。たとえば「1 shared · 1 personal」です。

**完了の条件**：ランタイムに **Personal** と **Online** が表示され、使いたいコーディングツールに **Signed in** と表示されていること。

## どんな作業がここで実行されるか

- **あなたが責任者のタスク**：コーディネーターエージェントが手配するすべてのステップ（設計、開発、テスト、レビュー）はタスク責任者の代わりに行われるため、あなたの個人ランタイムで実行できます。
- **あなたのセッション**：**My sessions** でのチームのエージェントとの会話。
- **個人ランタイムにしかないエージェント**：たとえば、あなたのマシンでしかサインインしていないモデルです。コーディネーターエージェントは、あなたが責任者のタスクでだけそれを使います。ほかの人のタスクがそのようなエージェントを待っている場合、タスクページの **Now** の行には、ほかの人の個人ランタイムしかオンラインでないことが表示されます。
- **シークレットが必要な作業**：プロジェクトで **Shared runtimes only** と指定された変数は個人ランタイムには送られないため、それを使う作業は共有ランタイムでだけ実行されます。その他の変数は、作業を引き受けたランタイムに送られます。[プロジェクト設定](../project/settings.md#エージェント実行の変数) を参照してください。

あなたが責任者のタスクにほかの人がコメントし、次の作業にあなたの個人ランタイムが必要になると、Studio はまずあなたに確認します。タスクページに、あなたの個人 runner で続行するかどうかの確認が表示されます。**Confirm** をクリックするとあなたのランタイムで作業が続き、**Reject** をクリックすると止まります。[エージェントの質問に答える](../use/answer.md#個人ランタイムの使用リクエスト) を参照してください。

## 管理する

- **変更する**：ランタイムの詳細で、名前と最大同時実行数を変更し、コーディングツールをオン・オフし、各ツールで同時に実行できる数を設定します。変更できるのは所有者だけです。
- **一時停止する**：マシンで `nocobase-runner stop` を実行し、再開するには `nocobase-runner start` を実行します。150 秒間 Studio に接続していない runner はオフラインと表示され、保持していた作業はキューに戻ります。
- **このマシンの変数**：このマシンにだけ置いておきたい値です。`nocobase-runner env set NAME` で設定し、Studio には名前だけが表示されます。
- **チームと共有する**：全員の作業を実行させるには、詳細で使用範囲を **Shared** に変更するよう管理者に依頼します。その後は、ほかの人の作業もその人の変数とシークレットとともにこのマシンで実行され、マシン上のものを読めるようになるため、問題がないことを先に確認してください。
- **使うのをやめる**：先に詳細で認証情報を取り消してから削除します。実行履歴は保持されます。マシンで `nocobase-runner uninstall` を実行すると、runner とそのバックグラウンドサービスが削除されます。
