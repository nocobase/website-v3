---
title: "チェックとレビュー"
description: "チェック結果、エージェントのレビュー、マージ条件を確認します。"
---

引き渡し前に、コーディネーターエージェントがプロジェクトのスキルに従って検証とコードレビューを手配します。タスクの責任者が引き渡しレポートを読み、マージするかを判断します。

完了済みタスクやプロジェクト全体のテストには[Quality](../quality/overview.md)を使います。専用のレポートとフォローアップタスクで結果を追跡します。

## チェックを確認する

タスクの **Code & previews** で、各 PR のチェック取得元、結果、ログを確認します。取得元はリポジトリで選んだコードプラットフォームの CI、外部 CI、エージェントのセルフチェックです。[チェックと CI](../configure/checks.md)を参照してください。

![タスク上で PR のチェック結果を確認する](https://static-docs.nocobase.com/studio-en-req-preview-20261111-normal-2x.webp)

**Project settings › Code repositories › Branch rules** で設定します。

- 必須チェックの失敗時にコーディネーターエージェントを起動するか。
- チェック通過時に次のステップを開始するか。
- PR の競合時に修正を開始するか。
- どのチェックを参考情報とし、Studio の通常のマージを妨げないようにするか。

参考情報に指定していないチェックは必須です。コードプラットフォームのブランチ保護も適用されます。自動起動を無効にした場合は、タスクのコメントでコーディネーターエージェントに続行を依頼します。

## レビューを手配する

既定のフローでは、別のベンダーの適切で利用可能なレビュアーを優先します。適切な候補がなければ同じベンダーのモデルも使えます。`studio-review` などの[スキル](skills.md)でレビュー基準と問題の重大度を定めます。

コーディネーターエージェントは、進行を妨げる指摘を実装担当に戻します。無関係な問題は影響と根拠を記録し、別途対応します。

## マージを判断する

| PR の状態 | 対応 |
| --- | --- |
| 必須チェックが通過し、マージ可能 | 責任者が検収してマージ |
| 必須チェックの失敗、結果の不足 | 強制マージ権限を持つ人が明示的に続行可能。操作を記録 |
| チェック待ち、競合、ドラフト | 待機するか阻害要因を解消 |
| コードプラットフォームが拒否 | プラットフォームの条件を満たす |

エージェントは PR をマージできません。手順は[タスクを検収する](../use/accept.md)を参照してください。
