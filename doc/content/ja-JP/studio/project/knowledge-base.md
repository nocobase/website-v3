ナレッジベースには人が作成・アップロードしたものだけが入り、エージェントは読むだけで書き込みません。エージェントが作業中に学んだことは [プロジェクトメモリー](project-memory.md) に、仕事の進め方は [スキル](skills.md) に入ります。

## システムナレッジとプロジェクトナレッジ

| | 入れるもの | 管理者 |
| --- | --- | --- |
| システムナレッジ | 会社の購買承認規程や共通の技術規約など、プロジェクトをまたいで共有するドキュメント | 管理者 |
| プロジェクトナレッジ | プロジェクトごとに 1 つのスペースがあり、そのプロジェクトの業務資料を入れる | プロジェクトリーダー |

プロジェクトナレッジにはシステムナレッジも含まれます。プロジェクト内では、人もエージェントも両方を見られます。

**Development › Knowledge** には、アクセスできるすべてのスペースがまとめて表示され、プロジェクトの **Knowledge** セクションにはそのプロジェクトのものだけが表示されます。検索はアクセスできるすべてのスペースが対象で、各結果にはどのプロジェクトとフォルダーのものかが表示されます。

## ナレッジベースに追加する

先にスペースまたはフォルダーを選んでから作成します。

- **記事**：Studio で直接、Markdown で書きます。
- **ファイル**：規程、スプレッドシート、ドキュメントなどをアップロードします。PDF、Word、Excel、PowerPoint、CSV、プレーンテキスト、Markdown、JSON のファイルからはテキストが抽出され、検索とエージェントの閲覧に使われます。画像内のテキストは認識されません。元のファイルは保持され、ダウンロードできます。
- **フォルダー**：4 階層まで作れます。

保存するたびに新しいバージョンになり、以前のバージョンを振り返れます。読んで確認済みの記事は、検証済みとして印を付けられます。使われなくなったものはアーカイブします。アーカイブした内容は検索に表示されず、必要なときに元に戻せます。

> [!TIP] 書き残す価値があるもの
> エージェントがコードからは読み取れない業務情報です。業務ルールとその理由、用語の意味、例外の扱い方、下された重要な判断などです。

## タスクからのファイル

仕入先評価シートなど、要件にファイルを添付すると、エージェントがそれを使ったあとでナレッジベースへの保存を提案することがあります。タスクにカードが表示され、そのファイルをナレッジベースに保存するかどうかを尋ねられます。プロジェクトナレッジかシステムナレッジに保存するか、**No thanks** をクリックします。

保存できるのは、ファイルをアップロードした人かタスク責任者だけで、保存先のスペースの編集権限も必要です。

## だれが何を読んで変更できるか

スペース、フォルダー、記事、ファイルのそれぞれに個別の権限を設定でき、4 つのレベルがあります。

| 権限 | できること |
| --- | --- |
| Read | 閲覧と検索 |
| Propose | 変更を提案する。管理権限を持つ人が受信トレイで受け入れるか断る |
| Edit | 直接変更する |
| Manage | だれが読んで変更できるかを決める |

権限は、個人、ロール、プロジェクトのメンバー、プロジェクトリーダーに付与できます。フォルダーやドキュメントは既定で上の階層の権限を継承し、独自の権限を追加します。独自の権限だけを使うこともでき、たとえば価格表を購買マネージャーにだけ見せることができます。

プロジェクトリーダーは自分のプロジェクトのナレッジスペースを管理し、管理者はすべてのスペースを管理します。既定では、メンバーは閲覧と提案ができ、自分がリーダーのプロジェクトでは編集もできます。

## エージェントはナレッジベースをどう使うか

- タスクで作業するとき、エージェントは関連するナレッジを作業ディレクトリの横にファイルとして受け取り、必要なものを読みます。
- セッションでは、エージェントはナレッジベースを検索し、どのセクションを引用しているかを示します。
- エージェントが読めるのは、作業を開始した人が読めるものだけで、同じ権限に従います。
