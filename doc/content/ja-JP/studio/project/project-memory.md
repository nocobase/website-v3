title: "プロジェクトメモリー"
description: "確定したルール、制約、知見をエージェント間で共有し、コードと一緒に管理します。"
---

プロジェクトメモリーはコードリポジトリに保存します。後続のタスクでエージェントが読み取り、担当者やモデルが変わってもチームで再利用できます。

## 記録する内容

| 種類 | 内容 | 例 |
| --- | --- | --- |
| Feedback | 確定した進め方や訂正 | C ランクの仕入先への注文はすべて承認が必要 |
| Project | コードだけでは分からない決定や制約 | マイグレーションはマージ順に番号を付ける |
| Reference | リポジトリ外の資料の場所 | スコアの重みはナレッジベースの評価表を使う |

コード、README、AGENTS.md に書かれた内容を繰り返さないでください。進捗、一時ログ、シークレット、個人情報は記録しません。

## メモリーを読む

**Project memory** でプロジェクトとリポジトリを選ぶか、プロジェクトの **Memory** を開きます。種類で絞り込むか検索し、項目を開いて内容と元のコミットを確認します。

![共有されたプロジェクトメモリーを読む](https://static-docs.nocobase.com/studio-en-guide-memory-20261031.png)

## メモリーを更新する

エージェントは `.nb-studio/memory/` に項目ごとのファイルを作成します。タスクの PR と一緒にレビュー・マージし、後続タスクがリポジトリから読み取ります。

長く使うルールをタスク内で伝えると、エージェントが記録の要否を判断します。現在のコードと矛盾する項目は、タスクの PR で更新・削除します。メモリーはリポジトリごとに管理します。

言語はリポジトリの規約に従い、指定がなければ英語にします。目安はリポジトリ当たり約 50 件、1 件 4 KB 未満です。メンバーが管理する業務資料は[ナレッジベース](knowledge-base.md)、開発手順は[スキル](skills.md)に保存してください。
