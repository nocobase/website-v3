仕組みは Claude Code の自動メモリーと同じで、エージェントが自分で書いて自分で読み、だれも管理する必要はありません。違いは、プロジェクトメモリーがリポジトリに置かれ、チームのすべてのエージェントで共有されることです。

## エージェントが記憶するもの

以降のタスクで必要になり、かつコードからはわからないことだけです。ほとんどのタスクでは何も追加されません。

| 種類 | 例 |
| --- | --- |
| Feedback | 人が修正または確認したやり方や、落とし穴。たとえば「ランク C の仕入先への発注は、金額にかかわらずすべて購買マネージャーの承認が必要」 |
| Project | コードやコミット履歴からはわからない判断、制約、背景。たとえば「マイグレーションの番号はマージ順に付ける」 |
| Reference | リポジトリ外の資料の場所。たとえば「評価の重みは、ナレッジベースの購買承認規程に従う」 |

コード、ディレクトリ構成、コミット履歴から読み取れること、リポジトリの `AGENTS.md` や README にすでに書かれていること、現在のタスクにしか関係しない進捗は記録しません。

> [!WARNING] メモリーに機密情報を書かない
> メモリーはリポジトリに入ります。リポジトリが公開でも非公開でも、シークレット、トークン、パスワード、接続文字列、個人の連絡先を書かないでください。公開リポジトリのメモリーは公開されます。

## 保存場所とレビュー

メモリーはリポジトリの `.nb-studio/memory/` ディレクトリにあるファイル群で、1 つのメモリーが 1 つのファイルです。エージェントはタスクのブランチでメモリーを書いて PR と一緒にコミットし、レビューするエージェントがコードと一緒に確認します。あなたが検収してマージすると既定のブランチに入り、以降のタスクで読めるようになります。

メモリーは、リポジトリ自身の規約（たとえば `AGENTS.md`）で指定された言語で書かれ、指定がなければ英語で書かれます。

プロジェクトに複数のリポジトリがある場合、各リポジトリのメモリーはそのリポジトリだけを対象とし、別々に保存されます。

## メモリーを見る

**Development › Project memory** には各プロジェクトのメモリーが一覧表示され、プロジェクトの **Memory** セクションにはそのプロジェクトのものだけが表示されます。検索したり、Feedback、Project、Reference で絞り込んだりでき、各エントリーにはどのブランチとコミットから来たものかが表示されます。

メモリーはエージェント向けに書かれているので、読んだり整理したりする必要はありません。エージェントチームがプロジェクトから何を学んだか気になったときに眺めてみてください。

## エージェントに何かを覚えてもらう

エージェントにルールを覚えてもらいたいときは、タスクでエージェントに伝えれば、書き留めるかどうかをエージェントが判断します。人とエージェントの両方が長期的に参照すべき資料は、[ナレッジベース](knowledge-base.md) に入れます。

## メモリーが古くなったとき

メモリーは、書かれた時点で正しかったことを記録しています。エージェントはメモリーに頼る前に、現在のコードと照らし合わせます。食い違う場合はコードが優先され、エージェントは現在の PR でメモリーを更新または削除します。

各リポジトリのメモリーは 50 件程度、1 件あたり 4 KB 以内に収めます。それを超えると Studio が整理を提案しますが、現在のタスクを止めることはありません。
