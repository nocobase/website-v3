プロジェクトの設定はプロジェクトリーダーが管理します。プロジェクトを作成した人が既定でリーダーになり、管理者はすべてのプロジェクトを管理できます。

プロジェクトページの上部には 6 つのセクションがあります。**Overview**、**Issues**、**Knowledge**、**Members**、**Releases**、**Settings** です。ナレッジベースについては [ナレッジベース](knowledge-base.md)、リリースについては [リリースの承認とロールバック](release.md)、概要については [プロジェクトの進捗](progress.md) を参照してください。

## 公開範囲、リーダー、メンバー

- **公開範囲**：**Everyone** にすると、ワークスペースのすべてのメンバーがプロジェクトを見られます。**Members only** にすると、プロジェクトのメンバーと管理者だけがプロジェクトとそのタスクを見られます。
- **リーダー**：**Members** で、メンバーの **Set as lead** をクリックします。プロジェクトリーダーはプロジェクトのメンバーである必要があります。現在のリーダーを外すには、先に新しいリーダーを選びます。
- **メンバー**：**Members** で、名前で検索して人を追加したり、外したりします。まだ Studio に参加していない同僚を招待するには、[メンバーを招待する](../setup/invite.md) を参照してください。招待時にこのプロジェクトを直接選べます。
- **ステータス、優先度、日付**：プロジェクトのプロパティで設定します。プロジェクトの一覧はこれらで並べ替えと絞り込みができます。プロジェクトのステータスは Planned、In progress、Paused、Completed、Cancelled のいずれかです。

## Settings

**Settings** には 6 つのセクションがあります。

| セクション | 内容 |
| --- | --- |
| General | プロジェクトの名前と説明、エージェントのコミットの帰属方法 |
| Code repositories | プロジェクトが使うリポジトリ。最初のものがプライマリリポジトリで、作業はそこから始まります。追加、並べ替え、削除ができます |
| Deployment | リポジトリの CI がプレビューをビルドして Studio にデプロイする方法。[CI を接続する](../setup/ci.md) を参照してください |
| Branch rules | エージェントが作業するブランチ、タスクにひも付ける PR、チェック結果がコーディネーターエージェントを起動するタイミング。[チェックとレビュー](checks-and-review.md) を参照してください |
| Agent run variables | エージェントがこのプロジェクトで作業するときに受け取る変数とシークレット。下記を参照してください |
| Default skills | すべての実行が既定で持っていくスキル。プロジェクト全体または特定のリポジトリ向けです。[スキル](skills.md) を参照してください |

### コードリポジトリ

1 つのプロジェクトに複数のリポジトリを持てます。たとえばアプリとそのプラグインを分けて管理する場合です。最初のものがプライマリリポジトリで、タスクは既定でそこから始まります。リポジトリを削除しても、タスクがそこで作業しなくなるだけです。リポジトリ自体には手を加えません。

リポジトリのないプロジェクトでは、エージェントはコードにかかわらないタスクしか作業できません。プロジェクトの概要の **Next steps** に、**Add a code repository** のリマインダーが表示されます。

### 既存のリポジトリを接続する

既存のアプリの場合は、プロジェクトの作成時に **Existing repository** を選び、Git 接続で利用できるリポジトリを選びます。**No initialization** を選ぶと、そのコードをそのまま使います。

初期化が必要な場合は、**NocoBase application** または **From a prompt** を選びます。既存のファイルは保持され、変更はブランチとプルリクエストで提出されます。責任者が PR をレビューしてマージすると、初期化が完了します。このオプションを選ぶ前に、リポジトリの構成と開発手順を確認してください。

**Add later** を選ぶと、プロジェクトの作成後に **Settings › Repositories** からリポジトリを接続できます。それまでは、エージェントはコードを必要としないタスクしか実行できません。

### コミットの帰属

エージェントは、作業を開始した人としてコードをコミットします。各自が **Account settings › Preferences** で、自分のコミットにエージェントを共同作成者としても記載するかどうかを選べます。ここでの設定は、まだ選んでいない人の既定値です。

### エージェント実行の変数

エージェントがここで実行するときに必要な環境変数を設定します。テスト用の API アドレスや、サードパーティサービスのキーなどです。

- プロジェクト全体、または特定のリポジトリだけに設定します。リポジトリの変数は同じ名前のプロジェクトの変数を上書きし、エージェント自身の変数はその両方を上書きします。
- 保存した値は二度と表示されず、実行記録ではマスクされます。どうしても確認が必要な場合は、**Reveal values** をクリックします。表示するたびに、あなたの名前と日時がアクセスログに記録されます。
- **From the runtime**：値はここには保存されません。代わりに、作業を引き受けたランタイムが自分のマシンから値を提供します。マシンでは `nocobase-runner env set NAME` で設定します。変数を提供しないランタイムでは、実行は開始前に失敗します。
- リスクの高いシークレットには **Shared runtimes only** にチェックを入れます。その変数を使う実行は共有ランタイムでだけ行われ、メンバーの個人ランタイムには送られません。

プレビューを含め、デプロイされたアプリが読み取る変数はここでは設定しません。リリース管理で、環境ごとまたはアプリごとに設定します。

## プロジェクトを削除する

プロジェクトは **More project actions** から削除できます。管理者の権限が必要です。プロジェクト、そのメンバー、リポジトリとのひも付けが削除されます。プロジェクトのタスクは残り、どのプロジェクトにも属さなくなります。コードホスト上のリポジトリには影響しません。
