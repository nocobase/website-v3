title: "プロジェクト設定"

---

プロジェクト責任者と管理者が設定を変更できます。アクセス管理は **Members**、開発作業の設定は **Settings** を開きます。

## メンバーと公開範囲

既存のメンバーを検索し、プロジェクトに追加します。新しいメンバーは [Studio への招待](../setup/invite.md)が必要です。招待時にプロジェクトも指定できます。

- **Everyone**：ワークスペースの全メンバーが参照できます。
- **Project members only**：プロジェクトメンバーと管理者に限定します。
- **Project lead**：プロジェクトメンバーから選びます。現在の責任者を外す前に、新しい責任者を割り当ててください。

プロジェクトのプロパティで状態、優先度、日付を変更します。

![プロジェクトのメンバーと責任者](https://static-docs.nocobase.com/studio-en-project-members-20261111-normal-2x.webp)

## プロジェクトを設定する

| セクション | 設定 |
| --- | --- |
| General | 名前、説明、既定のコミット名義 |
| Code repositories | リポジトリ、チェック、ブランチルール、プレビュー |
| Agent run variables | 開発タスクの環境変数とシークレット |
| Default skills | プロジェクトやリポジトリの実行で使うスキル |

![リポジトリごとにチェック、ブランチルール、プレビューを設定する](https://static-docs.nocobase.com/studio-en-project-repositories-20261111-normal-2x.webp)

最初のリポジトリが主リポジトリです。関連付けを外しても、Git プラットフォームのリポジトリは削除しません。[チェックと CI](../configure/checks.md)、[スキル](skills.md)も参照してください。

### 既存リポジトリを接続する

**New project** で **Existing repository** を選び、Git 接続から利用可能なリポジトリを指定します。既存アプリは通常、初期化なしを選びます。

アプリのひな形を追加する場合は **NocoBase application** またはプロンプトによる初期化を選びます。エージェントは既存ファイルを保ち、ブランチと PR で変更を提出し、責任者が検収します。後からリポジトリを追加することもできます。空のアプリから始める場合は[最初のプロジェクトを作成する](../setup/new-project.md)を参照してください。

### コミットの名義

メンバーだけを作成者にするか、エージェントを共同作成者に含めるかを選びます。メンバーの個人設定が、プロジェクトの既定値より優先されます。

### エージェント実行用の変数

プロジェクト全体またはリポジトリ単位で変数を設定します。同名の場合、リポジトリの値がプロジェクトの値より優先され、エージェントの値が両方に優先されます。

- 保存後の値は非表示になります。シークレットを表示すると、閲覧者と時刻を記録します。
- ランタイムから渡す値は、そのマシンで `nocobase-runner env set NAME` を使って設定します。
- 個人ランタイムで実行させたくない作業の変数は、共有ランタイムに限定します。

プレビューとテスト用アプリの変数は、[ホスト環境](../admin/environments.md)またはアプリの設定で管理します。

## プロジェクトを削除する

管理者は追加操作から削除できます。タスクは残りますが、プロジェクトから外れます。Git リポジトリには影響しません。
