スキルは `SKILL.md` と、必要に応じた参考ファイルやスクリプトで構成します。`name` は識別名、`description` は使う場面、本文は作業方法を定めます。

## 標準スキル

| スキル | 用途 |
| --- | --- |
| studio-workflow | 割り当て、タスクのステップ、引き渡し条件 |
| studio-development | 実装、検証、失敗時の対応 |
| studio-approach | 設計案 |
| studio-review | コードレビューと問題の重大度 |
| studio-comment-style | コメントと引き渡しレポート |

最初の 4 つは、既定で新しいプロジェクトに適用されます。コメントのスタイルは全体に適用されます。標準スキルも編集でき、保存した変更はアップグレード後も残ります。NocoBase アプリのテンプレートには、Core 開発の指示も含まれます。

![チームのスキルとバージョンを管理する](https://static-docs.nocobase.com/studio-en-skills-20261111-normal-2x.webp)

## 作成・更新する

**Skills › New skill** で `SKILL.md` を書き、補助ファイルを追加します。Agent Skills 形式の ZIP をインポートすることもできます。

変更は新しいバージョンとして保存します。過去のバージョンは閲覧し、ZIP でエクスポートできます。作成にはエージェント管理権限が必要です。作成者と管理者が編集し、プロジェクト責任者は既存スキルをプロジェクトに適用できます。

## 適用範囲を設定する

| 範囲 | 設定場所 | 対象 |
| --- | --- | --- |
| 全体 | スキル詳細の全体適用 | すべてのプロジェクト |
| プロジェクト | Project settings › Default skills | プロジェクト内の実行 |
| リポジトリ | Default skills でリポジトリを選択 | そのリポジトリの実行 |

適用範囲は組み合わされます。同名のスキルは、より具体的な範囲の設定が優先されます。新規プロジェクトへの自動適用は、今後作成するプロジェクトだけが対象です。

必須テスト、レビュー基準、引き渡し時の証拠など、チーム固有のルールを書きます。1 つのスキルは 1 種類の作業に絞ってください。変更後は、後続の実行や引き渡しレポートで使われ方を確認します。

品質の評価項目は[テスト設定](../quality/settings.md)で Skill を指定します。各テストは作成時のバージョンを保持し、変更は後続のテストに適用されます。
