スキルは `SKILL.md` ファイルで、いくつかの補助ファイルを添えることもできます。形式は Claude Code や Codex と同じです。ファイル先頭の `name` がスキルの名前で、`description` はエージェントにいつそれを読むべきかを伝えます。

## 組み込みスキル

Studio には、エージェントチームの働き方を定める 5 つのスキルが付属しています。

| スキル | 定めること | 既定の適用先 |
| --- | --- | --- |
| studio-workflow | コーディネーターエージェントが仕事をステップに分ける方法、各ステップの担当、方針を先に立てるタイミング、レビューの進め方、作業を引き渡せる状態の判断 | 新しいプロジェクト |
| studio-development | 実行エージェントがステップを進める方法：設計、検証、CI の失敗への対応、引き渡し | 新しいプロジェクト |
| studio-approach | 方針書の書き方 | 新しいプロジェクト |
| studio-review | PR のレビュー方法：何を見るか、指摘の重要度の付け方、何がマージを止めるか | 新しいプロジェクト |
| studio-comment-style | コメントと引き渡しレポートの書き方。引き渡しレポートのセクションはここで定められています | グローバル |

組み込みスキルは、チームの働き方に合わせて調整できます。変更は Studio に保存され、Studio をアップグレードしても上書きされません。

NocoBase のアプリテンプレートで初期化したリポジトリには Core の開発規約も含まれており、エージェントはリポジトリで作業するときにそれを読みます。

## スキルを作成・編集する

**Agent management › Skills** で次の操作ができます。

- **New skill**：`SKILL.md` を書き、ファイルを今またはあとで追加します。Agent Skills のディレクトリ形式で構成された zip を **Import** することもできます。
- **Edit**：**Edit** をクリックして変更し、**Save new version** をクリックします。変更内容のメモを付けることもできます。保存するたびに新しいバージョンになり、古いバージョンも表示・エクスポートできます。
- **Export**：バージョンを zip としてエクスポートし、別の場所で使えます。

スキルの作成にはエージェントを管理する権限が必要で、通常は管理者です。スキルの作成者と管理者がスキルを編集でき、プロジェクトリーダーは既存のスキルを自分のプロジェクトに適用できます。スキルを削除すると、適用されているすべての場所から外れます。

## どこに適用するか

スキルを適用すると、そこでのすべての実行がそのスキルを持っていきます。適用範囲は 3 つです。

| 範囲 | 設定する場所 | 対象 |
| --- | --- | --- |
| グローバル | スキルの詳細の **Global attachment** | すべてのプロジェクト |
| プロジェクト | **Project settings › Default skills** で **The whole project** を選ぶ | このプロジェクトのすべての実行 |
| リポジトリ | **Project settings › Default skills** でリポジトリを選ぶ | そのリポジトリでの実行 |

3 つの範囲のスキルはすべて合算されます。同じ名前のスキルが 2 つある場合は、より限定的な範囲のものが優先されます。

スキルの詳細で **Attach to new projects automatically** をオンにすると、それ以降に作成されたプロジェクトに自動で適用されます。既存のプロジェクトはそのままです。

## スキルを書くためのヒント

- 1 つのスキルは 1 つのテーマに絞り、`description` でいつ使うかを明確に書いて、エージェントが読むタイミングをわかるようにします。
- 命名規則、必ず実行するチェック、変更してはならないディレクトリなど、チーム固有のことを書きます。一般的なプログラミングの知識は書く必要はありません。
- 変更したら、その後のいくつかのタスクのアクティビティと引き渡しレポートを見て、エージェントが従っていることを確認します。
