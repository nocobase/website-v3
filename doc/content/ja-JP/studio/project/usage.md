エージェントチームが何をしているか、処理能力が足りているか、コストがいくらかを確認する場所は 2 つです。稼働状況は **Agent queue**、使用量とコストは **Agent management › Usage** です。

## Agent queue

**Development › Issues** の右上で **Agent queue** に切り替えると、エージェントチーム全体が何をしているかがわかります。エージェントごとに専用のレーンがあります。

| エリア | 内容 |
| --- | --- |
| Now | ランタイムで実行中の作業、経過時間、直近に行ったこと |
| Up next | キューに入っているタスクと、待っている理由。たとえば「No runtime online」「All slots busy」「Blocked by PUR-12」 |
| Waiting for reply | 失敗した実行、質問、検収待ちのタスクなど人を待っているものと、だれを待っているか。あなたの番のものは強調表示され、**Handle** で直接移動できます |
| Assigned, idle | エージェントに割り当てられているが何も起きていないタスクと、その理由。たとえば「In Backlog, won't start on its own」 |

最上部の行には、実行中、キュー待ち、あなた待ちの件数と、ランタイムの混み具合がまとめて表示されます。**Only mine** にチェックを入れると、あなたが責任者、作成者、またはフォローしているタスクだけが表示されます。

::figure agent-queue | Agent queue：エージェントごとに 1 レーンで、あなたの番のものが強調表示されます

「All slots busy」やキューの長さがよく目に付く場合は、ランタイムが足りません。ランタイムの最大同時実行数を上げるか、別のランタイムを接続します。[共有ランタイムを接続する](../setup/shared-runtimes.md) を参照してください。いつも手が空いているエージェントがいる場合は、**Good at** の記述が狭すぎて、コーディネーターエージェントが候補として思い浮かべないのかもしれません。[エージェントを有効にする](../setup/agents.md) を参照してください。

## 使用量

**Agent management › Usage** には、エージェントの実行が使ったトークンと、設定したモデル価格での推定コストが一覧表示されます。

- 過去 7 日間、今月、先月などの期間を選びます。
- エージェント、起動した人、対象（タスクまたはセッション）、モデル、コーディングツール、日付でグループ化したり、1 つのエージェントや 1 人だけを表示したりできます。
- 各行には、実行回数、所要時間、入力と出力のトークン数、キャッシュの読み取りと書き込み、推定コストが表示されます。
- **Daily trend** は、日ごとのコストまたはトークン数をグラフで表示します。

ダッシュボードの **Cost per issue** も同じ価格を使います。ナレッジベースのインデックス作成や検索など、エージェントの実行以外でのモデルの呼び出しは、**Other model use** に別に表示されます。

## モデルの価格

コストは、設定したモデル価格から推定されます。使用量のページで **Set prices** をクリックします。

- コーディングツールごとに、その実行で報告されたモデルが一覧表示されます。モデルごとに 100 万トークンあたりの入力と出力の価格を入力するか、ルールでモデルのグループにまとめて価格を設定します。
- サブスクリプションアカウントでサインインした Claude Code など、月額で支払うコーディングツールは **Subscription (not billed)** をオンにすると、その実行は課金されません。
- 価格が設定されていないモデルは、レポートのコストに「—」と表示されます。

価格の設定にはモデル価格を管理する権限が必要で、通常は管理者です。
