![記録された結果と未検証の項目を区別する指標](https://static-docs.nocobase.com/studio-en-quality-metrics-20261111-normal-2x.webp)

## 評価項目ごとの指標と基準

標準の確認方法、既定の基準、統計指標を以下に示します。性能予算はプロジェクトで上書きでき、他のルールは評価項目の Skill で定義します。ツールが元データを生成し、サーバーが解析・集計し、Agent が実行と分析を担当します。

<strong style="color: #b91c1c">公開前の確認：中リスクの問題数、複雑度 15 超の関数数、未使用エクスポート数、テストカバレッジの既定値は参考資料で未確定です。仮の値は記載していません。公開前に最終基準を確認してください。</strong>

### 機能

| テスト項目 | 指標と基準 | ツールと方法 |
| --- | --- | --- |
| タスクの機能とコアシナリオ | 失敗シナリオ数 = 0。期待結果はタスク、シナリオ、明確な業務ルールに基づく | Vitest、Playwright、Agent の実操作 |
| 自動テスト | 製品不具合による失敗数 = 0。失敗、スキップ、タイムアウト、古いテストの原因を確認 | 既存の Vitest と Playwright テストを実行。品質テスト中に E2E テストを追加しない |
| シナリオカバレッジ | （成功 + 失敗）÷ シナリオ総数。推移の比較に使い、固定の合格値は設けない | シナリオと確認項目の結果 |
| 成功率と自動化率 | 成功率 = 成功 ÷ 検証済み。自動化率 = 自動テストで証明したシナリオ ÷ 検証済み。固定の合格値は設けない | 自動テスト、Agent 操作、未検証を区別。分母がゼロでも合格とは扱わない |

### 権限

| テスト項目 | 指標と基準 | ツールと方法 |
| --- | --- | --- |
| 未ログインでのアクセス | 未ログインでの権限違反数 = 0 | 権限エンジンが匿名で API にアクセス |
| 読み書きの権限違反 | 読み取り違反数 = 0、書き込み違反数 = 0 | 権限のないアカウントでデータを読み、書き込み後は再読込して変更を確認 |
| 正常アクセスとの対照 | 正当なアクセスの対照失敗数 = 0 | 権限のあるアカウントで同じ要求を実行。API の障害を正しい権限制御と誤認しない |
| API の権限宣言 | 権限未宣言の API 数 = 0 | タスク CI で Vitest により確認 |

### セキュリティ

| テスト項目 | 指標と基準 | ツールと方法 |
| --- | --- | --- |
| 依存関係の脆弱性 | 重大・高リスクの脆弱性数 = 0。実行用と開発用の依存関係を区別 | pnpm audit で監査し、パッケージごとに対応 |
| 秘密情報の漏えい | 漏えいした秘密情報の件数 = 0 | gitleaks で現在のコードと Git 履歴を検査 |
| コードのセキュリティ確認 | 確認済みの重大・高リスク問題数 = 0 | Agent がチェックリストでレビューし、根拠を残す |
| 受動・能動スキャン | 確認済みの高リスク問題数 = 0。中低リスクの明細を残し、未完了を警告ゼロと扱わない | OWASP ZAP でヘッダー、Cookie、情報漏えい、インジェクション、XSS を検査。権限違反は権限項目で確認 |

### パフォーマンス

| テスト項目 | 指標と基準 | ツールと方法 |
| --- | --- | --- |
| 画面の JavaScript サイズ | 初期表示の JavaScript（非圧縮）≤ 2 MB | Lighthouse で測定し、条件を記録 |
| API 応答サイズ | 応答本文 ≤ 500 KB | 画面が実行する業務 GET 要求を採取 |
| 要求ごとの SQL 数 | 要求ごとの SQL 数 ≤ 20 | 要求 ID ごとに SQL を追跡し、バックグラウンド処理を除外 |
| API と SQL の時間 | 診断用予算：P95 ≤ 500 ms、最も遅い SQL ≤ 50 ms。共有マシンでは時間だけで判定しない | ウォームアップ後に各 API を 10 回順次測定し、遅い SQL を PostgreSQL EXPLAIN で分析 |
| 画面読み込み指標 | Lighthouse スコア、FCP、LCP、TBT、CLS、SI は参考と推移に使い、一律の合格スコアは設けない | 画面、データ量、条件を揃え、主要画面は複数回測定して中央値を使用 |

### コード品質

| テスト項目 | 指標と基準 | ツールと方法 |
| --- | --- | --- |
| 重複コード | 新規コードの重複率 ≤ 3% | jscpd で重複箇所を検出 |
| 認知的複雑度 | 複雑度 > 50 の新規関数数 = 0。複雑度 > 15 の関数を集計 | eslint-plugin-sonarjs の cognitive-complexity ルール |
| 未使用コード | 新規の未使用ファイル数 = 0、未使用依存関係数 = 0。未使用エクスポートも記録 | knip |
| 循環依存 | 新規循環依存数 = 0 | dependency-cruiser でインポート関係を分析 |
| テストカバレッジ | 行・分岐カバレッジを記録。既定の最低値は未確定 | Vitest coverage-v8 で全テストを実行 |
| Agent レビュー | 高レベルの問題数 = 0 | 設計、プロジェクト規約、テストの価値を確認。lint と型チェックは CI で実施 |

### 適用範囲と未対応の確認

共有 Runner の負荷は測定時間に影響します。画面スコアと時間は条件や推移と合わせて確認します。時間予算は診断用の参考値であり、単発の変動だけで製品不具合と判断しません。リアルタイム通知は現在コード確認のみで、到達時間の実測ではありません。操作応答、大量データ、同時実行と容量、バックグラウンド処理、一括ファイル処理、長時間稼働は実測の対象として未対応です。

権限テストはすべてのフィールド変更制限を網羅していません。HTTPS とデプロイ設定には対応する環境が必要で、隔離した HTTP 環境の結果で本番環境を検証済みとはいえません。スモークと UX は計画段階で、現在の五つの標準項目には含めません。外部サービスやデータが不足する確認は未検証とします。

コード品質基準は新規部分に適用します。比較の基準と範囲を確認してください。lint と型チェックは GitHub CI が担当し、既存コード全体の集計を今回の追加問題とは扱いません。


## 指標の定義

| データ | 出所 |
| --- | --- |
| タスク、シナリオ、確認項目の結果 | 各評価項目から提出された結論と証拠 |
| 自動テストの成功、失敗、スキップ、時間 | Vitest、Playwright などのテストレポート |
| 依存関係の脆弱性 | 依存関係の監査結果。実行用と開発用を区別 |
| 画面と API の性能 | 同じ画面またはエンドポイントの実測値を比較 |
| 権限チェック | ロールと操作ごとに期待した結果と実際の結果を比較し、未検証の項目を確認 |
| スキャンの検出結果 | SARIF 形式で報告された結果と該当箇所を確認 |
| コード品質 | コード品質レポートに記録された問題と該当箇所 |
| フォローアップタスク | 関連する不具合、質問、テストケース、シナリオ、整理作業 |

レポートがなければ該当する指標もありません。空欄は問題がゼロという意味ではありません。未検証と対象外も成功には数えません。

## 推移と明細

指標を開くと関連するテスト、シナリオ、問題を確認できます。比較前に、種類、範囲、コミット、評価項目が一致しているか確かめます。

シナリオの追加や削除で総数は変わります。同じ識別子のシナリオはテスト間で比較できます。件数の増減だけで判断せず、範囲の変化と[レポートの証拠](runs.md#reports)を確認します。

## 評価項目の結論と個別の結果

評価項目全体の結論は「合格」「問題あり」「一部未検証」「未検証」です。確認済みの問題があれば証拠を確認します。未完了の確認が残る場合、問題が見つからなかっただけでは全体の合格とはいえません。有効な結論がない場合は未検証です。

シナリオや確認項目の個別結果は、成功、失敗、未検証、対象外として確認します。対象外は成功にも失敗にも数えません。実行中や完了などの進捗状態も、品質基準への適合を直接表すものではありません。
