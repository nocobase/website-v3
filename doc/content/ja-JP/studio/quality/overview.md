品質管理は Studio エンタープライズ版（EE）の機能です。コアシナリオの管理、プロジェクトテストの実行、レポートと指標の確認、問題を追跡するタスクの作成ができます。エンタープライズ版の入手は[お問い合わせください](https://www.nocobase.com/ja-JP/contact/)。

![品質テストの全体像](/assets/studio/quality/quality-flow-ja-JP.svg)

## 品質基準、ツール、レポート、フォローアップ

品質管理は、基準の定義、ツールと Agent による検証、証拠に基づくレポート作成、問題への対応という四つの活動をつなぎます。

### 品質基準：標準を用意し、プロジェクトごとに調整

機能、権限、セキュリティ、パフォーマンス、コード品質の五つの評価項目に、確認方法、指標、基準を定義します。OWASP ASVS、Sonar way、RAIL などを参考にし、予算はプロジェクトに合わせて設定します。これらの確認は規格への適合認証を意味しません。性能予算の上書き、Skill の変更、評価項目の追加ができます。詳細は[品質指標と基準](metrics.md)を参照してください。

### テストツール：実測を行い、Agent が準備と分析を担当

Vitest、Playwright、Lighthouse、OWASP ZAP などのツールが元の結果を生成します。Agent は環境とデータの準備、ツールの実行、結果の分析を担当し、業務画面の操作や設計レビューを補います。数値は実行結果から取得し、コードを読むだけで推定しません。

### レポート：証拠から確認可能な結論を作成

評価項目ごとのレポートを作り、納品レポートにまとめます。サーバーが JUnit、SARIF、監査 JSON、Lighthouse などの結果を解析して指標を計算し、適用するルールで判定します。データ不足、ツールの未完了、解析失敗は未検証として残し、問題ゼロとは扱いません。

### フォローアップ：タスクで対応し、修正後に再検証

発見事項を原因ごとにまとめ、通常の開発、レビュー、受け入れフローで対応します。不明確な業務ルールの判断と納品レポートの受け入れは人が行います。テスト中は製品コードを変更せず、マージ後のテストで修正を確認します。

**Development › Quality** でプロジェクトを選びます。[設定](settings.md)を確認してから[テストを開始](runs.md)します。新規プロジェクトでは自動実行は無効です。

## テストの種類

| 種類 | 対象と実行方法 |
| --- | --- |
| Daily | 完了済みで未検証の業務タスクを定時に確認。初回や長期間停止後は最大で直近 3 日間が対象 |
| Release | リリース待ちのタスクを確認。手動または設定した件数で実行 |
| Project | プロジェクト全体のコアシナリオを確認。手動、毎週、毎月の実行に対応 |
| Custom | 完了済みの業務タスクを選択するか、プロジェクト全体のコードを確認 |

Daily は定時実行のみです。今すぐ指定タスクを確認する場合は Custom を使います。

## テストとタスクの関係

テストごとに通常のタスクを作成します。対象範囲、固定した Skill のバージョン、実行履歴を保持し、タスクの納品レポートで受け入れます。

エージェントは評価項目ごとに確認し、発見事項をフォローアップタスクに関連付けます。テストの完了だけでは問題は解決しません。[フォローアップ](runs.md#follow-ups)で対応し、後続のテストで修正を確認します。

PR チェックとコードレビューは個々の変更を検証します。プロジェクトの品質テストは、より広い範囲を継続的に確認します。[PR のチェックとコードレビュー](../project/checks-and-review.md)も参照してください。

## コアシナリオ

コアシナリオは「取引停止中の仕入先には新規注文できない」などの期待する業務動作です。Project とプロジェクト全体の Custom テストで使います。

## 評価項目

| 標準の評価項目 | 確認内容 |
| --- | --- |
| Functional | 業務タスクとコアシナリオの期待する動作 |
| Permissions | アカウント、ロール、データアクセスの境界 |
| Security | 依存関係の脆弱性とセキュリティスキャンの検出結果 |
| Performance | 画面の読み込みと API 応答。実測値、計測条件、コード上のリスクを確認 |
| Code quality | 保守性の問題、遅いテストや不安定なテスト |
