品質管理は Studio エンタープライズ版（EE）の機能です。明確な品質基準に沿ってプロジェクトをテストします。Agent が実績のあるテストツールで実測し、Studio がテストレポートを生成し、発見事項はフォローアップタスクとして登録され、後続のテストで修正を確認します。エンタープライズ版の入手は[お問い合わせください](https://www.nocobase.com/ja-JP/contact/)。

![品質テストの全体像](https://static-docs.nocobase.com/studio-guide-flow-ja-JP-20261127-2525582ffe34.svg)

## 主な特長

### 標準の品質基準を用意し、プロジェクトごとにカスタマイズ

機能、権限、セキュリティ、パフォーマンス、コード品質、ユーザー体験の六つの評価項目に、それぞれ指標と合格基準があります。例：「読み取り権限違反数 = 0」「初期表示の JS ≤ 2 MB」「新規循環依存数 = 0」。テストに合格すると、対象バージョンがこの基準を満たしていることを意味します。

**プロジェクトは独自の基準を定義できます**：評価項目が使う Skill の差し替えや、評価項目の追加ができます。一覧は[品質基準](standards.md)を参照してください。

### 実績のあるテストツールで実測

テスト結果はテストツールを実際に実行して得たもので、Agent がコードを読んで推定した値ではありません。Vitest と Playwright で自動テスト、pnpm audit と gitleaks で依存関係の脆弱性と秘密情報の漏えい、OWASP ZAP でセキュリティスキャン、Lighthouse で画面性能、jscpd・knip・dependency-cruiser でコード品質を確認します。サーバーがその結果を基準と照らし合わせ、合格かどうかを判定します。

評価項目ごとに Runner 上で専用のテスト環境とテストデータを用意し、並行して実行します。チームが使用中のシステムには影響しません。

### テストレポートを自動生成

サーバーが JUnit、SARIF、依存関係の監査、Lighthouse などの結果を解析し、指標を計算して基準で判定します。評価項目ごとのレポートを一つの納品レポートにまとめ、失敗と未検証の項目には証拠を付けます。すべての結論は実測データに基づきます。環境などの理由でテストできなかった確認項目は「未検証」と明示し、担当者に確認を促します。

### 発見事項をフォローアップタスクに

発見事項は原因ごとにまとめ、不具合、確認事項、テストデータ、コード整理、性能改善、依存関係の修正のタスクとして登録します。通常の開発、レビュー、受け入れのフローで対応し、修正のマージ後に後続のテストで問題が解消したことを確認します。

## テストの種類

| 種類 | 対象 | 実行方法 |
| --- | --- | --- |
| Daily | 最近完了し、まだテストしていない業務タスク | 毎日定時。設定した件数のタスクがたまった場合に実行 |
| Release | リリース待ちのタスク | 手動、またはリリース待ちタスクが設定件数に達したとき |
| Project | プロジェクト全体のコアシナリオ | 手動、毎週、毎月 |
| Custom | 選択した完了済みタスク、またはプロジェクト全体のコード | 手動 |

テストごとにテストタスクを作成し、タスクの納品レポートで結果を受け入れます。

## 評価項目

| 評価項目 | 確認内容 | 主なツール |
| --- | --- | --- |
| Functional | 業務タスクとコアシナリオが期待どおりに動作するか | Vitest、Playwright、ブラウザー |
| Permissions | 未ログインでのアクセス、読み取り・書き込みの権限違反 | 権限エンジン |
| Security | 依存関係の脆弱性、秘密情報の漏えい、コードのセキュリティ問題、API スキャンの警告 | pnpm audit、gitleaks、OWASP ZAP |
| Performance | 画面の読み込み、API 応答、データベースクエリ | Lighthouse、autocannon、PostgreSQL |
| Code quality | 重複コード、認知的複雑度、未使用コード、循環依存 | jscpd、eslint-plugin-sonarjs、knip、dependency-cruiser |
| ユーザー体験 | デスクトップとモバイルの画面がプロジェクトの UI 基準を満たしているか | ブラウザー、axe |

## コアシナリオ

コアシナリオは、プロジェクトの機能をモジュールごとに業務シナリオとして整理したものです。各シナリオには、ユーザーが達成したい目標と最終的に目にする結果を記載します（例：「取引停止中の仕入先には新規注文できない」）。

- **統一された基準で分割**：1 つのシナリオは 1 つのユーザー目標と 1 つの最終結果だけに対応します。Studio は組み込みの分割基準と粒度でシナリオを整理し、粒度をそろえます。
- **プロジェクトの機能の設計図**：Project テストはコアシナリオを中心に、プロジェクト全体を一つずつ検証します。チームメンバーもここでプロジェクトにどんな機能があるかを確認できます。
- **手動でのメンテナンスは不要**：シナリオはタスクとテストに合わせて継続的に更新されます。機能を変更する開発タスクは関連するシナリオを同時に更新し、Project テストは不足しているシナリオを補い、古くなったシナリオを更新します。[コアシナリオ](settings.md#scenarios)を参照してください。

## はじめに

プロジェクトの **Quality** タブでテスト結果と未解決の問題を確認できます。プロジェクトの切り替えはサイドバーの **Quality** から行います。

![7 日、30 日、90 日から期間を選び、テスト回数、問題件数、合格率の推移を確認](https://static-docs.nocobase.com/studio-guide-en-quality-20261127-974c6ade0ca0.webp)

1. [品質設定](settings.md)：実行ルールと評価項目を設定します。新規プロジェクトでは自動実行は無効です。
2. テスト権限がある場合は **Run test** から[対象を選んでテストを開始](runs.md)します。
3. [テストレポート](reports.md)：結果と証拠を確認し、納品を受け入れ、フォローアップに対応します。
4. [品質基準](standards.md)：評価項目ごとの指標と合格基準を確認します。
