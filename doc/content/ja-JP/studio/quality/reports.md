title: テストレポート

テストごとに、評価項目の結論をまとめた納品レポートと、評価項目ごとの詳細レポートを作成します。レポートはツールの結果からサーバーが生成し、受け入れはテストタスク上で行います。

## 納品レポート

**Quality › Testing issues** からテストを開き、納品レポートを確認します。最初に対象範囲、テスト対象のコミット、評価項目を確認し、次に各評価項目の結論を見ます。

![引き渡しレポートを確認し、受け入れまたは修正を依頼](https://static-docs.nocobase.com/studio-en-quality-report-20261111-normal-2x.webp)

評価項目ごとの結論は次のとおりです。

| 結論 | 意味 |
| --- | --- |
| 合格 | すべての確認に結果があり、基準を満たしている |
| 問題あり | 基準を満たさない確認が一つ以上ある |
| 一部未検証 | 問題は見つからないが、環境、データ、ツールの結果が不足して完了しなかった確認がある |
| 未検証 | 評価項目に有効な結果がない |

結果がないことは、問題がないことを意味しません。未検証と対象外は合格に数えません。

## 評価項目のレポート

評価項目を選ぶと詳細レポートが開きます。タブごとに結果を表示し、元のファイルと証拠を添付します。

| 評価項目 | レポートの内容 |
| --- | --- |
| Functional | タスクとコアシナリオの検証結果、自動テストの結果と失敗の原因 |
| Permissions | API ごとの権限チェック。使用したアカウント、操作、実際の結果 |
| Security | 依存関係の脆弱性、秘密情報のスキャン、コードのセキュリティ確認、ZAP の検出結果 |
| Performance | 画面と API の実測値、予算を超えた項目 |
| Code quality | 各指標の値と新規問題の場所 |

環境の準備、テストデータ、実行などの段階ごとの所要時間も表示します。

![評価項目の詳細レポートとテスト証拠](https://static-docs.nocobase.com/studio-en-quality-dimension-20261111-normal-2x.webp)

シナリオと確認項目の個別結果は四種類です。

| 結果 | 意味 |
| --- | --- |
| Passed | 期待する動作を証拠で確認できた |
| Failed | 実際の動作が期待と異なる。説明と再現証拠を添付 |
| Unverified | 環境やアカウントなどが不足し、判断できない |
| Not applicable | この評価項目と無関係。成功にも失敗にも数えない |

機能の結果では、自動テストで証明したシナリオと Agent が実際に操作したシナリオを区別します。シナリオを選ぶと、確認項目、実際の結果、証拠を確認できます。

## 受け入れまたは差し戻し

範囲が適切で、証拠を確認でき、すべての発見事項にフォローアップタスクがあれば、テストタスクで受け入れます。不足するシナリオや証拠があれば、内容を示して差し戻します。

テストタスクの受け入れは、テストの結論を受け入れることです。フォローアップタスクの修正完了を意味しません。

<h2 id="follow-ups">フォローアップタスク</h2>

発見事項は原因ごとにまとめ、元のテストと評価項目に関連付けたフォローアップタスクとして登録します。**Quality › Follow-ups** で一覧できます。

![フォローアップタスクと元のテストの関係](https://static-docs.nocobase.com/studio-en-quality-follow-ups-20261111-normal-2x.webp)

| 種類 | 対応内容 |
| --- | --- |
| 不具合 | 確認済みの機能不良、権限違反、セキュリティ問題。再現証拠付き |
| 確認事項 | 不明確な業務ルール。期待する動作を人が決定 |
| テストデータ | 未検証の確認を実行するためのレコード、アカウントなどを補充 |
| コード整理 | 新しい複雑な関数、未使用コード、循環依存などに対応 |
| 性能改善 | 予算を超えた画面と API を原因ごとにまとめて対応 |
| 依存関係の修正 | パッケージごとに脆弱性を修正 |

フォローアップタスクは通常のタスクと同じ責任者、議論、受け入れの手順を使います。同じ問題に未完了のタスクがある場合は、重複して登録せずそのタスクを再利用します。

## 修正して再テストする

1. フォローアップタスクで修正を完了し、受け入れます。
2. 影響範囲を含む Project、Release、Custom テストを開始します。
3. 元のシナリオやタスクの新しい結果を確認します。

フォローアップタスクを完了しても過去の結果は変わりません。過去のレポートには当時の証拠が残り、後続のテストで修正後の動作を確認します。

<h2 id="metrics">指標と推移</h2>

**Quality › Metrics** でテストの種類と期間を選び、評価項目ごとの指標の推移を確認します。指標を選ぶと、関連するテスト、シナリオ、問題を確認できます。

![記録された結果と未検証の項目を区別する指標](https://static-docs.nocobase.com/studio-en-quality-metrics-20261111-normal-2x.webp)

テストを比較する前に、種類、範囲、テスト対象のコミット、評価項目が一致しているか確認します。シナリオの追加や削除で総数は変わります。同じ識別子のシナリオだけがテスト間で比較できます。
