**Quality › Testing issues** からテストを開きます。納品レポートは通常のタスクと同じ手順で受け入れます。

![引き渡しレポートを確認し、受け入れまたは修正を依頼](https://static-docs.nocobase.com/studio-en-quality-report-20261111-normal-2x.webp)

## 結果と証拠

最初に対象範囲、コードのコミット、評価項目を確認します。各項目を開くと詳細レポートと添付ファイルを読めます。

| 結果 | 意味 |
| --- | --- |
| Passed | 期待する動作を証拠で確認できた |
| Failed | 実際の動作が期待と異なる。問題と再現証拠を確認する |
| Unverified | 環境やアカウントなどが不足し、判断できない |
| Not applicable | この評価項目と無関係。成功にも失敗にも数えない |

機能検証では、既存の自動テストとエージェントによる操作を区別します。自動テストの結果は提出されたレポートに基づきます。シナリオの結果には確認内容を記録します。権限、性能リスク、コード品質では、ブラウザー操作ではなくコードを調べる場合もあります。

失敗の証拠、未検証の理由、関連するフォローアップを確認します。スクリーンショットだけでなく、期待する結果と実際の結果を明確にします。

![評価項目の詳細レポートとテスト証拠](https://static-docs.nocobase.com/studio-en-quality-dimension-20261111-normal-2x.webp)

## 受け入れまたは差し戻し

範囲が適切で、証拠を確認でき、発見事項の対応方針が決まっていれば、タスクから受け入れます。不足するシナリオや証拠があれば差し戻します。

テストケースやコアシナリオの更新で PR を作成する場合があります。業務上の修正は別の[フォローアップタスク](follow-ups.md)で扱います。テストを受け入れても、修正タスクは自動完了しません。
