title: テストの実行

---

テストは[テストの種類ごとの設定](settings.md#テストの種類ごとの設定)に従って自動で実行されるほか、いつでも手動で開始できます。

## 準備

- プロジェクトにコードリポジトリが設定されている。
- 有効な Agent とオンラインの Runner がある。
- 実行者にはプロジェクトへのアクセスと、タスク作成、品質テスト実行、添付ファイルのアップロード権限が必要です。自動実行には[テスト種別に設定した担当者](settings.md)を使います。

## テストを開始する

1. プロジェクトを開き、**Quality** タブに移動します。
2. **Run test** から Release、Project、Custom を選びます。
3. Custom では完了済みタスク、またはプロジェクト全体のコードを選びます。必要に応じて評価項目を調整します。
4. 確認し、作成されたテストタスクを開きます。

![テストの対象範囲と評価項目を選択](https://static-docs.nocobase.com/studio-en-quality-new-20261111-normal-2x.webp)

| 種類 | 手動での開始 |
| --- | --- |
| Daily | 非対応。定時にのみ自動実行します。指定したタスクを今すぐテストする場合は Custom を使います |
| Release | 対応。リリース待ちのタスクが必要です |
| Project | 対応。いつでも開始できます |
| Custom | 対応。完了済みタスク、またはプロジェクト全体のコードを選びます |

作成時に対象範囲と各評価項目の Skill のバージョンが固定されます。後から設定を変えてもこのテストには影響しません。新しい範囲や基準を使う場合は新しいテストを開始します。

## テストの進め方

1. テスト対象のコミットを確定し、今回の変更に関係しない評価項目を省きます。
2. 評価項目ごとに Agent に割り当て、Runner 上で並行して実行します。
3. 各評価項目が専用のテスト環境とデータを用意し、ツールを実行して、基準に沿った結果と証拠を提出します。
4. すべての評価項目の提出後、納品レポートを生成します。

テスト中に製品コードは変更しません。不明確なルールは確認事項として登録し、環境やデータが不足する確認は理由を付けて未検証とします。

## 進捗を確認する

**Quality › Testing issues** または **My issues** からテストを開きます。テストタスクには評価項目ごとの状態、確認件数、各段階の所要時間が表示されます。

![テストタスクと各評価項目の実行状況](https://static-docs.nocobase.com/studio-en-quality-runs-20261111-normal-2x.webp)

## 阻害要因に対応する

ランタイム、権限、テスト用アカウントが不足している場合は準備してから、テストタスクに返信します。業務上の判断は責任者が行います。[質問への回答](../use/answer.md)を参照してください。

## テストをキャンセルする

不要になったテストはキャンセルできます。提出済みの結果は残り、未完了の評価項目はキャンセル済みになります。

テストが終わったら、[テストレポート](reports.md)を確認します。
