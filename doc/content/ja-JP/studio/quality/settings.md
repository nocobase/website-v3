---
title: テストルールと評価項目を設定する
description: 実行時刻、条件、シナリオの言語、確認方法を設定します。
---

プロジェクト管理者が **Quality › Settings** で設定します。先に責任者、リポジトリ、Agent、ランタイムを準備します。自動実行を有効にするだけでは準備は完了しません。

## 実行ルール

| 種類 | 設定 |
| --- | --- |
| Daily | 毎日の実行、時刻、完了済みタスクの最低累積件数 |
| Release | リリース待ちタスクの件数による実行としきい値 |
| Project | 自動実行なし、毎週、毎月。日付と時刻を指定 |
| Custom | 手動実行。定期実行は設定しない |

新規プロジェクトでは自動実行は無効です。有効にする前にタイムゾーンを明示します。定期テストはプロジェクト責任者の権限で実行します。アカウントが無効、または権限不足の場合は先に復旧します。

シナリオの言語は、新しく生成するコアシナリオに適用します。未指定の場合はインスタンスの言語を使います。既存のテストは作成時の範囲とルールを維持します。

![実行ルール、評価項目、Skill の設定](https://static-docs.nocobase.com/studio-en-quality-settings-20261111-normal-2x.webp)

## 評価項目と Skill

| 標準の評価項目 | 確認内容 |
| --- | --- |
| Functional | 業務タスクとコアシナリオの期待する動作 |
| Permissions | アカウント、ロール、データアクセスの境界 |
| Security | 依存関係の脆弱性と影響 |
| Performance | コード上の性能リスク。有効な場合、Daily、Release、Project テストで Lighthouse 測定も実行可能 |
| Code quality | 保守性の問題、遅いテストや不安定なテスト |

Functional は常に有効です。他の項目は適用するテスト種類と Skill を選びます。追加する場合は名前を入力し、ライブラリの Skill と適用するテスト種類を選びます。

確認方法は Skill が定め、指標は実際の提出結果から計算します。Skill の更新は新しいテストに適用し、既存テストは作成時のバージョンを使います。

保存後に[テストを開始](runs.md)して設定を確認します。対応できる人がいないまま自動実行を続けず、ランタイムや権限の問題を先に解決します。
