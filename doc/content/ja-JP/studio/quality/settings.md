プロジェクト管理者が **Quality › Settings** で設定します。先にプロジェクト責任者、リポジトリ、Agent、ランタイムが使えることを確認します。

![実行ルール、評価項目、Skill の設定](https://static-docs.nocobase.com/studio-en-quality-settings-20261111-normal-2x.webp)

## テストの種類ごとの設定

| 種類 | 設定できる項目 |
| --- | --- |
| Daily | 毎日実行するか、実行時刻、実行に必要な完了済みタスクの最低件数、含める評価項目 |
| Release | 自動実行するか、リリース待ちタスクが何件増えるごとに実行するか、含める評価項目 |
| Project | 自動実行なし・毎週・毎月、曜日または日付、実行時刻、含める評価項目 |
| Custom | 既定で選択する評価項目。開始時にも変更できます |

新規プロジェクトでは自動実行は無効です。定期テストはプロジェクト責任者として実行します。プロジェクトに責任者がいない場合や、責任者のアカウントが無効、プロジェクトを閲覧できない、タスクの作成と品質テストの開始の権限がない場合は、定期テストはスキップされ、品質の概要に責任者の設定を促す表示が出ます。

## シナリオの言語

シナリオの言語は、新しく生成するコアシナリオの言語です。未指定の場合はインスタンスの既定の言語を使います。

## 評価項目と Skill

Functional は常に有効です。他の評価項目は適用するテストの種類を選び、Skill を割り当てます。Skill がその評価項目のテスト方法と判定方法を定義します。

評価項目を追加する場合は、名前を入力し、ライブラリから Skill を選び、適用するテストの種類を選びます。

Skill を更新すると新しいテストに適用されます。既存のテストは作成時のバージョンを使います。

## プロジェクトの基準を調整する

各評価項目の確認方法と合格基準は、割り当てた Skill に書かれています。基準を調整するには、スキルライブラリでその Skill を編集するか、評価項目に別の Skill を割り当てます。

たとえば Performance の予算は Skill の `budgets.json` にあり、API の P95 応答時間は既定で 500 ms 以下です。これを 800 ms に変更すると、以降のテストは 800 ms を基準に判定します。

新しい基準は変更後に開始したテストから適用されます。既存のテストは作成時の Skill のバージョンを使い、結果は書き換えられません。既定の基準は[品質基準](standards.md)を参照してください。

<h2 id="scenarios">コアシナリオ</h2>

**Quality › Core scenarios** で、機能ごとのシナリオ、期待結果、直近の検証結果を確認します。

![コアシナリオと直近の検証結果](https://static-docs.nocobase.com/studio-en-quality-scenarios-20261111-normal-2x.webp)

**コアシナリオはシステムが自動で管理し、手動で整理する必要はありません**：

- 機能を変更する開発タスクで、関連するシナリオも同時に更新します。
- Project テストで不足しているシナリオを追加し、古くなったシナリオを更新します。

シナリオはテスト対象リポジトリの `.nb-studio/scenarios/` に保存され、コードと一緒にレビューされ、バージョン管理されます。特別な業務ルールを補足したい場合は、タスクで説明すれば Agent が更新します。
