---
title: 品質テストの設定
description: 実行ルール、性能予算、Skill、コアシナリオを管理します。
---

プロジェクト管理者が **Quality › Settings** で設定します。先に責任者、リポジトリ、Agent、ランタイムを準備します。自動実行を有効にするだけでは準備は完了しません。

## 実行ルール

| 種類 | 設定 |
| --- | --- |
| Daily | 毎日の実行、時刻、完了済みタスクの最低累積件数 |
| Release | リリース待ちタスクの件数による実行としきい値 |
| Project | 自動実行なし、毎週、毎月。日付と時刻を指定 |
| Custom | 手動実行。定期実行は設定しない |

新規プロジェクトでは自動実行は無効です。有効にする前にタイムゾーンを明示します。定期テストはプロジェクト責任者の権限で実行します。アカウントが無効、または権限不足の場合は先に復旧します。

シナリオの言語は、新しく生成するコアシナリオに適用します。未指定の場合はインスタンスの言語を使います。既存のテストは作成時の範囲とルールを維持します。

## 評価項目と Skill

評価項目の内容は[品質の概要](overview.md)、具体的な指標と基準は[品質指標と基準](metrics.md)を参照してください。

Functional は常に有効です。他の項目は適用するテスト種類と Skill を選びます。追加する場合は名前を入力し、ライブラリの Skill と適用するテスト種類を選びます。

確認方法は Skill が定め、指標は実際の提出結果から計算します。Skill の更新は新しいテストに適用し、既存テストは作成時のバージョンを使います。

保存後に[テストを開始](runs.md)して設定を確認します。対応できる人がいないまま自動実行を続けず、ランタイムや権限の問題を先に解決します。

## プロジェクトの基準を調整する

**Quality › Settings** で性能予算を上書きできます。未指定の項目は既定値を使います。他の確認方法と判定ルールは評価項目の Skill で調整します。すべての指標に専用のしきい値入力欄があるわけではありません。既定値と適用範囲は[品質指標と基準](metrics.md)を参照してください。

変更後は新しいテストを開始します。既存テストの対象範囲と Skill のバージョンは固定され、新しい基準で過去の結果を書き換えません。

<h2 id="scenarios">コアシナリオを管理する</h2>

**Quality › Core scenarios** で、機能ごとのシナリオ、期待結果、確認項目を開きます。

シナリオは対象リポジトリの `.nb-studio/scenarios/` に保存します。要件の変更に合わせてエージェントが更新します。追加や修正はタスクで業務ルールを伝え、更新内容をレビューします。タイトルは変更できますが、安定した識別子でテスト間の比較を行います。

画面にはテストが提出したスナップショットを表示します。リポジトリのファイルを変更しただけでは更新されません。後続のテストで新しいスナップショットを提出します。
