title: 品質テストの設定

---

プロジェクト管理者が **Quality › Settings** で設定します。先にプロジェクト責任者、リポジトリ、Agent、ランタイムが使えることを確認します。

![実行ルール、評価項目、Skill の設定](https://static-docs.nocobase.com/studio-en-quality-settings-20261111-normal-2x.webp)

## 実行ルール

| 種類 | 設定 |
| --- | --- |
| Daily | 毎日の実行、時刻、完了済みタスクの最低累積件数 |
| Release | リリース待ちタスクの件数による実行としきい値 |
| Project | 自動実行なし、毎週、毎月。日付と時刻を指定 |
| Custom | 手動のみ |

新規プロジェクトでは自動実行は無効です。有効にする前にタイムゾーンを選び、時刻がチームの予定に合うか確認します。定期テストはプロジェクト責任者として実行します。アカウントが無効、または権限不足の場合は先に復旧します。

## シナリオの言語

シナリオの言語は、新しく生成するコアシナリオの言語です。未指定の場合はインスタンスの既定の言語を使います。

## 評価項目と Skill

Functional は常に有効です。他の評価項目は適用するテストの種類を選び、Skill を割り当てます。Skill がその評価項目のテスト方法と判定方法を定義します。

評価項目を追加する場合は、名前を入力し、ライブラリから Skill を選び、適用するテストの種類を選びます。

Skill を更新すると新しいテストに適用されます。既存のテストは作成時のバージョンを使います。

## プロジェクトの基準を調整する

- 性能予算：設定画面で直接変更します。変更しない項目は既定値を使います。
- その他の基準：評価項目の Skill を変更または差し替えます。

既定の基準は[品質基準](standards.md)を参照してください。変更は新しいテストから適用され、既存の結果は書き換えられません。

<h2 id="scenarios">コアシナリオを管理する</h2>

**Quality › Core scenarios** で、機能ごとのシナリオ、期待結果、直近の検証結果を確認します。

![コアシナリオと直近の検証結果](https://static-docs.nocobase.com/studio-en-quality-scenarios-20261111-normal-2x.webp)

シナリオはテスト対象リポジトリの `.nb-studio/scenarios/` に保存します。

- 機能を変更する開発タスクで、関連するシナリオも同時に更新します。
- Project テストで不足しているシナリオを追加し、古いシナリオを更新します。
- 特別な業務ルールを補足したい場合は、タスクで説明すれば Agent が更新してレビューに提出します。

シナリオには安定した識別子があり、タイトルを変えても識別子でテスト間の結果を比較します。画面には直近のテストが提出したスナップショットを表示します。リポジトリのファイルを変更した場合は、次のテストが新しいスナップショットを提出した時点で更新されます。
