> [!TIP] 何か問題が起きたら、まずエージェントに聞く
> どんな問題でも、まず Claude Code や Codex などのエージェントに任せましょう。見えている状況とエラーを伝えてください。エージェントはサーバーにサインインしてログを読み、`nb-studio` で Studio の状態を確認し、このページやほかのドキュメントを使って原因を突き止めて修正できます。ブラウザーでの操作や認証情報の提供が必要なときは、作業を止めて知らせてくれます。

## インストールとサインイン

**アドレスにアクセスしてもサインインページが表示されない。** アドレスに `/main/` を含めてください。たとえば `https://studio.example.com/main/` です。

**どのアカウントでサインインすればよいかわからない。** デプロイディレクトリの `.env` にある `INITIAL_ADMIN_USERNAME` と `INITIAL_ADMIN_PASSWORD` を使います。[Studio をインストールする](../setup/install.md#サインインする) を参照してください。

**サインインページに Sign up のリンクがある。** `config.yml` で `auth.emailAndPassword.disableSignUp: true` を設定し、Studio を再起動します。

**イメージの取得に失敗する。** unauthorized と表示される場合はトークンが間違っているので、レジストリにサインインし直します。`postgres:16` の取得がタイムアウトする場合は、サーバーから Docker Hub に到達できないため、レジストリのミラーを設定するか、既存の PostgreSQL を使います。イメージレイヤーのダウンロードが止まる場合は、トークンと一緒に受け取ったイメージレイヤーのダウンロード先へのアクセスを許可します。[Studio をインストールする](../setup/install.md#トラブルシューティング) を参照してください。

**コンテナが起動しない、または再起動を繰り返す。** `docker compose logs studio` を実行して原因を確認します。よくある原因：先に `config.yml` をコピーしなかったため、Docker がその名前のディレクトリを作成した。`storage` ディレクトリの所有者が UID 1000 でない。暗号化キーが設定されていない。

**`nb-studio login` を承認したのに、サインインできていない。** `nb-studio login` は、承認する間ずっと実行中である必要があります。終了後に承認しても効果はありません。もう一度 `nb-studio login` を実行し、新しいコードを承認します。

## Git の接続

**GitHub App の作成時に「Hook url is not supported because it isn't reachable over the public Internet」と表示される。** Studio に公開アドレスがないのに、Webhook がオンになっています。**Webhook** をオフにして作り直すと、Studio は代わりに 1 分ごとに確認します。[Git を接続する](../configure/git.md#webhook-をオンにすべきか) を参照してください。

**プロジェクトの作成時に「The repository was created, but the App could not confirm access.」と表示される。** GitHub App が一部のリポジトリだけにアクセスできるようインストールされています。GitHub の App のインストール設定でこのリポジトリを追加してから、もう一度プロジェクトを作成し、**Existing repository** を選びます。

**エージェントが PR を作成するときに、プッシュする権限がないと言う。** メンバーが自分の Git アカウントを接続していますが、そのアカウントにはリポジトリの読み取り権限しかありません。アカウントに書き込み権限を付与するか、個人アカウントの接続を解除してワークスペースの接続を使うようにします。

## ランタイムとエージェント

**ランタイムがオフラインと表示される。** 150 秒間 Studio に接続していない runner はオフラインと表示されます。そのマシンで `nocobase-runner status` を実行し、動作していて Studio のアドレスに到達できることを確認します。

**コーディングツールに Login required または Not installed と表示される。** そのマシンで、runner を実行するシステムユーザーとしてツールをインストールしてサインインし、ランタイムの詳細で **Detect again** をクリックします。インストール済みなのにまだ Not installed と表示される場合は、バックグラウンドサービスの PATH にツールが含まれていません。`which claude` が動作するターミナルで `nocobase-runner service install` をもう一度実行し、サービスを再起動します。[共有ランタイムを接続する](../configure/runtimes.md#トラブルシューティング) を参照してください。

**エージェントの一覧にモデルがない。** よく使われるモデルは、ランタイムが報告すると自動で有効になります。ほかのモデルは **Add agent** の **Available models** から追加します。モデルに **Needs setup** や **Version too low** と表示される場合は、ヒントに従ってランタイムで対処します。

## タスクの進行

**タスクがいつまでも始まらない。** タスクページの **Now** の行を確認します。何を待っているかが表示されます。オンラインのランタイムがない、すべての枠が使用中、エージェントがほかの人の個人ランタイムにしかない、ブロッカーがある、「Initialize project」がまだ実行中、などです。Backlog のタスクは、先に **Start** をクリックする必要があります。

**作業が 24 時間以上待って、実行が失敗した。** どのランタイムも作業を引き受けませんでした。ランタイムを接続または起動してから、タスク責任者が受け取ったカードで再試行をクリックします。

**コーディネーターエージェントが、CI を追加するかどうかを尋ねて止まる。** プロジェクトにまだ CI がないため、PR にチェック結果がありません。CI を接続するか、CI なしで検収すると返信します。タスクの説明で最初からそう伝えておくこともできます。[CI を接続する](../setup/ci.md) を参照してください。

**エージェント同士が何度も行き来したあと、一時停止した。** 既定では、エージェントのコメントで起動できる実行は、タスクごとに 24 時間あたり最大 20 回です。まずアクティビティと実行記録を確認し、同じ問題を何度も直そうとしていないかを確かめます。続けるべきだと確信できたら、タスクページで **Continue (comment-triggered runs reached their limit)** をクリックします。[エージェントの質問に答える](../use/answer.md#コメントによる実行の上限) を参照してください。

**引き渡しレポートにスクリーンショットがない、またはスクリーンショットの撮影に失敗したと書かれている。** ランタイムにブラウザーがありません。[共有ランタイムを接続する](../setup/shared-runtimes.md) の準備のセクションに従って、Chromium とそのシステム依存関係をインストールします。

**コーディングツールの利用枠が尽きた。** コーディネーターエージェントは、すぐにステップを別の適切なエージェント（できれば別ベンダー）に引き渡します。そのツールは、そのランタイムで作業を引き受けなくなります。リセット時刻がわかっている場合は、その時刻に自動で再開します。わからない場合は、利用枠が戻ったら、ランタイムの所有者か管理者がランタイムの詳細で利用枠の印を解除します。

## 検収とマージ

**Merge ボタンが無効になっている。** PR にコンフリクトがある、まだ下書きである、チェックが実行中のいずれかです。コンフリクトは、コーディネーターエージェントが解決を手配します。チェックが終わったらマージしてください。

**ボタンが Merge anyway と表示される。** 必須のチェックが失敗したか、チェック結果がありません。マージしてよいと確信できたら、理由を入力してマージします。マージは PR とタスクのアクティビティに記録されます。

**GitHub で直接 PR をマージしたのに、Studio のタスクが変わらない。** Studio は 1 分ごとに確認します（Webhook がオンならすぐに検知します）。少し待つと、タスクは自動で Done に移ります。

## プレビューとデプロイ

**PR にプレビューがない。** プロジェクトでまだ CI が接続されていないか、CI から Studio のアドレスに到達できません。[CI を接続する](../setup/ci.md) を参照してください。

**プレビューを開くのに時間がかかる。** プレビューは、しばらくアクセスがないと停止またはスリープし、開くと起動または準備し直す必要があります。少しお待ちください。

**本番にデプロイしても何も起きない。** 本番は保護されているため、デプロイは承認者を待つデプロイリクエストになりました。承認者が受信トレイの **To decide** で対応します。

## 通知

**招待メールが送信されなかった。** Studio にまだメールチャネルがなく、結果に **Email not sent** と表示されます。招待リンクをコピーして同僚に送るか、メールを設定します。[通知とプッシュ](../admin/notifications.md) を参照してください。

**プッシュ通知がスマートフォンに届かない。** プッシュ通知には、Studio が HTTPS で提供され、管理者がプッシュ用の秘密鍵を設定している必要があります。iPhone では、先に Studio をホーム画面に追加し、ホーム画面から開いて登録します。
