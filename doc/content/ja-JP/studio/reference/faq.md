---

症状、関連タスク、エラーをローカルのコーディングエージェントに伝えて調査を依頼できます。プロンプトにパスワードやトークンを含めないでください。Studio に接続したエージェントは `nb-studio` で状態を確認できます。

## インストールとサインイン

| 問題 | 確認すること |
| --- | --- |
| サインイン画面が出ない | `https://studio.example.com/main/` を使い、コンテナの正常性とリバースプロキシを確認 |
| 初期アカウントで入れない | 最初に設定した管理者のユーザー名とパスワードを確認。環境変数の変更では既存アカウントを再設定しない |
| コンテナが再起動を繰り返す | `docker compose logs --tail=100 studio` で設定、DB 接続、保存先の権限を確認 |
| CLI を承認してもログインできない | コマンドを実行したまま承認。期限切れなら新しいコードで再試行 |

[Studio のデプロイ](../setup/install.md)、パスワード再設定は[通知とプッシュ](../admin/notifications.md)を参照してください。

## Git 接続

GitHub がプライベートな Webhook URL を拒否する場合は、Webhook を無効にしてポーリングを使います。新しいリポジトリに接続できない場合は、GitHub App のインストール範囲を確認します。権限を付与してから[既存リポジトリ](../project/settings.md#既存リポジトリを接続する)として接続してください。

個人の Git アカウントが読み取り専用の場合は、PR をプッシュできません。書き込み権限を付けるか、チームの方針に従ってワークスペース接続を使います。[Git プラットフォーム](../configure/git.md)を参照してください。

## ランタイムとタスク

| 症状 | 次の操作 |
| --- | --- |
| ランタイムがオフライン | マシンで `nocobase-runner status` を実行し、サービスとネットワークを確認 |
| ツールがない・未ログイン | サービスのシステムユーザーでインストール・サインインし、再検出 |
| ターミナルで使えるがサービスで使えない | 正しいターミナルで `nocobase-runner service install` を実行 |
| タスクが始まらない | 状態、先行タスク、初期化、待機理由を確認 |
| 多数の実行後に停止する | 実行上限と繰り返す失敗を調べてから続行 |
| ツールの利用枠を消費した | 回復を待つか別のモデルを使用。回復後、再開時刻不明の表示を解除 |

Backlog のタスクは **Start** で開始します。共有ランタイムが埋まっている間の待機は正常です。[進捗を追う](../use/follow-progress.md)を参照してください。

## チェック、プレビュー、マージ

結果がない場合は、リポジトリで選択した取得元を確認します。コードプラットフォームの CI、外部 CI、セルフチェックの結果は合算しません。[チェックと CI](../configure/checks.md)を参照してください。

プレビューがない場合は、ビルド記録、CI から Studio への接続、必須変数、`no-preview` ラベルを確認します。停止・休止したプレビューは、アクセスすると起動します。

競合、ドラフト状態、チェック待ちはマージ前に解消します。失敗・不足したチェックを無視して続けるには権限が必要で、コードプラットフォームの保護は回避できません。

マージ済み PR がタスクに反映されない場合は、同期を待ち、すべての関連 PR がマージされたか確認してください。

## メールとリリース

招待メールを送れない場合は、招待リンクをコピーします。招待とパスワード再設定の送信設定は別です。[通知とプッシュ](../admin/notifications.md)でそれぞれ確認してください。

保護されたテスト環境へのデプロイは承認を待ちます。本番デプロイ後は、責任者が[バージョンを記録](../project/release.md#本番バージョンを記録する)するとリリースの表示が更新されます。
