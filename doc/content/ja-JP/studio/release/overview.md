変更がマージされてから本番に反映されるまでには、3 つの段階があります。

| 段階 | 動作する場所 | デプロイする人 |
| --- | --- | --- |
| プレビュー | Studio がホスト | リポジトリの CI が PR でビルドしてデプロイします。[PR プレビュー](previews.md) を参照してください |
| テスト | Studio がホスト | CI、あなたのエージェント、またはあなた自身が成果物をアップロードしてデプロイします。[デプロイ環境](../admin/environments.md) を参照してください |
| 本番 | 自社のサーバー | あなたまたはあなたのエージェントがデプロイ手順に従ってデプロイし、デプロイ後に Studio でバージョンを記録します。[本番へのデプロイ](../project/release.md) を参照してください |

Studio は本番サーバーに接続せず、本番へのデプロイも代行しません。本番でどのバージョンが動いているかを記録し、まだ本番に反映されていない変更を知らせます。

## Releases ページ

![Releases ページ：左側にプロジェクト、右側にプレビュー、テスト環境、バージョン、リリース待ちのタスク](https://static-docs.nocobase.com/studio-zh-releases-20261030-v2.png)

左側はプロジェクトの一覧で、各プロジェクトに最新のバージョンとリリース待ちのタスク数が表示されます。「リリース待ちあり」「最新」「バージョンなし」「リリースライン未設定」で絞り込めます。

プロジェクトを選ぶと、右側の上部にその 3 つの段階が表示されます。

- **プレビュー**：アクセスできる PR プレビューの数と、最新の PR。
- **テスト**：テスト用のアプリがどの環境にあり、どのバージョンが動いているか。
- **本番**：本番として記録されたバージョン。新しいバージョンがある場合は、どのバージョンを本番に反映でき、いくつのタスクを含むかが表示されます。プロジェクトリーダーはここから「デプロイ手順」を開きます。

下部には 4 つのタブがあります。

| タブ | 内容 |
| --- | --- |
| プレビュー環境 | 各 PR のプレビュー：アクセス URL、コミット、ビルドの状況 |
| テスト環境 | テスト用のアプリ：環境、バージョン、状態。デプロイ、ログの表示、変数の設定、停止、削除ができます |
| バージョン | リリースラインに一致するタグ。各バージョンに含まれるタスクと成果物 |
| リリース待ち | マージ済みだが、まだどのリリース済みバージョンにも含まれていないタスクと、それらがテスト環境にあるかどうか |

プロジェクトページの **Releases** セクションにも同じ内容が表示され、そのプロジェクトだけが対象になります。

## タスクのデプロイ表示

タスクの一覧とタスクページには、変更がどこまで届いているかが表示されます。テスト環境に反映済み、本番に反映済み（記録されたバージョンに基づく）、ロールバックによる取り下げです。表示は、Studio がデプロイされたコミットとタスクの PR を比較して算出するので、手作業で管理する必要はありません。

## 通知

- プロジェクトで最も古いリリース待ちの変更がマージされてから 3 日が経つと、プロジェクトリーダーにリマインダーが届きます。
- リポジトリに新しいバージョンタグが作成されると、Studio はそのバージョンがリリースされたことと、含まれるタスク数を通知します。
- 保護された環境へのデプロイリクエストとデプロイの失敗は、関係する人の [受信トレイ](../use/inbox.md) に届きます。
