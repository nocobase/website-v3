---

**Releases** は、プロジェクトごとのリリース状況をまとめます。プロジェクトを選び、プレビュー、ステージングのアプリ、バージョン、記録済みの本番デプロイを確認します。

![プロジェクトのプレビュー、テスト、バージョンのリリースを追う](https://static-docs.nocobase.com/studio-en-guide-releases-20261031.png)

| 段階 | 表示内容 | 次の操作 |
| --- | --- | --- |
| Preview | PR 専用のアプリとビルド状態 | 変更を検証 |
| Staging | テスト用アプリのコミットやバージョン | マージ後の変更を確認 |
| Release | Git タグで識別するバージョンと成果物 | リリースするバージョンを選ぶ |
| Production | チームが記録したバージョン | 自社インフラへのデプロイ後に記録を更新 |

Studio はプレビューとテスト用アプリをホストできます。本番はチームが自分たちのイメージや Installer でデプロイし、Studio は本番デプロイを管理しません。

## 未リリースの作業を確認する

**Pending release** は、完了したものの本番に届いていないタスクを表示し、テスト中かも示します。リリース・デプロイ前に、そのバージョンに含まれるタスクを確認してください。

タスクのテスト・本番の表示は、コミットの関係から計算します。本番は責任者が記録したバージョンに基づきます。古いバージョンを記録すると、そのバージョンに含まれない変更の表示は外れます。

## リリースを進める

- マージ前に検証する：[PR プレビュー](previews.md)。
- テスト用アプリを管理する：[ホスト環境](../admin/environments.md)。
- バージョンと成果物を準備する：[バージョンとリリース](versions.md)。
- 本番にデプロイして記録する：[本番環境へのデプロイ](../project/release.md)。

未対応の作業は責任者に通知されます。デプロイ失敗や、保護されたテスト環境の承認依頼は[受信トレイ](../use/inbox.md)に届きます。
