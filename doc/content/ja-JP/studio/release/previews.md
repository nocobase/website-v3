プレビューを使うと、タスク責任者はマージの前に実際に動いているアプリを開き、検収基準に沿って自分で試せます。先に [CI を接続](../setup/ci.md) し、トリガーに「Pull request」を選んでおく必要があります。

## プレビューができるまで

1. エージェントが PR を作成または更新すると、CI が PR の最新のコミットでアプリをビルドします。
2. CI は成果物を Studio にアップロードし、アプリ `<アプリ ID>-pr-<番号>` としてデプロイします。アプリはプレビュー環境（既定では Studio に付属の「Preview」環境）で動作します。
3. Studio はこのアプリをその PR のプレビューとして記録し、ひも付いたタスクの **Code & previews** に、アクセス URL、コミット、ビルドの状況とログを表示します。

![タスクページの Code & previews にあるプレビュー：最新のコミット、ビルドの状況、初期管理者、再デプロイと破棄](https://static-docs.nocobase.com/studio-zh-req-preview-20261030-v2.png)

PR に新しいコミットが追加されると、プレビューは新しいコミットのビルドが完了してから更新され、それまでは古いコミットのまま動き続けます。

Studio 自体はプレビューをビルドせず、PR にコメントも書きません。プレビューが不要なタスクでは、タスクのプロパティで「プレビュー不要」をオンにすると、エージェントが PR に `no-preview` ラベルを付け、CI テンプレートがそれを見てスキップします。

## プレビューを開く

タスクページの **Code & previews** で、プレビューのアクセス URL をクリックします。

- プレビューは初回のデプロイ時にサンプルデータを読み込み、初期管理者を自動で生成します。自社の実データは含まれません。初期管理者のアカウントとパスワードはタスクページのプレビューエリアに表示され、その PR にひも付いたタスクを編集できる人だけが見られます。
- 必須の変数が足りないプレビューはデプロイされません。タスクページのプレビューエリアに、足りない変数と設定する場所が表示されます。プレビュー環境に設定するとすべてのプレビューで使え、個々のプレビュー用アプリに設定するとそのアプリだけに適用されます。

## 停止、休止、削除

プレビュー環境の既定の設定は次のとおりです。

| 状況 | 結果 |
| --- | --- |
| 10 分間アクセスがない | 停止してメモリを解放します。次にアクセスすると自動で起動し、ブラウザーには先に「起動中」のページが表示されます |
| 24 時間アクセスがない | 休止し、展開したファイルを削除します。設定とデータは保持されます。次にアクセスすると準備し直すため、時間が長くかかります |
| PR がマージまたはクローズされた、またはだれかが「破棄」をクリックした | このプレビューとそのデータを削除します |

プレビュー環境に同時に置けるプレビューは最大 20 個です。これらの既定値は **Releases › Deploy environments** で調整します。[デプロイ環境](../admin/environments.md) を参照してください。

> [!NOTE] 本格的に使うときはプレビューを Studio から分離する
> プレビューで動いているのは、まだマージされていないコードです。プレビューには専用のドメインを使い、プレビューを実行するプロセスには Studio の設定を読めない別のシステムユーザーを使うことをおすすめします。[設定項目](../reference/config.md) を参照してください。
