Studio は Git タグからバージョンを識別し、含まれるタスクを計算します。リリースラインはタグの系列を定義し、成果物にはデプロイに使うファイルやイメージを保存します。

![バージョン、含まれるタスク、デプロイ成果物](https://static-docs.nocobase.com/studio-en-guide-versions-20261031.png)

## リリースラインを設定する

**Project settings › Code repositories** の **Release lines** を編集します。既存タグから候補を選ぶか、`v*`、`release-beta/*` など、末尾が `*` のパターンを入力します。

1 つのリポジトリに、重ならない複数のラインを設定できます。プレフィックスを非表示にすると、`release-beta/1.2.0` を `1.2.0` と表示できます。タグがない場合は、最初のバージョンタグを作成してください。

## バージョンを公開する

1. **Releases** でプロジェクトを選び、**How to publish** を開きます。
2. ライン、ブランチ、対象コミットを選びます。テスト用アプリのコミットを使うか、完全な SHA を入力します。
3. 含まれるタスクと、そのコミットに含まれない未リリースタスクを確認します。
4. タグを確認し、生成されたコマンドをコピーして実行し、作成・プッシュします。

Studio は Webhook とポーリングで新しいバージョンを取得します。ラインを変更するとバージョンとタスクの関係を再計算し、成果物とデプロイ履歴は保持します。

## 成果物

成果物はアプリのアーカイブまたはイメージです。NocoBase アプリは `pnpm build --tar` でデプロイ用アーカイブを作成します。イメージのビルドとレジストリへのプッシュは CI またはコーディングエージェントが行います。

バージョン一覧から成果物を確認し、アーカイブをダウンロードし、デプロイ操作を開けます。ビルドとアップロードは[チェックと CI](../configure/checks.md)、テストは[ホスト環境](../admin/environments.md)、本番は[本番環境へのデプロイ](../project/release.md)を参照してください。
