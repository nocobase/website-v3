description: 小さな要件を出し、エージェントチームが計画、開発、レビューする様子を見ます。質問に答え、検収してマージし、ワークフロー全体が最後まで動くことを確認します。
---

招待を受けてサインインしたら、管理者が準備したプロジェクトを開きます。小さな要件を出し、開発から検収までを追ってみましょう。

## 始める前に

- プロジェクトの「Initialize project」タスクが完了していること。[プロジェクトを作成する](new-project.md) を参照してください。
- 管理者が、利用可能なエージェントチームとコーディネーターエージェントを設定していること。
- チームのランタイムがオンラインで、リポジトリに [チェックの取得元](ci.md) があること。

## 1. 要件を出す

1. プロジェクトを開き、**New issue** をクリックします。右側にエージェントとのセッションが開き、現在のプロジェクトがコンテキストとして渡されます。
2. 小さな要件を業務の言葉で説明し、どう確認するかも書きます。たとえば次のとおりです。

   ```text
   アプリに Suppliers テーブルを追加してください。項目は名前、担当者、電話番号、ステータス（有効または一時停止）です。ナビゲーションに Suppliers ページを追加し、仕入先を追加、編集、閲覧できるようにしてください。
   検収：サインイン後、ナビゲーションから Suppliers ページを開き、仕入先を追加して、一覧に表示されることを確認する。
   ```

3. 送信します。要件が明確なら、エージェントはすぐにタスクにします。不明な点があれば、先に質問してきます。
4. タスクが作成されたら、セッションで **Start 1 issue** をクリックするか、タスクを開いて **Start** をクリックします。

セッションを使わない場合は、**Fill in manually** をクリックし、タイトルと説明を自分で入力します。

**完了の目安**：タスクが **In progress** になり、実行者がコーディネーターエージェントになっていること。

## 2. エージェントチームの作業を見る

タスクを開きます。上部の **Now** の行には、どのエージェントがどのランタイムで、どれくらいの時間作業しているかが常に表示され、その下に次の予定が表示されます。

**Activity** には、割り振り、エージェントの返信、レビューの結果が記録されます。エージェントは変更を設計、実装、検証し、PR を作成して、レビューの指摘に対応します。

::figure req-now | タスクページの上部：今だれが作業しているか、次に何をするか

**Runs** には、すべての実行の完全な記録があり、問題を掘り下げるときに役立ちます。

## 3. 質問に答える

2 つの方針のどちらにするかなど、要件に不明な点があると、コーディネーターエージェントはタスクを **Blocked** にし、何を決めてほしいかを具体的に示します。タスクは **My issues** の先頭に表示されます。開いて **Needs you** カードの **Reply** をクリックし、判断を書きます。コーディネーターエージェントはあなたの返信から作業を再開します。

要件が明確に書かれていれば、このステップは発生しないこともあります。

チェックやプレビューが完了できない場合は、エージェントのレポートを読んでください。設定の問題は、管理者が [チェックと CI](../configure/checks.md) を使って解決できます。要件を出すために、ローカルにコーディングツールをインストールする必要はありません。

## 4. 結果を検収する

PR がレビューとチェックを通過すると、タスクは **In review** に移り、**My issues** の **Waiting for you** に表示されます。

1. タスクを開きます。**Needs you** カードに何の検収を求められているかが書かれ、その下に引き渡しレポートがあります。以前の状況、変更内容、確認方法、推奨事項付きの未解決の課題、最後に検収基準とスクリーンショットです。
2. **View changes** をクリックして PR を確認します。
3. プレビューがあれば、タスクページから開き、最初の管理者としてサインインして、検収基準に沿って試します。
4. 期待どおりに動けば、**Merge** をクリックします。確認画面には、マージ方法（たとえば `main` へのスカッシュ）、コミットのタイトル、タスクが **Done** に移ることが表示されます。確定してください。チェック結果がない場合、ボタンは **Merge anyway** と表示され、理由を入力できます。Studio はマージを PR とタスクのアクティビティに記録します。
5. 問題があれば、**Send back for changes** をクリックし、何を直す必要があるかを書きます。コーディネーターエージェントが修正を手配し、再びあなたに引き渡します。

::figure req-accept | 検収では、引き渡しレポート、検収基準、スクリーンショットを確認します

**完了の目安**：タスクが **Done** になり、変更がリポジトリの既定のブランチに入っていること。テスト環境への配信が設定されている場合は、その進捗をタスクで追います。

## トラブルシューティング

**タスクがいつまでも始まらない。** タスクページの **Now** の行を確認します。何を待っているかが表示されます。オンラインのランタイムがない、すべての枠が使用中、エージェントがほかの人の個人ランタイムにしかない、などです。24 時間以内にどのランタイムも作業を引き受けないと、実行は失敗し、再試行できるよう通知が届きます。

**「Initialize project」がまだ完了していない。** プロジェクトの新しいタスクは、それが完了するまで待機します。

**エージェントがスクリーンショットを撮れなかったと言っている。** ランタイムにブラウザーがありません。[共有ランタイムを接続する](shared-runtimes.md) の準備のセクションを参照してください。

続けて、[My issues](../use/my-tasks.md) で保留中の作業に対応するか、[My sessions](../use/sessions.md) で次の要件を相談しましょう。
