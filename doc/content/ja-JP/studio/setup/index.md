デプロイ、接続、プロジェクトの準備は、[インストールと設定のガイド](with-agent.md) をローカルのコーディングエージェントに渡して任せることをおすすめします。承認やサインインにあなたの操作が必要なときは、その指示に従ってください。

すでに招待を受けている場合は、[はじめる](../join/index.md) に進んでください。

このガイドでは Docker Compose、GitHub、1 台の共有ランタイムを使います。コーディングツールとモデルのアカウントは、今お使いのものをそのまま使えます。

## 始める前に

- Studio の商用版イメージとアクセス許可を入手します。[お問い合わせ](https://www.nocobase.com/ja-JP/contact/) ください。
- Docker と Docker Compose を用意します。ローカルで試すだけならドメインは不要です。
- リポジトリを作成でき、GitHub App をインストールできる GitHub アカウントまたは組織を用意します。
- Claude Code や Codex など、コーディングツールをインストールしてサインイン済みのマシンを用意します。

ランタイムは、Studio から分離した専用のコンテナまたは仮想マシンにすることをおすすめします。コーディングツールと runner はその環境内にインストールします。

## チームの環境を準備する

| ステップ | 結果 |
| --- | --- |
| 1. [Studio をデプロイする](install.md) | 管理者がサインインできる |
| 2. [Git プラットフォームを接続する](git.md) | Studio がリポジトリを作成し、コードを提出できる |
| 3. [ランタイムを接続する](shared-runtimes.md) | コーディングツールがオンラインになり、作業できる |
| 4. [エージェントを設定する](agents.md) | コーディネーターエージェントが仕事を割り振れる |
| 5. [最初のプロジェクトを作成する](new-project.md) | アプリのコードが初期化される |
| 6. [チェックとプレビューを設定する](ci.md) | 変更の検証にエージェントのセルフチェックか CI を選べる |
| 7. [メンバーを招待する](invite.md) | メンバーが招待を受けてプロジェクトに参加できる |

## メンバーが作業を始める

[招待を受けてサインイン](../join/sign-in.md) したら、メンバーは [最初の要件を一通り試します](first-request.md)。要件を出し、開発を追い、結果を検収します。自分の PC を接続しなくても、チームのランタイムを使えます。

## 設定を調整する

| 設定 | ドキュメント |
| --- | --- |
| モデルの担当、実行マシン、共有スキル | エージェント管理：[エージェント](../configure/agents.md)、[ランタイム](../configure/runtimes.md)、[スキル](../project/skills.md) |
| チェックの取得元と CI パイプライン | 品質管理：[チェックと CI](../configure/checks.md) |
| プロジェクト情報、メンバー、既定のスキル | プロジェクト管理：[プロジェクト設定](../project/settings.md) |
| Git の接続とその他のコードプラットフォーム | システム管理：[コードプラットフォーム](../configure/git.md) |
| データベース、アクセス URL、デプロイのパラメーター | リファレンス：[設定](../reference/config.md) |
