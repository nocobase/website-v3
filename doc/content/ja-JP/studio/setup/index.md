インストールと設定は、ローカルの Claude Code や Codex などのコーディングエージェントに任せることをおすすめします。すでに招待を受けている場合は、[はじめる](../join/index.md) に進んでください。

## エージェントに任せる

```prompt
https://docs.nocobase.com/ja-JP/studio/setup/ に従って NocoBase Studio をインストールし、最初のプロジェクトを設定してください。
```

エージェントは対象の環境を確認し、不足している情報を質問します。その後、下記の手順に沿って設定と検証を進めます。本人によるサインインや承認が必要な場合は、案内に従って操作してください。

## 始める前に

このガイドでは Docker Compose、GitHub、1 台の共有ランタイムを使います。次のものを用意してください。

- **イメージの利用権限**：Studio は商用製品です。イメージとアクセス許可については[お問い合わせ](https://www.nocobase.com/ja-JP/contact/)ください。
- **デプロイ先の環境**：サーバーへのアクセス方法と Studio のアクセス URL。ローカルで試すだけならドメインは不要です。
- **Git アカウント**：リポジトリを作成でき、GitHub App をインストールできるアカウントまたは組織。
- **コーディングツールとモデルのアカウント**：Claude Code や Codex など。既存のアカウントを引き続き使えます。

ソフトウェアのインストールと設定はエージェントに任せられます。既存のデータベース、リバースプロキシ、ストレージ、メールサービスがあれば、利用できるものを引き継ぎます。必要な情報が不足している場合は、エージェントが質問します。

ランタイムは、Studio から分離した専用のコンテナまたは仮想マシンにすることをおすすめします。コーディングツールと runner はその環境内にインストールします。

## チームの環境を準備する

| ステップ | 結果 |
| --- | --- |
| 1. [Studio をデプロイする](install.md) | 管理者がサインインできる |
| 2. [Git プラットフォームを接続する](git.md) | Studio がリポジトリを作成し、コードを提出できる |
| 3. [ランタイムを接続する](shared-runtimes.md) | コーディングツールがオンラインになり、作業できる |
| 4. [エージェントを設定する](agents.md) | コーディネーターエージェントが仕事を割り振れる |
| 5. [最初のプロジェクトを作成する](new-project.md) | アプリのコードが初期化される |
| 6. [チェックとプレビューを設定する](ci.md) | 変更の検証にエージェントのセルフチェックか CI を選べる |
| 7. [メンバーを招待する](invite.md) | メンバーが招待を受けてプロジェクトに参加できる |

## メンバーが作業を始める

[招待を受けてサインイン](../join/sign-in.md) したら、メンバーは [最初の要件を一通り試します](../../getting-started/collaborate-with-studio.md)。要件を出し、開発を追い、結果を検収します。チームが用意したランタイムを使えます。

## 設定を調整する

| 設定 | ドキュメント |
| --- | --- |
| モデルの担当、実行マシン、共有スキル | エージェント管理：[エージェント](../configure/agents.md)、[ランタイム](../configure/runtimes.md)、[スキル](../project/skills.md) |
| チェックの取得元と CI パイプライン | 品質管理：[チェックと CI](../configure/checks.md) |
| プロジェクト情報、メンバー、既定のスキル | プロジェクト管理：[プロジェクト設定](../project/settings.md) |
| Git の接続とその他のコードプラットフォーム | システム管理：[コードプラットフォーム](../configure/git.md) |
| データベース、アクセス URL、デプロイのパラメーター | リファレンス：[設定](../reference/config.md) |
