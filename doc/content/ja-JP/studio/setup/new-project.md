---
title: 最初のプロジェクトを作成する
description: プライベートリポジトリを作成して NocoBase アプリを初期化し、業務のタスクを追加できる状態にします。
---

先に [Git プラットフォームを接続](git.md) し、[エージェントを設定](agents.md) しておきます。Node.js 24 と pnpm 11 がインストールされたランタイムが、少なくとも 1 つオンラインである必要があります。

チームメンバーはプロジェクトを作成でき、そのプロジェクトのリーダーになります。GitHub App が **All repositories** にアクセスできることを確認してください。[GitHub を接続する](git.md#github-を接続する) を参照してください。

## プロジェクトの情報を入力する

1. **Development › Projects** を開き、**New project** を選びます。
2. 名前と説明を入力します。たとえば **Supplier Management** と **Manage supplier records, scoring, and purchase approvals** です。
3. コードの保存先として **New repository** を選びます。
4. 接続済みの Git アカウントまたは組織を選び、使われていないリポジトリ名を入力します。リポジトリはプライベートのままにします。
5. **NocoBase app** を選び、既定のアプリテンプレートのままにします。
6. **Create** を選びます。

![プライベートリポジトリを作成し、既定の NocoBase テンプレートで初期化します](https://static-docs.nocobase.com/studio-en-new-project-20261111-normal-2x.webp)

Studio は、選んだアカウントまたは組織の下にリポジトリを作成します。リポジトリ名は、すでに使われているものであってはなりません。

## 初期化を待つ

Studio は **Initialize project** タスクを作成します。コーディネーターエージェントが作業を割り振ります。実行エージェントがランタイム上で Core アプリを作成し、依存関係をインストールして、コードをコミットします。

タスクを開くと、進捗、エージェントの返信、チェックの結果を追えます。プロジェクトのほかのタスクは、初期化が終わるまで待機します。

最初のコミットは既定のブランチにプッシュされます。チェックを通過したとき、またはリポジトリにチェックが設定されていないとき、初期化タスクは自動で完了します。

初期化ではテンプレートと依存関係をダウンロードするため、かかる時間はネットワーク、ランタイム、モデルによって変わります。作業がキューに入ったままの場合は、ランタイムがオンラインで、コーディネーターエージェントが利用可能であることを確認してください。

## タスクの追加を始める

次のことを確認します。

- **Initialize project** が **Done** になっている。
- リポジトリの既定のブランチにアプリのコードが含まれている。
- 概要に、初期化を完了するよう求める表示がなくなっている。

アプリの準備ができました。チェックとプレビューを準備してから、メンバーを招待します。

![タスクの進捗と設定を確認できるプロジェクト概要](https://static-docs.nocobase.com/studio-en-supplier-overview-20261111-normal-2x.webp)

## 次のステップ

エージェントのセルフチェック、GitHub Actions、外部の CI のいずれかで [チェックとプレビューを設定します](ci.md)。そのあと [メンバーを招待します](invite.md)。

プロジェクトのドキュメント、メンバー、既定のスキルは [プロジェクト設定](../project/settings.md) で管理します。モデルは [エージェントの設定](../configure/agents.md) で、実行リソースは [ランタイム](../configure/runtimes.md) で調整します。
