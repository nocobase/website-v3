## エージェントに依頼する

ローカルのコーディングエージェントに次の依頼を渡します。サーバーとプロジェクトの情報は自分のものに置き換えてください。

```prompt
https://docs.nocobase.com/ja-JP/studio/setup/with-agent/ と、そこからリンクされているデプロイ手順を読んでください。私のサーバーの https://studio.example.com/main/ に、空の NocoBase Studio をインストールしてください。

私の GitHub 組織を接続し、「Supplier Management」用のプライベートリポジトリを作成して、NocoBase のアプリテンプレートで初期化してください。準備済みのランタイムとコーディングツールを接続し、エージェントチームを設定してください。セットアップが終わったら、業務のタスクを追加できるようにしたいです。

イメージとサーバーへのアクセスは準備できています。ブラウザーでの承認やサインインが必要なときは教えてください。
```

既存のデータベースやリバースプロキシがあれば伝えておくと、エージェントがその構成を使えます。

## 情報を準備する

| 項目 | 用意するもの |
| --- | --- |
| デプロイ先 | ローカルマシンまたはアクセス可能なサーバー、インストール先ディレクトリ、Studio の URL |
| Studio のイメージ | 商用製品のため、[お問い合わせ](https://www.nocobase.com/ja-JP/contact/) のうえ、提供されたアクセス手順に従ってください |
| コードホスト | GitHub と、対象のアカウントまたは組織 |
| ランタイム | タスクを実行するマシンと、インストールしてサインイン済みのコーディングツール |
| ストレージとメール | 永続化されたローカルディレクトリまたはプライベートなオブジェクトストレージと、招待メールとパスワード再設定メールの送信用アカウント |
| 最初のプロジェクト | プロジェクト名と、新しいリポジトリの名前 |

認証情報は、認証情報マネージャーかアクセスを制限したローカルの設定ファイルで渡します。プロンプトには含めないでください。ブラウザーでの承認やコーディングツールへのサインインには、あなたの操作が必要になる場合があります。

## インストールの流れ

| ステップ | 結果 |
| --- | --- |
| [Studio をデプロイする](install.md) | アクセスできる URL、ファイルと成果物のストレージ、招待メールとパスワード再設定メールを備えた空のインスタンス |
| [Git プラットフォームを接続する](git.md) | 新しいリポジトリを作成してアクセスする権限を持つ Git 接続 |
| [ランタイムを接続する](shared-runtimes.md) | サインイン済みのコーディングツールを備えた、オンラインの runner |
| [エージェントを設定する](agents.md) | 利用できるモデル、作業内容の説明、コーディネーターエージェントの選択 |
| [最初のプロジェクトを作成する](new-project.md) | NocoBase アプリとして初期化された新しいリポジトリ |
| [チェックとプレビューを設定する](ci.md) | エージェントのセルフチェックまたは CI と、変更をプレビューする方法 |

管理者の認証情報と暗号化キーは、アクセスを制限した設定ファイルに保存します。エージェントにはその場所だけを報告させ、値は表示させないでください。一度きりのインストール用認証情報も、共有の記録に残さないでください。

チェックとプレビューの準備ができたら、[メンバーを招待します](invite.md)。メンバーは [はじめる](../join/index.md) に従ってサインインし、要件を出します。

## 結果を確認する

1. 管理者として Studio にサインインします。
2. ランタイムがオンラインで、コーディングツールがサインイン済みであることを確認します。
3. 有効なエージェントと、コーディネーターエージェントのメインとフォールバックの選択を確認します。
4. 最初のプロジェクトを開き、初期化が完了してリポジトリにアプリが含まれていることを確認します。
5. 業務のタスクを作成できることを確認します。

Studio を再起動して、プロジェクトと設定が保持されていることを確認します。デプロイ先、バージョン、バックアップの保存先、未完了の設定をエージェントに書き残してもらいましょう。
