title: API keys
description: Grant limited access to CI, scripts, and integrations.

| Type | Managed under | Identity and purpose |
| --- | --- | --- |
| Organization key | Settings › API keys | Independent of members; for CI and long-running integrations |
| Personal key | Account settings › API keys | Acts as its owner; for personal scripts |

Organization keys hold only their selected permissions. Personal keys are also limited by their owner's current access. For repository CI, use the key generated by [Checks configuration](../configure/checks.md).

## Create a key

1. Select **Create key** and enter a name and purpose.
2. Choose a preset, then narrow it to specific projects or applications as needed.
3. Choose an expiry, which defaults to 90 days.
4. Save the value immediately after creation; it appears only once.

![Create an organization key with limited permissions](https://static-docs.nocobase.com/studio-en-guide-api-keys-20261031.png)

**CI deploy** permits uploads and deployment to selected applications. **CI upload** permits uploads only. **Read only** reads authorized data. You can grant only permissions you hold.

Keys cannot manage other keys or member accounts, or deploy directly to protected environments. Protected deployment requires a request approved by a person.

## Maintain keys

- **Rotate**: preserve the name and permissions, generate a new value, and invalidate the old one immediately. Update CI or scripts at the same time.
- **Disable**: stop access immediately; enable it again if needed.
- **Delete**: revoke access while preserving the key's identity in past records.

Organization key history records creation, permission changes, rotation, and disabling. Repository-managed keys show their source. Disabling one affects that repository's pipeline reporting and deployments.

Remove the personal-key creation permission from a role to prevent new personal keys. Existing keys remain available to inspect and revoke.
