The knowledge base stores material written or uploaded by members. Agents read it within the user's permissions. Lessons learned during development belong in [Project memory](project-memory.md).

## Choose a knowledge space

| Space | Purpose | Maintained by |
| --- | --- | --- |
| System knowledge | Policies, terminology, and background shared across projects | Administrators |
| Project knowledge | Project requirements, business rules, and attachments | Project leads and authorized members |

Open a project's **Knowledge** tab. Project work can reference both project knowledge and accessible system knowledge.

![Organize business material in the project knowledge base](https://static-docs.nocobase.com/studio-en-guide-knowledge-20261031.png)

## Add and maintain material

1. Select a space or folder.
2. Create a Markdown article or upload a file.
3. Review the saved content and mark it as verified when appropriate.

Text can be extracted from PDF, Word, Excel, PowerPoint, CSV, text, Markdown, and JSON files for search and reading. Images are not processed with OCR. Original files remain available to download. Folders support up to four levels.

Each save creates a version. Archive outdated material to exclude it from search; restore it when needed.

## Save task attachments

An Agent can suggest saving a task attachment to the knowledge base. The uploader or task owner can choose a destination if they have editing permission there. Files useful only to the current task can stay with the task.

## Control access

Set access for spaces, folders, articles, and files. Entries inherit access from their parent by default. Grant access to members, roles, or project members.

Members with editing permission maintain content directly. Otherwise, request changes in a task comment. Management permission controls access rules. Agents can read only what the person requesting the work can access.
