**Acceptance standards** provides shared requirements for quality plans. Select a project to see system standards and project-specific standards. Project leads and members with project management permission can maintain them.

![System standards and project acceptance requirements](https://static-docs.nocobase.com/studio-en-guide-standards-20261031.png)

## System standards

System standards cover business behavior, error handling, access and data consistency, test layers, and test directory conventions. Enable or disable them for the project.

They define verification principles. The Agent determines concrete functions and checkpoints within the plan's scope.

## Add a project standard

Enter a name and describe an observable requirement. For example:

> Every tier C supplier order requires purchasing manager approval, even when its amount is below the normal approval threshold.

Later plans can use the saved standard. Replace vague requirements such as “works correctly” or “well tested” with behavior that can be checked.

## How standards apply

The Agent reads enabled standards when proposing a plan and confirms them with its goal and scope. Started plans retain their agreed requirements for traceability.

Changing project defaults does not rewrite existing reports. To revise an existing plan, confirm the change and its effect on current work in the plan's conversation.
