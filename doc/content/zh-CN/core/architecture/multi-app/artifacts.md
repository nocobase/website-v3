## 应用包、版本与构建产物的关系

应用包由子应用项目的 `package.json.name` 标识；版本标识一次不可变交付；构建产物是实际上传的部署归档。同一个应用包可以发布多个版本，一个版本可以创建多个实例。

用于创建项目的 `sub-app` 模板与这里的构建产物不同。部署时选择的是已经构建并发布的版本，不是开发脚手架。

## 上传并发布构建产物

在子应用项目中使用 CLI，可以一次完成构建、上传和发布：

```bash
pnpm nocobase deploy artifact upload --build --yes
```

首次上传会按应用包名创建记录。也可以执行 `pnpm build --tar`，取得 `storage/exports/dist.tar.gz`，在主应用的**系统设置 → 部署管理 → 构建产物**中选择**上传构建产物**，按界面核对包名、版本和校验结果后提交。

上传不会创建实例，也不会升级已有实例。版本已存在时，为修改后的代码使用新版本号；不要删除并覆盖旧内容来复用版本号。

![上传后的 child-app 应用包展示已发布版本及关联实例数量。](/assets/core/multi-app/hd-build-artifacts.png)

## 查看构建平台、运行要求与配置项

打开应用包下的版本详情，检查构建平台、Node.js 要求、数据库驱动、平台 SSO 依赖、配置示例和变量声明。创建实例时，界面根据这些声明提供可配置项。

目标节点必须兼容操作系统、CPU 架构、libc 和运行时要求。缺少所需数据库驱动或插件时，需要在子应用项目中安装、注册并重新构建；修改实例配置不会给归档补装依赖。

归档用于分发代码和运行依赖，不用于分发某个实例的数据库、上传文件、密钥或 `config.yml`。

![版本详情展示构建兼容信息及关联的应用实例。](/assets/core/multi-app/hd-artifact-version.png)

## 从同一版本创建多个实例

在版本或应用包的更多操作中选择**创建应用实例**，分别设置不同的实例标识、名称和运行节点。为每个实例配置独立数据库及业务参数，平台 SSO 凭据也由平台按实例签发。

发布一次可以部署多次，不需要为每个实例重新构建相同代码。具体创建流程见[管理应用实例](management.md)。

![选择版本、运行节点和数据库后，在提交前核对实例访问地址。](/assets/core/multi-app/hd-create-instance.png)

## 查看版本关联的应用实例

在应用包的**应用实例**页签查看部署情况，进入实例详情核对当前实际版本。存在更新版本只是提示，不代表该实例已经升级。判断升级完成应以实例状态和部署记录为准。

## 弃用、恢复与删除版本

通过版本的更多操作弃用不再推荐使用的版本；弃用不自动停止已经运行的实例。恢复后可以重新使用该版本。

删除前检查实例引用及页面提示。CLI 删除需要显式重复版本号，例如 `artifact delete 0.0.1 --confirm-delete 0.0.1 --yes`；替换为实际目标版本，仅在确定不再需要时执行。服务端的引用和状态校验仍然生效，不能用删除产物代替删除实例。
