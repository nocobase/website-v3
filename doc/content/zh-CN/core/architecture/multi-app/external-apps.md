## 选择接入方式

独立接入适用于继续使用原部署环境的应用。平台登记入口并按所选方式提供登录，不创建 Host 实例，也不接管原应用的数据库、升级或备份。

| 方式 | 适合情况 | 目标应用需要准备 |
| --- | --- | --- |
| Web 链接 | 只希望从工作台打开已有网站 | 可访问的地址，自己的登录和访问控制 |
| NocoBase 应用 | 希望 NocoBase 3 应用使用平台登录和应用切换 | 兼容的商业 SSO 插件与可信 HTTPS 地址 |
| Web OIDC 应用 | 第三方应用支持标准 OIDC 登录 | OIDC 客户端及精确回调地址 |

由无限制管理员登记和配置接入。已有 NocoBase 业务系统接入 SSO 前，先阅读[从单应用迁移](migration.md)，确定现有用户和权限如何保留。

## 添加 Web 链接

1. 打开**应用实例 → 接入应用**。
2. 填写名称，选择 Web 类型和链接登录方式。
3. 填写目标完整地址，例如 `https://inventory.example.com/reports?view=monthly`，然后保存。
4. 在**访问授权**中为需要看到入口的用户授予成员资格。

链接可以包含路径和查询参数。登记地址只接受 HTTP/HTTPS，不接受内嵌用户名、密码或片段标识。

用获授权用户从工作台打开入口，确认进入正确页面，路径和查询参数保留。如果目标网站要求登录，用户仍需使用该网站的登录方式；添加链接不会自动建立统一登录。

平台控制链接是否向用户显示，不控制目标服务器。用户通过书签直接访问时，仍由目标网站检查权限。

## 接入 NocoBase 应用的统一登录

目标应用需要安装和注册兼容的 `@nocobase/app-plugin-platform-sso`，并保留原有认证和业务权限。具体开发位置见[开发新的子应用](development.md#开发新的子应用)。

1. 在**接入应用**中选择 NocoBase 类型，填写名称和包含部署前缀的应用根地址，例如 `https://inventory.example.com/sub/`。地址不带查询参数。
2. 保存接入，取得平台提供的登录接入参数。
3. 由目标应用负责人配置实际 issuer、应用标识、客户端凭据、公网源和挂载路径，核对回调与平台登记一致。
4. 部署或重启目标应用，使新配置生效。
5. 授予测试用户成员资格，从工作台进入应用，确认平台登录完成后能访问预期业务。

配置项含义见[统一登录配置](single-sign-on.md#为子应用接入统一登录)。目标应用服务器需要能够访问平台的 discovery、token、JWKS、userinfo 和身份检查接口。

**查看接入指令**会遮盖密钥，**复制接入指令**包含完整密钥。只通过安全渠道交给可信应用开发者或 Coding Agent，不放入仓库、日志或公开会话。重新生成指令仍使用已有密钥，不代表已经轮换凭据。

## 接入第三方 OIDC 应用

先确认第三方应用支持授权码流程、PKCE S256、`client_secret_basic`，以及标准的 issuer、audience 和签名校验。

1. 在第三方应用中查明其 OIDC 回调地址。
2. 在平台登记 Web OIDC 应用，填写入口和精确的 HTTPS 回调地址。
3. 将平台提供的 issuer、客户端标识和密钥安全配置到第三方应用。
4. 在第三方应用中设置用户关联和业务角色规则，再按其要求重启或重新部署。
5. 为测试用户授予平台成员资格，完成一次真实浏览器登录。

回调使用第三方应用实际提供的地址，不追加 NocoBase 的登录路径。用户映射、已有账号关联、业务角色和会话撤销由第三方应用负责，平台不会自动同步组织或转换其业务权限。

## 授权用户并检查访问

创建接入或拥有平台管理员身份，都不自动获得应用成员资格。对需要访问的具体用户授权，并按接入方式检查结果：

| 接入方式 | 检查内容 |
| --- | --- |
| Web 链接 | 获授权用户能看到入口，打开后地址正确；未获授权用户看不到入口 |
| NocoBase SSO | 获授权用户能完成登录，未获授权用户不能通过平台身份进入；业务读写符合子应用角色 |
| 第三方 OIDC | 能完成认证并关联到正确账号，目标应用的业务权限和会话策略生效 |

NocoBase 子应用降权或撤权时，还应检查后续访问和直接业务 API。完整行为见[撤销访问与退出登录](single-sign-on.md#撤销访问与退出登录)。

## 停用或更换应用入口

停用接入后，平台隐藏入口并拒绝新的平台访问，但不停止外部服务器，也不删除成员记录或业务数据。

NocoBase 子应用会在后续平台会话检查中复核访问资格；第三方应用是否结束已有会话取决于自己的实现。Web 链接停用后，目标网站的直接访问仍由它自己控制。

当前接入地址和类型不能原地修改。需要更换时，安排停用旧入口并重新登记；使用 SSO 的已有应用还需要处理客户端回调和账号绑定，见[保留用户身份与业务权限](migration.md#保留用户身份与业务权限)。
