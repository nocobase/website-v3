---
title: 接入独立部署的子应用
description: 保留子应用原有部署，将其接入主应用工作台，配置统一登录并管理用户访问。
---

子应用已经部署在自己的服务器上时，可以直接接入主应用，不必上传部署包或创建托管实例。主应用提供工作台入口和统一登录，子应用的部署、升级和备份仍由其负责人维护。

与托管实例自动获得登录配置不同，独立部署的子应用需要在登记后，由应用负责人把 SSO 配置应用到自己的项目和运行环境。

## 在主应用登记子应用

使用拥有完整管理权限的账号，在主应用打开**应用实例 → 接入应用**（Connected applications），点击**接入应用**（Connect application）。

1. 填写应用名称。
2. 应用类型选择**独立 NocoBase 3 应用**（Independent NocoBase 3）。
3. 填写完整应用入口，例如 `https://crm.example.com/`。如果应用部署在 `/crm/` 下，地址也要包含该路径，不带查询参数。
4. 登录方式选择**平台统一登录**（Platform sign-in），保存。

![登记独立应用的名称、访问地址和登录方式](/assets/core/multi-app/zh-CN/external-connect.png)

主应用和子应用应使用可访问的 HTTPS 地址。受控本地或内网环境使用 HTTP 时，先在主应用[允许对应地址](environments.md#添加部署环境)。

如果只需要工作台入口而不需要统一登录，可选择 Web 应用及链接方式；用户仍使用原网站的账号登录。支持 OIDC 的第三方应用则选择 Web 应用及统一登录，并填写该应用提供的准确回调地址。

## 为子应用配置统一登录

登记完成不代表子应用已经完成登录接入。打开接入应用的详情，在登录接入区域选择**复制接入指令**（Copy setup instructions），交给负责该子应用的开发者或可信 Agent。

在子应用项目目录开启 Agent 会话，提供接入指令，并说明现有用户和业务权限如何保留。Agent 需要完成平台登录、业务角色和应用切换入口的接入；具体准备与托管应用相同，见[准备子应用部署包](templates.md#准备子应用部署包)中的登录接入说明。独立应用不需要执行该节的托管打包流程。

**查看接入指令**会遮盖密钥，复制的内容包含完整密钥。只交给可信接收方，不提交到 Git 或公开对话中。

手动配置时，将接入指令中的 `serverEnvironment` 写入子应用服务器的私有环境配置：

| 配置 | 填写方式 |
| --- | --- |
| `PLATFORM_SSO_ISSUER`、`PLATFORM_SSO_APP_ID`、`PLATFORM_SSO_CLIENT_ID`、`PLATFORM_SSO_CLIENT_SECRET` | 使用主应用为此应用生成的值，不复制其他应用的配置 |
| `PLATFORM_URL` | 使用指令给出的主应用入口，包含 `/main/` 等路径 |
| `APP_PUBLIC_ORIGIN`、`APP_BASE_PATH` | 与登记的子应用地址保持一致 |

完成后重新部署或重启子应用。子应用服务器需要能访问主应用的登录服务，登录回调必须与接入指令中的 `callbackUrl` 一致。

接入已有业务系统时，保留原数据库、用户和业务权限，不要重新初始化。平台账号与已有本地账号不会仅凭相同邮箱自动合并；需要沿用已有账号时，应先由开发者确认身份关联方式，并保留本地管理员登录。

第三方 OIDC 应用不安装 NocoBase 登录插件，按其自身的登录设置填写接入指令中的地址和客户端凭据。

## 授权用户并验证访问

1. 在接入应用的**访问授权**中添加用户，选择查看或编辑权限。登记应用不会自动授权已有用户。
2. 用获授权用户登录主应用，从工作台点击该应用，确认能进入业务页面，不需要再次输入密码。
3. 检查查看、编辑操作是否符合子应用的业务权限，再打开[应用切换入口](management.md#从工作台进入与切换应用)，确认可以切换应用并返回工作台。

主应用管理员也需要单独获得应用访问资格。验证时再使用一个未授权账号，确认它不能通过主应用登录该子应用。

## 维护或停用接入入口

在接入应用详情中管理用户授权。不再需要某位用户访问时，撤销其访问资格；不再接入整个应用时，选择停用。

停用后，主应用不再显示该入口，也不再允许通过平台身份进入，但不会停止外部服务器或删除业务数据。Web 链接的直接访问始终由目标网站控制。

现有接入的地址和类型不能原地修改。需要更换时，先准备新的接入和登录配置，确认用户访问正常后停用旧入口。不要直接覆盖已有账号绑定或复制旧应用密钥；重新生成接入指令也不代表密钥已经轮换。
