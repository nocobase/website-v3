以下操作适用于由 App Host 托管的应用，需要相应管理页面、操作和数据范围权限。只拥有应用访问资格的用户不能因此管理实例。外部系统的部署和启停由其负责人处理，见[接入独立应用](external-apps.md)。

## 创建模板并发布版本

先准备适合目标运行环境的[子应用部署归档](deployment.md#构建部署归档)，并确认平台的 Host 环境可用。

1. 打开**应用模板**，创建一个业务模板，或选择已有模板。
2. 上传子应用的 `dist.tar.gz`，核对识别出的应用包名和版本。
3. 发布版本，保留对应归档及校验和，供后续部署和排查使用。

同一模板的后续版本应保持应用包名稳定。已发布版本不可覆盖；代码改变后，构建并发布新版本。此时已有实例仍运行原来的版本。

停用模板会阻止新的发布和实例创建，但不会删除已发布版本或既有实例。

## 创建实例并授予访问权限

1. 在**应用实例**中填写名称和唯一标识。
2. 选择已发布的模板版本及部署环境，完成环境要求的审批。
3. 跟踪操作和部署结果，确认实例的实际版本、运行状态及访问地址。
4. 由无限制管理员在**访问授权**中为需要进入的用户授予成员资格。

实例标识用于运行路径，显示名称则用于识别应用。创建时应选定稳定的标识。

启用平台身份集成后，新实例会登记自己的登录客户端，但不会自动允许所有平台用户进入。用获授权的普通用户从工作台打开实例，确认能够登录并访问所需业务；业务权限另由子应用管理。

## 查看状态与修改配置

查看实例时，区分以下信息：

| 信息 | 含义 |
| --- | --- |
| 目录是否启用 | 平台是否提供该入口，还需结合用户成员资格判断可见性 |
| 实际运行状态 | 实例当前是否已启动、停止或发生异常 |
| 当前版本 | 实际部署的版本 |
| 目标版本及操作记录 | 正在申请或执行的变更，不代表变更已经完成 |

在实例配置中修改支持的标题、默认语言等选项后，进入应用确认生效。基础设施配置和密钥由授权的部署流程管理，不通过实例展示配置编辑。

查看初始管理员凭据需要实例配置权限和相应数据范围，且不向非用户或受限密钥调用者开放。该功能只返回最初生成的凭据，不会显示后来修改的密码。凭据仅用于授权的管理操作，不写入工单、日志或 URL。

## 启动、停止与重启实例

| 操作 | 结果 | 操作后检查 |
| --- | --- | --- |
| 启动 | 运行已停止的实例 | 应用可访问，原有业务数据仍在 |
| 停止 | 停止运行，保留持久化数据 | 直接访问不会使实例重新启动 |
| 重启 | 停止后重新启动 | 应用恢复可用，关键业务正常 |

等待操作完成后再检查运行状态。停止不删除数据库和附件，也不构成数据备份。因空闲而休眠的实例可以按 Host 策略被请求唤醒，这与管理员明确停止不同。

## 升级指定实例

升级前备份数据，记录当前版本，并确认新版本的数据库迁移和运行环境要求。

1. 构建并发布真实的新版本。
2. 选择需要升级的实例和目标版本，提交升级操作。
3. 查看部署记录，等待当前版本更新为目标版本。
4. 检查已有业务记录、附件、登录和权限，以及本次新增或修改的功能。
5. 确认未选择的实例仍保持原版本。

选择旧版本前，需要确认旧代码能够使用当前数据库。代码版本回退不会自动撤销已经执行的数据库迁移。

## 归档与恢复实例

归档适用于暂时不再使用但需要保留的实例。归档会停止实例，保留数据、文件和配置，并阻止平台身份进入。

恢复归档后，成员关系仍保留，但还需要明确启动实例。启动后检查原业务数据和用户访问。恢复归档只是改变实例的管理状态，不是恢复数据库备份。普通管理流程不提供永久删除。

## 处理失败或未完成的操作

遇到超时、失败或中断时，先在该实例的操作记录中检查：

- 失败发生在哪个阶段，是否已经产生部署或审批请求。
- 操作和部署标识，以及实际执行结果。
- 是否仍有未完成操作占用实例。

请求超时不一定表示部署没有执行。结果不明确时，使用受支持的协调恢复操作核对已有部署，再决定是否重试；不要重复创建实例或直接修改内部状态。

自动化管理通过带合法认证的 `<应用路径>/api/swagger` 查看接口要求。重试同一次请求时保留原提交标识；确认需要发起新的恢复操作时使用新的标识，并遵守接口的版本检查和确认要求。

数据库迁移失败时，保留错误和操作标识，先判断当前代码与数据是否兼容。需要恢复数据时，按[备份与恢复数据](deployment.md#备份与恢复数据)恢复匹配的代码、数据库、文件和配置。
