## 什么时候使用多应用

当多个业务系统需要独立管理数据、配置和发布版本，同时又希望提供统一入口与登录体验时，可以采用多应用架构。

| 业务需求 | 使用方式 |
| --- | --- |
| 多家门店使用相同的库存功能，各自保存数据 | 为每家门店运行独立的库存应用，分别管理数据和安排更新 |
| 客户管理与采购管理由不同团队维护，发布节奏不同 | 分别开发和部署应用，通过同一个工作台访问 |
| 已有系统继续运行，希望增加统一入口 | 将系统加入工作台，按需接入统一登录，保留原有部署方式 |
| 多个入口共用同一套应用、数据和版本 | 使用[多门户](../multi-portal/create-app.md)，不必拆成多个应用 |

平台既可以部署和管理子应用，也可以接入已经独立运行的系统。应用之间不会自动共享业务数据；需要交换数据时，通过 API 和相应权限进行集成。

## 主应用与子应用

**主应用**提供工作台、应用管理和统一登录。用户登录后，从工作台进入自己有权访问的应用。

**子应用**承载具体业务，例如客户管理、库存管理或费用管理。每个子应用拥有自己的页面、数据、配置和业务权限，可以独立开发、部署和更新。

![工作台显示当前用户可以进入的客户与费用应用](/assets/core/multi-app/zh-CN/workbench.png)

主应用决定用户可以进入哪些应用，子应用决定用户进入后可以做什么。例如，员工获准进入库存应用后，能否调整库存仍由该应用的业务权限决定。主应用管理员不会自动成为子应用管理员。

子应用可以使用自己的登录方式，也可以接入主应用的统一登录。统一登录不意味着共享用户表、业务数据或所有权限。

## 使用前提

多应用需要兼容版本的商业插件、有效商业许可和包下载权限。项目模板不包含商业插件的实现，也不提供商业授权。

| 插件 | 使用位置 | 提供的能力 |
| --- | --- | --- |
| `@nocobase/app-plugin-multi-app` | 主应用 | 应用模板、版本、实例和外部入口管理 |
| `@nocobase/app-plugin-identity-provider` | 主应用 | 平台身份服务、OIDC 客户端和成员授权 |
| `@nocobase/app-plugin-platform-sso` | 子应用 | 平台登录、会话检查及应用切换 |

新项目从[快速开始](quickstart.md)入手；已有 NocoBase 3 应用从[接入独立部署的子应用](external-apps.md)选择接入方式。
