## 平台登录与子应用账号

用户登录平台后，可以进入自己获准访问的子应用。平台会话有效时，浏览器完成认证跳转，无需再次输入平台密码；子应用随后建立自己的会话。

平台与子应用不共享用户表或 Cookie。子应用通过 issuer（身份提供方标识）和 subject（身份源中的用户标识）关联账号，不会自动按相同邮箱合并用户。接入已有业务系统前，应先确定[用户身份保留方案](migration.md#保留用户身份与业务权限)。

## 为子应用接入统一登录

多应用模板中的 Main 已集成身份提供方，默认 Sub 已集成平台 SSO、登录页面和应用切换器。其他 NocoBase 应用需要先完成[插件接入](development.md#开发新的子应用)，再配置登录参数。

接入前准备可信 HTTPS 地址和非回环主机名，为每个应用登记独立客户端及精确回调地址。`https://localhost` 不满足 Web 回调要求。反向代理可以终止 TLS，再通过受保护的内部网络转发到后端。

| 部署方式 | 配置来源 |
| --- | --- |
| 托管实例 | 平台登记客户端，并通过接入和秘密变量机制交付实例配置 |
| 独立 NocoBase 应用 | 在平台登记接入，由应用负责人配置运行环境，见[接入独立应用](external-apps.md#接入-nocobase-应用的统一登录) |
| 第三方 OIDC 应用 | 将平台参数配置到第三方应用自己的 OIDC 客户端 |

NocoBase 子应用使用以下配置：

| 配置 | 含义 |
| --- | --- |
| `PLATFORM_SSO_ISSUER` | 平台认证服务的实际 issuer，不是工作台首页，不带尾部斜杠 |
| `PLATFORM_SSO_APP_ID` | 平台登记的应用标识 |
| `PLATFORM_SSO_CLIENT_ID` | 此应用的客户端标识 |
| `PLATFORM_SSO_CLIENT_SECRET` | 仅在服务端使用的客户端密钥 |
| `PLATFORM_URL` | 返回平台的导航地址，包含平台部署路径 |
| `APP_PUBLIC_ORIGIN` | 子应用公网源，不含路径 |
| `APP_BASE_PATH` | 子应用挂载路径 |
| `PLATFORM_SSO_IDENTITY_NAMESPACE` | 保留账号绑定使用的身份命名空间，默认使用当前 issuer；平台迁址时见[迁移说明](migration.md#保留用户身份与业务权限) |

客户端密钥通过安全的运行环境配置交付，不进入浏览器、源码或构建归档。子应用服务器需要能够访问平台身份服务，回调地址必须与登记值一致。

没有配置 issuer 时，子应用保留本地认证；配置 issuer 后缺少其他必要凭据会导致配置失败。修改启动配置或解决身份服务发现问题后，需要重启或重新部署子应用。已有实例接入 SSO 时，先登记客户端，再部署支持 SSO 的版本。

## 授予应用访问资格

由无限制管理员在应用的**访问授权**中，为具体用户授予成员资格。平台管理员也需要明确的成员资格，才能通过 SSO 进入子应用。

获授权用户可以在工作台找到相应入口。托管实例还需要处于可运行状态，且没有阻止进入的未完成部署。入口未出现时，先检查成员资格、实例状态和部署记录。

授权后，用该用户打开子应用，确认浏览器完成登录并进入预期页面。访问需要登录的深链接时，登录完成后应返回原页面。

## 配置子应用业务权限

成员资格决定用户能否进入应用，业务角色决定进入后能做什么。平台的 `reader`、`editor` 需要由子应用映射为具体权限，不是适用于所有业务的固定权限集。

例如，在库存应用中，可以将只读成员映射为库存查询权限，将编辑成员映射为库存维护权限，但不授予用户管理或系统配置权限。

角色权限可能来自多个来源。将平台成员降为只读，不会抵消另一个业务角色授予的写权限。配置映射时，应移除已失效的 SSO 授权，同时保留用户独立获得的合法角色。

用只持有所需角色的普通用户检查页面按钮和直接 API 请求。隐藏编辑按钮不能代替服务端拒绝未授权写入。

## 撤销访问与退出登录

撤销成员资格或禁用用户后，NocoBase 子应用会在后续平台会话检查中拒绝访问。已经处理中的请求不会追溯撤销。平台身份服务不可用时，平台身份访问也会被拒绝。

退出子应用只结束当前子应用的会话，不会同时退出平台和其他子应用。退出后停留在 `/login?signedOut=1`，由用户主动选择再次通过平台登录。当前不提供全平台联动退出或组织同步。

第三方 OIDC 应用自行管理已有会话。平台撤权后，它是否立即结束已有会话，取决于该应用的实现，不能直接套用 NocoBase 子应用的会话检查行为。

## 使用本地恢复账号

为子应用保留一个妥善管理的本地恢复管理员。当平台身份服务不可用或 SSO 配置错误时，可通过子应用的应用内路径 `/login?auth=local` 登录；实际访问地址需要包含该应用的部署前缀。

本地恢复登录不依赖平台会话检查，但也不会因此获得平台应用目录。上线前确认该账号可用，将凭据保存在授权的凭据管理系统中，并限制使用人员。
