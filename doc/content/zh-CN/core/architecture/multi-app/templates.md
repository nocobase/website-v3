title: 管理应用模板

---

应用模板用来保存一个子应用的可部署版本。例如，将客户管理应用上传为模板后，可以为不同团队创建各自的客户管理实例；它们使用相同的业务功能，但独立保存数据和配置。

主应用的**应用模板**页面可以查看模板的最新版本和实例数量。这里的模板用于部署已有应用，不是创建源码项目时选择的 `default` 项目模板。

![应用模板列表展示已发布版本及使用该模板的实例数量](/assets/core/multi-app/template-list.png)

## 准备子应用部署包

在子应用项目中完成业务开发，确认应用可以正常运行，再打包交给主应用。主应用不需要保存子应用源码，两个项目可以使用独立的 Git 仓库。

**准备统一登录和应用切换。** 子应用需具备平台登录能力，才能使用主应用在部署时自动提供的 SSO 配置。尚未接入的项目，先在子应用目录注册插件：

```bash
pnpm nocobase plugin register @nocobase/app-plugin-platform-sso --dry-run
pnpm nocobase plugin register @nocobase/app-plugin-platform-sso
```

注册后，按项目内同步的 `nocobase-app-plugin-platform-sso` Skill 完成登录页面、业务权限和应用切换入口的接入。也可以在子应用目录向 Agent 提出需求：

```prompt
请让这个客户管理应用支持主应用统一登录，并在侧栏提供切换应用和返回工作台的入口。
只读用户可以查看客户，编辑用户可以维护客户，但不能管理用户或系统设置。保留本地管理员登录，供统一登录不可用时恢复访问。
```

托管部署时，主应用会自动登记登录客户端并向实例提供登录配置，不需要把客户端密钥写进源码或部署包。

**构建部署包。** 在子应用根目录执行：

```bash
pnpm build --tar
```

产物为 `storage/exports/dist.tar.gz`。部署包需匹配实际运行环境的操作系统、CPU 架构、libc 和 Node.js 版本；跨机器交付时，按[构建部署包](../../tutorials/deploy-with-app-installer.md#构建部署包)指定目标参数。不要将开发数据库、上传文件或实例密钥打入共用部署包。

## 创建模板并上传部署包

1. 在主应用打开**应用模板**（Templates），点击**创建模板**（Create template）。
2. 填写名称和说明，选择已经检查通过的[部署环境](environments.md)。
3. 创建后进入模板详情，打开右上角操作菜单，选择**上传产物**（Upload archive），上传子应用的 `dist.tar.gz`。

![创建应用模板时填写名称、说明并选择部署环境](/assets/core/multi-app/template-create.png)

上传完成后核对识别出的应用包名和版本。上传只保存部署包，还需要发布版本，才能用它创建实例。

## 发布和维护版本

打开模板操作菜单，选择**发布版本**（Publish version），从已上传的产物中选择要发布的版本并确认。

![模板操作菜单提供上传、发布和退役入口](/assets/core/multi-app/template-actions.png)

发布成功后，版本出现在**已发布版本**（Published versions）中。选择一个版本，即可[创建托管实例](management.md#创建实例并授权访问)。

![已发布版本可用于创建新的应用实例](/assets/core/multi-app/template-versions.png)

更新业务功能时，在原子应用项目中修改代码、更新 `package.json` 的版本号，再重新构建、上传并发布。保持应用包名不变，不覆盖已经发布的版本。

发布新版本不会改变现有实例。各实例可以继续使用原版本，也可以由管理员[分别升级](management.md#升级归档与恢复)。

## 停用不再使用的模板

在模板操作菜单中选择**退役模板**（Retire template），核对目标后确认。退役后不能继续发布版本或创建新实例，已有实例及其数据不会因此删除或停止。

需要停止某个业务应用时，应操作对应的[应用实例](management.md#修改配置与管理运行状态)，而不是退役模板。
