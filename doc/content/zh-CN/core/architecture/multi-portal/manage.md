使用具有 `unrestricted` 权限的管理员账号，打开 **系统设置 → 门户管理**。页面展示应用已注册的门户，可搜索名称、筛选安装状态，并安装、进入或卸载门户。

门户管理操作的是应用已经包含的代码，不是从 npm 下载新门户的商店。新增门户源码后，需要完成 Client/Server 注册，并重启开发服务；生产环境需要重新构建、部署应用。

## 安装门户

1. 在门户管理中找到未安装的门户，点击 **安装**。
2. 等待依赖检查、各连接的迁移与 seed、门户启动完成。
3. 确认状态变为已安装，再进入门户。

生成的门户默认未安装。安装前必须具备所需数据库连接与驱动，并先安装该门户声明的依赖门户。单独生成源码或注册包，不会让门户自动可用。

安装过程中的门户不可用。数据库任务未完成或启动失败时，不会把门户当作已安装展示。

## 卸载与重新安装

卸载会关闭门户入口并停止它登记的运行资源，保留业务数据、配置记录和迁移执行历史。它不删除源码或 npm 依赖，也不是删除业务数据库。

如果另一个已安装门户依赖它，应先处理依赖方；系统会阻止不安全的卸载。确认卸载前，检查相关业务是否仍在使用该门户。

重新安装时，系统按执行历史处理尚未完成的数据库任务，已有业务数据继续保留。不要删除历史迁移文件，也不要修改已执行迁移来让重新安装“从头开始”。

## 查看状态并处理失败

| 状态 | 含义与处理 |
| --- | --- |
| 未安装 | 代码已经注册，但门户尚不可用 |
| 正在安装／正在升级 | 正在检查依赖、执行数据库任务或启动资源，等待完成 |
| 已安装 | 门户已完成激活，可以按权限访问 |
| 正在卸载 | 正在停止门户资源，等待完成 |
| 失败 | 根据显示的失败阶段与服务端日志定位原因，修复后重试 |

常见失败阶段包括依赖检查、数据库初始化、门户启动或停止。数据库失败时，核对连接配置、账号权限、迁移与 seed 的执行情况；启动或停止失败时，检查门户服务及其资源清理逻辑。`start(onStop)` 中取得的资源应登记对应的清理函数。

多连接安装可能只完成了部分任务，重试按每个连接的执行历史继续，不保证把已经成功的连接整体回滚。应用重启也会尝试恢复已接纳但未完成的操作。不要通过手动改安装状态或删除执行历史来跳过失败。

同时有其他管理员操作时，页面可能提示门户已被修改；刷新获取最新状态后再决定操作，不要反复提交旧状态。

## 随应用升级

门户不独立选择运行版本，代码随宿主应用一起构建、发布和升级。已安装门户在应用启动或执行 `pnpm nocobase db apply` 时参与待执行的数据库升级；未安装门户不会因此自动安装。

通过启动执行数据库任务时，各连接需要启用相应的迁移和 seed `autoRun` 配置；如果选择显式执行数据库计划，必须覆盖门户所需的完整任务。升级失败的门户保持不可用，应先解决失败原因再恢复。

即使门户已经卸载，也应保留其历史迁移和 seed 源码，以供校验和重新安装。发布前验证升级路径，备份业务数据，并按[发布应用版本](../../deployment/publish-app-release.md)和[升级 NocoBase](../../developing-apps/upgrade-nocobase-core.md)处理应用与模板的更新。
