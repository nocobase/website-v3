## 打开门户管理

使用有门户管理权限的管理员账号登录，打开 **系统设置 → 门户管理**。门户管理的查看、安装和卸载是三项单独的权限，与门户的访问权限分开。

列表展示应用已注册的门户、说明和安装状态，可以按名称或说明搜索，也可以按 **全部、已安装、未安装** 筛选。

门户管理操作的是应用中已经包含的门户代码，不会从 npm 下载新门户。需要新增门户时，先按[快速开始](quickstart.md#生成第一个门户)生成并注册，再重启开发服务；生产环境需要重新构建和部署。

![门户管理列表，展示门户名称、说明、安装状态与操作入口](/assets/core/multi-portal/manage/list.png)

每行右侧的 **…** 菜单提供操作，内容随门户状态变化：

| 门户状态 | 可用操作 |
| --- | --- |
| 未安装 | 安装 |
| 已安装 | 进入、卸载 |
| 失败 | 重试 |
| 正在安装、升级或卸载 | 等待完成，暂不能操作 |

## 安装与进入门户

1. 找到未安装的门户，打开 **… → 安装**。
2. 等待安装完成。系统会检查依赖，执行门户的数据库任务，再启动门户。
3. 状态变为 **已安装** 后，打开 **… → 进入**。

新生成的门户默认未安装。安装前，应用要先配置好门户所需的数据库连接和驱动；门户依赖其他门户时，先安装被依赖的门户。

安装后，管理员可以从我的门户进入。其他成员要等管理员在角色中开放门户和页面后才能看到，见[门户权限](access.md)。

![已安装门户的操作菜单](/assets/core/multi-portal/manage/actions.png)

## 卸载与重新安装

1. 在已安装门户的 **…** 菜单中选择 **卸载**。
2. 阅读确认提示后点击 **卸载**；点击 **取消** 可以保留当前状态。
3. 等待状态变为 **未安装**。

![卸载门户确认框，提示保留数据和配置](/assets/core/multi-portal/manage/uninstall.png)

卸载会关闭门户入口并停止门户的运行资源，**保留业务数据、配置和数据库任务的执行历史**，不会删除源码或数据库。成员再打开门户地址时，会看到门户未安装的提示。另一个已安装的门户依赖它时，系统会阻止卸载，需要先卸载依赖它的门户。

需要恢复使用时，从 **… → 安装** 重新安装。系统按执行历史处理未完成的任务，已有数据继续保留，不会重置为全新门户。

## 查看状态与重试失败操作

安装、升级或卸载期间，门户暂不可用。状态显示 **失败** 时，查看列表中的失败阶段，并结合服务端日志定位原因：

| 失败阶段 | 检查什么 |
| --- | --- |
| 依赖检查失败 | 所需门户是否已安装，是否还有已安装的门户依赖当前门户 |
| 数据库初始化失败 | 连接和驱动是否配置正确，数据库账号权限是否足够，迁移或 seed 是否出错 |
| 门户启动失败、门户停止失败 | 门户服务是否报错，资源能否正确启动和释放 |

修复原因后，打开 **… → 重试**。重试会继续之前的安装或卸载，并依据各数据库连接的执行历史处理任务。多个连接的操作可能已完成一部分，不保证整体回滚；不要手动修改安装状态、删除执行历史或改写已执行的迁移来绕过错误。

页面提示门户已被修改时，先刷新获取最新状态，再决定是否操作。应用重启时，也会尝试恢复已经开始但未完成的操作。

## 随应用升级与部署

门户代码随应用一起构建、发布和升级，门户管理不提供单独选择门户版本的操作。

- **数据库升级**：已安装的门户在应用启动或执行 `pnpm nocobase db apply` 时执行新增的迁移和 seed；未安装的门户不会因此自动安装。通过启动执行时，相关连接需要开启迁移和 seed 的 `autoRun`；使用显式的数据库计划时，计划要覆盖门户所需的全部任务。
- **部署包**：运行 `pnpm build --tar` 生成部署包，门户会随应用一起打包。导入部署包时会校验门户的地址和图标等信息，不合法时在上传时就会报错。
- **门户地址**：门户发布后保持 `nocobase.portal.key` 不变，否则成员保存的旧链接会失效。
- **历史源码**：即使门户已卸载，也要保留它的迁移和 seed 源码，以便校验和重新安装。

发布前备份数据并验证升级路径，具体步骤见[发布应用版本](../../deployment/publish-app-release.md)。
