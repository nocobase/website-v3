主应用制品、子应用模板制品和实例数据是三类不同内容。部署主应用不会自动发布所有子应用；发布模板也不会自动升级实例。

## 部署主应用与 App Host

先准备主应用和子应用所需的[三个商业插件](overview.md)及兼容依赖，并确定目标操作系统、CPU 架构和 Node.js 运行时。选择实际支持该制品的 Releases 部署环境，不把示例的单 Host 部署当作集群调度方案。

主应用本身按[应用部署](../deployment/publish-app-release.md)的流程构建。例如目标为 Linux x64、Node.js 24 时，在主应用目录运行：

```bash
pnpm build --target linux-x64 --node-version 24 --tar
```

部署归档前配置数据库、持久化存储、私有配置和进程管理。显式启用并配置 Releases 的 App Host；注册插件不等于 Host 已启动。以环境检查结果和实际部署验证它能运行子应用。

生产服务运行构建后的主应用，不使用 `pnpm demo` 作为通用启动入口。后者会执行示例模板发布、实例创建和演示成员授权。子应用按照各自的构建流程产生归档，再通过[模板和实例管理](management.md)发布。

## 配置域名、HTTPS 与应用路径

示例使用 `/main/` 访问主应用，托管实例使用 `/<appId>/`。部署时根据实际配置设置反向代理，保留协议、Host、Cookie 和 WebSocket 升级，并限制内部控制端口的访问。

| 配置 | 要确认的内容 |
| --- | --- |
| `APP_PUBLIC_ORIGIN` | 公网源，不包含路径 |
| `APP_BASE_PATH` | 当前应用的挂载路径 |
| 部署环境的公开地址规则 | 每个实例实际可访问的地址，示例使用 `{appId}` |
| `PLATFORM_URL` | 返回平台的导航地址 |
| `PLATFORM_SSO_ISSUER` | 平台身份服务标识，与回调和账号绑定关联 |

地址规则只生成 URL，不配置 DNS、TLS 或代理。检查持久化的部署环境设置，不只看源码中的默认值。

HTTPS 部署应启用安全 Cookie 策略，配置真实的可信来源。不要复制演示的非 Secure Cookie 设置，也不要为绕过登录错误放宽 TLS、回调或 CSRF 校验。

稳定域名应在实例开通和用户登录前确定。变更域名时，把主应用入口、环境地址、回调、子应用变量和已有身份绑定作为一次维护处理，详见[统一登录](single-sign-on.md)。

## 管理制品、持久化数据与密钥

下面是示例使用的存储布局，实际部署以生效配置为准：

| 内容 | 示例路径 |
| --- | --- |
| 主应用构建归档 | `storage/exports/dist.tar.gz` |
| 已上传制品 | `storage/artifacts/` |
| Releases 运行状态 | `storage/releases/` |
| Host 实例代码 | `storage/host/revisions/<appId>/<checksum>/` |
| Host 实例数据及私有配置 | `storage/host/volumes/<appId>/` |

不能把实例卷当作可随时重建的构建缓存。应用若使用外部数据库或对象存储，还必须把这些外部资源纳入备份。

保持加密主密钥和必要的签名配置稳定，并单独安全备份。实例客户端密钥由秘密变量机制交付，不进入源码、构建归档、日志或浏览器配置。只有数据库备份而没有解密所需密钥，可能无法恢复已保存的秘密配置。

## 发布升级与备份恢复

每次升级记录源码版本、制品版本与校验和、目标环境及实例标识。确认备份可恢复、迁移兼容，再升级明确选中的实例，不批量改变未选择的应用。

备份需要协调主应用数据库、子应用数据库、文件、私有配置、密钥以及恢复需要的制品和部署状态。存在写入和后台任务时，安排停写窗口或使用适合数据库的一致性备份方式；不能在写入中的 SQLite 文件上随意复制就认定备份完整。

恢复时使用匹配的代码与配置，保持单一写入方，并保留原本应停止的实例状态。归档恢复只改变管理状态，不恢复历史数据库。旧制品也不保证兼容新迁移后的数据。

升级或恢复后，从真实公网入口验证静态资源、登录、业务读写、附件和权限，再重启检查持久化。选择性升级时额外检查一个未升级实例。

## 排查部署、登录与应用访问故障

| 现象 | 优先检查 |
| --- | --- |
| 创建请求成功，但实例还不能访问 | 操作与部署状态、是否等待审批、Host 环境检查和运行日志 |
| 当前版本与目标版本不同 | 部署是否完成、迁移是否失败，不以目标版本代替运行结果 |
| 页面打开但资源或接口 404 | 挂载路径、代理规则和应用内 URL，是否写死了某个实例前缀 |
| `Discovery fetch failed` 或 `Provider skipped` | 子应用服务器能否访问 issuer 的发现地址；修复后重启以重新初始化 |
| 平台登录后仍被拒绝 | 明确的成员资格、客户端配置、回调和实例状态 |
| 工作台或切换器没有某个应用 | 成员授权、运行状态、未完成部署或独立接入是否停用 |
| 退出子应用后立即重新登录 | 退出是否转到 `/login?signedOut=1`，是否错误地自动发起 SSO |
| 操作超时，结果未知 | 保留操作与部署标识，先协调已有结果，不重复开通或直接清锁 |

主应用、Host、子应用日志分别对应不同阶段。排查时记录失败时间、实例和操作标识，不输出客户端密钥、Cookie 或管理员密码。复杂操作恢复见[管理模板与应用实例](management.md)，历史身份变化见[从单应用迁移](migration.md)。

独立应用的服务故障和数据恢复仍由它自己的部署负责人处理。平台停用接入不会停止其进程，也不会为它建立备份。
