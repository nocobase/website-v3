title: 接入独立应用
description: 将独立部署的 NocoBase、Web 链接或 OIDC 应用接入平台，管理入口与访问授权。
---

独立应用继续使用自己的部署、数据库和运维流程。平台登记它的入口并提供可选的统一登录，不创建模板、Host 实例或部署记录。

## 选择 NocoBase 应用、Web 链接或 OIDC 应用

| 类型 | 平台提供什么 | 应用需要做什么 |
| --- | --- | --- |
| 独立 NocoBase 3 应用 | 统一入口、成员授权和平台登录 | 接入商业插件 `@nocobase/app-plugin-platform-sso`，保留自己的会话和业务权限 |
| Web 链接 | 按授权显示入口 | 自行处理登录和访问控制 |
| Web OIDC 应用 | OIDC 客户端注册和平台访问授权 | 使用自己的 OIDC 客户端，验证令牌并管理会话 |

主应用依赖多应用管理和身份提供方两个商业插件，详见[插件职责](overview.md)。外部网站只是链接时，不会因为平台隐藏入口就禁止用户通过书签直接访问它。

## 登记应用与配置访问入口

当前登记、配置和停用接入需要无限制管理员权限。

1. 在**应用实例 → 接入应用**中创建接入。
2. 填写名称、类型、完整地址和登录方式。
3. 如果是 Web OIDC，填写外部应用提供的精确回调地址。
4. 保存后在登录配置中取得该应用的接入参数。
5. 为需要进入的用户显式授予访问权限。

NocoBase 应用地址应为包含部署前缀的应用根地址，不带查询参数。Web 链接保留原路径和查询参数。地址只接受 HTTP/HTTPS，不接受嵌入用户名密码或片段；统一登录正式入口使用 HTTPS。

当前登记地址和类型不能原地修改。更换地址或接入方式时，需停用旧接入并重新登记；有已有用户时同时安排身份绑定迁移，不以创建重复账号代替。

登录配置提供**查看接入指令**和**复制接入指令**。预览会遮盖密钥，但复制内容包含完整密钥，只能交给可信的目标应用开发者或 Coding Agent，不要提交到代码仓库或公开会话。重新生成指令复用已有密钥，不自动轮换、部署或完成接入。

## 接入独立部署的 NocoBase 应用

在目标应用中完成[子应用插件接入](development.md)，不仅设置变量，还要注册服务端、客户端、配置工厂和原生认证配置。

使用平台提供的应用标识、issuer 和客户端凭据，设置目标应用自己的公网源及路径。重启后确认：

- 子应用服务器能访问平台的 discovery、token、JWKS、userinfo 和身份检查接口。
- 实际 OAuth 回调与平台登记的地址一致。
- 普通成员可以通过平台登录，未授权用户被拒绝。
- 业务角色按目标应用的规则生效，本地恢复账号仍可用。

从应用切换器进入另一应用时，目录请求应发给当前子应用后端，由后端使用自己的客户端凭据获取成员过滤后的目录。无需把平台 Cookie 跨域交给浏览器，也不能让浏览器指定其他用户的 subject。

## 接入第三方 OIDC 应用

先确认外部应用支持以下组合：Authorization Code、PKCE S256、`client_secret_basic`，以及标准 issuer、audience 和签名校验。不支持这些要求的应用不能仅靠填写入口完成统一登录。

在外部应用的 OIDC 设置中填入平台提供的 issuer、client ID 和 client secret，并将外部应用生成的精确回调登记到平台。由外部应用发起登录，不给它强行追加 NocoBase 登录路径。

验证真实登录后的身份、会话和权限，而不只是确认 discovery 可以读取。用户映射、业务角色、已有账号关联和会话撤销由外部应用负责；平台不会自动同步组织或转换它的业务权限。

## 管理访问授权与停用接入

创建接入、拥有平台账号或拥有平台管理员身份，都不会自动获得应用访问权限。授权给明确用户，再以该用户检查工作台入口和实际登录。

**停用接入**会隐藏入口并拒绝新的平台访问，但不会停止外部服务器，也不删除原有成员记录。NocoBase 子应用会在后续会话检查中复核访问资格；第三方应用已有会话是否失效，取决于它自己的实现。

外部应用的升级、数据备份和服务故障仍由其部署负责人处理。登记成功不代表平台接管了这些职责。可参考示例的[独立应用接入说明](https://github.com/nocobase/app-example-multi-app/blob/2e2df1793ec51372ca9b3890b37e9d4748732689/docs/external-apps.md)。
