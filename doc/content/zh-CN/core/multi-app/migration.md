---
title: 从单应用迁移
description: 选择现有 NocoBase 3 应用的多应用接入路线，保留数据与身份，并演练切换和恢复。
---

迁移面向已有业务数据的 NocoBase 3 应用。不要用多应用示例覆盖原项目，也不要把“创建了一个空实例”当作完成迁移。NocoBase 2 到 NocoBase 3 的迁移不在这里的步骤范围内。

## 评估现有应用与保留数据

先记录源应用、目标平台、框架及插件版本、部署方式和可接受的停机时间。三个商业插件的依赖见[概述](overview.md)，版本兼容性确认后再接入。

迁移清单至少覆盖：

| 内容 | 需要保留或确认的事项 |
| --- | --- |
| 业务代码与数据库迁移 | 自定义页面、接口、已执行迁移来源及历史 |
| 数据库与文件 | 业务记录、附件、用户外键、存储位置 |
| 身份与权限 | 用户 ID、外部账号绑定、角色分配、本地恢复管理员 |
| 私有配置 | 加密主密钥、签名配置、客户端密钥及第三方凭据 |
| 后台任务与外部集成 | 定时任务、队列消费者、回调地址、Webhook 和写入方 |

如果核心或模板版本不兼容，先按应用升级流程合并代码并验证保留数据，不直接复制新模板覆盖旧项目。

可以让 Coding Agent 先进行只读评估：

```prompt
这个库存应用已经在使用。我想把它接入多应用平台，但保留现有商品、出入库记录、用户和权限。先比较继续独立部署与迁入平台托管两种方式，告诉我需要准备什么，暂时不要改动系统。
```

## 选择独立接入、迁入 App Host 或改造为主应用

| 路线 | 适合情况 | 主要变化 |
| --- | --- | --- |
| 保留原部署，接入为独立应用 | 希望先统一入口或登录，减少部署改动 | 登记入口；需要 SSO 时增加身份和角色映射 |
| 迁入 App Host | 希望由平台管理版本、启动、停止和升级 | 构建模板制品，迁移运行配置、数据和文件 |
| 在现有应用增加主应用能力 | 现有系统本身应成为管理平台 | 接入管理和身份插件，保留原业务与登录方式 |

独立接入通常对部署改动较少，但不免除身份和权限评估。多应用也不要求立即把所有模块拆成不同数据库；业务拆分应作为单独的数据迁移处理。

迁入 Host 时，模板归档只提供代码，不携带原业务数据。需要针对所用数据库和存储制定恢复或连接方案，不存在适用于所有实例卷的一条通用导入命令。

## 保留用户身份与业务权限

在首次平台登录前确定：哪些平台用户对应哪些已有业务用户，以及平台访问角色应映射到哪些子应用权限。

统一登录按 issuer 和 subject 识别身份，不自动按邮箱合并。迁移应保留已有用户 ID 与业务外键；遇到身份冲突时停止处理，不能重新生成同名用户蒙混通过。

平台管理员不会自动成为业务管理员。为明确用户分配成员资格，保留原有合法角色，并处理 SSO 降权时应移除的授权。不要把业务权限授予所有已登录用户来绕过迁移问题。

如果 issuer 改变，需同时检查客户端回调、运行变量和已有账号绑定。即使域名下仍是同一个平台，也不能只改地址后期待旧身份自动识别。

## 演练迁移与切换入口

先用一致的数据库、文件和配置备份建立隔离演练环境。禁用生产通知、Webhook 和后台写入凭据，避免演练触发真实业务效果。

按所选路线演练：

- **独立接入**：保留原部署和数据，登记入口，接入所需登录并验证原有业务；不创建 Host 实例。
- **迁入 Host**：构建兼容制品并准备目标实例，确认迁移何时执行；停止目标写入后，按经过验证的顺序恢复数据库、文件和私有配置。
- **改造为主应用**：合并插件和认证配置，避免覆盖原用户字段、页面权限标识和登录方式；在恢复数据上运行需要的迁移。

正式切换前确认维护窗口、恢复负责人和最终备份。停止原应用写入及后台消费者，处理尚未结束的操作，再按演练步骤恢复、迁移和切换流量。每个定时任务、队列和业务写入只能有一个明确的执行方。

不要为追求不停机，让新旧应用未经设计同时写入同一份数据。

## 验证迁移结果与恢复原环境

对照迁移前基线检查记录数量、代表性记录、用户 ID、关联关系、附件、配置和权限。使用真实普通用户检查原有业务、SSO、本地恢复登录、直接 API 拒绝及重启后数据保留。

失败时先停止流量和不确定的后台操作，保留失败阶段及操作标识。只有旧代码兼容当前数据库时才可直接回退代码；否则使用与代码和配置匹配的一致备份恢复。数据库回滚或重置不是默认补救步骤。

保留旧部署但停止其写入，直到迁移结果被接受、恢复流程验证完毕，并确定保留期限。不要仅凭健康检查成功就删除旧环境。运行环境准备和备份范围见[部署与运维](deployment.md)。
