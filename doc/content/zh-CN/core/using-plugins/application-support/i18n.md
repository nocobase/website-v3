description: "接入应用语言切换，并协调浏览器与服务端语言。"
---

`@nocobase/app-plugin-i18n` 提供应用运行时语言切换接口与 hooks。翻译资源、命名空间和翻译机制由框架负责；本插件负责让用户选择语言并同步服务端偏好。

## 接入与语言来源

注册 Client 与 Server 插件。可选语言来自应用自己的 `client/locales/index.ts` 和 `server/locales/index.ts` 中声明的加载器，不是插件额外维护的一份语言清单。

新增一种语言时，为应用补充相应资源与加载器。其他插件即使提供某种语言，也不会自动将其加入应用的语言选择列表。默认语言配置为：

```yaml
i18n:
  defaultLocale: zh-CN
```

`APP_DEFAULT_LOCALE` 可以覆盖默认值。应用未提供资源的默认语言不会作为一个新选项出现。

## 接入语言选择器

插件提供行为，选择器外观由应用负责。在 `AppClientRoot` 内使用：

```tsx
import { useAppLocale } from '@nocobase/app-plugin-i18n/client';

const { locale, locales, setLocale, switching } = useAppLocale();
```

这是组件内的调用片段。用 `locales` 渲染选项，选择后调用 `setLocale(next)`，切换期间按 `switching` 禁用重复操作，并处理 Promise 失败。

切换会加载各命名空间资源、更新界面与 HTML 语言方向、保存浏览器偏好并通知服务端。各插件共享翻译运行时，无需另写一套跟随切换逻辑。

## 示例：中英文界面

1. 应用同时提供 `zh-CN` 和 `en-US` 的客户端与服务端资源。
2. 在顶栏接入语言选择器，或复用默认模板已有的实现。
3. 选择另一种语言，检查页面、插件内容和服务端错误提示。
4. 刷新页面，确认浏览器保留选择；启动同步可使用 `useSyncServerLocale()`。

接口为 `GET /api/i18n/locales` 和 `PUT /api/i18n/locale`。若服务端不支持所选语言，会保存 `en-US` 并返回 `fallback: true`，浏览器界面仍保留自己的语言；网络失败也不会自动撤销浏览器选择。

## 验证与边界

多个标签页共享会话的服务端语言，可能出现一个标签页切换后另一个标签页的接口提示也改变。自定义界面可按稳定的 `error.reason` 显示对应语言文案。

本插件不提供业务内容的自动翻译或翻译管理后台。资源编写见[客户端多语言](../../developing-apps/localization.md)和[服务端多语言](../../developing-apps/server-localization.md)。
