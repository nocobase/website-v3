开发业务功能前，先检查应用已经安装和注册的插件。认证、用户、权限、文件、通知等能力，可以通过插件的公开入口接入自己的业务。插件目录和用途见[插件索引](../reference/plugins.md)。

## 从能力到业务功能

NocoBase 3 的插件提供可组合、可扩展的能力。根据插件的设计，它可能提供服务端接口、业务服务、页面、组件、命令或 Skills；具体业务界面和流程由应用组合完成。

例如，为一个业务页面增加文件上传，需要先了解文件插件的上传与访问方式，再在应用中组合组件、调用接口并处理权限。安装插件只是接入过程的一部分，不能据此判断业务页面已经完成。

## 接入已有插件

1. **检查现有能力。** 查看 `package.json` 和 Client、Server、CLI 的插件注册文件，确认哪些部分已经接入。
2. **安装、注册与配置。** 按插件说明处理依赖和运行配置，具体步骤见[安装、注册与配置](../developing-apps/manage-plugins.md)。
3. **使用公开入口。** 在应用中调用插件提供的接口、服务或组件，保留 `node_modules/` 中的依赖源码原样。
4. **参考 Skills 与示例。** 让 Agent 理解插件提供什么、接入前提是什么，以及应用还需要实现哪些业务行为。
5. **验证完整流程。** 检查正常操作、无权限、空数据和失败情况，并运行相关测试与应用构建。

应用和插件都可以自由组织前端组件，基础组件使用 shadcn。组合界面时优先参考 [NocoBase UI Library](https://ui.nocobase.com/)。通过 UI Registry 添加的源码由使用方维护，其更新与运行时插件包的升级分别处理。
