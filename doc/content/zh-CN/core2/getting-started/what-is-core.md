NocoBase Core 是开发和运行业务应用的基础。它提供应用框架，以及登录、用户、权限、文件、通知等通用能力，你的应用可以直接使用。

无论是任务管理、采购系统还是客户管理，都要处理账号、数据、权限和界面交互。Core 把这些共同的基础准备好，你和 Coding Agent 就可以把精力放在业务本身：要保存哪些数据、谁能操作、操作之后应该发生什么。

创建应用后，你得到的是一个独立的应用项目。Core 以项目依赖的形式提供基础能力；页面、接口、数据结构和业务规则都写在你自己的应用里。

## Core 提供什么

- **应用模板与运行框架**：从一个可以直接启动的项目开始，客户端、服务端和运行配置都已就绪，在此基础上添加自己的功能。
- **通用能力**：通过插件和基础库使用认证、用户、权限、数据访问、文件存储和通知等能力，按应用需要组合。
- **UI 组件库**：复用表格、表单、弹窗等组件和业务区块。组件安装到应用源码后，可以按需修改。
- **开发工具与 Skills**：命令行工具负责配置、迁移、插件管理和构建；Skills 为 Agent 提供与所装依赖版本相匹配的使用指引。

三者的分工是：模板决定项目的起点，插件和库提供能力，应用把这些能力组织成业务功能。应用实际能用哪些能力，取决于它安装并注册了哪些包。

## 你需要开发什么

入门教程会一步步完成一个任务应用。Core 提供基础机制，任务的内容和规则由应用自己定义：

| 场景 | Core 提供 | 应用实现 |
| --- | --- | --- |
| 用户登录 | 账号、登录和会话能力 | 哪些人可以使用任务应用 |
| 保存任务 | 数据访问和迁移机制 | 任务标题、完成状态、负责人，以及相关接口 |
| 展示任务 | 表格、表单、弹窗等 UI 组件 | 任务列表、新建弹窗、筛选和分页交互 |
| 控制权限 | 权限模型与服务端检查能力 | 谁能查看、新建或完成任务，以及能操作哪些记录 |

以“完成任务”为例：用户点击按钮后，应用先借助 Core 的认证和权限能力检查这次操作，再按自己的业务规则更新任务状态，最后在页面上展示结果。

这些功能通常直接在应用项目中开发。只有当同一项能力需要独立发布、在多个应用中复用时，才考虑把它做成插件。

## 怎样开发和维护

**和 Agent 一起开发。** 你说明业务需求、使用者和验收标准；Agent 读取项目约定和 Skills，编写数据结构、接口、页面和测试。你通过实际试用检查结果，再继续调整需求。

**手动开发。** 你也可以直接编写代码，使用的是同一套框架、组件、接口和命令行工具。两种方式可以在同一个项目中混合使用，后续教程会分别提供“使用 Agent”和“不使用 Agent”两种步骤。

**代码由你管理。** 应用源码保存在你自己的仓库中，可以评审、测试、按版本发布，也可以部署到自己的服务器。升级 NocoBase 时，对照新版模板合并变更，保留业务定制，并用测试验证兼容性。

应用上线后，管理员可以在已启用的管理页面中调整用户、角色和数据权限；而页面、数据结构或业务逻辑的变化，需要通过修改代码、验证并重新部署来交付。

Core 可以独立使用。Studio 用于组织团队的开发、评审和发布；Solutions 是基于 Core 构建的现成业务应用。跟随入门教程学习不需要先搭建 Studio。

然后从 [搭建第一个应用](../tutorials/build-your-first-app-agent-first.md) 开始，搭建一个完整的团队任务应用，验证权限并完成部署。
