完成这一篇，你会得到一个可以实际使用的团队任务应用：

- 任务有标题、描述、负责人、截止日期和进度（待处理、进行中、已完成），可以新建、查看、编辑、删除，按标题搜索、按进度筛选和分页，界面支持中英文。
- 三种任务角色：任务管理员管理全部任务；任务成员只看到分配给自己的任务，只能更新进度；任务只读用户能看到全部任务，但不能修改。
- 一套自动化测试，覆盖建表、接口、权限和页面。

![团队任务列表，包含进度、负责人、截止日期和分页。](/assets/core/tutorials/team-tasks/task-list.png)

你还会走一遍之后开发每个功能都会重复的过程：用业务语言描述需求，检查 Agent 的交付，换不同账号验收，再提出修改。需求分两轮提出：先做出能用的任务管理，再加上角色和数据范围。

本文的截图来自[示例源码](#示例源码)中的应用。同样的需求，每次生成的布局、按钮名称和文件组织可能不同，以你的应用为准。验收时关注每种账号能看到什么、能做什么，而不是按钮叫什么。

## 准备

- 按[创建应用](../getting-started/create-app.md)创建并启动应用，能用管理员账号登录。
- 把项目提交到 Git，之后能清楚地看到每一轮改了哪些文件。
- 在应用目录开启 Agent 会话。应用自带的 `AGENTS.md` 和 `.agents/skills/` 告诉 Agent 代码放在哪里、迁移和权限怎么写，内容和安装的版本配套。如果 Agent 找不到 `nocobase-app-development` 技能，先确认 `.agents/skills/` 存在（不存在时在应用目录运行 `pnpm nocobase skills sync`），再重新开启会话。

## 1. 做出任务管理

### 描述需求

把下面的需求发给 Agent：

```text
帮我做一个团队任务管理应用。任务有标题、描述、负责人、截止日期，以及待处理、进行中、已完成三种进度。
支持新建、查看详情、编辑、删除，按标题搜索、按进度筛选和分页，界面支持中英文。
这一轮先不区分角色，由管理员使用；角色和权限下一轮再加。
请按项目的 AGENTS.md 和技能完成开发和相关测试，保留已有功能和数据。
做好后运行起来，告诉我访问地址、改了哪些文件、运行了哪些测试及结果，以及还有哪些部分没有验证。
```

这段需求说清了三件事：任务有哪些信息和操作，这一轮做到哪里为止，做完后要交付什么。表名、字段类型、用哪个组件，交给 Agent 按项目指引决定。

### 检查交付

Agent 会新建任务表、接口和页面，编写并运行测试，再启动应用。完成后，它应该告诉你：

- 应用的访问地址；
- 改了哪些文件，运行了哪些测试，结果如何；
- 哪些部分还没有验证。

缺了哪一项，直接让它补上。

### 试用

打开 Agent 给出的完整地址，保留末尾的 `/main/` 等路径，用管理员账号登录，进入任务页面：

1. 新建一条任务：标题 `Prepare the project kickoff`，描述 `Draft the agenda and list the decisions to confirm.`，选一个将来的截止日期，进度为待处理，负责人先不选。
2. 打开任务详情，检查各项信息；再编辑描述，保存后重新打开，确认修改已生效。
3. 把进度改为进行中，刷新浏览器，任务和进度都还在。
4. 再新建一条 `Review the project budget`，负责人同样不选。搜索 `kickoff`，再按进度筛选，确认只找到对应的任务。
5. 新建一条临时任务，再把它删除，确认它从列表中消失。

![任务详情抽屉，显示进度、负责人、截止日期和描述。](/assets/core/tutorials/team-tasks/task-detail.png)

**完成的标志**：能新建、查看、编辑和删除任务，刷新后数据仍在，搜索和筛选的结果正确。

## 2. 加上角色和数据范围

现在任务应用只有管理员在用。这一轮让团队成员也用起来：不同角色能看到的任务、能做的操作各不相同。

### 描述需求

```text
给任务应用加上三种角色：
- 任务管理员：管理全部任务。
- 任务成员：只能看到分配给自己的任务，只能更新这些任务的进度，不能新建、编辑或删除。
- 任务只读用户：能看到全部任务，但不能修改。
提供用户和角色管理入口，方便我添加测试成员并分配角色。
权限要在服务端检查：直接调用接口时，越权的请求也要被拒绝。不要把任务权限授给所有登录用户。
已有的任务和数据保持不变，补充相应的测试。
完成后告诉我怎样准备测试账号和角色，以及检查结果和未验证的部分。
```

角色、操作授权和数据范围都是 Core 现成的能力，所以这一轮一段话就够了。Agent 不需要从头写权限系统，只需要声明任务有哪些操作（查看、新建、编辑、更新进度、删除）、“分配给我的任务”是哪些记录，再初始化三种角色。用户和角色的管理页面模板里已经准备好，Agent 会把它们接入「系统设置」。

需求里特意写了“在服务端检查”。页面上隐藏按钮只是为了好用，真正拦住越权请求的是服务端。

### 检查交付

Agent 会声明任务操作和数据范围，初始化三种任务角色，接入用户和角色管理，并补充权限测试。交付报告里除了改动和测试结果，还应该说明怎样添加测试成员、分配哪个角色。

让 Agent 确认测试覆盖了“没有权限时直接调用接口被拒绝”，而不只是检查页面上有没有按钮。

![权限管理中的三种任务角色。](/assets/core/tutorials/team-tasks/roles.png)

### 换不同账号验收

1. **添加成员。** 进入「系统设置 › 用户」，新建用户 Alice：用户名填 `alice`（只用字母和数字），再填邮箱和初始密码。保留默认的通用角色（示例中叫 `Member`），再加上任务成员角色（示例中叫 `Task member`）。

   通用角色不包含任务权限。检查成员能看到什么时，不要同时分配任务管理员或系统管理员角色，它们会扩大能看到的任务和能做的操作。

2. **分配任务。** 用管理员把 `Prepare the project kickoff` 的负责人改为 Alice，`Review the project budget` 保持未分配。
3. **用成员登录。** 在另一个浏览器或无痕窗口用 Alice 登录：
   - 任务列表里只有 `Prepare the project kickoff`，看不到 `Review the project budget`；
   - 能把这条任务的进度改为已完成；
   - 看不到新建、编辑和删除的入口。
4. **回到管理员。** 刷新任务列表，`Prepare the project kickoff` 的进度已经是已完成。
5. **检查只读角色。** 再添加一个账号，保留通用角色，只加任务只读角色（示例中叫 `Task reader`）。用它登录，能看到两条任务，但不能新建或修改。

**完成的标志**：Alice 只看到分配给自己的任务，能把它标记为完成，但不能新建、编辑或删除；管理员刷新后能看到 Alice 的更新；只读账号能看到全部任务，但不能修改。

## 3. 看看 Agent 改了什么

用 `git status` 和 `git diff` 查看两轮的改动。示例应用改动了下面这些位置，你的应用大致相同：

| 位置 | 改动 |
| --- | --- |
| `database/main/migrations/`、`database/main/seeds/` | 新建任务表；初始化三种任务角色 |
| `server/tasks/` | 输入校验、业务服务和权限声明 |
| `server/providers/`、`server/routes/` | 注册任务服务和 HTTP 接口 |
| `client/pages/tasks/` | 列表、详情、表单和任务操作 |
| `client/routes.ts`、`client/pages/settings/` | 注册任务页面和系统设置；在权限编辑器中展示任务操作 |
| `client/locales/` | 中英文文案 |
| `client/components/ui/calendar.tsx` | 用 shadcn 添加的日历组件 |
| `tests/` | 任务相关的测试 |

有三处值得打开看看：

- **迁移**（`database/main/migrations/`）：任务表有哪些字段和索引。迁移合并后就不再修改，以后的结构变化写成新的迁移。
- **权限声明**（示例中是 `server/tasks/permissions.ts`）：任务有哪些操作，“分配给我的任务”的条件是什么。
- **测试**（`tests/`）：覆盖了哪些情况，特别是没有权限时的请求。

自己运行一遍测试，不需要先启动应用：

```bash
pnpm test
```

提交前运行 `pnpm check`，它依次执行包检查、lint、格式检查、类型检查、测试和构建。命令成功退出不等于测试都运行了，看一眼报告里的文件数和用例数。

想逐行看懂这些代码，或者不使用 Agent 自己实现，见[团队任务应用的实现](team-tasks-explained.md)。

## 4. 继续修改

应用做出来以后，修改也是同样的方式：描述你要的结果，检查交付，重新验收。试一个小修改：

```text
任务列表里，截止日期已过、进度还不是已完成的任务，把截止日期标成红色。
补充相应的测试，完成后告诉我改了什么、怎样验证。
```

检查时，分别看一条截止日期已过的未完成任务和一条已完成的任务，确认只有前者标红。

遇到不符合预期的地方，把用的账号和角色、做了什么、看到了什么告诉 Agent，例如：

```text
我用只分配了任务成员角色的账号登录，仍能看到没有分配给自己的任务。
请检查数据范围权限，修复后补充相应测试，并告诉我怎样重新验证。
```

每次修改后，重新走一遍受影响的操作，确认没问题再提交。描述需求和检查结果的更多方法，见[和 Agent 一起开发](../developing-apps/develop-with-an-agent.md)。

## 遇到问题

| 现象 | 处理 |
| --- | --- |
| 浏览器打开后找不到页面 | 使用 `pnpm dev` 打印的完整 `Local:` 地址，包括端口和末尾的 `/main/`。默认端口被占用时会自动换一个 |
| 需要从局域网的其他设备访问 | 在 `.env.local` 中设置 `APP_SERVER_HOST=0.0.0.0` 和 `APP_SERVER_PORT`，再运行 `pnpm nocobase config set app.publicOrigin=http://<局域网 IP>:<端口>`，并确认与 `pnpm dev` 打印的实际端口一致 |
| Agent 找不到项目的技能 | 确认 `.agents/skills/` 存在，不存在时在应用目录运行 `pnpm nocobase skills sync`，再重新开启会话 |
| Agent 没有说明运行了哪些测试 | 让它列出运行的测试命令和结果，并说明哪些部分没有验证 |
| 页面上没有按钮，但直接调用接口仍然成功 | 权限只做在了页面上。让 Agent 在服务端检查，并补充直接调用接口被拒绝的测试 |
| 新建用户时提示 `Username is invalid` | 用户名只用字母和数字，例如 `alice`。当前版本中，含短横线的用户名会报错 |
| 成员登录后看不到任务菜单 | 确认分配了任务成员角色。通用角色本身不包含任务权限 |
| 成员能看到没有分配给自己的任务 | 检查是否还分配了任务管理员、任务只读或系统管理员角色，只保留通用角色和任务成员角色再试 |
| 保存时提示任务已被其他人修改 | 另一个窗口或其他人先改了这条任务。重新加载最新的任务后再保存，草稿会保留 |

<details>
<summary>获取并运行完整应用</summary>
