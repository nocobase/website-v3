## 提供的能力

`@nocobase/app-plugin-knowledge` 提供知识空间、目录、Markdown 文档、文件、版本、搜索和修改建议等能力。基础知识库可以独立使用，不要求启用 Agents 或语义检索。

基础知识库独立于 Agents 和语义索引；空间的业务归属和授权由应用定义。

## 使用场景与示例

### 示例：团队知识的变更审阅

1. 应用为团队配置知识空间，以及读取、提出建议和编辑的权限。
2. 成员为某篇文章提交修改建议，编辑者检查差异和所基于的版本。
3. 编辑者接受或拒绝建议；接受后，会生成文档的新版本。
4. 检查搜索结果和历史记录，并验证其他空间的成员看不到自己无权访问的内容。

设置 `knowledge.proposals: false` 可以关闭建议流程，改为直接编辑；已有的建议数据会保留，直接编辑仍然需要原有的权限。代表用户执行工作的 actor 不能直接编辑，也不能对建议作出决定。

**开发提示词**（交给当前应用目录中的 Coding Agent）：

```prompt
请使用知识库插件，为团队接入知识空间与文档变更审阅。
提供 KnowledgeAccessResolver，按团队身份决定可见空间及 read、propose、edit、manage 权限。
复用知识库页面或组件，成员提交建议，编辑者检查版本后接受或拒绝。
先使用基础搜索，不假设已配置语义模型或 OCR。
验证跨团队隔离、并发编辑冲突、建议接受及文件解析失败。
```

**完成的标志**：成员能够提出建议，编辑者接受后生成新版本；其他团队既不能通过页面、也不能通过搜索读取这些内容。

## 重要原理与实现

下表列出实现本例时的接入位置和预期的界面变化。这些是开发说明，具体的文件名沿用当前应用的结构。

| 接入位置 | 代码或配置的变化 | 界面与行为的变化 |
| --- | --- | --- |
| 服务端的访问解析器 | 绑定 `knowledgeAccessToken`，解析空间和节点的权限 | 用户只能进入允许访问的团队空间 |
| 客户端路由或业务页面 | 注册知识库页面，或嵌入 `KnowledgeView` | 出现文档、目录、版本和建议的界面 |
| 可选的索引配置与 Jobs | 单独组合索引和索引管理权限 | 需要时增加语义检索，基础搜索始终可用 |

### 接入与空间权限

注册 Client 和 Server 插件并执行迁移。应用必须通过 `/server/tokens` 导出的 `knowledgeAccessToken` 提供一个 `KnowledgeAccessResolver`，用来定义空间是否存在、权限如何继承，以及当前读者拥有哪些权限。没有绑定访问解析器时，不会有任何可用的空间。

空间由 `scope` 和 `scopeId` 标识，例如系统空间，或者某个业务项目的空间。可选的空间列表和相应的权限都由应用决定，不能把数据库中的所有空间直接交给用户选择。

| 权限 | 可以进行的工作 |
| --- | --- |
| `read` | 读取允许访问的文档和文件 |
| `propose` | 提交修改建议 |
| `edit` | 编辑内容，并审阅自己可以处理的建议 |
| `manage` | 管理空间和节点的权限设置 |

目录、文档和文件还可以配置继承的或自定义的权限。页面的访问权限与内容的权限是分开的，能进入页面并不表示可以读取所有空间。

### 页面与内容的使用

`knowledge()` 默认注册 `/knowledge` 页面，也可以传入 `path` 和 `space`。如果需要把知识库嵌入业务页面，请使用 `knowledge({ routes: false })`，再自行组合 `/client/pages` 中的 `KnowledgePage` 或 `KnowledgeView`。

使用者可以创建目录和文章、编辑 Markdown、查看版本之间的差异以及恢复内容。提交编辑时会带上预期的版本；发生版本冲突时，应先读取最新的版本再处理，以免覆盖别人的修改。

上传文件还需要文件插件和 Drive。文件会保留原始内容，并尝试从支持的格式中提取文本；解析状态会显示为处理中、成功、失败或不支持。目前没有 OCR，因此不能假设图片或扫描件会得到可以搜索的文本。

### 搜索与语义索引

基础搜索在当前文档和已提取的文本中进行匹配。语义索引需要另外配置：Knowledge 可以维护自己的全局索引，Agents 只作为可选的 Embedding 网关，并不复用 Agents 的向量集合。

需要索引时，组合 `/config` 导出的 `defineKnowledgeConfig()`，配置索引实例、模型来源和宿主的 Jobs，并接入公开的索引管理组件。索引管理使用独立的 `settings:kb.indexing` 权限，不会随空间管理权限自动授予。索引不可用或正在重建时，普通的文本搜索仍然可以使用。

## AI 开发的约束与验证

### 本插件的开发约束

- 空间列表、文档读取和搜索使用同一个访问边界；页面可以访问，并不代表所有空间都可读。
- 写入时携带预期的版本，发生冲突时重新读取并处理；不能通过去掉版本检查来强行覆盖。
- 验证提出建议的资格、跨空间搜索和文件解析失败；不能通过伪造“提取成功”的状态，掩盖扫描件无法搜索的问题。

请验证空间隔离、版本冲突、文件解析失败、建议审阅和搜索范围。相关文档：[Agents](agents.md)、[文件](../data-and-files/file-management.md)、[管理插件](../../developing-apps/manage-plugins.md)。

以上检查是接入后的验收要求，并不表示本文已经完成了运行验证。请让 Agent 报告实际的改动、执行过的检查和未验证的部分；项目指引、Skills 和通用的检查流程见 [和 Agent 一起开发](../../developing-apps/develop-with-an-agent.md) 与 [测试与验收](../../developing-apps/testing-and-acceptance.md)。
