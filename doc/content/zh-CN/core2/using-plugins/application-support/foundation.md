## 提供的能力

`@nocobase/app-plugin-foundation` 提供应用的能力概览，帮助管理员了解当前应用接入了哪些 Core 能力、已经有哪些使用证据，以及各业务模块与这些能力的关系。

应用底座用于观察已有的接入，不负责安装插件，也不能代替实际的业务验收。

### 查看应用能力

打开应用底座后，选择账户、权限、文件、通知、AI 等能力，可以查看当前的配置、能够识别到的使用情况和相关的包。插件在每次请求时读取应用配置、已注册的服务、默认数据库连接以及迁移信息，结果会被短暂缓存；刷新时会重新采集。

“已安装”“已注册”“已配置”和“已使用”是不同层次的证据。一个包出现在依赖中，并不能证明业务正在使用它。无法识别的自定义扩展或商业扩展，可能显示为单独的一项，其使用情况可能仍有待确认。

## 使用场景与示例

### 示例：确认邮件能力是否已经接通

1. 在应用底座中查看，邮件能力是否识别到了运行时以及已连接的邮箱。
2. 打开相应的业务模块，确认确实接入了 [邮件](../notifications/mail.md) 的账户页和工作台。
3. 完成一次受控的收发验证，再结合底座中的统计检查使用情况。

底座展示的是它读取到的证据，并不能代替真实的邮件收发、模型调用或业务验收。只有在明确选择统计时，才会查询记录总数；采集失败不应被理解为数量为零。

**开发提示词**（交给当前应用目录中的 Coding Agent）：

```prompt
请使用应用底座插件，为管理员接入 Core 能力概览。
优先复用已注册页面，保留 unrestricted 访问要求，按应用导航放入系统设置。
需要部署后的模块关联时接入 CLI 构建贡献。
区分已安装、已注册、已配置和使用证据，采集失败不能显示成零或未使用。
验证普通用户直接请求被拒绝；邮件等能力另做受控业务验收。
```

**完成的标志**：管理员能看到各项能力及其证据，普通用户被拒绝访问；无法识别或采集失败的状态，不会被误报为业务结论。

## 重要原理与实现

下表列出实现本例时的接入位置和预期的界面变化。这些是开发说明，具体的文件名沿用当前应用的结构。

| 接入位置 | 代码或配置的变化 | 界面与行为的变化 |
| --- | --- | --- |
| Client、Server 插件配置 | 配置页面路径和导航选项 | 系统设置中展示能力概览 |
| 可选的 CLI 贡献与构建 | 生成 `foundation-modules.json` | 部署后可以读取静态的模块关联 |
| 业务验证记录 | 把底座的观察结果与实际的业务验收对应起来 | 不会把“依赖存在”误认为“业务已经跑通” |

### 接入与入口

在身份认证、权限管理等依赖之后注册 Client 和 Server 插件。`foundation()` 默认提供 `/foundation` 页面和菜单；默认模板使用 `foundation({ settingsGroup: true })`，把它放进系统设置分组中。

| Client 选项 | 用途 |
| --- | --- |
| `path` | 更改页面路径 |
| `navigation: false` | 保留页面，但不自动显示菜单 |
| `routes: false` | 由应用自己挂载公开的 `FoundationPage` |
| `settingsGroup: true` | 把入口放进设置分组 |

页面和 `GET /api/foundation/overview` 接口只允许 unrestricted 身份访问，例如持有 root 权限集的管理员。这并不是一个可以随意分配给普通角色的页面权限。

### 业务模块与部署

业务模块取自当前的导航树，关联关系则来自可以识别的页面、接口和后端依赖。矩阵中的空白表示没有识别到，不能据此判断该模块一定没有使用某项能力。

如果需要在部署产物中保留静态的模块关联，请注册 `/cli` 导出的贡献。应用构建时会生成 `dist/server/foundation-modules.json`；已有的应用需要重新构建后，才能得到这份信息。插件不会执行被扫描的业务源码来判断关联。

## AI 开发的约束与验证

### 本插件的开发约束

- 页面和接口保留 unrestricted 的要求，不要为了让入口出现，而放宽为“普通登录即可访问”。
- 不要把空白的关联或采集失败解释为“没有使用”；显示保留下来的证据时，同时显示其原始的检查时间。
- 部署时核对构建产物；具体的邮件、模型或数据库操作仍需分别验收，不能用底座的统计代替业务测试。

### 验证与限制

检查管理员的访问、普通用户被拒绝、刷新，以及信息读取失败时的展示。默认连接以外的数据、无法静态识别的服务组合，或者尚未支持的扩展，可能不在统计范围内；历史上可靠的数据会标注原始的检查时间。

本插件不负责安装、启用或升级其他插件，也不能证明升级检查、迁移校验或业务测试已经通过。相关文档：[管理插件](../../developing-apps/manage-plugins.md)、[数据库浏览](../data-and-files/database-explorer.md)。

以上检查是接入后的验收要求，并不表示本文已经完成了运行验证。请让 Agent 报告实际的改动、执行过的检查和未验证的部分；项目指引、Skills 和通用的检查流程见 [和 Agent 一起开发](../../developing-apps/develop-with-an-agent.md) 与 [测试与验收](../../developing-apps/testing-and-acceptance.md)。
