## 提供的能力

`@nocobase/app-plugin-template-print` 提供模板打印相关的 Agent Skills 和参考实现，帮助应用根据 Office 模板和业务数据生成文档，并按需处理图片、二维码和 PDF 转换。

### 安装后会得到什么

当前的包只分发开发指引，没有 Client、Server 或 CLI 运行时入口，也不提供模板表、打印路由、渲染引擎或现成的打印页面。安装之后，应用仍需自己实现打印功能。

把兼容的版本作为应用的直接开发依赖安装，然后在应用根目录同步：

```bash
pnpm nocobase skills sync
```

确认应用能够读取 `nocobase-app-plugin-template-print` 这个 Skill。不需要把这个包加入 Client 或 Server 的插件注册数组，也不要为了安装 Skill 而虚构一个运行时入口。

## 使用场景与示例

### 示例：为订单生成打印文档

可以把下面的需求交给应用的 Agent：

```prompt
请使用模板打印 Skill，为当前应用的订单详情增加“下载订单”功能。

使用我提供的 DOCX 模板，填充订单信息、明细与合计。
读取数据时复用当前用户的订单与字段权限。
先实现 DOCX 下载；如果需要 PDF，说明转换依赖并接入应用部署环境。
覆盖无明细、长文本、图片缺失和无权限访问，验证生成文件可正常打开。
```

实现应由应用或业务插件自己持有：模板资产、数据查询、渲染依赖、下载接口和按钮。可以先用一个固定的模板跑通一条业务流程，再决定是否需要模板上传、版本管理和预览。

**完成的标志**：获得授权的用户能够下载字段和排版都正确的 DOCX；需要 PDF 时，在目标环境中也能生成可以打开的文件。

## 重要原理与实现

下表列出实现本例时的接入位置和预期的界面变化。这些是开发说明，具体的文件名沿用当前应用的结构。

| 接入位置 | 代码或配置的变化 | 界面与行为的变化 |
| --- | --- | --- |
| 开发依赖与 Skills 同步 | 安装指引包，并同步到应用 | Coding Agent 能读取当前版本的指引；不新增运行时插件 |
| 模板资产、业务查询与下载接口 | 实现经过授权的数据装配和 DOCX 渲染 | 返回真实、可以打开的文档 |
| 订单详情与可选的 PDF 环境 | 接入下载按钮、转换依赖和失败反馈 | 用户可以下载，转换失败时能给出解释 |

### 内容的组织与使用

先确定模板中的字段和需要重复的明细区域，再准备经过授权的数据。图片、二维码、字体和分页，需要在生成的文档中实际检查。PDF 只是一种可选的输出，转换工具、运行环境和部署依赖必须另外落实，不能因为安装了本包，就认为服务器已经具备转换能力。

插件源码中的 `app-plugin-template-print-example` 是一个独立的示例，拥有自己的发票数据、授权、固定的 DOCX 和下载界面；它并不是本 Skill 包内置的通用渲染服务。

## AI 开发的约束与验证

### 本插件的开发约束

- 这个包只提供开发指引，不要导入并不存在的运行时入口，也不要声称已有通用的打印服务。
- 模板字段只能使用当前用户获准访问的数据，下载接口需要重新检查记录和字段权限。
- 实际打开输出的文件，检查明细、合计、分页和图片；PDF 转换要在真实的部署依赖下验证，不能只测接口返回了 200。

### 验证结果

检查生成的文档能否打开、字段值和合计是否正确、重复区域和分页是否合理，并验证当前用户无法打印自己无权查看的记录或字段。需要 PDF 时，还要在部署环境中验证转换、字体和错误处理。
