## 提供的能力

`@nocobase/app-plugin-approval` 把人工审批接入业务记录的生命周期，管理审批参与人、任务、操作记录和内容快照，适合请假、采购、合同等需要人工确认的业务。它是商业插件，安装前请确认已获得相应的包访问权限和使用授权。

插件提供审批的编排能力和读模型；业务页面、接口、授权和定时执行由应用组合。

## 使用场景与示例

### 示例：采购申请

申请人在草稿中填写采购内容，提交后进入主管审批。主管可以通过、驳回，或者退回草稿。审批通过时，审批结论和采购记录的状态在同一个事务中推进；被退回后，申请人通过业务允许的入口修改，然后再次提交。

处理页面应使用 `runViewsFor`、`upcomingStagesFor`、`previewRoute` 等公开的读模型来展示进度和可选的操作。应用可以安装 UI Library 中 `approval-ui` 组件的源码，把读模型映射为进度条、时间线、预览和操作栏。

接口必须重新检查当前用户、记录权限、任务资格和内容版本，不能仅仅因为浏览器上显示了“通过”按钮就允许提交。审批内容发生变化后，原先作出的同意结论可能需要重新审阅。

**开发提示词**（交给当前应用目录中的 Coding Agent）：

```prompt
请使用已获授权的审批插件，为采购申请接入主管审批。
沿用业务记录生命周期，明确草稿、审批、退回与最终状态及审批人范围。
用公开读模型和审批 UI 组件显示进度、时间线与允许操作，接口重新校验资格和内容版本。
最终审批结论与业务状态在同一事务推进，接入宿主 Jobs 的定时检查。
验证无审批人、重复操作、退回修改、并发冲突和事务失败。
```

**完成的标志**：采购申请可以提交、通过或被退回；没有资格的操作会被拒绝，事务失败时不会留下不一致的最终状态。

## 重要原理与实现

下表列出实现本例时的接入位置和预期的界面变化。这些是开发说明，具体的文件名沿用当前应用的结构。

| 接入位置 | 代码或配置的变化 | 界面与行为的变化 |
| --- | --- | --- |
| 业务生命周期、审批配置与事务存储 | 组合审批阶段、参与人和结论映射 | 采购记录的状态与审批结果保持一致 |
| 业务接口与详情页 | 接入读模型、进度和经过授权的操作 | 申请人和审批人分别看到各自可执行的操作 |
| Jobs 与后续的业务处理 | 接入 sweep、prune 以及外部执行的状态 | 定时工作和业务失败都有明确的处理方式 |

### 接入前的准备

插件的 Server 入口提供审批数据的迁移和公开的编排 API，Client 入口提供语言资源和读模型工具；插件不会自动生成审批中心、业务接口或工作流设计器。

应用需要提供：

- 业务 Collection、记录的生命周期及其事务存储。
- 身份认证、业务权限，以及组织与人员的查询。
- 审批配置、操作接口和业务页面。
- 定时检查，以及提交后的通知、业务执行等集成。

通过 `/server` 导出的 `defineApproval`、`stagesFor`、`approvalState` 等声明审批流程，再把生命周期交给宿主的 LifecycleRuntime，把审批配置交给 `ApprovalService`。一条业务记录对应一个流程，不要为审批另建一份脱离业务状态的“流程状态”。

### 配置审批

先确定草稿、审批中、退回修改和最终状态，再为每个审批阶段设置参与人、决策规则和允许的操作。公开的策略涵盖单人审批、会签、任一人通过、依次审批、按阈值通过以及自定义聚合；转交或加签时，还需要配置可以选择的接收人范围。

| 业务问题 | 配置要点 |
| --- | --- |
| 谁来审批 | 参与人的解析、人员的有效性，以及没有审批人时如何处理 |
| 什么时候算通过 | 阶段的决策规则，以及审批结果到业务状态的映射 |
| 能否退回或转交 | 显式声明允许的操作、退回的目标和接收人范围 |
| 审批期间能否修改数据 | 冻结的字段、内容 hash 和版本检查 |
| 通过之后做什么 | 业务生命周期的后续状态和副作用 |

## AI 开发的约束与验证

### 本插件的开发约束

- 复用业务记录作为流程的标识，不能维护一份与业务状态脱节的第二份状态。
- 按钮可见并不代表有权审批；服务端要同时校验用户、记录、任务资格和内容版本。
- 在隔离的数据上验证重复操作、并发操作和最终事务失败；外部执行失败时，使用业务上的重试状态，而不是让人重复审批。

### 定时工作与验证

插件自己不运行定时器。应用通过 `createLifecycleJobs` 接入宿主的 Jobs，在 sweep 回调中调用 `ApprovalService.sweep()` 和 `runtime.prune()`，处理任务的计时和生命周期触发器。

请验证没有审批人、不同的决策规则、重复操作、退回修改、内容冲突和最终事务失败等情况。后续的外部执行失败，应由业务记录上可以观察的失败和重试状态来承接，避免让人重复审批。
