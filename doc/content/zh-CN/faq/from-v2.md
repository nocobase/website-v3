## 产品与开发方式的区别

NocoBase 2 的无代码页面、数据表定义、权限和工作流主要通过平台配置维护。NocoBase 3 Core 应用的页面、接口、业务逻辑和数据库迁移由应用源码维护，Core 以 npm 包提供运行时、基础库和插件，Skills 指引 Agent 使用这些能力。

应用代码可以由 Agent 编写，也可以人工维护。代码变更通过分支、评审、测试和部署交付；用户、角色分配等日常管理数据仍可保存在数据库中，由应用接入的管理页面维护，不必每次修改代码。基础能力与业务开发的边界见 [Core 提供哪些能力](core-capabilities.md)。

## AI Portal 与 Core 应用的区别

[AI Portal](https://nocode.docs.nocobase.com/ai-builder/ai-portal/) 在无代码平台提供的数据、认证、权限和 API 基础上开发自定义界面。Portal 项目本身以客户端代码为主，配套 Agent 也能通过平台工具建表和配置权限。

V3 Core 应用在自己的仓库中维护客户端、服务端接口、业务服务和数据库迁移，复用 Core 的基础能力。它与 AI Portal 的区别在于应用结构和后端的维护方式，不只是是否使用 AI 写代码。V3 不沿用 V2 的无代码页面与数据建模界面；建表和结构变更见[建表与数据初始化](../core/developing-apps/data-models-and-migrations.md)。

## 功能对应关系

| NocoBase 2 | NocoBase 3 | 说明 |
| --- | --- | --- |
| 用户、角色与权限 | 认证、用户、权限插件，以及默认数据范围、共享规则、限制规则三个插件 | 默认模板已注册相关插件；管理页面按应用需要接入，业务操作和数据范围仍需定义 |
| 数据源、数据表 | 数据库基础库和迁移；外部数据库作为第二个连接接入 | 支持 SQLite、PostgreSQL、MySQL、SQL Server、Oracle；达梦、人大金仓、OceanBase 在商业版 |
| 文件管理器 | 文件插件和存储基础库 | 本地存储、S3 兼容存储、阿里云 OSS |
| 工作流 | 记录生命周期（基础库）、定时任务插件 | 流程结构写在代码里，没有拖拽设计器 |
| 审批 | 审批插件 <span class="tag pro">商业版</span> | 多级、会签、或签、加签、转交、退回 |
| 通知、站内信 | 通知、站内信、通知渠道插件 | 站内信；邮件（SMTP、Resend）；飞书、钉钉群机器人 |
| 邮件管理 | 邮件插件 | 关联个人邮箱，收发和同步邮件 |
| AI 员工、AI 知识库 | Agents 插件、知识库插件 | 默认模板包含依赖；使用时注册插件、接入界面并配置模型或知识库 |
| 多语言、主题 | 多语言插件；主题在模板里 | |
| API keys | API keys 插件 | 默认模板已启用 |
| 模板打印 | 模板打印技能包 | 只提供给 Agent 的指引，由 Agent 在应用里实现 |
| 图表、导入导出等区块 | 由 Agent 在应用里实现 | UI 组件库提供数据表格、看板等组件 |
| 审计日志 | 暂无 | 「应用底座」的操作审计一项显示尚未识别到提供方 |
| LDAP、SAML、钉钉、企业微信、飞书、Slack 等登录 | 认证插件 | 基于 Better Auth 扩展；按具体提供方和协议配置或开发，并验证账号映射与回调，不代表全部开箱即用 |

查看应用已使用的插件及其注册、更新和移除方式，见 [管理插件](../core/developing-apps/manage-plugins.md)。

## NocoBase 2 还会继续更新吗？

会。NocoBase 2 与 NocoBase 3 并行维护，V3 的推出不意味着必须把现有 V2 应用迁走。维护方向见[官方合作伙伴说明](https://www.nocobase.com/partner/)，具体版本的功能、优化和修复见 [NocoBase 2 发布日志](https://nocode.nocobase.com/cn/blog/timeline)。两个版本的架构和开发方式不同，不代表每项功能都会同步提供。

## 使用 NocoBase 3 需要同时安装 NocoBase 2 吗？

不需要。V3 Core 应用使用自己的运行时、数据库和基础能力，可以独立开发、部署和运行，不以安装 V2 为前提。

如果已有 V2 系统，可以按业务需要通过 API 等方式与新应用集成；这是可选的系统集成，不是 V3 的运行依赖。集成时仍需明确身份、数据和权限边界，见[现有系统集成](existing-systems.md)。

## 现有应用的迁移

两者的应用结构不同，不能通过更换版本号或镜像将 V2 应用直接升级为 V3 Core 应用。迁移通常需要按原业务需求重建页面、接口、数据结构和权限，再导入业务数据。

迁移前梳理原有表与关联、角色和数据范围、工作流、附件及外部集成；迁移后验证数据对应关系和实际业务操作。原有无代码配置、插件配置和 AI 员工配置不能假定可直接复用。业务 AI 的接入见[如何在应用中加入 AI 助手](business-ai.md)，数据恢复与搬迁见[备份、恢复和迁移](backup-and-migration.md)。

现有的 [Core 升级指南](../core/developing-apps/upgrade-nocobase-core.md)用于更新 V3 应用的框架依赖和模板，不是 V2 到 V3 的自动迁移工具。
