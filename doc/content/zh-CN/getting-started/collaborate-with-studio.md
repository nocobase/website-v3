Studio 将需求、Agent 执行和交付结果放在同一套项目与任务中，让团队一起推进开发。

## 为什么使用 Studio

### 从个人会话到团队共享的任务

需求背景和结果留在个人会话里，其他成员就要靠转述了解进展。Studio 的任务集中记录需求、负责人、代码改动与检查结果，业务同事和开发者可以在同一处补充规则、跟进和验收。

### 让 Agent 分工推进开发与检查

调度 Agent 安排设计、开发、测试和独立评审，由执行 Agent 完成具体工作；发现问题后继续安排修复。交接与结果留在任务中，人不必逐次转交。多个任务可在独立分支中并行推进，详见[Agent 执行规则](../studio/intro/agent-team.md)。

### 人掌握决策、验收与项目经验

业务规则由人决定，结果由人验收，调度 Agent 不替人合并 PR。项目知识库保存业务资料，项目记忆保留已确认的规则与设计约定，供后续需求和接手的人或 Agent 使用。

## 接入 Studio

### 加入已有团队

[接受邀请并登录](../studio/join/sign-in.md)，打开管理员准备的项目即可，不必先在本地创建应用。

### 准备团队环境与项目

Studio 在商业版中提供。管理员按[安装与配置](../studio/setup/index.md)获取访问授权、部署服务、接入 Git 与 Agent，再准备项目并邀请成员。

下面以新增供应商页面为例。开始前确认：

- 项目的「初始化项目」任务已完成。
- 已配置调度 Agent，且至少一个运行环境在线。
- 仓库已[选择检查方式](../studio/setup/ci.md)。需要试用应用时，准备好预览或测试环境。

## 提出需求并确认方案

在项目页点「新建任务」，向 Agent 描述目标和检查方式。例如：

```prompt
加一个供应商页面，记录名称、联系人、电话和合作状态。采购员可以新增、编辑和查看供应商。

做好后，我要能新增一家供应商，把状态改为暂停，并在列表中按状态筛选。
```

Agent 会先确认不清楚的规则，再整理为任务。检查内容后点「开始执行」。也可选择「手动填写」，直接创建任务。

![新建任务时，通过会话补充目标和业务规则](https://static-docs.nocobase.com/studio-en-guide-new-task-20261031.png)

开始后，任务进入「进行中」，由调度 Agent 安排设计、开发和评审。

开始前，确认供应商状态有哪些值、采购员可以操作哪些供应商，以及“暂停”是否只改变合作状态。尚未决定的规则直接告诉 Agent，和它讨论后写入任务。若已有采购制度或字段说明，把资料附到任务或[知识库](../studio/project/knowledge-base.md)，供后续设计与评审使用。

## 跟进开发、检查与评审

任务顶部显示当前 Agent、运行环境和下一步。「动态」保留交接、回复和评审结果；「运行记录」提供具体执行过程。

![任务详情显示当前执行步骤及后续安排](https://static-docs.nocobase.com/studio-en-guide-task-progress-20261031.png)

调度 Agent 根据改动安排设计与实现。执行 Agent 在任务分支修改代码并创建 PR（合并请求）；检查与评审的结果仍关联到同一任务。检查失败或评审提出问题时，调度 Agent 安排修复，再次检查和评审，通过后交给你验收。

例如，供应商状态筛选没有排除其他状态的记录，应先修复并验证，再交付。关注交付报告中的实际检查结果和未验证项；任务处于“进行中”并不表示所有业务行为已经通过验证。检查来源和评审机制见[检查与评审](../studio/project/checks-and-review.md)。

## 回答问题与验收结果

需要业务决策时，任务进入「阻塞中」，并排到「我的任务」的「等你处理」中。打开「需要你」卡片，回复规则或补充资料，调度 Agent 会继续安排。

若缺少检查或预览配置，请管理员按[检查与 CI](../studio/configure/checks.md)处理。

任务进入「待验收」后：

1. 阅读交付报告，核对改动、验证结果和遗留问题。
2. 点「看改动」查看 PR；有预览时，按验收场景试用。
3. 满足要求后点「合并」，确认目标分支和合并方式。
4. 需要调整时点「退回修改」，写清问题和预期结果。

![通过交付报告和验收标准确认任务结果](https://static-docs.nocobase.com/studio-en-guide-accept-20261031.png)

任务显示「已完成」，且默认分支包含此次改动，表示本次开发完成。后续进入测试与发布的状态可在[发布](../studio/release/overview.md)中查看。

## 发布改动与积累项目经验

合并代码不等于已经上线。配置了自动部署的项目，可由 CI 将合并后的代码部署到测试环境；未配置时，按团队的部署流程执行。负责人确认版本包含哪些任务，完成生产部署后在 Studio 记录生产版本。具体操作见[发布管理](../studio/release/overview.md)。

本次确认的采购规则和设计约定可以沉淀为[项目记忆](../studio/project/project-memory.md)，随代码评审与合并；采购制度等原始资料放在知识库。后续调整供应商功能时，Agent 可以读取这些背景，不必从新的会话重新确认。

完成这次流程后，从[我的任务](../studio/use/my-tasks.md)处理后续决策与验收。需要配置团队、管理项目或了解各类手册时，按[学习路径](learning-path.md)继续。
