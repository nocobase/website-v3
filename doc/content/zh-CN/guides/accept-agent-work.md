Agent 说“完成了”，不等于能用。这一篇给领用申请加一个“期望到货日期”，完整走一遍验收：Agent 第一次交来的结果有问题，打回后修好。

## 1. 提需求时要求分开报告

```prompt
给领用申请加一个选填的“期望到货日期”，不能早于今天，列表和详情里都显示。已提交的申请留空。
验收：Alice 提交一个期望 11 月 6 日到货的申请，列表和详情里能看到这个日期；选昨天提交不了。
完成后分开报告：跑了哪些自动检查；用哪个账号实际操作了什么、看到了什么，附截图；哪些没验证。
```

Agent 的报告：

| | 内容 |
| --- | --- |
| 自动检查 | `pnpm typecheck`、`pnpm lint` 通过；新增迁移测试和接口测试（保存日期、Ben 能读到、早于今天被拒绝），5 个用例通过 |
| 实际操作 | 用 Alice 提交了一个期望 11 月 6 日到货的笔记本申请，附详情截图 |
| 没验证 | 浏览器自动化测试 |

每类检查确认什么，见 [和 Agent 一起开发](../core/getting-started/develop-with-an-agent.md#验收)。

## 2. 自己跑一遍业务场景

用 Alice 登录，打开「领用申请」：

![旧申请显示 1970 年，新申请多了一个时间](https://static-docs.nocobase.com/20261030-itam-lite-accept-needed-by-wrong.webp)

两个问题：

- 「设备领用与审批」「角色与权限」里提交的旧申请没有期望日期，却显示 `Jan 1, 1970, 7:30 AM`。
- 新申请显示 `Nov 6, 2026, 8:00 AM`，日期后面多了一个时间。Agent 附的详情截图里其实也能看到。

Agent 的测试和实际操作都只用了新数据。验收时用已有数据，按每个角色的日常操作走一遍。走熟的场景可以让 Agent 写成浏览器测试，见 [测试与验收](../core/developing-apps/testing-and-acceptance.md#浏览器测试与功能验收)。

## 3. 看改动

用 `git diff` 看这一轮改了什么。这次重点看：

- **数据**：新增了迁移 `202610300401_add_device_request_needed_by`，没有改已经执行过的迁移；旧申请的这一列为空。
- **权限**：领用申请的可读字段里加了 `neededBy`，三个角色不用另外授权；“不能早于今天”在服务端检查。
- **页面**：期望日期复用了“提交时间”的格式化函数，它会带上时间；类型里把期望日期写成了必填。上面两个问题都出在这里。

其余检查项见 [和 Agent 一起开发](../core/getting-started/develop-with-an-agent.md#验收)。

## 4. 打回

验收标准有一条没做到、旧数据显示或处理错误、权限不对，都打回。打回时给复现步骤和预期：

```prompt
期望到货日期显示不对：
1. Alice 的「领用申请」里，没填日期的旧申请显示 Jan 1, 1970, 7:30 AM，应该显示“—”。
2. 填了 11 月 6 日的申请显示 Nov 6, 2026, 8:00 AM，应该只显示日期。
列表和详情都要改。修好后用 Alice 再看一遍，附截图。
```

Agent 新增了一个只显示日期的格式化函数，没有日期时显示“—”，类型改为可以为空；新测试在 UTC、洛杉矶、上海三个时区下都通过。再看一遍：

![旧申请显示“—”，新申请只显示日期](https://static-docs.nocobase.com/20261030-itam-lite-accept-needed-by-fixed.webp)

再选昨天提交，日期输入框旁提示 `Choose today or a later date.`；用 Ben 登录，列表里能看到 Alice 的期望日期。

## 5. 提交

```prompt
提交代码。
```

**完成的标志**：新申请的期望到货日期在列表和详情里只显示日期，旧申请显示“—”；早于今天的日期提交不了并在输入框旁提示；Ben 能看到这个日期；全部测试通过。
