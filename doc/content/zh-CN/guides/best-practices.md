## 在 Studio 里先聊清楚需求，再建任务

不要一上来就新建任务、直接开始执行。先在「我的会话」里和 Agent 把需求聊清楚：要做什么、规则和边界、怎样验收。聊清楚之后，再让 Agent 建任务、开始执行。

需求在任务开始前定下来，Agent 团队推进时就少问、少返工，任务描述里也留下了完整的规则和验收标准。

```prompt
<需求，两三句话>
有不清楚的先问我。聊清楚后，把规则和验收标准写进任务描述，建成任务。
```

![在「我的会话」里描述需求，Agent 拆解成可执行的任务](https://static-docs.nocobase.com/20261029151954700.png)

## 对项目有疑问，直接在 Studio 里问

不管是业务同事还是研发，想了解某个项目的业务逻辑、某个功能怎样运作，都可以直接问 Agent，不用去翻代码或找人。在项目页或任务页点「问 Agent」，会带上当前页面作为上下文开始会话：

```prompt
领用申请什么情况下需要资产管理员审批？审批通过后，设备的状态和使用人会怎样变？
```

![在项目页点「问 Agent」，当前项目作为上下文](https://static-docs.nocobase.com/20261030-studio-ask-agent.webp)

也可以直接在「我的会话」里提问，选上要问的项目：

## 其他团队提需求，也先用 Agent 写清楚

行政、财务等团队来提需求时，请他们也让自己的 Agent 先把需求写清楚：谁在用、要做什么、有哪些规则。页面说不清时，附一个 HTML Demo。

```prompt
我要给 IT 部门提一个需求：<一句话>。先问我几个问题，写成需求文档，再做一个单文件的 HTML Demo 展示主要页面。
```

研发收到后，先和 Agent 对照设计文档更新设计，再开发。
