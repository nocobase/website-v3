报价版本和客户交接的规则已经在任务中确认。我们将长期有效的结论整理到团队资料里，让下一位开发者或 Agent 能继续沿用。

| 位置 | 保存什么 |
| --- | --- |
| 知识库 | 人维护的业务规则、制度及决策背景 |
| 技能 | 开发、验证和评审时应遵循的方法 |
| 项目记忆 | 随代码维护的项目约束、纠正和经验 |

这里的资料服务于 Studio 中的开发协作。CRM 内供销售和业务 Agent 查询的产品知识、客户资料属于应用功能，不能靠添加 Studio 知识库自动接通。

## 将 CRM 业务规则与决策放进知识库

打开 CRM 项目的 **知识库**，新建“CRM 业务规则”文档，将已确认的规则写进去：

- 已提交的报价版本不可修改，后续调整创建新草稿；历史金额不随产品目录价格变化。
- 旧报价保留已有编号和内容，不补造过去的修订记录。
- 主管可以交接客户，记录原因、操作人和时间；原跟进作者和报价历史保持不变。
- 原负责人失去基于归属的访问权；继续协助时，由主管显式设置只读共享。

注明规则的适用范围和对应任务。已有折扣审批规则时，引用团队确认的规则，不另造一个审批阈值。为 Morgan 授予所需文档的编辑权限，让业务负责人维护业务含义。见[知识库](../studio/project/knowledge-base.md)。

![CRM 项目知识库中可阅读验收规则，并查看文档的维护信息。](/assets/guides/studio/knowledge.png)

在 CRM 会话中询问：

```prompt
客户交接后，原负责人还能查看吗？请根据项目知识库说明条件，并给我对应的资料。
```

**步骤检查**：Agent 的回答与文档一致，并能指出依据；不能读取时，先检查发起人的资料访问权限。

## 建立 CRM 开发与评审检查清单

向有权读取项目和交付报告的 Coding Agent 提出：

```prompt
根据这次报价版本对比和客户交接的经验，整理一份以后改进 CRM 时都要核对的清单，重点检查客户访问范围、历史报价是否保留，以及交接记录是否完整。先给我看内容。
```

清单应让开发和评审人员知道如何检查，而不是只写“注意权限”：

| 检查对象 | 检查方法 |
| --- | --- |
| 客户及关联记录 | 用负责人、无权销售和主管分别检查页面与接口 |
| 已提交报价 | 修改新草稿和产品目录后，核对旧版本内容与金额 |
| 交接和共享 | 检查撤销后的访问变化，以及显式只读共享的限制 |
| 已有数据升级 | 保留升级前样本，核对客户关系、原作者与历史记录 |

确认后，在 **技能** 创建技能，填写 `SKILL.md`：以 `name: crm-checklist` 标识，`description` 说明在 CRM 开发、自测和评审时使用，正文写入确认的检查方法。也可让有管理权限的 Agent 协助创建。将技能挂到 CRM 的 **设置 → 默认技能**，多仓库项目按需限定仓库。格式与权限见[技能](../studio/project/skills.md)。

![项目默认技能可绑定指定仓库，并管理当前项目采用的技能。](/assets/guides/studio/default-skills.png)

**步骤检查**：项目已挂载 `crm-checklist`；后续任务的运行记录和交付报告中，能看到针对这些规则的实际检查。仅挂载技能不代表检查已执行。

## 查看和积累项目记忆

打开项目的 **记忆**，查看 Agent 随任务留下的长期结论。例如“旧报价没有修订历史，不推测补造”和“撤销负责人权限时仍需检查独立共享授权”。

![项目记忆按仓库与类型查看，保留可复用的项目经验。](/assets/guides/studio/memory.png)

记忆保存在仓库的 `.nb-studio/memory/`，随 PR 评审和合并。将“请长期记住这条已确认规则”写在任务里，由 Agent 判断如何记录；审核时删除重复、过时或不准确的内容。不要把密钥、客户隐私或临时进度写成记忆。详见[项目记忆](../studio/project/project-memory.md)。

**完成的标志**：业务规则有明确来源，检查方法绑定到项目，长期经验随代码保存，下一次任务能读到一致的背景。
