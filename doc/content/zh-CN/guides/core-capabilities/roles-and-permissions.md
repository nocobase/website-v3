当销售团队多人共用同一个 CRM 应用时，通常不希望销售互相修改彼此的客户或随意改动产品价格；主管需要查看并分配全部客户，而在多人协作或客户交接时，又需要临时只读共享或转移负责人。你将为 CRM 应用配置销售和销售主管两类角色，分别限定页面入口、业务操作和客户数据范围，并验证只读共享、负责人交接以及直接调用接口时的权限边界。

你可以在自己的 NocoBase Core 项目中跟着配置，也可以运行[完整 CRM 示例](https://github.com/nocobase/doc-demo-crm/blob/main/README.MD)直接查看配置好的角色与共享效果。

## 确定销售和主管的职责

将“能做什么”和“能处理哪些记录”分开确定。能打开客户页面，不代表能修改任意客户；获得某个客户的共享，也不代表能修改它。

| 行为                                   | 销售                                     | 销售主管             |
| -------------------------------------- | ---------------------------------------- | -------------------- |
| 新建客户                               | 可以，新客户归自己                       | 可以，并可分配负责人 |
| 查看客户及相关记录                     | 自己负责的客户，以及明确共享给自己的客户 | 全部客户             |
| 修改客户、联系人、商机和报价，添加跟进 | 仅自己负责的客户                         | 全部客户             |
| 查看共享客户                           | 只读                                     | 可以管理             |
| 分配负责人、建立或撤销共享             | 不可以                                   | 可以                 |
| 查看产品目录                           | 可以                                     | 可以                 |
| 维护产品目录                           | 不可以                                   | 可以                 |

Core 的[权限管理](../../core/using-plugins/authorization/permissions.md)同时限制操作和记录范围。例如，销售可以修改客户，但只能修改自己负责的客户。主管可以维护全部客户。

联系人、跟进、商机和报价都遵循所属客户的权限。工作台数量、搜索结果和最近跟进也只能包含有权查看的数据。这些规则需要由应用接入，不能只隐藏页面按钮。

角色把一组职责赋予用户，操作权限决定能做什么，数据范围决定能对哪些记录执行该操作。读取和修改的范围可以不同：销售能读取共享客户，却只能修改自己的客户。共享只追加记录范围，不授予操作权限。

[默认数据范围](../../core/using-plugins/authorization/default-access.md)用于给已有操作权限的用户追加共同可访问的记录范围，例如公开客户；它不是“只能访问自己的客户”的同义词。本专题按角色和负责人限定范围，再向指定销售共享客户。

## 在系统设置中配置菜单、业务对象和数据范围

管理员打开 **系统设置 → 角色和权限 → 角色**，编辑示例预置的 **销售** 或 **销售主管**。按以下三处核对角色。修改后点击 **检查并保存**，核对变更，再确认保存。

| 编辑位置     | 在 CRM 中怎么配                                                                                                                                                                  |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **页面访问** | 销售工作台、客户、产品和我的任务各有独立的入口权限。勾选页面后，编辑器会选中它用到的操作。在「业务操作」里核对并取消岗位用不到的操作。                                           |
| **业务操作** | 分别展开客户、联系人、跟进、商机、报价、产品和客户批量导入。销售的客户及关联对象选择「我负责的客户」，产品可查看全部，导入批次选择「我提交的批次」。主管的相应范围选择全部记录。 |
| **系统设置** | 单独配置集成和工作流等管理权限。例如，销售主管可以处理分配给自己的报价审批，修改审批流程配置需要另行授权。                                                                       |

![销售角色的业务操作页。客户、联系人和商机的查看范围为「我负责的客户」，分配负责人和管理共享均未勾选。](/assets/guides/crm-sales-role-operations.png)

在 **报价** 下，编辑、提交、撤回、通过、拒绝、退回和生成正式单据可以分别勾选。销售可以提交自己的报价；主管要处理审批，还需是该任务的处理人。新建报价要选择已有产品，给销售保留产品的「查看」，并核对报价操作中的产品范围。附件、提醒和销售助手的操作在 **客户** 下配置。邮件和知识库沿用各自的权限。

示例源码中的[业务授权定义](https://github.com/nocobase/doc-demo-crm/blob/main/server/providers/crm-permissions.ts)和[角色编辑器配置](https://github.com/nocobase/doc-demo-crm/blob/main/client/pages/settings/permission-workspace.ts)分别声明可执行的操作及其在编辑器中的位置。

如果从基础 CRM 开始练习，可以请 Agent 按上述职责配置角色：

```prompt
在系统设置的角色编辑器里配置销售和销售主管。销售工作台、客户、产品和我的任务可以分别开放，联系人、跟进、商机和报价也可以分别授权。

- 销售只能维护自己负责的客户，新建客户归自己。
- 主管可以维护全部客户、分配负责人，也可以把客户只读共享给指定销售，再撤销共享。
- 只读共享的客户可以查看，不能修改。联系人、跟进、商机和报价都遵循所属客户的访问范围。
- 销售可以查看产品，主管可以维护产品。
- 管理员能给选定用户分配角色。不要让所有登录用户自动获得 CRM 权限。
```

## 给用户分配角色

管理员打开 **系统设置 → 账号与权限 → 用户管理**，编辑 Alex 和 Taylor，给两人分配 **销售**，再给 Morgan 分配 **销售主管**。在用户列表的角色列核对结果，并检查测试账号已有的授权，避免额外角色扩大访问范围。

下面的验证步骤用 Alex 和 Taylor 表示两位销售，Morgan 表示主管。名称可以替换，但验收时要使用三个不同用户和独立浏览器会话。在自己的测试环境中设置密码，不写入源码或截图。

## 验证角色权限与客户共享

### 在界面中体验客户归属与只读共享

使用 Morgan、Alex 和 Taylor 三个独立浏览器会话，选一条包含联系人、跟进与报价的客户记录（例如 **Northstar Labs → Northstar sales workspace → Annual rollout proposal**，可参考[数据建模与表结构变更](data-modeling.md#接入业务操作与事务保存)和[搭建业务页面](pages-and-ui.md#继续跟进客户并查看报价)准备，或直接使用示例数据）。开始前确认 Northstar Labs 没有额外共享，再按顺序完成以下四步：

| 操作 | 立即核对的结果 |
| --- | --- |
| Morgan 打开 Northstar Labs 的 **概览**，将负责人设为 Alex | Alex 可打开并编辑该客户及其商机、报价；Taylor 在列表、搜索和工作台中均看不到该客户 |
| Morgan 在 Northstar Labs 的 **只读共享** 中选择 Taylor 并保存（负责人仍为 Alex） | Taylor 能查看该客户、已有跟进和报价，但没有可用的编辑或新增入口 |
| Morgan 撤销 Northstar Labs 对 Taylor 的共享 | Taylor 刷新后无法继续读取该客户和报价，搜索和工作台数量也不再包含其记录；Alex 仍可维护 |
| 确认撤销生效后，Morgan 将 Northstar Labs 的负责人改为 Taylor（不再给 Alex 共享） | Taylor 可维护该客户及其关联记录，原联系人、跟进和报价内容保持不变；Alex 刷新后失去访问 |

[共享规则](../../core/using-plugins/authorization/sharing-rules.md)只追加记录访问范围，不授予操作权限；Taylor 的角色仍需保留对应对象的「查看」（例如关闭报价查看后，即使客户共享仍有效，也无法打开报价或下载报价单）。先验证撤销共享再转移负责人，是因为 Taylor 成为负责人后，即使没有共享也拥有访问权。

### 让 Agent 自动检查其余权限与接口边界

页面按钮是否隐藏不足以证明权限正确。产品目录写限制、无角色或未登录拦截以及直接调用接口等边界检查，不必在浏览器里逐项手工切换账号，直接交给 Agent 用独立测试账号完成：

```prompt
请用独立的销售、主管和无 CRM 角色账号测试权限边界，不要用管理员代替销售，并直接调用接口确认：
- 销售不能新增产品或修改价格，主管可以；无 CRM 角色的用户和未登录访客不能访问客户数据。
- 销售不能读取或修改他人负责且未共享的客户，只读共享用户不能修改共享客户。
- 撤销共享或转交负责人后，原用户再次读取或重发之前的保存请求都会被拒绝；工作台数量与关联记录始终与客户范围一致。
```

重发保存请求时，应保留原登录身份与完整请求（包括请求标识），确认权限变更后会重新校验，而不会沿用先前的成功结果。如果检查未通过，先核对用户详情中的角色分配，再检查角色的操作权限与数据范围，不要通过授予管理员角色让测试通过。

**完成的标志**：已在界面中走通客户归属、只读共享、撤销与交接，并由 Agent 用独立账号验证了产品目录、未授权访问和直接调用接口的权限边界。

要为报价设置审批流程，可参考[审批流程与待办](approval-workflows.md)。
