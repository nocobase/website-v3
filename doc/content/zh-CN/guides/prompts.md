---
title: 常用提示词
metaDescription: 按场景整理的提示词模板：创建应用、写设计文档、提需求、先出方案、验收与打回、交接给新会话、写规则、升级、部署和评审。
---

尖括号里的内容换成你自己的。

## 创建应用

```prompt
在当前目录创建一个 NocoBase 3 应用，数据库用 SQLite。启动后告诉我访问地址和登录账号。
```

## 聊设计

```prompt
我要做一个<系统>，先不写代码，和我把设计聊清楚。
<角色和主要流程，两三句话>
有需要我决策的问题就问，一次问一组，每个问题给出你的建议。
```

## 写成设计文档

```prompt
把定下的设计写进 docs/design.md：角色、数据、流程、页面、权限，以及分步交付计划和每步的验收标准。
在 AGENTS.md 里登记它：做业务改动前先读；需求改变了设计时，先更新它再改代码。
```

## 提需求

```prompt
<谁在用，要做什么>
<有哪些规则：谁能做什么，哪些数据不能动>
```

## 先出方案

```prompt
先不改代码，列出这次要改哪些部分、需要我决策的问题，以及打算怎样验证。
```

## 打回

```prompt
<功能>有问题：用<账号><操作步骤>，看到<实际结果>，应该是<预期结果>。修好后用同一个账号再看一遍，附截图。
```

## 评审

换另一家厂商的模型开一个会话：

```prompt
评审当前未提交的改动，按 AGENTS.md 的约定找问题，按严重程度列出，不要改代码。
```

## 交接给新会话

```prompt
先读 AGENTS.md、docs/design.md 和最近的提交，告诉我这个应用做到哪了、还有什么没做。然后做：<需求>。
```

## 把约定写进规则

```prompt
把这条约定记到 .agents/rules/<主题>.md，并在 AGENTS.md 的索引里登记，写明什么时候读它：
<约定>
```

## 升级 NocoBase Core

```prompt
把 NocoBase 升级到最新版本。先给我升级计划，我确认后再改；改完跑全部测试，确认业务数据都还在。
```

## 部署

```prompt
用 Docker 把这个应用部署到服务器 <用户>@<服务器地址>，目录 <路径>，访问地址 https://<域名>/<路径>/，数据库用新的空库。
配置和数据放在部署目录里，重建容器不能丢。管理员密码我单独给你，不要写进代码和报告。
部署后登录、新建一条数据、重建容器，确认数据还在。最后告诉我还有哪些没配好，例如 HTTPS。
```

## 其他团队提需求

```prompt
我要给研发提一个需求：<一句话>。先问我几个问题，写成需求文档，再做一个单文件的 HTML Demo 展示主要页面。
```
