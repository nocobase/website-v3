---
title: 常用提示词
metaDescription: 按场景整理的提示词模板：创建应用、写设计文档、提需求、先出方案、验收与打回、交接给新会话、写规则、升级、部署和评审。
---

尖括号里的内容换成你自己的。

## 创建应用

```prompt
在当前目录创建一个 NocoBase 3 应用，用于本地开发，数据库用 SQLite。
创建好后启动它，告诉我访问地址和首次登录的账号。
```

## 聊设计

```prompt
我要在这个应用里做一个<系统>，先不要写代码，先和我把设计聊清楚。
<角色和主要流程，两三句话>
请先问我需要决策的问题，一次问一组，每个问题给出你建议的答案。
```

## 写成设计文档

```prompt
把刚才定下的设计写进 docs/design.md，包括：目标、角色、核心对象和字段规则、主要流程和规则、通知、页面、权限矩阵、设计规范、这一版做与不做、分步交付和每步的验收标准。
在 AGENTS.md 的索引里登记这份文档，写明做任何业务改动前先读它；需求改变了设计时，先更新它再改代码。
```

## 提需求

```prompt
<要做什么>。
<谁在什么地方使用，希望完成什么>
<规则和边界：谁能做、什么情况不能做，直接调用接口也要被拒绝>
<失败时怎么办>
验收：<用哪个账号做什么，看到什么结果>
完成后把自动检查和实际操作分开报告：自动检查写明跑了哪些命令、多少用例；实际操作写明用哪个账号做了什么、看到了什么，附截图；没验证的单独列出。
```

## 先出方案

```prompt
先不要改代码。请阅读 docs/design.md 和相关实现，列出这次要改哪些部分、需要我决策的问题，以及打算怎样验证。
```

## 打回

```prompt
<功能>有问题，请修复：
1. 用<账号>登录，<操作步骤>，看到<实际结果>。预期<预期结果>。
修复后补测试覆盖这种情况，并用同一个账号在页面上再看一遍，附截图。
```

## 评审

换另一家厂商的模型开一个会话：

```prompt
请评审当前未提交的改动（git diff）。先阅读 AGENTS.md，按项目的约定检查缺陷、安全、权限和测试。
只指出问题和修改建议，按严重程度排序，不要直接修改代码。
```

## 交接给新会话

```prompt
先不要改代码。读 AGENTS.md、docs/design.md 和最近 10 个提交，告诉我：这个应用现在有哪些功能，最近一次改了什么，对照设计文档的范围还有什么没做。
然后做下一个需求：<需求>。
```

## 把约定写进规则

```prompt
把这条约定记到 .agents/rules/<主题>.md，并在 AGENTS.md 的索引里登记，写明什么时候读它：
<约定>
```

## 升级 NocoBase Core

```prompt
把 NocoBase 升级到<版本>，按项目的升级技能做。
先给我计划，不要改文件：两版模板改了哪些文件、其中哪些应用也改过、依赖怎么变、数据库有没有要执行的迁移、出了问题怎样回退。
我确认后在新分支上合并；完成后跑全部测试和构建，并确认开发数据库里的业务数据都还在。
```

## 部署

```prompt
用 Docker 把当前应用首次部署到下面的服务器，按项目的部署技能和 Dockerfile 做。

服务器：<用户>@<服务器地址>，平台 linux/amd64
部署目录：<服务器上的绝对路径>/<应用>
数据库：<数据库>，新建空库，不带开发环境的数据
服务器本地监听：127.0.0.1:13000
访问地址：https://<域名>/<路径>/

镜像只放代码和依赖；config.yml 和 storage 放在部署目录，挂载进容器，重建容器后不能丢。
管理员密码我单独告诉你，不要写进代码、镜像或报告。缺配置或存储位置时停下来问我。
启动后检查健康接口，用管理员登录，新建一条数据，再重建容器，确认数据还在。
完成后告诉我访问地址、镜像标识、验证结果，以及域名、HTTPS 等还没完成的配置。
```

## 其他团队提需求

```prompt
我要给研发提一个需求：<一句话>。先问我问题，帮我写成需求文档：谁在什么地方使用、希望完成什么、规则和边界、失败时怎么办、验收标准。
再做一个单文件的 HTML Demo，展示主要页面，数据写死即可。
```
