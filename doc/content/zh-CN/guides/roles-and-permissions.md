上一步三个角色已经能走通流程，但谁能看到哪些记录还没细化。这一步对照设计文档第 6 节的权限矩阵，换账号逐项检查，发现问题再让 Agent 改。

## 1. 换账号检查

用 Alice（员工）、Ben（IT 支持）、Cathy（资产管理员）分别登录，对照这张表：

| 检查 | 期望 | 实际 |
| --- | --- | --- |
| Alice 的「领用申请」 | 只有自己的申请 | 能看到所有人的申请 |
| Alice 的「设备台账」 | 只有自己名下的设备 | 能看到全部设备 |
| Ben 打开待审批的申请 | 没有「批准」「驳回」 | 有「批准」，点了提示没有权限 |
| Cathy 打开待发放的申请 | 没有「发放」 | 有「发放」，点了提示没有权限 |
| 系统管理员打开「权限管理」里的员工角色 | 能看到每个业务操作和数据范围 | 只有页面访问 |

![IT 支持看到「批准」，点击后被拒绝](https://static-docs.nocobase.com/20261030-itam-lite-roles-it-support-approve-denied.webp)

Ben 点「批准」被拒绝，说明接口本身是对的：每个动作在服务端单独授权，没有权限就返回 403。按钮只是没跟着角色隐藏。反过来也一样，**按钮隐藏不等于接口拒绝**：只藏按钮、不在服务端检查，任何人都能直接调接口越权。所以验收权限要两头都查：页面上看不到，接口也拒绝。

## 2. 提修改意见

```prompt
按 docs/design.md 第 6 节的权限矩阵修正权限：
1. 员工只能看到自己提交的申请、只能撤回自己的申请，设备台账里只看到分配给自己的设备。已经安装的应用要一起更新；管理员在权限管理里改过的角色不要覆盖。
2. 申请详情只显示当前角色有权限的操作：IT 支持看不到批准、驳回，资产管理员看不到发放。
3. 在「权限管理」的角色编辑里显示设备、领用申请的每个业务操作和数据范围，流程管理的查看、修改也能在那里配置。
验收：用员工、IT 支持、资产管理员的普通账号直接调用接口（不经过页面）写成测试：员工读不到别人的申请（404）、不能审批和发放（403）、不能新建和修改设备（403）；IT 支持不能审批、不能删除设备；资产管理员不能发放；三个角色都打不开流程管理。
```

Agent 的改法：

| 问题 | 改法 |
| --- | --- |
| 员工能看到全部 | 新增一个种子数据，把员工角色的查看、撤回改为“我提交的申请”，设备改为“分配给我的设备”；只在角色还是初始内容时才改 |
| 按钮没跟着角色 | 申请详情接口返回当前角色能做哪些操作，页面只显示流程允许、角色也允许的按钮 |
| 权限管理里看不到业务操作 | 在权限编辑器里登记两组业务操作和流程管理的设置项 |
| 接口越权 | 新增权限测试，用三个普通账号直接调用接口，覆盖上面的验收项 |

种子数据由 Agent 运行 `pnpm nocobase db apply` 写入正在使用的数据库。

## 3. 再检查一遍

Alice 只看到自己的三个申请和名下的两台设备；Ben 打开待审批的申请，只显示“这个申请现在没有需要你处理的操作”。在 Alice 的浏览器控制台里直接调用审批接口，仍然返回 403。

![员工只看到自己的申请](https://static-docs.nocobase.com/20261030-itam-lite-roles-employee-own-requests.webp)

系统管理员在「系统设置 › 权限管理」里编辑员工角色，「业务操作」里列出每个操作和它的数据范围，之后可以直接在这里调整。

![角色的业务操作和数据范围](https://static-docs.nocobase.com/20261030-itam-lite-roles-business-operations.webp)

权限怎样声明、检查和验证，见 [认证与权限](../core/developing-apps/authentication-and-permissions.md)；权限管理页面见 [权限](../core/using-plugins/authorization/permissions.md)。

## 4. 提交

```bash
git add -A && git commit -m "feat: limit each role to its own records and actions"
```

**完成的标志**：三个账号登录后看到和能做的与权限矩阵一致；权限测试里，普通账号直接调用越权接口全部被拒绝；权限管理里能看到并调整每个业务操作和数据范围。
