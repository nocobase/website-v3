业务规则和踩坑经验如果只留在零散任务里，换人或换 Agent 很快就会重复提问甚至破坏旧约定。下面假设 CRM 项目已经确定了一组报价版本与客户交接规则（自有项目可换成团队已确认的规则），把它们分别放进 Studio 的知识库、技能和项目记忆中。

开始前，准备一个已接入 Studio 的项目（具备项目知识维护与技能管理权限）以及待沉淀的业务规则。三类资料的分工如下：

| 位置 | 保存什么 |
| --- | --- |
| 知识库 | 人维护的业务规则、制度及决策背景 |
| 技能 | 开发、验证和评审时应遵循的方法 |
| 项目记忆 | Agent 随任务自动沉淀、随代码维护的项目约束、踩坑与经验 |

这里的资料服务于 Studio 中的开发协作；CRM 应用内供销售查询的业务知识库属于应用功能，不会自动互通。

## 将 CRM 业务规则与决策放进知识库

打开 CRM 项目的 **知识库**，在项目空间新建“CRM 业务规则”文章并写入已确认的规则，保存后在权限设置中给业务负责人 Morgan 授予编辑权限（详见[知识库](../../studio/project/knowledge-base.md)）：

- 已提交的报价版本不可修改，后续调整创建新草稿；历史金额不随产品目录价格变化。
- 旧报价保留已有编号和内容，不补造过去的修订记录。
- 主管可以交接客户，记录原因、操作人和时间；原跟进作者和报价历史保持不变。
- 原负责人失去基于归属的访问权；继续协助时，由主管显式设置只读共享。

![CRM 项目知识库中可阅读验收规则，并查看文档的维护信息（界面为示例项目展示）。](/assets/guides/studio/knowledge.png)

在 CRM 项目页点 **问 Agent**（或在绑定了 CRM 项目的 **我的会话** 中）验证：

```prompt
客户交接后，原负责人还能查看吗？请根据项目知识库说明条件，并给我对应的资料。
```

**步骤检查**：Agent 的回答与文档一致并能指出依据；不能读取时，检查发起人的知识库访问权限。

## 建立 CRM 开发与评审检查清单

在绑定 CRM 项目的会话（或已接入 Studio 的本地 Coding Agent）中，先让 Agent 起草清单：

```prompt
根据我们在 CRM 报价版本和客户交接中总结的经验，整理一份以后改进 CRM 时都要核对的清单，重点检查客户访问范围、历史报价是否保留，以及交接记录是否完整。先给我看内容。
```

好的清单应给出可执行检查方法，而不是泛泛写“注意权限”：

| 检查对象 | 检查方法 |
| --- | --- |
| 客户及关联记录 | 用负责人、无权销售和主管分别检查页面与接口 |
| 已提交报价 | 修改新草稿和产品目录后，核对旧版本内容与金额 |
| 交接和共享 | 检查撤销后的访问变化，以及显式只读共享的限制 |
| 已有数据升级 | 保留升级前样本，核对客户关系、原作者与历史记录 |

确认内容后，直接让 Agent 建成技能并挂到项目上：

```prompt
把这份确认好的检查清单建成 Studio 技能 crm-checklist，用于 CRM 开发、自测和评审，并挂载到 CRM 项目的默认技能里。
```

也可以在左侧 **Agent 管理 › 技能** 手动创建 `SKILL.md`，再到项目 **设置 › 默认技能** 添加并保存（格式与权限见[技能](../../studio/project/skills.md)）。

![项目默认技能可绑定指定仓库，并管理当前项目采用的技能（界面为示例展示）。](/assets/guides/studio/default-skills.png)

**步骤检查**：CRM 项目的默认技能中已挂上 `crm-checklist`；后续任务的 **运行记录** 和 **交付报告** 中能看到对应的实际检查。仅挂载不代表已执行。

## 让 Agent 自动沉淀项目记忆

与需要人手动维护的知识库不同，项目记忆不需要逐条手写。Agent 在完成任务的过程中，会自动总结值得长期复用的项目经验——例如反复出现的 bug 成因、性能隐患、被人纠正过的做法、代码中看不出的业务约束（如“旧报价没有修订历史，不推测补造”“撤销负责人权限时仍需检查独立共享授权”）以及外部资料位置——并以单条文件的形式写入当前任务分支的 `.nb-studio/memory/`。普通改动如果没有新的长期结论，Agent 不会强行记录；当旧记忆与最新代码不再一致时，Agent 也会在任务 PR 中自动修改或删除。

如果你希望把某次讨论确认的规则或踩坑教训明确留下来，也可以在任务评论中直接告诉 Agent 长期记住这条结论。

记忆文件会随任务 PR 一起提交和评审。验收时点击 **看改动**，顺带核对 `.nb-studio/memory/` 的新增或修改内容，删去不准确、过时或多余的条目（不要写入密钥、客户隐私或临时进度）。**该 PR 合并后**，打开 CRM 项目的 **记忆** 页签即可按仓库和类型查看已沉淀的条目及来源提交（刚接入的新项目初始为空属正常）；后续任务开工前，Agent 会自动读取这些记忆，避免在相同问题上重复踩坑（详见[项目记忆](../../studio/project/project-memory.md)）。

![项目记忆按仓库与类型查看，保留可复用的项目经验（界面为示例展示）。](/assets/guides/studio/memory.png)

**完成的标志**：业务规则有明确来源，检查清单已挂载到项目，任务中自动沉淀或补充的长期经验随代码 PR 合并保存，后续任务能读到一致的背景。

## 小结与下一步

业务规则、开发评审清单和长期约束分别落位后，无论换人接手还是切换 Agent，项目都具备可查阅、可执行的统一基准，不再依赖口头提醒。

接下来，如果想在发版前通过持续测试与问题跟踪系统把关质量，继续阅读[管理交付质量](enterprise-management.md)；若已准备好验证并上线，可直接进入[发布到生产](release.md)。
