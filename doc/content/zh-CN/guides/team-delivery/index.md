适合已经在 Studio 中或准备引入 Studio 开展多人开发的团队。通过本系列，你可以把已有 Core 代码仓库接入 Studio，让业务同事直接参与需求与验收，将业务规则沉淀为团队资产，并把代码更新安全推进到测试与生产环境。

## 开始前的准备

开始本系列前，确认具备以下条件：

- **Studio 环境与账号**：已部署并可登录的 Studio 工作台，至少有一台在线运行环境和可用 Agent。尚未搭建时，管理员按[安装与配置](../../studio/setup/index.md)完成部署、[Git 平台连接](../../studio/setup/git.md)与 [Agent 配置](../../studio/setup/agents.md)；已加入团队的成员按[加入项目](../../studio/join/index.md)登录。
- **代码仓库与项目**：手头已有 NocoBase Core 仓库时，可从第一篇接入 Studio；已有接入好的 Studio 项目，可直接进入后续协作与发布课程。
- **团队成员与环境权限**：业务同事参与相关课程需要独立的 Studio 账号与成员邀请权限；发布相关课程需要配置好[检查与预览](../../studio/setup/ci.md)、[托管环境](../../studio/admin/environments.md)及对应的发布权限。

> [!NOTE]
> 如果是首次接触 Studio、希望先体验单个需求的完整流程，可先阅读[使用 Studio 协作开发](../../getting-started/collaborate-with-studio.md)。

## 课程列表

除第一篇用于将已有仓库接入 Studio 外，其余各篇均围绕独立的团队协作环节展开，可按团队当前阶段直接选用，无需按固定顺序全部做完。

| 课程 | 完成后的结果 | 开始条件 |
| --- | --- | --- |
| [将已有项目接入 Studio](../open-crm-project.md)（准备中） | 将已有代码仓库连接至 Studio，配置检查来源与 PR 预览，准备团队协作迭代。 | Studio 工作台可用，具备目标代码仓库访问权限，且有在线运行环境与可用 Agent。 |
| [让业务同事直接参与需求](../business-colleagues.md) | 业务负责人在 Studio 中直接提出需求、回答规则问题并在预览环境完成验收。 | 已接入 Studio 的项目、业务同事账号与成员邀请权限。 |
| [沉淀业务规则与开发经验](../capture-knowledge.md) | 将已确认的业务规则、设计决定与评审检查清单整理进项目知识库与记忆。 | 已启用知识库的 Studio 项目，以及待沉淀的业务规则或团队约定。 |
| [使用 Studio 管理质量](../enterprise-management.md)（准备中） | 通过持续测试、核心场景检查与问题跟踪管理多人和 Agent 并行开发的交付质量。 | 已接入 Studio 的项目（具体配置随课程发布）。 |
| [发布更新并维护已有应用](../release.md) | 在测试环境验收候选版本并发布到生产，同时保留已有业务数据。 | 已接入 Studio 的项目、候选提交、测试与生产环境及发布权限。 |
