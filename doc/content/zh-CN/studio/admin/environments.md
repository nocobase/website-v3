管理员在「托管环境」中添加和维护环境。每个环境用于预览或测试，包含独立的应用、变量和运行策略。

![预览与测试环境的运行方式和策略](https://static-docs.nocobase.com/studio-zh-environments-20261111-normal-2x.webp)

## 添加环境

1. 点「添加环境」，填写名称与 ID，例如「测试」、`staging`。
2. 选择用途和运行方式。
3. 设置访问地址规则，例如 `https://apps.example.com/{appId}/`。使用子域名时准备对应 DNS 和证书。
4. 按需要设置应用容量、停止和休眠时间，测试连接后保存。

默认的「在 Studio 内运行」使用应用子进程，适合压缩包制品。启用 Docker 托管后，也可将测试应用运行在独立容器中；此方式使用镜像制品，并需要配置镜像仓库和拉取权限。相关开关见[配置参考](../reference/config.md)。

生产在团队自己的环境部署，不在此处创建生产托管环境。

## 交付测试应用

在托管环境或项目的发布页添加测试应用，也可以由 CI 首次上报时创建。部署对话框提供给 Agent 的提示词、CI 配置和手动命令。

持续测试可使用分支推送触发 CI，见[检查与 CI](../configure/checks.md)。应用详情提供部署记录、日志、停止、唤醒和删除操作。

## 配置变量

环境变量对其中所有应用生效，单个应用的同名变量优先。必填变量缺失时，部署会停止并列出缺项。修改变量后，在应用中执行「应用并重启」。

密钥加密保存，保存后不再显示。应用变量与开发任务的[Agent 运行变量](../project/settings.md#agent-运行变量)分别配置。

## 受保护的环境和审批

需要限制测试交付时，启用「受保护」并指定审批人。部署和回滚转为申请，由审批人在收件箱确认具体应用和制品后批准。API 密钥可提交申请，Agent 不能部署到受保护环境。

## 回滚

在应用的部署记录中选择之前的版本回滚，或使用 `nb-studio app rollback`。受保护环境仍需审批。

回滚不会自动恢复数据库。测试数据需要保留时，部署前先备份。回滚后的任务部署标记重新计算，任务状态不会自动改变。
