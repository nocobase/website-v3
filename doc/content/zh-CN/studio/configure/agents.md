---
title: Agent 配置
description: 启用运行环境上报的模型，设置工作分工，并为调度 Agent 选择首选和备选。
---

先确认[运行环境](../setup/shared-runtimes.md)在线，编码工具已登录。管理员在「Agent 管理 › Agent」完成以下配置。

## 检查 Agent 团队

每个“编码工具 · 模型”组合对应一个 Agent。运行环境上报模型后，常用模型会自动加入列表并启用。

![运行环境上报并启用的 Agent 团队](https://static-docs.nocobase.com/studio-zh-setup-agents-full-1440x900-20261030.png)

检查「在哪跑」是否包含刚接入的运行环境。点「编辑」，调整「擅长什么」和推理强度。分工描述应简短、具体，例如：

| 工作方向 | 「擅长什么」示例 |
| --- | --- |
| 方案与评审 | 方案设计、疑难排查和代码评审 |
| 功能开发 | 常规功能开发、跨模块改动和重构 |
| 小范围修改 | 小改动、补测试和分析 CI 失败 |

调度 Agent 根据这些描述分派工作。推理强度由管理员设置，调度 Agent 不会在分派时修改它。

## 添加模型

1. 点「添加 Agent」。
2. 从运行环境上报的模型中选择所需模型。
3. 填写「擅长什么」，点「添加」。

模型显示「需要设置」或「版本过低」时，先在运行环境上处理，再重新检测。建议启用两家厂商的 Agent，让开发和评审使用不同模型。

仅由个人运行环境提供的 Agent，只能执行该成员发起的任务。

## 设置调度 Agent

所有项目共用一个调度 Agent。它负责分派工作、读取结果和安排下一步，本身也需要选择一个可运行的 Agent。

1. 在页面上方的「调度 Agent」中点「设置」。
2. 「首选」选择适合推理和任务规划的 Agent。
3. 「备选」选择另一个 Agent。
4. 保存，其他设置先保留默认值。

![为调度 Agent 设置首选和备选模型](https://static-docs.nocobase.com/studio-zh-setup-coordinator-full-1440x900-20261030.png)

首选排队超过默认的 120 秒时，空闲的备选可以接手。没有运行环境能执行首选时，直接使用备选。

分配原则和任务流转见[Agent 团队怎样工作](../intro/agent-team.md)。


## 调整团队

不再使用的 Agent，可以在「编辑」中关闭「启用」。勾选「显示已停用」后可以重新启用。某个模型不再由运行环境提供时，先检查工具和运行环境状态，再调整分工。
