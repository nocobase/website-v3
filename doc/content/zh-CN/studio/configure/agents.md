管理员打开「Agent」。运行环境上报的每个“编码工具 · 模型”组合都可配置为一个 Agent。首次接入见[配置 Agent](../setup/agents.md)。

![Agent 团队的分工、运行环境和推理强度](https://static-docs.nocobase.com/studio-zh-guide-agents-20261031.png)

## 设置工作分工

点「编辑」，填写「擅长什么」，并选择推理强度。调度 Agent 根据能力描述分派工作，不会自行修改推理强度。

| 工作方向 | 描述示例 |
| --- | --- |
| 设计与评审 | 方案设计、疑难排查和代码评审 |
| 功能开发 | 常规实现、跨模块改动和重构 |
| 小范围修改 | 小改动、补测试和分析 CI 失败 |

「在哪跑」显示能提供该模型的运行环境。仅在个人运行环境可用的 Agent，只为该环境的所有者工作。

## 添加与停用

点「添加 Agent」，选择运行环境上报的模型，填写能力描述。模型提示需要设置或版本过低时，先在运行环境中处理，再重新检测。

在编辑中关闭「启用」可暂停分派。勾选「显示已停用」后可以重新启用。模型从列表中缺失时，检查编码工具登录状态和运行环境连接。

## 设置调度 Agent

所有项目共用一个调度 Agent。在页面上方点「设置」，选择首选和备选模型，设置分配原则及任务运行上限。

![选择调度 Agent 的首选与备选](https://static-docs.nocobase.com/studio-zh-guide-coordinator-20261031.png)

首选排队超过配置的时间后，空闲的备选可以接手，默认等待 120 秒。没有可执行首选的运行环境时，直接尝试备选。

分配原则决定选谁，项目[技能](../project/skills.md)决定怎样开发、评审和交付。完整流程见[Agent 团队怎样工作](../reference/agent-execution.md)。
