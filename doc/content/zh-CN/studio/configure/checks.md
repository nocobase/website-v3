description: 选择检查来源，接入自动验证、PR 预览和测试环境交付。
---

打开「项目设置 › 代码仓库」，点仓库卡片上的「检查」。每个仓库选择一个检查来源，Studio 只采用该来源的结果。

| 来源 | 执行方式 | 预览发布者 |
| --- | --- | --- |
| 代码平台 CI | GitHub Actions、GitLab CI 等 | 同一流水线 |
| 外部 CI | Jenkins 或已有 CI 服务 | 外部流水线 |
| Agent 自检 | Agent 按项目脚本和开发规范验证 | 执行任务的 Agent |

![为仓库选择检查来源和预览方式](https://static-docs.nocobase.com/studio-zh-guide-ci-20261031.png)

## Agent 自检

选择后保存，无需 CI 文件。Agent 运行项目要求的检查，用 `nb-studio check report` 逐项上报，再构建并发布 PR 预览。

自检结果由执行工作的 Agent 上报。需要独立流水线验证时，选择代码平台或外部 CI。

## 代码平台 CI

以 GitHub Actions 为例：

1. 选择检查来源，设置触发方式和目标环境。
2. 填写应用目录，仓库根目录填 `.`，并设置应用 ID。
3. 复制给 Agent 的提示词，交给能访问仓库的 Coding Agent。
4. Agent 添加 CI 文件并配置密钥，提交后检查流水线结果。

| 触发方式 | 用途 |
| --- | --- |
| Pull request | 创建 PR 预览 |
| 推送到分支 | 更新测试环境 |
| 标签 | 将版本交付到测试环境 |

每次生成一种触发方式的配置。需要多种时分别接入。手动配置可展开页面中的命令和 CI 文件；GitHub 使用 Actions 密钥 `NB_STUDIO_API_KEY`。

CI 必须能访问 Studio。云端 CI 无法访问本机地址，需要可达的 HTTPS 地址或自托管执行机。测试目标先在[托管环境](../admin/environments.md)中配置。

## 外部 CI

选择 Jenkins 或其他 CI，按页面说明生成仓库 CI 密钥。将 Studio 地址和密钥保存为流水线变量，再采用页面生成的脚本。脚本上报检查开始、结果和日志链接，并按需要发布预览。

CI 密钥只在生成时显示，不应提交到仓库。密钥属于组织，默认 90 天到期。负责人和管理员会收到到期提醒；更新密钥后同步修改流水线配置。

## 验证接入

提交一个 PR，检查仓库卡片中的构建记录。任务的「代码与预览」应显示检查结果和预览链接。打开预览验证应用可用。

「还没收到上报」表示当前来源尚无结果。预览缺少变量时，按页面提示在环境或应用中补齐。无需预览的任务可在任务属性中选择「不需要预览」，CI 模板会按 `no-preview` 标签跳过。

检查如何参与任务流转，见[检查与评审](../project/checks-and-review.md)。
