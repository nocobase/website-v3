在「项目设置 › 代码仓库」中分别修改「检查」和「预览环境」。例如，GitHub Actions 可以提供检查结果，Agent 可以为同一个 PR 发布预览。

![在仓库的「检查」中选择 GitHub Actions](https://static-docs.nocobase.com/studio-guide-zh-checks-20261127-10558ddc7784.webp)

## Agent 自检

新仓库默认使用 Agent 自检。Agent 按项目脚本运行检查，用 `nb-studio check report` 上报每项结果。要让 Agent 同时发布预览，在「预览环境」中选择「Agent 构建」。

## 代码平台 CI

已有 GitHub Actions、GitLab CI 或 Gitea Actions 时，在「检查」中选择代码平台并保存。Studio 从关联 PR 或 MR 读取平台上已有的检查。

如果还要由 CI 发布预览：

1. 在「预览环境」中选择「CI 构建」。
2. 将仓库的 CI 密钥保存为流水线的 `NB_STUDIO_API_KEY`，设置可从执行机访问的 `NB_STUDIO_URL`。外部 CI 上报检查和发布预览可以共用同一把仓库密钥。
3. 按面板提供的配置，为 PR 添加构建任务。使用已有流水线时，按面板列出的步骤构建部署包并发布。保存后，用一个 PR 验证。

使用代码平台自带的流水线时，选择触发条件、目标环境和应用目录（仓库根目录填 `.`）。PR 触发用于预览，分支推送或标签可部署到[测试环境](../admin/environments.md)。每种触发方式分别生成配置。运行流水线的机器必须能访问 Studio。

![在「CI 构建」中查看仓库密钥和流水线配置](https://static-docs.nocobase.com/studio-guide-zh-ci-build-20261127-83f163c60fa7.webp)

## 外部 CI

在「检查」中选择「外部 CI」，将仓库 CI 密钥保存为流水线的保密变量。使用生成的脚本上报每项检查的状态和日志链接。如果还要发布预览，在「预览环境」中选择「CI 构建」。

CI 密钥只在生成时显示，不应提交到仓库。仓库 CI 密钥默认 90 天到期。收到到期提醒后，更换密钥并更新流水线变量。

## 配置分支规则

在「项目设置 › 代码仓库 › 分支规则」中设置：

- 必需检查失败时是否唤醒调度 Agent。
- 检查全部通过后是否继续推进。
- PR 出现冲突时是否安排修复。
- 哪些检查仅作参考，失败时不阻止 Studio 内的正常合并。

未列为参考的检查按必需检查处理。代码平台的分支保护规则仍然有效。关闭自动唤醒后，可在任务中评论，请调度 Agent 继续处理。

## 验证接入

提交 PR 后，在任务的「代码与预览」中核对检查结果。预览发布后，仓库卡片「预览环境」行的「构建记录」会列出已发布的应用及发布者。

「还没收到上报」表示当前来源尚无结果。预览缺少变量时，按页面提示在环境或应用中补齐。无需预览的任务可在任务属性中选择「不需要预览」，CI 模板会按 `no-preview` 标签跳过。

检查如何参与任务流转，见[PR 检查与代码评审](../project/checks-and-review.md)。
