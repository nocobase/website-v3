---
title: 运行环境
description: 接入共享运行环境，让已安装并登录的编码工具执行团队任务。
---

运行环境是 Agent 执行工作的机器。本节由管理员接入一个共享运行环境，供团队成员使用。只为自己执行任务时，使用[个人运行环境](../join/personal-runtime.md)。

## 准备机器

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS 或 Linux；Windows 使用 WSL |
| 基础软件 | Node.js 24 或更高版本、Git。开发 NocoBase 应用还需要 pnpm 11 |
| 编码工具 | 安装 Claude Code、Codex 等支持的工具，并使用运行执行机的系统用户完成登录 |
| Git 工具 | GitHub 使用 `gh`，GitLab 使用 `glab`，Gitee 使用 `gitee` |
| 网络 | 可以访问 Studio、代码平台、模型服务和项目依赖源 |
| 浏览器 | 需要验证界面的任务，应能运行 Chromium 及其系统依赖 |

建议接入两家厂商的编码工具，便于由不同模型开发和评审。先在终端确认要使用的工具能够正常运行。

> [!NOTE] 使用专用执行环境
> 建议在独立的容器或虚拟机中安装编码工具和执行机，与 Studio 隔离。Agent 可以读写执行用户有权访问的文件，并运行命令。

## 添加共享运行环境

1. 打开「Agent 管理 › 运行环境」，点「添加运行环境」。
2. 「使用范围」选择「共享」。
3. 勾选这台机器已经准备好的编码工具。
4. 设置「最大并发数」。首次接入可以设为 1，验证通过后再按资源和模型额度调整。
5. 点「生成安装命令」，选择机器的操作系统。

![选择共享运行环境、编码工具和最大并发数](https://static-docs.nocobase.com/studio-zh-setup-runtime-options-full-1440x900-20261030.png)

并发数和启用的工具，之后可以在运行环境详情里修改。

## 安装执行机

在准备好的机器上，任选一种方式：

- **交给本地 Agent**：复制对话框中的安装提示词，交给这台机器上的 Coding Agent。
- **手动执行**：复制对话框中的安装命令，在已登录编码工具的系统用户下运行。

安装命令从当前 Studio 下载执行机 `nocobase-runner` 和 CLI `nb-studio`，完成注册并安装后台服务。已经安装过执行机时，使用对话框提供的注册命令。

命令包含短期有效的一次性凭证。过期后重新生成，不要把完整命令放进文档、截图或共享聊天记录。

![复制安装命令或交给本地 Agent；截图中的凭据已隐藏](https://static-docs.nocobase.com/studio-zh-setup-runtime-install-full-1440x900-20261030.png)

Windows 用户先安装并打开 WSL，再在其中安装 Node.js、编码工具和执行机。

## 确认在线

回到运行环境列表，等待机器显示「在线」。打开详情，检查每个工具：

| 状态 | 下一步 |
| --- | --- |
| 已登录 | 可以执行任务 |
| 需要登录 | 在执行机上登录该工具，再点「重新检测」 |
| 未安装 | 安装工具，并确认后台服务的 PATH 可以找到它 |


![共享运行环境已在线，Claude Code 和 Codex 已登录](https://static-docs.nocobase.com/studio-zh-setup-runtime-online-full-1440x900-20261030.png)

## 排查连接问题

- **显示离线**：在执行机运行 `nocobase-runner status`，检查服务和 Studio 地址是否可达。
- **终端可用，后台显示未安装**：在可以找到编码工具的终端重新运行 `nocobase-runner service install`，然后重启服务。
- **下载失败**：检查下载和后台服务的代理设置。npm 权限不足时，使用当前用户的安装目录或 Node 版本管理器。

执行机空闲时会自动升级，也可以运行 `nocobase-runner update`。运行环境详情提供工具状态、工作目录和运行记录。停用一台机器前，先吊销它的凭证；历史记录会保留。
