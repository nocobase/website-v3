Claude Code、Codex 等编码工具接入 Studio 后，组成 Agent 团队。调度 Agent 分派工作，执行 Agent 完成设计、开发、测试与评审。需要决策或验收时，任务交给负责人。

## Agent 团队

| 角色 | 来源 | 职责 |
| --- | --- | --- |
| 调度 Agent | Studio 内置，全团队共用一个 | 分派步骤，读取结果，决定下一步。需要时向负责人提问或提交验收。不写代码，也不合并 PR。 |
| 执行 Agent | 运行环境中已安装并登录的编码工具 | 完成设计、开发、测试、评审或 CI 排查。完成后回复结果，不修改任务状态，也不转派工作。 |

每个「工具 · 模型」组合对应一个执行 Agent。管理员填写「擅长什么」，例如「方案设计和代码评审」。调度 Agent 仅依据这段描述判断其能力。见 [启用 Agent](../setup/agents.md)。

调度 Agent 也需要模型。管理员指定首选和备选。首选在 2 分钟内未能开始，备选接手。

![Agent 列表展示模型分工、可用运行环境，以及调度 Agent 的首选和备选](https://static-docs.nocobase.com/studio-zh-agent-team-20261030-v3.png)

列表中的「在哪跑」显示 Agent 可用的运行环境。共享环境由管理员接入，服务全体成员。个人环境由成员接入，只执行本人发起的任务。仅在个人环境中可用的 Agent，也只为该成员工作。见 [核心概念](concepts.md#agent-与运行环境)。

成员也可以先在「我的会话」中讨论需求，再整理成任务交给团队执行。见 [我的会话](../use/sessions.md)。

## 工作分派

任务开始时，调度 Agent 分派第一步。执行 Agent 回复、成员评论或 PR 检查结果更新后，它会再次读取进展，安排下一步。

设计、开发、测试和疑难排查，分别交给擅长这些工作的 Agent。评审优先交给另一家厂商。若没有在线的候选，则使用同厂商的另一个模型。写代码的模型不评审自己的代码。

每次交接都留在任务评论中。交接内容包括执行 Agent、目标、参考资料、完成条件和选择理由。执行 Agent 回复结果后，调度 Agent 继续推进。

![调度 Agent 分派方案设计，交接内容包括业务资料和验证要求](https://static-docs.nocobase.com/studio-zh-req-dispatch-20261030-v3.png)

管理员可以按团队习惯调整分配原则，也可以恢复内置规则。见 [启用 Agent](../setup/agents.md)。

## 任务流转

技能规定各环节的做法和完成要求。调度 Agent 按技能安排步骤，执行 Agent 按对应要求完成工作。Studio 内置技能覆盖以下环节：

| 环节 | 推进方式 | 对应技能 |
| --- | --- | --- |
| 方案设计 | 涉及跨模块、数据迁移、并发或权限时，先写简短方案。实现方式不明确时也先设计。范围明确的改动可直接开发。 | `studio-workflow`、`studio-approach` |
| 开发与验证 | 按确认的方案开发并验证结果。超出方案范围，需经调度 Agent 同意。 | `studio-development` |
| 检查与评审 | 运行检查，由独立 Agent 评审。需要修复的问题交回开发 Agent，修复后再次评审。 | `studio-development`、`studio-review` |
| 交付验收 | PR 通过评审和全部检查后，整理交付报告。随后提交负责人验收。 | `studio-workflow`、`studio-comment-style` |

![Codex 修复检查发现的问题，Claude 完成独立评审](https://static-docs.nocobase.com/studio-zh-review-thread-20261030-v3.png)

需要负责人决策时，调度 Agent 将任务设为「阻塞中」，说明待确认的问题。准备好交付时，设为「待验收」并附上交付报告。执行 Agent 不修改任务状态。

团队可以修改内置技能，也可以添加自己的规范。技能可用于全局、项目或代码仓库，供后续任务复用。见 [技能](../project/skills.md)。

## 多任务并行

运行环境从队列中领取工作。多个任务可以同时推进，每个任务使用独立的分支和工作目录。

| 机制 | 行为 |
| --- | --- |
| 任务隔离 | 代码改动保存在各自的工作目录中，默认分支名为 `agent/任务编号`。 |
| 单任务内的并发 | 同一时间只有一个步骤修改代码。评审、CI 排查等只读步骤使用独立副本，可与开发并行。 |
| 执行容量 | 每个运行环境默认并行执行 3 项工作，可按资源和额度调整。增加运行环境可提高容量。紧急任务优先领取。 |
| 任务依赖 | 需要等待前置任务或全部子任务时，暂不开始。依赖完成后自动继续。 |
| 持续执行 | 运行环境在线时持续领取排队工作，无需人工值守。 |

![Agent 队列显示正在执行、等待执行和受依赖阻塞的工作](https://static-docs.nocobase.com/studio-zh-agent-queue-20261030-v2.png)


## 人工介入

以下任务会排在负责人「我的任务」的前面：

| 情况 | 任务状态 | 负责人需要做什么 |
| --- | --- | --- |
| 业务规则或方案取舍待确认，缺少权限或密钥 | 阻塞中 | 回答问题，补充继续执行所需的信息或权限。 |
| 合适的 Agent 均不在线，或同一步骤更换 Agent 后仍失败 | 阻塞中 | 根据任务中的说明，解决阻塞条件或调整安排。 |
| PR 已通过检查与评审 | 待验收 | 阅读交付报告，验收结果。 |

调度 Agent 不会将任务设为「已完成」或「已取消」，也不合并 PR。验收与合并由人完成。

- Agent 以发起人的身份工作，权限不超过发起人。
- 执行 Agent 可以在任务分支上提交、推送和创建 PR，不能改写已推送的历史。受保护分支由代码托管平台控制。
- 合并 PR、批准向受保护环境部署、管理成员，只能由人执行。

成员可以随时在任务中补充要求、停止运行，或接手任务。见 [跟进进展](../use/follow-progress.md)。

## 异常处理

| 情况 | 处理方式 |
| --- | --- |
| 检查失败或 PR 冲突 | 调度 Agent 安排修复。连续 3 次提交仍失败，通知任务负责人。 |
| 同一步骤失败两次 | 更换合适的 Agent。再次失败后，任务转为「阻塞中」。 |
| 编码工具额度用完 | 立即更换合适的 Agent，优先选择另一家厂商。 |
| 运行环境离线 | 工作返回队列，由其他运行环境接手。 |
| 排队超过 24 小时仍未被领取 | 本次运行失败，通知负责人。负责人可重试、转交或取消。 |
| Agent 反复交接 | 每个任务由 Agent 评论触发的运行，默认每 24 小时最多 20 次。超过后暂停并通知负责人，由其决定是否继续。 |
