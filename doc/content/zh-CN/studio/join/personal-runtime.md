---
title: 接入个人运行环境
description: 接入自己的编码工具与执行资源，仅承接代表自己执行的工作。
---

个人运行环境使用你登录的编码工具和订阅，只执行代表你发起的工作。它可以补充共享环境的容量，或提供团队尚未接入的模型。

## 准备

按[准备机器](../setup/shared-runtimes.md#准备机器)安装依赖和编码工具，并确认工具已登录。推荐使用独立容器或虚拟机，与 Studio 隔离。

## 添加

1. 打开「Agent 管理 › 运行环境」，点「添加运行环境」。
2. 确认使用范围为「个人」，选择已安装的编码工具。
3. 按机器资源和订阅额度设置最大并发数。
4. 生成安装命令，选择系统，将提示词交给该环境中的 Coding Agent 执行。

安装命令带一次性凭证，过期后重新生成。安装细节见[接入运行环境](../setup/shared-runtimes.md#安装执行机)。

![选择个人运行环境和要接入的编码工具](https://static-docs.nocobase.com/studio-zh-personal-runtime-20261111-normal-2x.webp)

## 确认接入成功

运行环境应显示「个人」和「在线」，选中的工具显示「已登录」。对应 Agent 启用后，「在哪跑」会包含这台环境。

## 哪些工作会派到这里

- 代表你执行的任务步骤和你发起的 Runner Agent 会话。
- 仅在个人环境可用的 Agent，只处理该所有者的工作。
- 使用「仅限共享运行环境」变量的工作，不会派到个人环境。

其他成员在你的任务上请求继续执行，且要使用你的个人环境时，Studio 会请你确认。见[个人运行环境的请求](../use/answer.md#个人运行环境的请求)。

## 管理

在运行环境详情中修改名称、并发数和可用工具。只有所有者能修改个人环境；管理员可按需将其改为共享环境。

在机器上暂停或恢复领取工作：

```bash
nocobase-runner stop
nocobase-runner start
```

不再使用时，先吊销凭证，再删除环境；历史运行记录保留。在机器上运行 `nocobase-runner uninstall` 移除服务。更多设置见[运行环境](../configure/runtimes.md)。
