title: 检查与评审
description: 跟进检查结果、Agent 评审和合并条件。
---

任务交付前，调度 Agent 根据项目技能安排验证与代码评审。任务负责人查看交付报告并决定是否合并。

针对已完成任务或整个项目的测试，使用[质量](../quality/overview.md)。测试报告和跟进任务在该模块中持续记录。

## 跟进检查

在任务的「代码与预览」中查看 PR 的检查来源、结果和日志链接。来源由仓库配置决定，可以是代码平台 CI、外部 CI 或 Agent 自检，见[检查与 CI](../configure/checks.md)。

![任务中的 PR 检查结果](https://static-docs.nocobase.com/studio-zh-req-preview-20261111-normal-2x.webp)

在「项目设置 › 代码仓库 › 分支规则」中设置：

- 必需检查失败时是否唤醒调度 Agent。
- 检查全部通过后是否继续推进。
- PR 出现冲突时是否安排修复。
- 哪些检查仅作参考，失败时不阻止 Studio 内的正常合并。

未列为参考的检查按必需检查处理。代码平台的分支保护规则仍然有效。关闭自动唤醒后，可在任务中评论，请调度 Agent 继续处理。

## 安排评审

默认工作流优先选择另一家厂商、能力适合且当前可用的 Agent 评审。没有合适的跨厂商模型时，可选同厂商模型。评审要求和问题分级由 `studio-review` 等[技能](skills.md)规定。

调度 Agent 将必须修复的问题交回实现者。与本次改动无关的问题应写明影响和证据，另行安排，不无限扩大当前任务。

## 决定合并

| PR 情况 | 处理方式 |
| --- | --- |
| 必需检查通过，PR 可合并 | 负责人验收后合并 |
| 必需检查失败或没有结果 | 有强制合并权限的人可明确选择仍然合并，操作会留痕 |
| 检查进行中、冲突或草稿 | 等待或先解决阻塞 |
| 代码平台禁止合并 | 按平台规则处理 |

Agent 不能合并 PR。具体操作见[验收任务](../use/accept.md)。
