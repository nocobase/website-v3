title: PR 检查与代码评审

任务交付前，调度 Agent 根据项目技能安排验证与代码评审。任务负责人查看交付报告并决定是否合并。

## 跟进检查

在任务的「代码与预览」中查看 PR 的检查来源、结果和日志链接。来源由仓库配置决定，可以是代码平台 CI、外部 CI 或 Agent 自检，见[配置仓库检查](../configure/checks.md)。

![任务中的 PR 检查结果](https://static-docs.nocobase.com/studio-zh-req-preview-20261111-normal-2x.webp)

必需检查失败时，打开日志查看原因。如果项目启用了自动处理，调度 Agent 会安排修复。否则，可在任务中留言，请它跟进。参考检查失败不会阻止 Studio 内的正常合并。

## 安排评审

标准流程优先选择另一家厂商、能力适合且当前可用的 Agent 评审。没有合适的跨厂商模型时，可选同厂商模型。评审要求和问题分级由 `studio-review` 等[技能](skills.md)规定。

调度 Agent 将必须修复的问题交回实现者。与本次改动无关的问题应写明影响和证据，另行安排，不无限扩大当前任务。

## 决定合并

| PR 情况 | 处理方式 |
| --- | --- |
| 必需检查通过，PR 可合并 | 负责人验收后合并 |
| 必需检查失败或没有结果 | 有强制合并权限的人可明确选择仍然合并，操作会留痕 |
| 检查进行中、冲突或草稿 | 等待或先解决阻塞 |
| 代码平台禁止合并 | 按平台规则处理 |

Agent 不能合并 PR。具体操作见[任务验收](../use/accept.md)。由两人分别负责需求和开发时，还需[需求负责人验收](../use/multi-role-workflow.md#requester)后，开发负责人才能合并。
