知识库只放人写和上传的内容，Agent 只读不写。Agent 在工作中学到的经验，记在 [项目记忆](project-memory.md) 里；做事的方法，写成 [技能](skills.md)。

## 系统知识和项目知识

| | 放什么 | 谁来管理 |
| --- | --- | --- |
| 系统知识 | 跨项目共用的资料，例如公司的采购审批制度、通用的技术约定 | 管理员 |
| 项目知识 | 每个项目一个空间，放这个项目的业务资料 | 项目负责人 |

项目知识会带上系统知识：在项目里，人和 Agent 都能同时看到两边的内容。

「开发 › 知识库」把你能访问的空间汇在一起；项目页的「知识库」分区只看这个项目的。搜索覆盖你能访问的所有空间，每条结果写明来自哪个项目、哪个文件夹。

## 写进知识库

先选中要放入的空间或文件夹，再新建：

- **文章**：直接在 Studio 里写，支持 Markdown。
- **文件**：上传制度文件、表格、说明文档等。PDF、Word、Excel、PowerPoint、CSV、文本、Markdown 和 JSON 会提取出文字，用于搜索和给 Agent 阅读；图片里的文字不会识别。原文件保留，可以下载。
- **文件夹**：最多四层。

每次保存都是一个新版本，历史版本可以查看。读过、确认过的文章可以标为已核实；不再用的可以归档，归档的内容不出现在搜索里，需要时可以恢复。

> [!TIP] 什么值得写进知识库
> 写 Agent 从代码里看不出来的业务信息：业务规则和它的来由、术语的含义、例外情况怎样处理、做过的关键决定。

## 任务里的文件

提出需求时附上的文件，例如一份供应商评分表，Agent 用过之后可能会建议把它存进知识库。任务里会出现一张卡片“把《供应商评分表》存入知识库？”，你可以选存入项目知识库或系统知识库，也可以点「不用」。

只有上传这个文件的人或任务的负责人，并且对要存入的空间有编辑权限，才能存入。

## 谁能看、谁能改

每个空间、文件夹、文章和文件都可以单独设置权限，分四级：

| 权限 | 能做什么 |
| --- | --- |
| 读 | 查看和搜索 |
| 提议 | 提出修改，由有管理权限的人在收件箱里决定是否采纳 |
| 编辑 | 直接修改 |
| 管理 | 设置谁能看、谁能改 |

权限可以给某个人、某个角色、项目成员或项目负责人。一个文件夹或文档默认继承上一级的权限，再加上自己的；也可以只用自己设置的权限，例如把一份价格表只给采购经理看。

项目负责人管理自己项目的知识空间，管理员管理所有空间。成员默认可以读、可以提议，在自己负责的项目里可以编辑。

## Agent 怎样用知识库

- 执行任务时，相关的知识会作为文件放在 Agent 的工作目录旁边，Agent 按需阅读。
- 在会话里，Agent 会搜索知识库，并注明引用了哪一节。
- Agent 能读到哪些内容，和发起工作的人一样，受同样的权限限制。
