生产不是 Studio 托管的环境。Studio 给出部署指引，部署由你或你的 Agent 在自己的服务器上完成；部署好后，在 Studio 里记录生产运行的版本。只有项目负责人可以查看部署指引和记录生产版本。

## 打开部署指引

在「发布」页选中项目，生产一栏写明当前记录的版本，以及能不能上线更新的版本、包含几个任务。点「部署指引」，或者在某个版本的「部署」菜单里选「部署到你的服务器」。

部署指引默认选最新的版本，也可以换成别的版本。部署需要这个版本的制品；还没有制品时，按指引先上传，见 [版本与发布](../release/versions.md#制品)。生产还没有记录版本时，指引给出首次安装的步骤；已经记录过时，给出从那个版本升级的步骤。

## 部署

指引有两种方式，每种都可以交给你的 Agent，也可以自己执行命令：

| 方式 | 服务器需要 | 过程 |
| --- | --- | --- |
| Docker（推荐） | Docker | 下载制品压缩包，用 `docker build` 构建镜像，和 PostgreSQL 一起用 Docker Compose 运行；升级前先用 `pg_dump` 备份数据库 |
| 安装器 | Node.js 24 和 pm2 | `@nocobase/app-installer` 解压制品、生成配置、迁移数据库，用 pm2 运行；升级时保留上一个版本 |

- **交给你的 Agent**：复制提示词交给能 SSH 到这台服务器的 Agent，它会下载制品、安装或升级，并检查能否访问。
- **自己执行命令**：复制命令，以及 `docker-compose.yml` 和 `.env` 清单。

下载链接 24 小时内有效，只能下载这一个制品；压缩包按 linux/amd64 构建。制品是镜像时，服务器按摘要拉取，不需要下载压缩包。

生产的配置和密钥保存在你的服务器上，不放进制品和代码仓库。

> [!WARNING] 升级前备份
> 新版本启动时会迁移数据库。每次升级前，先备份生产数据库；部署后按指引检查应用能否正常访问。

## 记录生产版本

部署成功后，在指引底部点「我已部署好，记录为 v1.4.0」（按你部署的版本显示）。也可以在「版本」分页里某个版本的「更多」菜单选「记录为生产版本」。

记录后，Studio 核对这个版本包含哪些已完成的任务，在任务上标出已在生产。记录只是你的声明，Studio 不会连接服务器验证。

## 回滚生产

生产的回滚在你自己的服务器上做：

- **安装器**：运行 `npx --yes @nocobase/app-installer rollback --dir <安装目录>`，回到上一个版本。
- **Docker**：改回上一个版本的镜像重新启动。新版本已经迁移过数据库时，要先恢复升级前的数据库备份。

回滚后，把回滚到的版本记录为生产版本。Studio 会重新核对，不再包含的任务撤下生产标记。
