「质量跟进」汇总质量计划留下的工作。按项目、类型和状态筛选，打开条目查看来源计划、轮次和关联任务。

![按项目和状态查看质量后续工作](https://static-docs.nocobase.com/studio-zh-guide-quality-followups-20261031.png)

| 类型 | 应如何处理 |
| --- | --- |
| 缺陷 | 查看复现步骤和影响，安排修复并验证 |
| 待确认问题 | 由负责人明确预期业务行为，再决定是否修改 |
| 自动化补充 | 为已验证但缺少稳定测试保障的行为补充测试 |
| 关联任务 | 跟进已安排的开发或其他工作 |

对业务行为不确定时，先回答问题，不直接把 Agent 的判断当成缺陷。修复通过普通任务执行，负责人仍按[任务验收](../use/accept.md)处理交付。

## 复测与历史

同一问题在多轮中出现时，沿用已有问题关联，避免重复创建。修复后启动[新一轮测试](plans.md#再次测试与定时执行)验证结果。

后续工作列表汇总整个计划，不随报告轮次切换。修复完成不会把历史报告中的失败改成通过；新轮次记录新的验证结果。
