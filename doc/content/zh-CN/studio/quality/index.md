## 简介

随着 Studio 中的功能持续开发与迭代，团队需要持续测试，了解每次交付的业务效果及其对已有功能的影响，持续掌握项目质量。

质量模块从业务视角验收开发成果，为项目交付提供质量保障，通过持续测试发现问题、跟进修复并验证效果，不断改进项目质量。

![质量计划列表，集中查看待发布验证、每日测试及具体功能的验证进度](/assets/studio/quality/quality-plans.png)

## 让质量验证跟上开发进度

- **持续验证待发布需求。** 随开发进度持续验证待发布需求，掌握待发布版本的质量与风险，为团队提供可持续发布的信心。
- **专业的测试能力。** 内置专业测试技能，按测试金字塔组织分层测试，拆分业务场景、设计测试用例，关注正常流程、边界与异常、权限、数据一致性、安全和性能。
- **从发现问题跟进到修复验证。** 测试发现直接关联开发任务，保留证据和处理进展，修复后在后续回归中再次验证。
- **充分利用项目知识。** Agent 读取项目需求、知识库和历史记录，并将历次测试发现、团队反馈和处理结论用于后续测试，让业务规则与测试经验持续积累，减少重复沟通与遗漏。

## 最佳实践

### 实践一：持续验证待发布任务

通过发布页随时了解待发布版本的质量与风险，为发布决策提供依据。

**从发布页查看质量**

在[发布页](../release/overview.md)选择项目，点击待发布任务旁的「查看质量」。

![在发布页选择供应商管理项目，通过「查看质量」了解待发布任务的质量](/assets/studio/quality/release-entry.png)

首次使用时，在「发布质量设置」弹窗中选择测试环境、确认验收要求，并设置后续定时执行的时间，点击「确认并开始首轮测试」。

![首次查看发布质量，在设置弹窗中选择测试环境、确认验收要求和每日执行时间](/assets/studio/quality/first-setup-modal.png)

**从报告判断发布风险**

测试完成后，先看报告中的本轮质量结论，再查看指标和具体场景。

![待发布质量报告，展示业务结论、检查点通过率、已有测试覆盖率、复用测试和待处理事项](/assets/studio/quality/report-overview-v2.png)

| 指标 | 含义 |
| --- | --- |
| 本轮检查点通过率 | 本轮业务检查点中，实际验证通过的比例 |
| 已有自动化覆盖率 | 被已有测试完整覆盖的业务检查点比例，不是代码行覆盖率 |
| 本轮复用测试数 | 本轮实际执行的已有测试数量 |
| 待办事项 | 计划中仍需处理的缺陷、业务疑问和自动化缺口 |

测试过程中，Agent 会将测试目标拆解为具体的业务场景和检查点。展开业务场景，可以查看具体的验证内容，以及各检查点是否通过。

![按业务分组展开测试场景，查看具体检查点及各项验证结果](/assets/studio/quality/scenario-tree.png)

点击「查看报告」打开详细报告预览，需要分享或留档时，在预览中下载。

![在原生 Markdown 预览中阅读完整质量报告，并通过右上角按钮下载](/assets/studio/quality/report-preview-v2.png)

**跟进问题，持续回归**

在「后续任务」中查看发现的问题，转成 Studio 任务后安排处理。修复进入测试环境后，再次验证相关场景。

![安全和性能问题关联开发任务，已修复问题保留处理进展](/assets/studio/quality/followups.png)

在计划的「设置」中查看或调整定时。需要调整验收重点时，点击「与 Agent 讨论」继续补充。

![在计划设置中按天安排凌晨 3 点执行，查看下次执行时间](/assets/studio/quality/schedule.png)

后续随时点击发布页的「查看质量」，即可查看最近一轮的待发布版本质量与风险，也可以在详情页中手动启动一轮验证。

![查看最近一轮质量结论，也可点击「再次测试」手动启动新一轮验证](/assets/studio/quality/latest-quality.png)

### 实践二：每日质量把控

每天定时验证前一天完成的开发任务，及时掌握交付质量、发现新问题。

在「质量」点击「新建计划」，向 Agent 说明：

```prompt
为「供应商管理」项目创建每日测试计划，每天凌晨 3 点检查昨天完成的开发任务。
```

![在 Studio 会话中提出每日验证要求，确认任务范围、测试环境和执行时间](/assets/studio/quality/daily-chat-framed.png)

确认后，每轮重新查找前一自然日符合条件的任务，留下当日范围和报告。

![11 月 2 日的测试报告：验证前一天完成的 5 项需求，发现暂停供应商仍可下单的问题](/assets/studio/quality/daily-round-1.png)

![11 月 3 日的测试报告：验证前一天完成的 8 项需求，原问题回归通过，新增问题关联修复任务](/assets/studio/quality/daily-round-2.png)

### 实践三：发起任意质量验证任务

在 Studio 的任意会话中，都可以依据当前业务需要提出质量需求，例如摸底整个项目、测试某个模块，或验证登录这样一个具体功能。

```prompt
帮我验证「项目名称」的登录功能，重点检查正常登录和密码错误时的处理。
```

![在已有会话中提出登录验证需求，Agent 继续确认测试环境与业务规则](/assets/studio/quality/quality-request-framed.png)

Agent 会根据需要追问测试环境与业务要求，梳理测试目标、范围、验收要求和执行安排，形成质量计划供你确认。

![Agent 整理测试目标、范围、验收要求和执行安排，供用户确认](/assets/studio/quality/plan-confirmation-framed.png)

确认后，Agent 按计划执行测试，并提供包含质量结论、验证结果和待处理问题的报告。

![Agent 返回登录验证结论和质量报告入口](/assets/studio/quality/quality-delivery-framed.png)

后续可在同一个计划中与 Agent 讨论，调整重点、再次测试，或改为定期回归，无需重新交代背景。
