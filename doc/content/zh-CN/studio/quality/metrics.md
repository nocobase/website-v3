## 各维度的指标与标准

以下列出内置维度的检查方法、默认标准与统计指标。性能预算可由项目覆盖；其他检查规则由维度绑定的 Skill 定义。工具生成原始数据，服务端解析和计算指标，Agent 负责组织执行与分析。

<strong style="color: #b91c1c">维护确认：安全中危数量、复杂度超过 15 的函数数量、未使用导出数量及测试覆盖率的默认阈值，在参考材料中尚未确定。本页不填入假定数值；上线前需确认这些项目的最终标准。</strong>

### 功能

| 测试项 | 指标与标准 | 工具与方法 |
| --- | --- | --- |
| 任务功能与核心场景 | 失败场景数 = 0；预期来自任务、场景清单和明确的业务规则 | Vitest、Playwright，加上 Agent 实际操作 |
| 自动化用例 | 产品缺陷导致的失败数 = 0；记录失败、跳过、超时和过时用例并分析原因 | 运行已有 Vitest、Playwright 用例；质量测试不补写 E2E 用例 |
| 场景覆盖率 | （通过 + 失败）÷ 场景总数；用于趋势比较，不设固定达标线 | 场景与检查点结果 |
| 通过率与自动化率 | 通过率 = 通过 ÷ 已验证；自动化率 = 自动化用例证明的场景 ÷ 已验证；不设固定达标线 | 区分自动化、Agent 操作和未验证；分母为零时不表示通过 |

### 权限

| 测试项 | 指标与标准 | 工具与方法 |
| --- | --- | --- |
| 未登录访问 | 未登录越权数 = 0 | 通用权限引擎以匿名身份请求接口 |
| 读越权与写越权 | 读越权数 = 0；写越权数 = 0 | 无权限身份读取标记数据；写入后读回确认是否发生修改 |
| 正向对照 | 对照失败数 = 0 | 用有权限的身份执行相同请求，避免把接口不可用当作权限正确 |
| 接口权限声明 | 未声明权限的接口数 = 0 | Vitest，在任务 CI 中检查 |

### 安全

| 测试项 | 指标与标准 | 工具与方法 |
| --- | --- | --- |
| 依赖漏洞 | 严重和高危漏洞数 = 0；区分生产与开发依赖 | pnpm audit 审计依赖，按依赖包跟进 |
| 密钥泄露 | 密钥泄露数 = 0 | gitleaks 扫描当前代码与 Git 历史 |
| 代码安全检查 | 已确认的严重和高危问题数 = 0 | Agent 按安全清单审查；保留依据 |
| 被动与主动扫描 | 已确认的高危问题数 = 0；中低危发现保留明细，不能把扫描未完成当作零告警 | OWASP ZAP 检查响应头、Cookie、信息泄露以及注入、XSS；权限越权由权限维度负责 |

### 性能

| 测试项 | 指标与标准 | 工具与方法 |
| --- | --- | --- |
| 页面脚本体积 | 首屏 JavaScript（未压缩）≤ 2 MB | Lighthouse 实测页面，记录测量条件 |
| 接口响应体 | 响应体 ≤ 500 KB | 采集页面实际发出的业务 GET 请求 |
| 数据库请求量 | 每次请求 SQL ≤ 20 条 | 按请求 ID 追踪 SQL，排除后台任务 |
| 接口与 SQL 耗时 | 诊断参考预算：P95 ≤ 500 ms；最慢 SQL ≤ 50 ms。共享机器上不单凭耗时判定 | 每个接口预热后串行采样 10 次；慢 SQL 用 PostgreSQL EXPLAIN 分析 |
| 页面加载指标 | Lighthouse 分数及 FCP、LCP、TBT、CLS、SI 用于参考与趋势，不设统一分数达标线 | 保持页面、数据规模和测量条件可比；核心页面多次测量取中位数 |

### 代码质量

| 测试项 | 指标与标准 | 工具与方法 |
| --- | --- | --- |
| 重复代码 | 新增部分重复率 ≤ 3% | jscpd 检测重复代码段 |
| 认知复杂度 | 新增复杂度 > 50 的函数数 = 0；复杂度 > 15 的函数保留统计 | eslint-plugin-sonarjs 的 cognitive-complexity 规则 |
| 未使用代码 | 新增未使用文件数 = 0；新增未使用依赖数 = 0；记录未使用导出 | knip |
| 循环依赖 | 新增循环依赖数 = 0 | dependency-cruiser 分析模块导入 |
| 测试覆盖率 | 记录行覆盖率与分支覆盖率；默认最低值尚未确定 | Vitest coverage-v8 运行全量测试 |
| Agent 审查 | 高级别问题数 = 0 | 按模块审查设计、项目约定和测试价值；lint 与类型检查由 CI 负责 |

### 适用范围与尚未覆盖的检查

性能耗时会受到共享 Runner 的负载影响，页面分数和耗时应结合测试条件及趋势查看。预算中的时间值用于诊断参考，不能把单次波动直接当成产品缺陷。实时消息目前只有代码检查，尚不能替代消息送达的实测。页面交互、大数据量、并发容量、后台任务、文件批量处理和持续运行还不属于已完成的性能实测范围。

权限检查尚未覆盖所有字段级修改限制。安全检查中，HTTPS 与部署配置依赖对应环境；不要把隔离 HTTP 环境的结果理解为生产部署已验证。冒烟和 UX 仍为计划维度，不计入当前五个内置维度。缺少外部服务或数据的检查应明确标为未验证。

代码质量标准针对新增部分，比较时必须核对基线和范围。lint 与类型检查继续由 GitHub CI 把关，已有代码的统计不能直接当作本次新增问题。


## 指标口径

| 数据 | 来源 |
| --- | --- |
| 任务、场景与检查点结果 | 各维度提交的明确结论和证据 |
| 自动化测试的通过、失败、跳过和用时 | 上传的 Vitest、Playwright 等测试报告 |
| 依赖漏洞 | 依赖审计输出，区分生产和开发依赖 |
| 页面和 API 性能 | 页面测量和接口测量分开查看，比较相同页面或接口的结果 |
| 权限检查 | 按角色和操作查看预期与实际结果，区分越权和未验证 |
| 扫描发现 | 查看工具提交的 SARIF 结果，并核对涉及的文件或位置 |
| 代码质量 | 代码检查报告中记录的问题及位置 |
| 跟进任务 | 测试关联的缺陷、问题、用例、场景和整理任务 |

没有报告就没有对应指标，不能把空值理解成零问题。未验证和不适用也不等于通过。

## 趋势与明细

点击指标查看对应测试、场景或问题明细。比较时先确认测试类型、范围、代码提交和维度是否一致。

新增或删除场景会改变总数。相同标识的场景可跨次比较；测试数量增加或问题数量下降，都需要结合范围变化判断。用[报告与证据](runs.md#reports)确认变化的原因。

## 维度结论与单项结果

维度汇总结论分为「通过」「有问题」「部分未验证」「未验证」。存在已确认的问题时，需要查看问题及证据；没有已确认的问题但仍有检查未完成时，不能把整个维度当作完全通过。整个维度没有可用结论时为未验证。

场景和检查点的单项结果仍需分别阅读：通过、失败、未验证、不适用。不适用不计为通过或失败。执行进度与结论也不同：进行中或已完成描述执行状态，不直接代表质量达标。
