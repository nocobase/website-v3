质量管理是 Studio 企业版（EE）的功能。它按一套明确的质量标准测试项目：由 Agent 调用成熟的测试工具实测，自动生成测试报告，再把发现的问题登记为跟进任务，修复后由后续测试确认。企业版镜像及授权请[联系我们](https://www.nocobase.com/zh-CN/contact/)获取。

![质量测试全景](/assets/studio/quality/quality-flow-zh-CN.svg)

## 核心能力

### 内置质量标准，项目可以自定义

功能、权限、安全、性能和代码质量五个维度，各有一组指标和达标标准，例如「读越权数 = 0」「首屏 JS ≤ 2 MB」「新增循环依赖数 = 0」。测试通过，表示被测版本满足这套标准。

**项目可以定义自己的标准**：调整性能预算、替换维度使用的 Skill，或新增维度。完整列表见[质量标准](standards.md)。

### 复用成熟的测试工具实测

测试结果由测试工具实际运行得出，不靠 Agent 读代码估算：Vitest 和 Playwright 跑自动化用例，pnpm audit 和 gitleaks 查依赖漏洞与密钥泄露，OWASP ZAP 做安全扫描，Lighthouse 测页面性能，jscpd、knip、dependency-cruiser 检查代码质量。服务端再把结果和标准比对，判定是否达标。

每个维度在 Runner 上准备独立的测试环境和测试数据，各维度并行执行，不影响团队正在使用的系统。

### 自动生成测试报告

服务端解析 JUnit、SARIF、依赖审计、Lighthouse 等原始结果，计算指标并按标准判定。每个维度一份报告，再汇总成一份交付报告，失败项和未验证项都附有证据。每个结论都以实测数据为准。因环境等原因未能测试的检查项，会如实标为「未验证」，提醒相关人员关注。

### 问题自动转为跟进任务

发现的问题按原因合并，登记为缺陷、待确认、补测试数据、代码清理、性能优化或依赖修复任务，走正常的开发、评审和验收流程。修复合入后，由后续测试确认问题不再出现。

## 测试类型

| 类型 | 测什么 | 怎么触发 |
| --- | --- | --- |
| 每日测试 | 最近完成、尚未测过的业务任务 | 每天定时，累计到设定的任务数量才运行 |
| 发布测试 | 当前待发布的任务 | 手动，或待发布任务达到设定数量时 |
| 项目测试 | 整个项目的核心场景 | 手动，或每周、每月定时 |
| 自定义测试 | 选定的已完成任务，或整个项目代码 | 手动 |

每次测试都会创建一项测试任务，结果通过任务的交付报告验收。

## 检查维度

| 维度 | 检查内容 | 主要工具 |
| --- | --- | --- |
| 功能 | 业务任务和核心场景是否符合预期 | Vitest、Playwright、浏览器 |
| 权限 | 未登录访问、读越权、写越权 | 通用权限引擎 |
| 安全 | 依赖漏洞、密钥泄露、代码安全问题、接口扫描告警 | pnpm audit、gitleaks、OWASP ZAP |
| 性能 | 页面加载、接口响应、数据库查询 | Lighthouse、autocannon、PostgreSQL |
| 代码质量 | 重复代码、认知复杂度、未使用代码、循环依赖 | jscpd、eslint-plugin-sonarjs、knip、dependency-cruiser |

## 核心场景

核心场景是项目需要持续满足的业务行为，例如「暂停合作的供应商不能新建订单」。项目测试和整个项目代码的自定义测试按核心场景逐条验证，见[维护核心场景](settings.md#scenarios)。

## 与 PR 检查的关系

PR 检查和代码评审把关每一次改动；质量测试在更大的范围内持续检查整个项目，见[PR 检查与代码评审](../project/checks-and-review.md)。

## 开始使用

1. [配置质量测试](settings.md)：设置触发规则和检查维度。新项目默认不自动触发。
2. [运行测试](runs.md)：选择范围，发起测试并跟进进度。
3. [查看测试报告](reports.md)：核对结果与证据，验收交付，处理跟进任务。
4. [质量标准](standards.md)：查看各维度的指标和达标标准。
