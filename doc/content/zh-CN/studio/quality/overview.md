Studio EE 的「质量」集中展示每个项目的测试、核心场景、报告和跟进任务。Studio EE 请[联系我们获取](../setup/install.md)。

打开「开发 › 质量」，选择项目。先在[设置](settings.md)中确认测试规则，再[发起测试](runs.md)。新项目默认不自动触发测试。

![示例项目的功能、权限、安全、性能和代码质量结果](https://static-docs.nocobase.com/studio-zh-quality-sample-20261111-normal-2x.webp)

## 测试类型

| 类型 | 范围与触发方式 |
| --- | --- |
| 每日测试 | 定时检查最近已完成、尚未覆盖的业务任务；首次或长时间停用后最多回看近三天 |
| 发布测试 | 检查当前待发布任务，可手动发起，也可达到配置的任务数量后触发 |
| 项目测试 | 检查整个项目的核心场景，可手动、每周或每月执行 |
| 自定义测试 | 手动选择已完成的业务任务，或检查整个项目代码 |

每日测试只按计划触发。想立即检查指定任务，使用自定义测试。

## 测试与任务的关系

每次测试都会创建一项普通任务。它保留测试范围、采用的 Skill 版本和执行记录，结果通过任务的交付报告验收。

Agent 按维度执行检查，并将发现的问题关联到跟进任务。测试任务完成，不代表这些问题已经修复；在[跟进任务](follow-ups.md)中继续处理，再通过后续测试核对。

仓库的 PR 检查和代码评审仍用于每次改动。项目质量测试用于持续检查更大范围，见[检查与评审](../project/checks-and-review.md)。
