质量计划把测试目标、执行任务、报告和后续工作放在一起。管理员启用 `studio.testing.enabled` 后，侧边栏显示质量管理入口，见[配置参考](../reference/config.md)。

## 创建计划

打开「质量计划」，选择项目，点「新建质量计划」。在 Agent 会话中说明要验证的业务范围，例如：

```prompt
检查供应商评分和订单审批：评分权重是否正确，C 级供应商的订单是否都需要审批。把发现的问题整理出来。
```

Agent 结合已有资料和[验收标准](standards.md)提出计划。确认目标、范围、交付内容和执行安排后，才创建并开始工作。测试点和环境准备由执行任务完成，不需要你预先列出所有测试用例。

![选择项目并新建质量计划](https://static-docs.nocobase.com/studio-zh-guide-quality-plans-20261031.png)

## 跟进执行

计划通过普通任务执行，进度和阻塞也在任务中处理。Agent 按技能准备独立测试环境，记录实际测试版本，运行已有测试并检查必要的页面操作。

在计划中查看：

| 页签 | 内容 |
| --- | --- |
| 目标 | 已确认的业务目标、范围、标准和安排 |
| 报告 | 当前轮次的结果，可切换历史轮次 |
| 后续任务 | 跨轮次汇总的缺陷、待确认问题和补测工作 |

无法执行的检查会保留原因，不计为通过。需要你确认业务规则时，在关联任务中回复。

## 阅读报告

报告按功能和检查点组织。分别查看已有自动化覆盖、本轮实际执行的测试、检查点结果和待跟进工作。

页面操作验证通过，不代表已有自动化测试覆盖；历史通过也不代表本轮通过。未执行、失败和待确认项应保留在报告中。报告中的问题通过[质量跟进](follow-ups.md)继续处理。

## 再次测试与定时执行

修复后可在同一计划中启动新一轮测试。新轮次保留计划目标，重新验证当前版本，不复制上轮通过结果。旧报告继续保留原始结论。

需要持续验证时，在计划中设置每日或每周执行时间。关闭定时执行只停止后续启动，不取消已派发的任务。修改测试范围时，先与 Agent 确认新安排，再更新计划。
