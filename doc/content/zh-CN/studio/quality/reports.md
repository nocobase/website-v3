从「质量 › 测试任务」打开测试。测试使用任务的交付报告，不需要到另一套报告系统验收。

![核对交付报告，验收或退回修改](https://static-docs.nocobase.com/studio-zh-quality-report-20261111-normal-2x.webp)

## 结果与证据

先核对测试范围、代码提交和采用的维度，再查看结果。点击维度可阅读详细报告及其附件。

| 结果 | 含义 |
| --- | --- |
| 通过 | 有证据支持预期行为 |
| 失败 | 实际行为不符合预期，需要查看问题和复现证据 |
| 未验证 | 缺少环境、账号或其他条件，不能判断是否通过 |
| 不适用 | 当前场景与该维度无关，不计为通过或失败 |

功能验证区分已有自动化用例和 Agent 实际操作。自动化结果来自提交的测试报告；场景结果需要说明检查了什么。权限、性能风险和代码质量等维度可能采用代码检查，不应把它们都当成浏览器测试。

检查失败项的证据、未验证项的原因，以及关联的跟进任务。截图只是证据的一种，不能代替明确的预期与实际结果。

![查看维度报告和测试证据](https://static-docs.nocobase.com/studio-zh-quality-dimension-20261111-normal-2x.webp)

## 验收或退回

确认测试范围完整、证据可核对、问题已有后续安排，再按任务页提示验收。报告有遗漏时，退回并说明缺少的场景或证据。

测试可能为用例或核心场景资产创建 PR。这类 PR 与业务修复分开；业务问题应进入[跟进任务](follow-ups.md)。完成测试验收，不会自动完成这些修复任务。
