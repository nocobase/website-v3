每次测试生成一份交付报告，汇总各维度的结论；每个维度另有一份详细报告。报告由服务端根据工具的原始结果生成，验收直接在测试任务上完成。

## 交付报告

从「质量 › 测试任务」打开测试，查看交付报告。先核对测试范围、被测提交和参与的维度，再看各维度的结论。

![核对交付报告，验收或退回修改](https://static-docs.nocobase.com/studio-zh-quality-report-20261111-normal-2x.webp)

每个维度给出一个结论：

| 结论 | 含义 |
| --- | --- |
| 通过 | 所有检查都有结果，且都达到标准 |
| 有问题 | 至少有一项没有达到标准 |
| 部分未验证 | 没有发现问题，但有检查因缺少环境、数据或工具结果未能完成 |
| 未验证 | 整个维度没有可用的结果 |

没有结果不等于没有问题。未验证和不适用都不计为通过。

## 维度报告

点击维度，打开它的详细报告。报告按页签展示该维度的结果，并附有原始文件和证据：

| 维度 | 报告内容 |
| --- | --- |
| 功能 | 任务验证结果、核心场景验证结果、自动化用例结果、失败原因分析 |
| 权限 | 越权问题、问题证据、未验证项及原因、身份覆盖情况、与上次的对比 |
| 安全 | 依赖漏洞、密钥泄露、代码安全问题、ZAP 被动扫描告警、ZAP 主动扫描告警 |
| 性能 | 页面性能数据、接口性能数据、超出预算的项 |
| 代码质量 | 各项指标数值、新增问题位置 |

报告还列出环境准备、测试数据、执行等阶段的用时。

![查看维度报告和测试证据](https://static-docs.nocobase.com/studio-zh-quality-dimension-20261111-normal-2x.webp)

场景和检查点的单项结果分为四种：

| 结果 | 含义 |
| --- | --- |
| 通过 | 有证据支持预期行为 |
| 失败 | 实际行为不符合预期，附有问题描述和复现证据 |
| 未验证 | 缺少环境、账号或其他条件，无法判断 |
| 不适用 | 与该维度无关，不计为通过或失败 |

功能结果区分自动化用例证明的场景和 Agent 实际操作的场景。点击场景，可以查看检查点、实际结果和证据。

项目测试和覆盖整个项目的自定义测试，还会在功能报告的「场景」中列出新增、修改和删除的核心场景。首次测试会显示本次建立的清单。

## 验收或退回

测试范围完整、证据可以核对、问题都有跟进任务时，在测试任务上验收。报告有遗漏时，退回并说明缺少的场景或证据。

验收测试任务，表示接受这次测试的结论，不表示跟进任务已经修复。

<h2 id="follow-ups">跟进任务</h2>

测试发现的问题按原因合并，登记为跟进任务，关联来源测试和维度。在「质量 › 跟进任务」中统一查看。新建的跟进任务自动指派给测试任务的当前负责人，可直接开始处理。

![跟进任务与来源测试的关联](https://static-docs.nocobase.com/studio-zh-quality-follow-ups-20261111-normal-2x.webp)

| 类型 | 处理内容 |
| --- | --- |
| 缺陷 | 已确认的功能失败、越权或安全问题，附复现证据 |
| 待确认 | 业务规则不明确，由人决定预期行为 |
| 补测试数据 | 补齐记录、身份等数据，让未验证的检查能够执行 |
| 代码清理 | 处理新增的复杂函数、未使用代码、循环依赖等问题 |
| 性能优化 | 按原因合并超出预算的页面和接口 |
| 依赖修复 | 按依赖包修复漏洞 |

同一问题已有未完成的任务时，会复用该任务，不重复登记。

## 修复与复测

1. 在跟进任务中完成修复和验收。
2. 发起覆盖受影响范围的项目、发布或自定义测试。
3. 查看原场景或任务的新结果，确认问题不再出现。

关闭跟进任务不会改写历史测试结果。历史报告保留当时的证据，后续测试反映修复后的状态。

在「质量 › 指标」中选择测试类型，查看各维度指标在最近几次测试中的变化。点击指标可以查看对应的测试、场景或问题。
