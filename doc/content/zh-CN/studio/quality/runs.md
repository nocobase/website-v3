测试可以按[各类型的配置](settings.md#各类型的配置)自动运行，也可以随时手动发起。

## 准备条件

- 项目已配置代码仓库。
- 有可用的 Agent 和在线的运行环境（Runner）。
- 发起人需要能访问项目，并有创建任务、运行质量测试和上传附件的权限。自动测试使用该类型配置的[负责人](settings.md)。

## 发起测试

1. 打开项目，进入「质量」页签。
2. 点「运行测试」，选择发布测试、项目测试或自定义测试。
3. 自定义测试选择已完成的任务，或选择整个项目代码；按需要调整检查维度。
4. 确认后，打开生成的测试任务。

![选择测试范围和检查维度](https://static-docs.nocobase.com/studio-zh-quality-new-20261111-normal-2x.webp)

| 类型 | 能否手动发起 |
| --- | --- |
| 每日测试 | 不支持，只按计划自动运行。想立即测试指定任务，使用自定义测试 |
| 发布测试 | 支持，需要有待发布的任务 |
| 项目测试 | 支持，随时可以发起 |
| 自定义测试 | 支持，需要选择已完成的任务，或者选择整个项目代码 |

创建测试时会固定测试范围和各维度的 Skill 版本。之后修改设置不影响这次测试；要使用新的范围或标准，重新发起。

## 测试如何执行

1. 确定被测的代码提交，跳过与本次改动无关的维度。
2. 每个维度交给一个 Agent，在 Runner 上并行执行。
3. 各维度自己准备测试环境和测试数据，运行测试工具，再按标准提交结果和证据。
4. 所有维度提交后，生成交付报告。

测试过程不修改产品代码。规则不明确的地方登记为待确认；缺少环境或数据的检查记为未验证，并写明原因。

## 查看进度

在「质量 › 测试任务」中查看各次测试，也可以从「我的任务」进入。测试任务显示每个维度的状态、已检查数量和各阶段用时。

![测试任务及各维度的执行状态](https://static-docs.nocobase.com/studio-zh-quality-runs-20261111-normal-2x.webp)

## 处理阻塞

缺少运行环境、项目权限或测试账号时，先补齐条件，再回复测试任务中的问题。需要业务决定时，由负责人回答，见[回答提问](../use/answer.md)。

## 取消测试

不再需要的测试可以取消。已提交的结果保留，尚未完成的维度显示已取消。

测试结束后，[查看测试报告](reports.md)。
