项目管理者打开项目的「质量 › 设置」，可以配置测试类型、负责人和检查维度。

![每日测试启用后，可选择负责人](https://static-docs.nocobase.com/studio-zh-quality-20261126-94a33cda6c.webp)

## 各类型的配置

| 类型 | 可配置项 |
| --- | --- |
| 每日测试 | 是否每天运行、运行时间、至少累积多少个已完成任务才运行、包含哪些维度 |
| 发布测试 | 是否自动触发、待发布任务每新增多少个触发一次、包含哪些维度 |
| 项目测试 | 不自动触发、每周或每月运行、星期或日期、运行时间、包含哪些维度 |
| 自定义测试 | 默认勾选的维度，发起时还可以调整 |

新项目默认关闭自动测试。开启某类测试的自动触发后，在该行选择「负责人」，再保存。默认使用项目负责人，也可以指定能访问项目、创建任务并运行质量测试的成员。自定义测试由发起人负责。

如果负责人停用或失去权限，该类型暂停自动触发。质量概览会显示原因和「更换负责人」入口。

## 场景语言

场景语言决定新生成的核心场景使用什么语言。未指定时使用实例的默认语言。

## 检查维度与 Skill

功能维度始终启用。其他维度可以选择适用的测试类型，并绑定 Skill；Skill 定义这个维度怎么测、怎么判定。

也可以新增维度：填写名称，从技能库选择 Skill，设置适用的测试类型。

修改 Skill 后，新测试使用新版本；已经创建的测试保留创建时的版本。

## 调整项目标准

要调整某个维度的标准，创建一个包含团队规则的 Skill，并在该维度的设置中选用它。质量插件提供的 Skill 为只读。

例如，性能维度的预算写在 Skill 的 `budgets.json` 里，接口 P95 响应时间默认不超过 500 ms。把它改成 800 ms 后，之后的测试就按 800 ms 判定是否达标。

修改后新发起的测试才使用新标准；已有测试保留创建时的 Skill 版本，结果不会被改写。默认标准见[质量标准](standards.md)。

<h2 id="scenarios">核心场景</h2>

打开「质量 › 核心场景」，按业务功能查看场景、预期结果和最近一次的验证结果。

![核心场景与最近一次验证结果](https://static-docs.nocobase.com/studio-zh-quality-scenarios-20261111-normal-2x.webp)

**核心场景由系统自动维护，不需要人工整理**：

- 开发任务改动功能时，同步更新相关场景。
- 项目测试会补齐缺失的场景，并更新过时的场景。

场景保存在被测仓库的 `.nb-studio/scenarios/` 中，和代码一起评审、一起留存版本。有特殊的业务规则需要补充时，也可以在任务中说明，由 Agent 更新。
