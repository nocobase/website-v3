title: 配置质量测试
description: 调整触发规则、性能预算、维度 Skill，并维护核心场景。
---

项目管理者在「质量 › 设置」中配置测试。先确认项目负责人、代码仓库、Agent 和运行环境可用；自动触发不会代替这些准备。

## 触发规则

| 类型 | 可配置项 |
| --- | --- |
| 每日测试 | 是否每日执行、执行时间、累计已完成任务的最低数量 |
| 发布测试 | 是否按待发布任务数量触发，以及触发阈值 |
| 项目测试 | 不自动触发、每周或每月，以及日期和时间 |
| 自定义测试 | 手动发起，不设置定时规则 |

新项目默认不自动触发。开启前明确选择时区，检查执行时间是否符合团队安排。定时测试由项目负责人承担；账号停用或权限不足时，需要先恢复条件。

场景语言决定新生成的核心场景使用什么语言。未指定时使用实例默认语言。已有测试的范围和规则不会随设置改变。

## 检查维度与 Skill

各维度检查的内容见[质量概览](overview.md)，具体指标和标准见[质量指标与标准](metrics.md)。

功能维度始终启用。为其他维度选择适用的测试类型，并绑定相应 Skill。也可新增维度，填写名称、选择技能库中的 Skill，并设置适用类型。

检查方法由 Skill 约定，指标依据实际提交的结果计算。修改 Skill 后，新测试使用新版本；已创建的测试保留其固定版本。

保存后，从[发起测试](runs.md)开始验证配置。无人处理的测试不宜持续自动触发，先解决运行环境或权限问题。

## 项目的质量标准

在「质量 › 设置」中覆盖性能预算，未覆盖的项目沿用默认值。其他检查方法与判定规则通过维度绑定的 Skill 调整；不是所有指标都提供独立的界面阈值输入。默认预算与适用范围见[质量指标与标准](metrics.md)。

调整规则后发起新测试。已有测试保留创建时固定的范围和 Skill 版本，不能用新标准改写历史结果。

<h2 id="scenarios">维护核心场景</h2>

打开「质量 › 核心场景」，按业务功能查看场景、预期结果和检查点。

场景资产保存在被测试仓库的 `.nb-studio/scenarios/` 中，由 Agent 随业务变化维护。需要新增或修改时，在任务中说明业务规则，让 Agent 更新并提交审阅。场景名称可以调整，稳定的场景标识用于跨次比较。

页面展示测试提交的场景快照。修改仓库文件后，需要后续测试提交新快照，页面才反映新的覆盖情况。
