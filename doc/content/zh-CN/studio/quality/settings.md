---
title: 配置测试规则与维度
description: 设置自动测试时间、触发条件、场景语言和检查方法。
---

项目管理者在「质量 › 设置」中配置测试。先确认项目负责人、代码仓库、Agent 和运行环境可用；自动触发不会代替这些准备。

## 触发规则

| 类型 | 可配置项 |
| --- | --- |
| 每日测试 | 是否每日执行、执行时间、累计已完成任务的最低数量 |
| 发布测试 | 是否按待发布任务数量触发，以及触发阈值 |
| 项目测试 | 不自动触发、每周或每月，以及日期和时间 |
| 自定义测试 | 手动发起，不设置定时规则 |

新项目默认不自动触发。开启前明确选择时区，检查执行时间是否符合团队安排。定时测试由项目负责人承担；账号停用或权限不足时，需要先恢复条件。

场景语言决定新生成的核心场景使用什么语言。未指定时使用实例默认语言。已有测试的范围和规则不会随设置改变。

## 检查维度与 Skill

| 内置维度 | 检查内容 |
| --- | --- |
| 功能 | 业务任务和核心场景的预期行为 |
| 权限 | 账号、角色和数据访问边界 |
| 安全 | 依赖漏洞及其影响 |
| 性能 | 代码中的性能风险；启用后，每日、发布和项目测试还可执行 Lighthouse 测量 |
| 代码质量 | 可维护性问题，以及慢或不稳定的测试 |

功能维度始终启用。为其他维度选择适用的测试类型，并绑定相应 Skill。也可新增维度，填写名称、选择技能库中的 Skill，并设置适用类型。

检查方法由 Skill 约定，指标依据实际提交的结果计算。修改 Skill 后，新测试使用新版本；已创建的测试保留其固定版本。

保存后，从[发起测试](runs.md)开始验证配置。无人处理的测试不宜持续自动触发，先解决运行环境或权限问题。
