项目管理者在「质量 › 设置」中配置测试。先确认项目负责人、代码仓库、Agent 和运行环境都可用。

![配置触发规则、检查维度和 Skill](https://static-docs.nocobase.com/studio-zh-quality-settings-20261111-normal-2x.webp)

## 触发规则

| 类型 | 可配置项 |
| --- | --- |
| 每日测试 | 是否每日执行、执行时间、累计已完成任务的最低数量 |
| 发布测试 | 是否按待发布任务数量触发，以及触发数量 |
| 项目测试 | 不自动触发、每周或每月，以及日期和时间 |
| 自定义测试 | 只能手动发起 |

新项目默认不自动触发。开启前选择时区，确认执行时间符合团队安排。定时测试以项目负责人的身份运行；负责人账号停用或权限不足时，先恢复后再开启。

## 场景语言

场景语言决定新生成的核心场景使用什么语言。未指定时使用实例的默认语言。

## 检查维度与 Skill

功能维度始终启用。其他维度可以选择适用的测试类型，并绑定 Skill；Skill 定义这个维度怎么测、怎么判定。

也可以新增维度：填写名称，从技能库选择 Skill，设置适用的测试类型。

修改 Skill 后，新测试使用新版本；已经创建的测试保留创建时的版本。

## 调整项目标准

- 性能预算：在设置中直接修改，未修改的项目沿用默认值。
- 其他标准：修改或替换维度绑定的 Skill。

默认标准见[质量标准](standards.md)。调整后发起新测试生效，已有测试的结果不会被新标准改写。

<h2 id="scenarios">维护核心场景</h2>

打开「质量 › 核心场景」，按业务功能查看场景、预期结果和最近一次的验证结果。

![核心场景与最近一次验证结果](https://static-docs.nocobase.com/studio-zh-quality-scenarios-20261111-normal-2x.webp)

场景保存在被测仓库的 `.nb-studio/scenarios/` 中：

- 开发任务改动功能时，同步更新相关场景。
- 项目测试会补齐缺失或过时的场景。
- 需要新增或修改场景时，在任务中说明业务规则，由 Agent 更新并提交评审。

每个场景有稳定的标识，标题可以修改，测试结果按标识跨次比较。页面显示的是最近一次测试提交的场景快照，修改仓库文件后，要等下一次测试提交才会更新。
