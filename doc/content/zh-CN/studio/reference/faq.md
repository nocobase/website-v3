可以把现象、相关任务和错误信息交给本地 Coding Agent 排查。不要在提示词中粘贴密码或令牌。已连接 Studio 的 Agent 可用 `nb-studio` 查询状态。

## 安装与登录

| 问题 | 检查方法 |
| --- | --- |
| 看不到登录页 | 使用 `https://studio.example.com/main/`，检查容器健康和反向代理 |
| 初始账号无法登录 | 核对部署时的 `INITIAL_ADMIN_USERNAME` 与密码；修改环境变量不会重置已有账号 |
| 容器反复重启 | 查看 `docker compose logs --tail=100 studio`；检查配置文件、数据库连接和 storage 写权限 |
| CLI 批准后未登录 | 保持登录命令运行，过期后用新验证码重试 |

安装步骤见[部署 Studio](../setup/install.md)，密码恢复见[通知与推送](../admin/notifications.md)。

## Git 连接

GitHub 拒绝内网 Webhook 地址时，关闭 Webhook，使用轮询。新仓库创建后不可见时，检查 GitHub App 的安装范围，将仓库加入授权后按[已有仓库](../project/settings.md#接入已有仓库)接入。

个人 Git 账号只有只读权限时，不能推送 PR。为该账号授予仓库写权限，或按团队安排使用工作区连接。详见[代码平台](../configure/git.md)。

## 运行环境与任务

| 现象 | 下一步 |
| --- | --- |
| 环境离线 | 在机器上运行 `nocobase-runner status`，检查服务与网络 |
| 工具未安装或未登录 | 用运行服务的系统用户安装和登录，再重新检测 |
| 终端可用，后台找不到工具 | 在正确终端运行 `nocobase-runner service install` |
| 任务不开始 | 查看状态、前置任务、初始化进度和队列等待原因 |
| 多次运行后暂停 | 查看是否达到任务运行上限，确认问题后继续 |
| 工具额度耗尽 | 等待额度恢复，或使用其他可用模型；未知恢复时间的标记需手动清除 |

待规划任务先点「开始」。共享运行环境忙碌时，任务可能正常排队。具体状态见[跟进任务](../use/follow-progress.md)。

## 检查、预览与合并

没有检查结果时，先核对仓库选择的检查来源。代码平台 CI、外部 CI 和 Agent 自检互不混用，见[检查与 CI](../configure/checks.md)。

没有预览时，检查构建记录、CI 到 Studio 的网络、必填变量和 `no-preview` 标签。停止或休眠的预览会在访问时重新启动。

PR 冲突、草稿或检查尚未结束时，先解决阻塞。失败或缺失检查的强制合并需要相应权限，代码平台保护规则仍有效。

已在 Git 平台合并但任务未更新时，等待同步，并检查所有关联 PR 是否都已合并。

## 邮件与交付

邀请邮件未发送时，可先复制邀请链接。邀请和密码重置使用不同发件配置，分别检查，见[通知与推送](../admin/notifications.md)。

受保护测试环境的部署会等待审批。生产部署完成后，需要负责人[记录生产版本](../project/release.md#记录生产版本)，发布页才会更新交付标记。
