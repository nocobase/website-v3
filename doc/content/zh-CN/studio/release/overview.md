一个改动从合并到上线，会经过三个阶段：

| 阶段 | 在哪里运行 | 谁来部署 |
| --- | --- | --- |
| 预览 | Studio 托管 | 代码仓库的 CI，在 PR 上构建并部署，见 [PR 预览](previews.md) |
| 测试 | Studio 托管 | CI、你的 Agent 或你自己上传制品并部署，见 [托管环境](../admin/environments.md) |
| 生产 | 你自己的服务器 | 你或你的 Agent 按部署指引部署，部署好后在 Studio 里记录版本，见 [部署到生产](../project/release.md) |

Studio 不连接生产服务器，也不替你部署生产。它记录生产运行的是哪个版本，告诉你还有哪些改动没有上线。

## 「发布」页

![「发布」页：左侧是项目，右侧是预览、测试环境、版本和待发布任务](https://static-docs.nocobase.com/studio-zh-releases-20261030-v2.png)

左侧是项目列表，每个项目写明最新的版本和有几个任务待发布，可以按「有待发布」「已是最新」「还没有版本」「未配置版本线」筛选。

选中一个项目，右侧上方是它的三个阶段：

- **预览**：有几个 PR 预览可以访问，最新的是哪个 PR。
- **测试**：测试应用在哪些环境、运行的是哪个版本。
- **生产**：生产记录的版本；有更新的版本时，写明可以上线哪个版本、包含几个任务。项目负责人从这里打开「部署指引」。

下方有四个分页：

| 分页 | 内容 |
| --- | --- |
| 预览环境 | 每个 PR 的预览：访问地址、提交、构建状态 |
| 测试环境 | 测试应用：所在环境、版本、状态；可以部署、查看日志、设置变量、停止、删除 |
| 版本 | 符合版本线的 tag，每个版本包含哪些任务，有哪些制品 |
| 待发布 | 已经合并、但还没有包含在任何已发布版本里的任务，以及它们是否已在测试环境 |

项目页的「发布」分区显示同样的内容，只看这一个项目。

## 任务上的部署标记

任务列表和任务页会标出改动已经到了哪里：已在测试环境、已在生产（按记录的版本），或者因为回滚被撤下。标记由 Studio 对比部署的提交和任务的 PR 得出，不需要手工维护。

## 通知

- 项目里最早的待发布改动合并满 3 天，项目负责人会收到提醒。
- 仓库里出现新的版本 tag，Studio 会通知这个版本已发布、包含几个任务。
- 部署到受保护环境的申请、部署失败，会出现在相关的人的 [收件箱](../use/inbox.md) 里。
