预览让任务负责人在合并前打开真实运行的应用，按验收标准亲自试一遍。它需要先 [连接 CI](../setup/ci.md)，触发方式选「Pull request」。

## 预览怎样产生

1. Agent 开出或更新 PR 后，CI 在 PR 的最新提交上构建应用。
2. CI 把制品上传到 Studio，部署成应用 `<应用 ID>-pr-<编号>`，运行在预览环境里（默认是 Studio 自带的「预览」环境）。
3. Studio 把这个应用记为这个 PR 的预览，显示在关联任务的「代码与预览」里：访问地址、提交、构建状态和日志。

![任务页「代码与预览」里的预览：最新提交、构建状态、初始管理员，以及重新部署和销毁](https://static-docs.nocobase.com/studio-zh-req-preview-20261030-v2.png)

PR 有了新的提交后，预览等新提交构建完成再更新，在此之前继续运行旧的提交。

Studio 自己不构建预览，也不往 PR 里写评论。不需要预览的任务，在任务属性里打开「不需要预览」，Agent 会给 PR 加上 `no-preview` 标签，CI 模板据此跳过。

## 打开预览

在任务页的「代码与预览」里点预览的访问地址。

- 预览第一次部署时加载示例数据，自动生成初始管理员，不包含企业的真实数据。初始管理员的账号和密码显示在任务页的预览区，只有能编辑这个 PR 所关联任务的人看得到。
- 预览缺少必填的变量时不会部署，任务页的预览区会列出缺了哪些变量，以及在哪里设置：设在预览环境上，所有预览都能用；设在单个预览应用上，只对它生效。

## 停止、休眠和删除

预览环境的默认设置：

| 情况 | 结果 |
| --- | --- |
| 10 分钟无人访问 | 停止，释放内存；下次访问时自动启动，浏览器先看到一个“正在启动”的页面 |
| 24 小时无人访问 | 休眠，再删除解压的文件，保留配置和数据；下次访问时重新准备，需要更长时间 |
| PR 合并或关闭，或有人点「销毁」 | 删除这个预览和它的数据 |

预览环境最多同时容纳 20 个预览。这些默认值在「发布 › 托管环境」里调整，见 [托管环境](../admin/environments.md)。

> [!NOTE] 正式使用时把预览和 Studio 分开
> 预览运行的是还没合并的代码。建议让预览使用单独的域名，并让运行预览的进程使用另一个系统用户，读不到 Studio 的配置，见 [配置项](../reference/config.md)。
