PR 预览是基于特定提交运行的独立应用。先在仓库中[配置检查与预览](../configure/checks.md)：CI 来源由流水线发布，Agent 自检来源由执行任务的 Agent 发布。

## 查看预览

打开任务的「代码与预览」，查看预览地址、对应提交和构建状态。也可以在「发布 › 预览环境」中查看项目的全部预览。

![查看 PR 预览及其构建状态](https://static-docs.nocobase.com/studio-zh-guide-previews-20261031.png)

有新提交时，预览在新构建完成后更新。验收前确认预览的提交与待合并改动一致。

初次部署加载示例数据，不包含企业业务数据。初始管理员凭据仅向有权编辑关联任务的人展示。缺少必填变量时，按页面提示在预览环境或单个应用中配置。

## 不需要预览时

在任务属性中打开「不需要预览」。Agent 为 PR 添加 `no-preview` 标签，生成的 CI 模板据此跳过预览。已有预览不会因此自动删除。

## 生命周期

默认预览策略如下，可在[托管环境](../admin/environments.md)中调整。

| 条件 | 行为 |
| --- | --- |
| 10 分钟无人访问 | 停止进程，下次访问自动启动 |
| 24 小时无人访问 | 休眠并清理解压文件，保留配置和数据 |
| PR 合并、关闭或手动销毁 | 删除预览及其数据 |

默认最多保留 20 个预览。休眠后的首次访问需要重新准备应用，可能比普通启动更久。

预览以 Studio 启动的应用子进程运行。正式使用时，为预览配置独立域名和受限的系统用户，相关配置见[配置参考](../reference/config.md)。
