---
title: 走完第一个需求
description: 提交一个小需求，跟进 Agent 开发，回答问题并验收结果。
---

接受邀请后，打开管理员为你准备的项目。选择一个小需求，完成从提交到合并的流程。

## 准备

- 项目的「初始化项目」任务已完成。
- 已配置调度 Agent，且至少一个运行环境在线。
- 仓库已[选择检查方式](ci.md)。需要试用应用时，准备好预览或测试环境。

## 1. 提出需求

在项目页点「新建任务」，向 Agent 描述目标和检查方式。例如：

```prompt
加一个供应商页面，记录名称、联系人、电话和合作状态。采购员可以新增、编辑和查看供应商。

做好后，我要能新增一家供应商，把状态改为暂停，并在列表中按状态筛选。
```

Agent 会先确认不清楚的规则，再整理为任务。检查内容后点「开始执行」。也可选择「手动填写」，直接创建任务。

![新建任务时，通过会话补充目标和业务规则](https://static-docs.nocobase.com/studio-zh-guide-new-task-20261031.png)

开始后，任务进入「进行中」，由调度 Agent 安排设计、开发和评审。

## 2. 看 Agent 团队推进

任务顶部显示当前 Agent、运行环境和下一步。「动态」保留交接、回复和评审结果；「运行记录」提供具体执行过程。

![任务详情显示当前执行步骤及后续安排](https://static-docs.nocobase.com/studio-zh-guide-task-progress-20261031.png)

## 3. 回答提问

需要业务决策时，任务进入「阻塞中」，并排到「我的任务」的「等你处理」中。打开「需要你」卡片，回复规则或补充资料，调度 Agent 会继续安排。

若缺少检查或预览配置，请管理员按[检查与 CI](../configure/checks.md)处理。

## 4. 验收

任务进入「待验收」后：

1. 阅读交付报告，核对改动、验证结果和遗留问题。
2. 点「看改动」查看 PR；有预览时，按验收场景试用。
3. 满足要求后点「合并」，确认目标分支和合并方式。
4. 需要调整时点「退回修改」，写清问题和预期结果。

![通过交付报告和验收标准确认任务结果](https://static-docs.nocobase.com/studio-zh-guide-accept-20261031.png)

任务显示「已完成」，且默认分支包含此次改动，表示本次开发完成。后续进入测试与发布的状态可在[发布](../release/overview.md)中查看。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 一直没有开始 | 查看任务顶部的等待原因，检查运行环境和并发容量 |
| 等初始化完成 | 先处理「初始化项目」任务，新任务会等待它 |
| Agent 无法验证界面 | 检查运行环境是否安装浏览器及依赖 |

日常从[我的任务](../use/my-tasks.md)继续处理待办。
