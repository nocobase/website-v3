title: 走完第一个需求
description: 提出一个小需求，看 Agent 团队写方案、开发和评审，回答提问，验收合并，确认整个流程走得通。
---

接受邀请并登录后，打开管理员为你准备的项目。提交一个小需求，体验从开发到验收的完整流程。

## 准备

- 项目的“初始化项目”任务已经完成，见 [新建项目](new-project.md)。
- 管理员已配置可用的 Agent 团队和调度 Agent。
- 团队运行环境在线，仓库已[选择检查方式](ci.md)。

## 1. 提出需求

1. 打开项目，点「新建任务」。右侧打开一段和 Agent 的会话，当前项目会作为上下文一起发过去。
2. 用业务语言写一个小需求，连同验收方式。例如：

   ```text
   在应用里新建“供应商”数据表，字段包括名称、联系人、电话、状态（合作中、暂停），并在导航里加一个“供应商”页面，可以新增、编辑和查看供应商。
   验收：登录后能从导航打开“供应商”页面，新增一条供应商并在列表里看到它。
   ```

3. 发送。需求说清楚了，Agent 会直接把它整理成任务；有不清楚的地方，会先问你。
4. 任务建好后，在会话里点「开始执行」。也可以打开任务，点「开始」。

不想经过会话，点会话里的「手动填写」，直接填写标题和描述。

**完成的标志**：任务进入「进行中」，执行者是调度 Agent。

## 2. 看 Agent 团队推进

打开任务。最上方的「现在」一行，随时写着哪个 Agent 在做、做了多久、在哪台运行环境上，下面是接下来做什么。

「动态」记录调度 Agent 的分派、执行 Agent 的回复和评审结果。Agent 完成设计、开发和验证后提交 PR，再根据评审意见修改。

![任务页最上方：现在谁在做，接下来做什么](https://static-docs.nocobase.com/studio-zh-req-now-20261030-v2.png)

「运行记录」里是每一次运行的过程，排查问题时用得上。

## 3. 回答提问

遇到需求里没有说清的事，例如方案有两种取法，调度 Agent 会把任务移到「阻塞中」，写清要你决定什么。你会在「我的任务」最前面看到它，打开后在“需要你”卡片里点「回复」，写下决定。调度 Agent 收到回复后接着安排。

需求写得清楚，这一步可能不会出现。

如果检查或预览无法完成，先查看 Agent 的说明。配置问题由管理员按[检查与 CI](../configure/checks.md)处理；不需要为了提出需求而安装本地编码工具。

## 4. 验收

PR 通过评审和检查后，任务进入「待验收」，「我的任务」的“等你处理”里会出现它。

1. 打开任务。“需要你”卡片写明要你验收什么，下面是交付报告：原来的情况、改了什么、怎么验证的、遗留问题和建议，最后是验收标准和截图。
2. 点「看改动」，查看 PR。
3. 有预览时，在任务页打开预览，用初始管理员登录，按验收标准试一遍。
4. 结果符合预期，点「合并」。确认框里写着合并方式（例如压缩合并到 `main`）、提交标题，以及合并后任务会进入「已完成」，确认即可。没有检查结果时，按钮是「仍然合并」，可以填写合并的原因，Studio 会把这次合并记在 PR 和任务动态里。
5. 有地方不对，点「退回修改」，写清哪里要改。调度 Agent 会安排修改，改完再交给你。

![验收时看交付报告、验收标准和截图](https://static-docs.nocobase.com/studio-zh-req-accept-20261030-v2.png)

**完成的标志**：任务「已完成」，代码仓库的默认分支上有了这次的改动。配置了测试环境交付时，可继续查看改动进入测试环境的状态。

## 常见问题

**任务一直没有开始。** 看任务页的「现在」一行，会写明在等什么：没有在线的运行环境、并发已满，或者这个 Agent 只在别人的个人运行环境上。排队超过 24 小时没有运行环境领取，这次运行会失败，你会收到可以重试的通知。

**“初始化项目”还没完成。** 项目里新建的任务都要等它完成后才开始。

**Agent 说截图没有做成。** 运行环境上缺少浏览器，见 [接入共享运行环境](shared-runtimes.md) 的准备。

后续从[我的任务](../use/my-tasks.md)处理待办，或在[我的会话](../use/sessions.md)中讨论下一项需求。
