## 交给 Agent

将下面的需求交给本地 Coding Agent，替换服务器和项目信息。提示词已包含线上指南地址：

```prompt
请阅读 https://docs.nocobase.com/zh-CN/studio/setup/with-agent/ 及其中链接的部署步骤，在我的服务器上安装空白 NocoBase Studio，访问地址是 https://studio.example.com/main/。

连接我的 GitHub 组织，为“供应商管理”创建私有仓库，并用 NocoBase 应用模板初始化。把准备好的执行机和编码工具接入 Studio，配好 Agent 团队。完成后，我希望能直接在项目里添加业务需求。

镜像和服务器访问方式已经准备好。需要我完成浏览器授权或登录时告诉我。
```

已经有数据库或反向代理时，一并说明，由 Agent 使用现有配置。

## 准备信息

| 信息 | 需要提供什么 |
| --- | --- |
| 部署位置 | 本机或可访问的服务器、部署目录、Studio 访问地址 |
| Studio 镜像 | 商业版本，请[联系我们](https://www.nocobase.com/zh-CN/contact/)获取；按交付说明准备访问授权 |
| GitHub | 项目所在的账号或组织，以及创建仓库和安装 App 的权限 |
| 运行环境 | 执行任务的机器，已安装并登录的编码工具 |
| 存储与邮件 | 本地持久化目录或私有对象存储，以及邀请和密码重置使用的发件账号 |
| 首个项目 | 项目名称和新建仓库名 |

凭据通过本机的凭据管理工具或受限配置文件提供，不要写进提示词。Git 平台授权和编码工具登录可能需要你在浏览器中完成。

## 安装路径

Agent 按以下顺序完成。每一步的配置和检查方法都在对应文档中。

| 步骤 | 要完成的工作 |
| --- | --- |
| [部署 Studio](install.md) | 检查端口和已有服务，部署空白实例，配置访问地址、文件与产物存储、邀请和密码重置邮件 |
| [连接 Git 平台](git.md) | 建立 Git 连接，确认目标仓库在授权范围内 |
| [接入运行环境](shared-runtimes.md) | 安装执行机，确认在线，检查编码工具登录状态 |
| [配置 Agent](agents.md) | 检查可用模型和分工，设置调度 Agent 的执行模型 |
| [创建首个项目](new-project.md) | 新建仓库，完成 NocoBase 应用初始化 |
| [配置检查与预览](ci.md) | 选择 Agent 自检或 CI，准备验证改动 |

管理员密码和加密密钥应保存在部署目录的受限配置文件中。Agent 只需报告文件位置，不应在输出中展示内容。安装命令中的一次性凭证也不应进入共享记录。

检查与预览准备好后，再[邀请成员](invite.md)。成员按[加入项目](../join/index.md)登录并提交需求。

## 检查结果

安装完成后，确认可以：

1. 打开 Studio 并以管理员登录。
2. 在运行环境中看到在线机器和已登录的编码工具。
3. 查看可用的 Agent 团队和调度 Agent。
4. 打开首个项目，看到已完成的初始化任务和仓库代码。
5. 新建业务任务。

重启 Studio 后，项目和配置应仍然保留。请 Agent 留下部署目录、版本、数据备份位置，以及尚未完成的配置项。
