---
title: 验收
description: 核对交付报告与实际结果，合并代码或退回修改。
---

任务进入「待验收」后，由负责人检查交付结果。Agent 提供报告、验证记录和相关截图，人决定是否通过。

## 读交付报告

从「我的任务 › 等你处理」打开任务。先读「需要你」，再核对报告。

![任务顶部提供验收操作，下方是交付报告](https://static-docs.nocobase.com/studio-zh-guide-accept-20261031.png)

| 内容 | 检查重点 |
| --- | --- |
| 原来的情况与确定的方案 | 是否对应原始需求和确认的业务规则 |
| 改了什么 | 本次交付的范围 |
| 怎么验证的 | 测试、检查环境和独立评审结果 |
| 遗留问题 | 未完成事项及其影响 |
| 验收标准 | 可核对的结果和相关证据 |

附有截图时，可点开放大查看。报告缺少关键证据时，先请 Agent 补充。

## 看改动与预览

「看改动」打开代码平台上的 PR。「代码与预览」集中展示关联 PR、检查结果和预览入口。

配置了 PR 预览的项目，可在预览中逐项试用验收场景。预览需要由所选检查来源完成构建和发布。见 [PR 预览](../release/previews.md)。

预览闲置后可能休眠，打开时会恢复。PR 合并或关闭后，预览会清理。

## 通过

有 PR 时点「合并」，检查目标分支、合并方式和提交标题，再确认。若 PR 在确认期间新增提交，需重新确认。关联 PR 全部合并后，任务自动完成。

没有 PR 的任务，例如调研或资料整理，可点「验收通过」。调度 Agent 和执行 Agent 不能代替人合并或完成验收。

合并优先使用你连接的个人 Git 账号，否则使用工作区连接。代码平台的权限和保护规则仍然生效。

## 检查没有通过时

冲突、进行中的检查、草稿 PR 或代码平台规则，都可能阻止合并。

检查失败或没有结果时，Studio 可能提供「仍然合并」。可补充原因，相关操作会记录在 PR 和任务动态中。此操作不会绕过代码平台的保护规则，Agent 也不能执行它。

## 退回修改

1. 点「退回修改」。
2. 描述实际结果和预期结果。
3. 发送并退回「进行中」。

```prompt
暂停合作的供应商仍能新建订单。请阻止新建，并保留已有订单的查看和收货能力。
```

调度 Agent 会安排修复并重新提交验收。

## 在代码托管平台上已经合并

Studio 通过 Webhook 或轮询同步合并结果。确需手工记录时，可使用「标记为已合并」。后续发布进度见[发布概览](../release/overview.md)。
