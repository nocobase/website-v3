描述要解决的问题、业务规则和验收方式。Studio 将需求整理为任务，开始后由调度 Agent 安排执行。

## 在会话里提出

1. 在「我的任务」、任务列表或项目页点「新建任务」，也可在列表中按 <kbd>C</kbd>。
2. 描述需求，按需附上图片或资料。
3. 回答 Agent 的问题，检查它整理的任务。
4. 点「开始执行」交给 Agent 团队，或选择「先不开始」保留在「待规划」。

![新建任务会打开带有当前项目上下文的会话](https://static-docs.nocobase.com/studio-zh-guide-new-task-20261031.png)

```prompt
在供应商列表中显示每家的评分和等级。采购员可以按等级筛选，暂停合作的供应商不能新建订单。
```

已有讨论可直接转成任务，见[我的会话](sessions.md)。

## 直接填写

在新建任务会话中点「手动填写」：

1. 填写标题和描述，确认项目和负责人。
2. 选择「立即开始」或「以后再说」。
3. 点「创建并开始」或「创建」。

![直接填写任务的标题、要求和开始时间](https://static-docs.nocobase.com/studio-zh-guide-manual-task-20261031.png)

负责人负责确认业务规则和验收结果。「待规划」任务不会自动执行，准备好后需点「开始」。

## 怎样说清一个需求

| 内容 | 示例 |
| --- | --- |
| 目标 | 采购员需要快速识别高风险供应商 |
| 业务规则 | C 级供应商的订单都要审批，不区分金额 |
| 验收场景 | 用 C 级供应商下一笔小额订单，应进入审批 |
| 范围 | 先改新订单，历史订单不重新审批 |
| 资料 | 参考知识库中的《供应商评分表》 |

方案尚不明确时，可以先请 Agent 比较可选方案及其影响。

## 需求比较大时

调度 Agent 会安排设计、开发和评审步骤。需要分别验收的部分可拆成子任务。

- 在任务页创建子任务，或让 Agent 根据父任务起草。
- 分阶段的子任务会等待前面的阶段完成。
- 在属性中添加「前置依赖」，任务会等待依赖完成或取消。

优先级影响运行队列的领取顺序。开始后可在[任务详情](follow-progress.md)补充要求。
