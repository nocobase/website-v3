## 已确认的差异

| 范围 | 当前实现 | 文档调整 |
| --- | --- | --- |
| 质量入口 | 开发下的「质量」，项目内也能进入；项目工作区包含概览、测试任务、核心场景、跟进任务、指标、设置 | 删除三个待编写项，按当前工作区写功能指南，不恢复旧计划/标准模块 |
| 质量工作模型 | 每次测试是一项原生任务，冻结范围和 Skill 版本，通过原生交付报告验收 | 不再描述创建计划、确认计划、独立质量报告记录和独立质量问题详情页 |
| 测试类型 | 每日、发布、项目、自定义 | 说明范围、触发条件与入口；每日测试只按计划触发，不能写成手动按钮 |
| 自动测试 | 新项目默认不自动触发；项目负责人承担定时任务，权限不足会阻塞 | 安装后的质量配置要包含负责人、运行环境、触发规则、时区和检查维度 |
| 检查维度 | 功能、权限、安全、性能、代码质量；支持绑定 Skill 和新增维度 | 区分 Agent 实测、自动化用例、依赖审计和代码审查，不把所有维度写成自动化测试 |
| 结果与问题 | 维度报告、通过/失败/未验证/不适用、证据预览；缺陷、补测试、补场景等关联原生跟进任务 | 展示真实报告与问题详情，解释指标口径；检查通过截图不是每项必需 |
| 版本与授权 | `studio` 和 `studio-ee` 两种镜像组成，质量随 EE 提供；EE 接受 Enterprise Key | 安装前说明所需版本、授权与首次激活；删除 `studio.testing.enabled` 开菜单的做法，不公开交付地址和密钥 |
| Runner 会话 | My Agent 默认隐藏；默认只展示 Runner 会话；支持会话分享和等待/切换提示 | 删除「连接自己的电脑」文章与相关引用，调整「我的会话」「与 Runner Agent 对话」。本地 Coding Agent + CLI 仍是独立使用方式 |
| 个人设置 | 通知与 Agent 分开，Agent 中可选优先使用个人/共享运行环境 | 更新登录设置、个人运行环境、提醒与推送的入口和截图 |
| 额度与异常 | 保留原 Runner 的会话和工作目录，按恢复时间继续或由人更换 Agent/Runner | 替换介绍里“额度用完立即换模型”的概括；解释更换 Runner 时未推送改动的边界 |
| 发布与托管 | 共享 Host 容量卡片、在环境中创建应用、预览排队/容量不足/空闲释放 | 重审发布、预览、环境三个章节；仍明确生产部署由团队自行完成 |
| Git 与运行环境 | 新增 Gitea、DeepSeek Harness；授权和所需工具不同 | GitHub 继续作为安装主线，完整配置补充支持范围；不把所有提供商塞进入门 |
| 邮件 | 共用 `mailers`；指定密码重置服务改为 `auth.passwordReset.mailer` | 修正上轮文档的 `auth.email.mailer`；仍只写当前方法，不写迁移史 |
| CLI | 当前质量命令围绕项目、测试、结果、报告、场景和问题 | 更新 nb-studio 参考；Runner 参考需对照当前框架版本与实装 CLI 再核对 |

### 第一批：版本、菜单与基础配置

1. 选择可运行且已交付的版本，记录代码提交、镜像版本、Runner 版本和版本类型。用支持质量的 EE 实例完成质量验证；同时核对普通 Studio 缺少的入口。
2. 对照实际 UI 固定导航、个人设置和文档目录。保留已校对首页与介绍的结构，不随产品导航整体重写文档。
3. 修正版本授权、质量开关、密码重置字段、默认会话入口、通知位置等会阻止读者完成操作的问题。
4. 在隔离的空白实例重走部署、授权、GitHub、运行环境、Agent、首个项目、检查与预览、邀请流程。能用 Agent/CLI 完成的优先自动化。
5. 交付小范围三语 PR，并列出需要用户操作的授权/账号问题。

### 第二批：质量完整流程

1. 沿用供应商项目，准备核心场景、可运行测试、可访问应用和独立测试数据。
2. 真正运行一轮项目测试，形成场景清单、维度报告、交付报告和可跟进的问题。
3. 验证每日测试的定时触发、发布测试的待发布范围、自定义任务范围/整个项目代码、取消、阻塞和验收。
4. 完成一次“发现问题 → 跟进任务 → 修复 → 后续测试核对”的流程；未跑通的行为列入验证记录，不用演示数据冒充成功。
5. 再写质量正文、三语菜单和截图，同时更新入门、发布与核心概念中的相关说明。
6. 交付质量专题 PR；七篇新文章以实际篇幅为准，不为匹配 UI 标签硬拆文章。

### 第三批：其余模块逐页更新
