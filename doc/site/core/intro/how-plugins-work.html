插件怎样工作

NocoBase 3 的插件大多没有设置界面。这一页讲清一个插件给应用带来什么、怎样进入应用、界面和管理入口在哪里，以及怎样知道应用用了哪些插件。

在 NocoBase 2 里，你在插件管理器里启用一个插件，再到它的设置页里配置，插件的功能就出现在界面上。

NocoBase 3 的应用是一份代码，插件的工作方式随之改变：插件是应用依赖的一个 npm 包，登记在插件清单里；它提供能力，Agent 读它的技能，把能力用进你的页面和流程；管理员在应用的「系统设置」里管理。下面逐一说明。

一个插件给应用带来什么

不同插件带来的东西差别很大。几个例子（对照 v3-develop 分支）：

插件 服务端能力 自带页面 UI 组件 技能 命令
文件 上传、文件仓库、稳定的文件地址；文件表由应用声明 — 上传、列表、缩略图、预览 有 —
权限 权限模型、检查、权限集 — 权限编辑器、角色列表 有 —
定时任务 计划、执行记录 — — 有 scheduler sync
应用底座 采集应用用到的能力 「应用底座」 — 有 构建时生成模块对照
数据库浏览 只读接口：连接、数据表、字段 — — 有 —
任务中心 商业版 待办索引和接口 「任务中心」 任务中心界面 有 —
模板打印 — — — 有 —

最后一个例子最能说明问题：模板打印插件只有技能，没有一行运行时代码。装上它，Agent 就学会了怎样在你的应用里实现“按 Word 模板生成采购单、转成 PDF”，代码写在应用里。

插件怎样进入应用

通常你不需要亲自做这些。你说出需求，Agent 发现需要某个插件时会自己完成，或者先征求你的同意（例如需要商业授权的审批插件）。了解过程，是为了能看懂它做了什么：

  1. 注册。 pnpm nocobase plugin register @nocobase/app-plugin-xxx 把包加进 package.json 的依赖，并在三个插件清单里各加一行（插件有哪部分就加到哪个清单）。
  2. 同步技能。 插件的技能被复制到应用的 .agents/skills/。
  3. 建表。 插件有自己的数据表时，pnpm nocobase db apply 执行它的迁移。
  4. 用起来。 Agent 读技能，通过插件公开的接口实现你的需求：在服务端调用它的服务，在页面里使用它的组件，在「系统设置」里加上它的管理页面。

注册之后，你在代码仓库里能看到插件清单多了一行：

// client/plugins.ts（节选）
const clientPlugins = defineClientPlugins([
  authentication(),
  authorization(),
  file(),
  approval(), // 新注册的审批插件
]);
注册不等于功能已经做好

注册一个插件，只是让它的能力可用。大多数插件不带页面，注册后应用里不会立刻多出什么，要等 Agent 按你的需求把它用起来。

界面从哪里来

应用的界面有三个来源，用同一套样式：

来源 例子 怎样修改
插件自带的页面 「应用底座」、任务中心 通过插件的注册选项或页面替换来调整，不改插件代码
UI 组件库的组件 「流程管理」页面、收件箱、审批进度、权限编辑器 复制进应用后归应用所有，可以直接改
Agent 为你的业务写的页面 供应商列表、采购订单详情 告诉 Agent，像改任何代码一样改

所以“插件没有界面”的准确说法是：插件很少替你决定界面。界面按你的业务做，插件提供做界面的零件和背后的能力。

配置在哪里

NocoBase 2 的插件设置页，在 3 里拆成了三个地方：

放在哪里 放什么 例子 谁来改
config.yml 部署相关、含密钥的配置 数据库、对象存储、邮件服务商的账号、后台任务用 Redis 运维
代码 业务规则和结构 采购订单的流程、谁能看哪些订单、每天几点提醒 Agent，改完重新部署
「系统设置」 管理员日常要调整的 用户和角色、数据范围、共享规则、审批人、金额阈值、暂停定时任务 应用管理员，保存就生效

哪些规则放进「系统设置」，是需求的一部分。上线后可能要调的值，提需求时说出来，Agent 会把它做成管理员可以调整的设置。

管理入口在哪里

不在一个统一的插件设置页里，而在应用的「系统设置」里，按应用用到的能力出现。应用开发技能要求 Agent 交付应用时默认做好这些页面，不需要你单独提：

  • 「用户管理」「权限管理」（角色与权限、默认数据范围）：模板已经备好，开发业务时启用；
  • 「流程管理」：应用里有流程时；
  • 定时任务、通知等：对应的任务列表、执行记录和投递记录；
  • 「应用底座」：看应用用到了哪些能力。

验收时可以检查：管理员能看到这些入口、页面里是真实数据；普通用户看不到入口，直接访问地址或调用接口也会被拒绝。

怎样知道应用用了哪些插件

打开「系统设置 › 应用底座」。它按 13 类能力列出应用实际用到的部分，点开一项能看到提供它的包、在本系统里做了什么、关联哪些业务模块。只安装了包、没有用到，不算在用。

开发者还可以：

  • 看 server/plugins.ts、client/plugins.ts、cli/plugins.ts：注册了哪些插件；
  • 看 package.json：安装了哪些 NocoBase 包和版本；
  • 运行 pnpm nocobase plugin inspect <插件名> --json：检查一个插件的注册情况。

增加、更新和移除插件

要做的事 命令
增加 pnpm nocobase plugin register <包名>
更新 pnpm nocobase plugin update <包名>；不写包名则更新全部
移除 pnpm nocobase plugin unregister <包名> 或 pnpm nocobase package remove <包名>

这些命令同时维护依赖、锁文件、插件清单和技能，不要只手改其中一处。移除前先确认应用不再用到它：命令只更新依赖和登记，不会改应用的代码和配置。详见 管理插件。

和 NocoBase 2 的插件对比

NocoBase 2 NocoBase 3
是什么 运行时安装的功能包 应用依赖的 npm 包
启用 在插件管理器里点启用 登记进插件清单（plugin register），随应用一起构建和部署
配置 插件的设置页 config.yml、代码、「系统设置」三处
界面 插件提供配置界面和区块 少数插件带页面；多数提供 UI 组件，由 Agent 做进你的页面
谁来用它 人在界面上配置 Agent 读技能后写代码；管理员在「系统设置」里管理
升级 在插件管理器里升级 plugin update，或随 NocoBase 版本一起升级
看装了什么 插件管理器 「应用底座」、插件清单

常见问题

注册了插件，应用里为什么没有多出页面？

大多数插件不带页面。把需求告诉 Agent，它会用这个插件的能力做出页面和管理入口。

能直接改插件的代码吗？

不能。插件随版本升级，改了会在下次更新时丢失。要定制插件自带的页面，用它的注册选项、client/extensions/ 里的扩展或 client/route-overrides.ts 里的页面替换；从 UI 组件库复制进来的组件归应用所有，可以直接改。

Agent 没用插件，自己写了一套权限（或通知、定时任务），怎么办？

让它改用插件。应用开发技能把“已有插件能做的事自己重写”列为代价最大的错误，要求 Agent 先查已安装的插件。验收时可以在「应用底座」里确认对应的能力是否点亮。

插件的数据在哪里？

在应用的数据库里，表由插件自己的迁移创建，名称有固定的前缀，例如定时任务插件的表以 schedule 开头。应用不直接读写这些表，通过插件的接口使用。

商业插件怎样安装？

需要相应的授权和兼容的版本。Agent 在需要时会告诉你，例如审批：确认授权和包的获取方式后，用同样的 plugin register 注册。见 开源与商业。
