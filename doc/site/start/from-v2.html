从 NocoBase 2 来

用过 NocoBase 2 的人最想知道的几件事：思路变了什么，插件管理器和配置界面去了哪里，2 的功能在 3 里对应什么。

一句话的区别

NocoBase 2 里，表、页面、权限和工作流以配置的形式存在数据库里，平台读取配置渲染界面。NocoBase 3 里，它们都是代码，在你自己的仓库里，由 Agent 编写；NocoBase 以 npm 包的形式提供运行时、插件和基础库。

改动变成了代码，就可以像代码一样管理：在分支上开发、评审、测试、按版本发布、出问题时回退。平台没有提供的能力，Agent 也可以直接写，不再受配置界面的限制。

原来的做法，现在怎么做

在 NocoBase 2 里 在 NocoBase 3 里
在插件管理器里启用插件 把插件注册进应用的插件清单，通常由 Agent 用 pnpm nocobase plugin register 完成。见 插件怎样工作
在插件的设置页里配置 分三种：部署相关的（数据库、存储、邮件服务商）写在 config.yml；业务规则由 Agent 写进代码；管理员需要日常调整的（用户、角色、数据范围、审批人、金额阈值）在应用的「系统设置」里
在界面上拖拽页面和区块 向 Agent 描述页面，Agent 用 UI 组件库的组件写成代码
在工作流画布上配置流程 流程写在代码里（记录生命周期）；管理员在「流程管理」里看流程图、调整流程参数、查执行记录。见 工作流与审批
在数据源管理里建表、加字段 Agent 写迁移文件，pnpm nocobase db apply 执行
改动保存后直接生效 改动是代码，经过开发、验证、部署后生效
AI 员工 业务 Agent，由 Agents 插件接入，使用和人一样的角色与权限

那插件还有界面吗

有，形式不同了。一个插件给应用带来服务端能力、技能和命令，少数插件自带页面（例如「应用底座」），更多界面以 UI 组件的形式提供，由 Agent 放进你的页面。管理入口集中在应用的「系统设置」里，Agent 交付应用时默认会做好。

想知道一个应用用了哪些插件，打开「系统设置 › 应用底座」，它列出应用实际用到的 Core 能力和提供它们的包。

2 的功能在 3 里对应什么

NocoBase 2 NocoBase 3 说明
用户、角色与权限 认证、用户、权限插件，以及默认数据范围、共享规则、限制规则三个插件 默认模板已启用，自带「用户管理」「角色与权限」「默认数据范围」页面
数据源、数据表 数据库基础库和迁移；外部数据库作为第二个连接接入 支持 SQLite、PostgreSQL、MySQL、SQL Server、Oracle；达梦、人大金仓、OceanBase 在商业版
文件管理器 文件插件和存储基础库 本地存储、S3 兼容存储、阿里云 OSS
工作流 记录生命周期（基础库）、定时任务插件 流程结构写在代码里，没有拖拽设计器；工作流插件已于 2026 年 10 月删除
审批 审批插件 商业版 多级、会签、或签、加签、转交、退回
通知、站内信 通知、站内信、通知渠道插件 站内信；邮件（SMTP、Resend）；飞书、钉钉群机器人
邮件管理 邮件插件 关联个人邮箱，收发和同步邮件
AI 员工、AI 知识库 Agents 插件、知识库插件 默认模板已安装，需要时注册启用
多语言、主题 多语言插件；主题在模板里
API keys API keys 插件 默认模板已启用
模板打印 模板打印技能包 只提供给 Agent 的指引，由 Agent 在应用里实现
图表、导入导出等区块 由 Agent 在应用里实现 UI 组件库提供数据表格、看板等组件
审计日志 暂无 「应用底座」的操作审计一项显示尚未识别到提供方
LDAP、SAML、钉钉、企业微信登录 待确认 认证插件基于 Better Auth，OIDC 和社交登录通过配置接入

每个插件的详情见 插件目录，每页都有“与 NocoBase 2 的对应”。

2 的应用能迁到 3 吗

两者的结构不同：2 的业务定义在数据库的配置里，3 的在代码里，不能直接升级。迁到 3 相当于在 3 上重新开发这个应用，再把业务数据导入。
