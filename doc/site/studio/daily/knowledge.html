Studio · 日常使用

知识库、项目记忆与技能

团队的方法和业务认知留在 Studio 里：业务资料由人写进知识库，经验由 Agent 记进项目记忆，开发方法内置在技能里。

Agent 做事时会读三样东西。只有知识库需要人来维护：

存什么 谁来维护
知识库 业务规则、产品说明、技术约定、决策记录 人写和上传；Agent 只读
项目记忆 Agent 在工作中学到的经验 Agent 自己记、自己读，人不需要管
技能 做事的方法：开发规范、评审要点、测试步骤 已内置 NocoBase 开发的最佳实践，随 Core 更新

知识库

知识库存放人写和上传的资料，人和 Agent 共用。下一次增加功能时，不必重新解释项目背景。

  • 系统知识：跨项目共享，例如公司的审批制度、通用的技术约定。
  • 项目知识：每个项目一个空间。能读项目知识的人，也能读系统知识。

查阅。 「开发 › 知识库」把你能访问的空间汇在一起，搜索覆盖所有这些空间，每条结果写明来自哪个项目、哪个文件夹。

编写。 先选中要放入的空间或文件夹，再新建文章、上传文件或建文件夹。有编辑权限的人可以直接修改；只有提议权限的人可以提出修改，由项目负责人（系统知识由管理员）在收件箱里决定是否采纳。文章保留历史版本。

Agent 怎样用。 执行任务时，相关的知识会放在 Agent 的工作目录旁边；在会话里，Agent 可以搜索知识库，并注明引用了哪一节。

什么值得写进知识库

只写 Agent 从代码里看不出来的业务信息：业务规则和它的来由、术语的含义、例外情况的处理办法、做过的关键决定。

项目记忆

项目记忆让 Agent 记住在这个项目里学到的东西，下次开工前先读，不再重复犯错。它和 Claude Code 的自动记忆是同一个思路，完全由 Agent 自己维护。

Agent 只在有值得记住的事情时才记，大多数任务一条也不写：

  • 人纠正或确认了什么，例如“新供应商默认 B 级”；
  • 失败之后才发现的约束，例如“迁移编号要按合并顺序”；
  • 代码里看不出原因的决定；
  • 外部资料放在哪里，例如“评分权重以知识库《采购审批制度》为准”。

记忆是代码仓库 .nb-studio/memory/ 目录里的文件，一条记忆一个文件，随任务的 PR 一起提交，由评审的执行 Agent 和代码一并检查，合并后进入默认分支。Agent 用到一条记忆时会和当前的代码核对；对不上时以代码为准，并修正这条记忆。

项目记忆是写给 Agent 看的，你不需要阅读或整理它。想让 Agent 记住某条业务规则，在任务里直接告诉它即可；需要长期给人和 Agent 共同参考的资料，写进知识库。

不要让 Agent 记下敏感信息

记忆会进入代码仓库，任何仓库都不能写入密钥、令牌、密码和个人信息；公开仓库里的记忆是公开的。

技能

技能是写成文字的做事方法，Agent 每次运行都会带上。Studio 已经内置了 NocoBase 开发的官方技能：怎样使用 Core 的能力，哪些直接用底座、哪些自己写，代码放在哪里，权限和迁移怎么写。官方技能随 Core 版本更新，开箱即用，不需要你另外编写。

在「Agent 团队 › 技能」可以查看当前的技能。团队有自己特殊的约定时，技术负责人可以在这里补充团队技能，并设置用在全局、某个项目或某个工作目录上。
