Studio · 入门

核心概念

Studio 里的人和 Agent、任务、交付流程、运行环境和团队积累，以及它们之间的关系。

概览

每个任务由一位任务负责人负责，由 Agent 团队完成：调度 Agent 安排，执行 Agent 在运行环境上做每一步。你在「我的任务」里按任务跟进，在「我的会话」里和 Agent 讨论、建任务。

人和 Agent

Studio 里的角色分两类：人做决定，Agent 做执行。名字里带“Agent”的都是 AI，人的角色名里不出现“Agent”。

Agent 只有一种：一个编码工具加一个模型，例如“Claude · Opus 5.5”“Codex · GPT-5.5”。区别只在于它在哪里、为谁工作：

  • Agent 团队是团队共用的 Agent，负责完成任务，运行在运行环境上。其中调度 Agent 是 Studio 内置的角色，用管理员指定的一个 Agent 来运行，负责安排；执行 Agent 负责做每一步。
  • 我的 Agent是你自己电脑上的编码工具，连接到 Studio 后，在会话里帮你讨论、看代码、把需求拆成任务。它不领取团队的任务；拆出来的任务交给 Agent 团队完成。

所以 Agent 只有三种角色：调度 Agent、执行 Agent、我的 Agent。

任务

任务是 Studio 里交付工作的基本单位。每个任务有：

  • 负责人（任务负责人）：对结果负责的人，默认是创建任务的人。Agent 需要决定时找他，完成后交给他验收。
  • 执行者：几乎总是调度 Agent。任务开始时，执行者会自动设为调度 Agent，由它安排执行 Agent 去做。少数任务由成员自己执行。
  • 项目、优先级、标签、日期。优先级会影响排队，运行环境先领取紧急任务的工作。
  • 子任务和前置依赖：前置依赖没完成的任务不会开始；依赖完成后，任务会被自动唤醒。

每个任务都处在下面六个固定状态之一：

待规划→进行中⇄阻塞中·待验收→已完成已取消
状态 含义
待规划 还没开始，Agent 不会动。在任务页点「开始」后进入进行中。
进行中 调度 Agent 正在安排，执行 Agent 正在做。
阻塞中 等任务负责人决定一件事。
待验收 已经交付，等任务负责人验收。
已完成 验收通过。任务关联的 PR 全部合并后，任务自动变为已完成。
已取消 不做了。

人可以把任务改到任意状态。调度 Agent 只在进行中、阻塞中、待验收之间移动任务；执行 Agent 不改状态。

交付流程

每个交给 Agent 的任务，都走同一条流程。每一道关口通过了，才进入下一步：

环节 谁来做 通过的条件
安排 调度 Agent 改动涉及数据结构、迁移、并发或权限，或者任务没说清怎么做时，先写出方案
开发 执行 Agent 在独立分支上开发，按验收场景写测试，开出 PR
检查 代码仓库的 CI 团队定义的检查（代码规范、类型、测试、构建等）全部通过；失败时 Agent 修复
评审 另一家厂商的执行 Agent 评审通过；写代码的模型不评审自己的代码
验收 任务负责人 看交付报告和改动，合并 PR；不通过就退回修改
发布 模块开发中 模块完善后补充

这些规则写在调度 Agent 的「分配原则」里。其中的几条：同一时间只有一个步骤修改代码，评审和调查以只读方式并行；同一步失败两次，换下一个合适的 Agent，再失败就转为阻塞中问任务负责人。为防止 Agent 之间来回触发，每个任务 24 小时内由 Agent 评论触发的运行有上限（默认 20 次），超过后由任务负责人决定是否继续。

两种跟进方式：任务和会话

我的任务 我的会话
以什么为单位 任务 一段会话
里面有什么 你负责、执行或关注的任务，按“轮到谁”分组 你和 Agent 的讨论、由这段会话创建的任务，以及这些任务的进展
适合 每天处理等你做的决定：验收、回答提问 想法还没成形时讨论；把一件事拆成几个任务后，在一个地方跟进它们

会话里和谁对话，有两种选择：

  • 我的 Agent：在你的电脑上运行，能直接看你本地的代码，适合结合代码讨论、拆分任务。需要先连接你的电脑。
  • Agent 团队里的某个 Agent：由运行环境执行，不需要连接你的电脑，适合提问、查资料、拆分任务。

两种会话都列在「我的会话」里，只有你自己能看到。不论和谁对话，会话里的 Agent 都以你的身份和权限在 Studio 里工作，例如建任务、发评论。

Agent 团队怎样组建

Agent 团队里的 Agent 不需要手动创建，它们来自运行环境：

  1. 管理员添加运行环境，也就是运行 nocobase-runner 的机器：团队服务器、虚拟机，或成员自己的电脑。
  2. 运行环境上报它装好并登录了的编码工具和可用的模型，每个“编码工具 · 模型”组合自动出现在「Agent 团队 › Agent」里，处于待启用。
  3. 管理员写好它擅长什么后启用，它就成为执行 Agent。擅长什么是调度 Agent 分派工作的唯一依据。
  4. 管理员再从已启用的 Agent 里，为调度 Agent 指定「首选」和「备选」，调度这个角色就由它来担任。

运行环境分两种：

团队运行环境 个人运行环境
运行谁的工作 全团队的 只运行主人自己发起的工作
适合 团队服务器，全天在线 成员的电脑，用自己的订阅和算力

成员的电脑可以同时用在两处：注册为个人运行环境，为 Agent 团队提供算力，执行你自己的任务；再连接为「我的 Agent」，在会话里直接和你对话。两者分别设置，互不影响。

  • 一台运行环境同时跑几个工作，由「最大并发数」决定。机器越多，能并行推进的任务越多。
  • 每个任务在运行环境上有自己固定的工作目录；评审、调查用单独的只读副本，可以和开发同时进行。
  • 运行环境离线后，它手上的工作会回到队列，由其他运行环境接手。
运行环境不是安全边界

Agent 在运行环境上以运行 nocobase-runner 的系统用户身份工作，能读写这个用户能访问的一切。请用专用的系统用户、容器或虚拟机来运行它。

项目与代码仓库

项目把相关的任务和代码放在一起。项目的工作目录说明代码在哪里：

工作目录 说明
新建仓库 在 GitHub 或 GitLab 上新建。可以用「NocoBase 应用默认模板」初始化，得到一个建在 Core 上的应用。
已有仓库 团队已有的仓库，任务在它的分支上进行，带有 PR。
运行器上的目录 某台运行环境上的目录，不使用 Git，没有分支和 PR。
暂无代码 先建空项目，之后再添加。
  • 新项目的第一个任务是“初始化项目”，项目里的其他任务都等它完成。
  • Studio 通过管理员添加的 Git 连接访问仓库；成员连接自己的 Git 账号后，Agent 为他开的 PR、他在 Studio 里的合并都以他的身份进行。
  • Agent 的分支默认叫 agent/任务编号，这个分支上的 PR 自动关联到任务。Agent 不能合并 PR。
分支保护要在代码托管平台上设置

Studio 不替你保护分支。请在 GitHub 或 GitLab 上为默认分支开启保护规则。

团队积累：技能、知识库、项目记忆

技能、知识库和项目记忆把团队的方法和业务认知留在团队里。Agent 做事时先读它们，换人、换 Agent 都能接着做，开新需求也不必重新交代背景。

存什么 谁来写 在哪里
技能 做事的方法：开发规范、评审要点、测试步骤 已内置 NocoBase 开发的最佳实践，随 Core 更新 「Agent 团队 › 技能」
知识库 业务规则、产品说明、技术约定、决策记录 人写和上传，Agent 只读 「开发 › 知识库」
项目记忆 Agent 在工作中学到的经验 Agent 自己写，自己读 代码仓库的 .nb-studio/memory/

项目记忆和 Claude Code 的自动记忆是同一个思路：人纠正或确认了什么、踩到了什么坑、代码里看不出原因的决定、外部资料在哪里，Agent 会自己记下来，作为代码仓库里的文件，随任务的 PR 一起提交、评审、合并。下次开工前，Agent 先读这些记忆；记忆和代码对不上时，以代码为准并修正记忆。项目记忆是写给 Agent 看的，人不需要阅读和维护。

权限

成员的角色决定他在 Studio 里能做什么。Agent 代表发起工作的人做事，权限不超过这个人；例如调度 Agent 和它安排的每一步，都代表任务的负责人。验收、合并和管理成员这些事，只能由人来做。
