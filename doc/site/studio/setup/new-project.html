Studio · 搭建 Studio

新建项目

新建或选择代码仓库，默认用 NocoBase 应用模板初始化，Agent 在统一的架构上开发企业的业务。

项目把相关的任务和代码放在一起。新建项目时，选择代码放在哪个仓库里；新建的仓库默认用 NocoBase 应用模板初始化，得到一个建在 Core 上的应用，Agent 之后在这个应用上开发业务。

团队里的成员都可以新建项目，新建项目的人默认是项目负责人。

新建项目

  1. 打开「开发 › 项目」，点「新建项目」。

  2. 填写项目名称和描述，例如“供应商管理”。

  3. 「代码位置」选一种：

    代码位置 适合
    新建仓库 新的业务系统。Studio 通过 Git 连接创建仓库，再完成初始化
    已有仓库 团队已有的代码仓库
    稍后添加 先建项目，之后在「项目设置 › 代码仓库」里添加。没有代码仓库时，Agent 只能处理不涉及代码的任务

  4. 选「新建仓库」时，选择 Git 连接，填写仓库名称，一般保持「私有仓库」。所有者由 Git 连接决定，要建到别的账号或组织下，换一个 Git 连接。

  5. 选择初始化方式和「初始化 Agent」，见下一节。

  6. 点「创建项目」。

选择初始化方式

初始化方式 结果
NocoBase 应用默认模板 Agent 在运行环境上用 NocoBase 应用的默认模板创建应用，作为首次提交推送到默认分支。之后的开发都在这个应用上进行
根据提示词 Agent 按你写的提示词完成首次提交，推送到默认分支
空仓库 只有代码托管平台的初始提交，不做初始化

选「已有仓库」时，可以填写初始化提示词，例如让 Agent 先整理开发环境的说明；不填就不初始化。

用 NocoBase 应用默认模板时，需要一台在线的运行环境，装有 Node.js 24 和 pnpm。当前没有在线的运行环境，项目会先建好，初始化等运行环境上线后再开始。

初始化项目

需要初始化时，Studio 会建一个“初始化项目”任务，交给调度 Agent 安排：它把这一步交给你选的初始化 Agent，写清做什么、做到什么程度算完成。项目里之后新建的任务，都会等这个任务完成后再开始。

初始化要安装依赖，通常需要十几到二十分钟。期间可以在任务页看到哪个 Agent 在做、做了多久、在哪台运行环境上。

完成的标志“初始化项目”任务变为「已完成」，代码仓库的默认分支上有了应用代码。项目概览的「接下来」里，“完成项目初始化”一项消失。

之后

  • 要让每个 PR 都有预览、合并后自动部署，连接 CI。项目概览的「接下来」里会提示这一项。
  • 项目负责人、成员、代码仓库、变量与密钥、默认技能，在项目设置里调整，见 项目设置。
新建仓库时提示“尚未确认 App 的访问权限”

GitHub App 安装时只允许访问部分仓库，Studio 新建的仓库它访问不到。到 GitHub 上 App 的安装设置里加上这个仓库，再新建项目，选「已有仓库」。见 连接 Git。
