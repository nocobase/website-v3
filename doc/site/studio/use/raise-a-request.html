Studio · 日常使用

提出需求

在会话里和 Agent 把需求说清楚，由它整理成任务交给 Agent 团队；也可以直接填写任务。

你提出的是需求：要解决什么问题，业务规则是什么，做完怎样检查。需求在 Studio 里整理成任务，开始执行后，由 Agent 团队推进。

在会话里提出

  1. 在「我的任务」「开发 › 任务」或项目页点「新建任务」，列表页也可以按 C。Studio 会打开一段和 Agent 的会话，带上“新建任务”和当前项目。
  2. 用业务语言描述需求。可以一次说好几件事，也可以贴截图。
  3. 需求清楚时，Agent 直接整理成任务；不清楚的地方，它会先问你，或者先看看现有的代码再建。
  4. 建好的任务列在会话里。点「开始执行」，交给 Agent 团队；暂时不做，点「先不开始」，任务留在「待规划」。

会话里由谁回复、它能不能看到你电脑上的代码，见 我的会话。

直接填写

想直接填表时，在会话里点「手动填写」：

  1. 填写标题和描述，描述支持 Markdown。
  2. 确认项目和负责人。负责人是对任务负责的人，默认是你。
  3. 「什么时候开始」选一个：
    • 立即开始：任务进入「进行中」，调度 Agent 马上开始安排。
    • 以后再说：任务放进「待规划」，之后在任务页点「开始」。
  4. 点「创建并开始」或「创建」。
待规划的任务不会自动开始

放在「待规划」里的任务，Agent 不会动它。准备好后，在任务页点「开始」。

怎样说清一个需求

Agent 团队按你写的内容理解需求，说得越清楚，返工越少，中途来问你的也越少。建议写上：

  • 目标：要解决什么问题，给谁用。
  • 业务规则：数据怎么算，流程怎么走，谁能看到什么。在会话里提出时，Agent 问到的规则，当场定下来。
  • 验收场景：做完后你会怎样检查，例如“采购员登录后，在供应商列表里能看到每家的等级”。
  • 范围：这次不做什么。
  • 资料：相关的表格、截图、制度文件。已经在知识库里的，写明文档名称即可。

拿不准怎么做时，可以直接写“不确定，请先提出方案”。调度 Agent 会先请一个 Agent 写出方案，需要你决定时再来问你。

拆成几个任务

需求比较大时，可以让会话里的 Agent 拆成几个任务，它们会一起列在会话里，在一处跟进。

已经有了任务，也可以在任务页点「新建子任务」：

  • 同样会开始一段会话，并带上父任务。也可以让 AI 先阅读父任务、起草子任务，你检查、修改后再创建。
  • 子任务可以分阶段：后面阶段的子任务，要等前面所有阶段完成后才开始。所有子任务完成后，父任务接着推进。
  • 在任务属性里添加「前置依赖」：依赖的任务完成或取消之前，这个任务不会开始。

任务的优先级会影响排队，运行环境先领取紧急任务的工作。

自己来做

任务的执行者也可以是一位成员，这样的任务不会交给 Agent。之后想交给 Agent 团队，在任务页点「交给项目经理开始」。
