---
title: 快速开始
description: 接入运行环境、Agent 和代码仓库，把第一个任务交给 Agent 团队并完成验收。
---

完成这篇之后，你会有：一台在线的运行环境、两个以上启用的 Agent、一个建在 NocoBase Core 上的项目，以及一个由 Agent 完成、你验收合并的任务。

## 准备

| 准备什么 | 要求 |
| --- | --- |
| Studio | 已经部署好，能用管理员账号登录。见 [安装 Studio](install.md) |
| 一台运行环境 | macOS、Linux 或 Windows 上的 WSL；Node.js 24 或更高版本、pnpm 11、Git；建议用单独的虚拟机 |
| 编码工具 | 在运行环境上装好并登录，例如 Claude Code 和 Codex。建议准备两家厂商的工具，用于交叉评审 |
| 代码托管 | 一个可以创建 GitHub App 的 GitHub 账号或组织；或者一个 GitLab 群组 |

> [!TIP] 为什么要两家厂商
> 调度 Agent 会把代码交给另一家厂商的 Agent 评审，没有时换同一家的另一个模型。接入两家厂商的编码工具，评审才更有效。

## 添加运行环境

运行环境是 Agent 实际工作的机器。

1. 打开「Agent 团队 › 运行环境」，点「添加运行环境」。
2. 选择这台运行环境为谁工作：
   - **团队**：运行全团队的工作，适合团队服务器；
   - **个人**：只运行你自己发起的工作，适合你自己的电脑。
3. 勾选这台机器上准备使用的编码工具。只有勾选的工具会被派活，之后可以修改。
4. 设置「最大并发数」，也就是这台机器同时运行几个工作，默认是 4。按机器资源和模型额度设置。
5. 点「生成安装命令」，选择运行环境的系统，复制命令。
6. 在运行环境上，用准备运行 Agent 的那个系统用户执行这条命令。它会下载 `nocobase-runner` 和 Studio 的命令行，注册并设置为登录后自动启动。

命令里带有一次性凭证，只能用一次，有效期很短；过期就重新生成。几秒钟后，运行环境会出现在列表里，并列出它发现的编码工具。

::figure qs-add-runtime | 添加一台团队运行环境

> [!WARNING] 运行环境不是安全边界
> Agent 在运行环境上以这个系统用户的身份工作，能读写它能访问的一切，包括 SSH 密钥和其他凭据。请用专用的系统用户、容器或虚拟机，不要和 Studio 本身装在同一个用户下。

**完成的标志**：运行环境显示在线，编码工具显示已安装、已登录。

## 启用 Agent

运行环境上报后，每个“编码工具 · 模型”组合都会作为一个 Agent 出现在「Agent 团队 › Agent」的新发现里，处于「待启用」。

1. 打开「Agent 团队 › Agent」，展开新发现。
2. 找到要用的 Agent，点「填写并启用」。
3. 写好「擅长什么」。Studio 会预填一段建议，按团队的实际用法修改。
4. 按需要选择默认的推理强度，点「启用」。

至少启用两家厂商的 Agent。「擅长什么」是调度 Agent 分派工作的唯一依据，写成它适合承担的工作，例如：

| Agent | 擅长什么（示例） |
| --- | --- |
| Claude · Opus 5.5 | 需求梳理、方案设计和代码评审 |
| Codex · GPT-5.5 | 功能开发与缺陷修复 |
| Claude · Sonnet 5.5 | 编写和运行测试、回归验证 |

::figure qs-agents | 两个已启用的 Agent，一个待启用

**完成的标志**：列表里有两个以上已启用的 Agent，「在哪跑」一栏显示你的运行环境。

## 设置调度 Agent

调度 Agent 负责安排所有交给 Agent 的任务，它本身也需要一个 Agent 来运行。

1. 在「Agent 团队 › Agent」打开「调度 Agent」。
2. 在「用哪个 Agent 跑」里选择「首选」，再选择一个「备选」。首选排队超时或没有可用的运行环境时，由备选接手。
3. 保存。

「分配原则」先保留内置的内容。

::figure qs-coordinator | 调度 Agent 的设置

**完成的标志**：调度 Agent 的首选显示在线。

## 连接代码托管

### 工作区的 Git 连接

1. 打开「设置 › 集成 › Git」，点「添加连接」。
2. 选择 GitHub 或 GitLab：
   - **GitHub**：Studio 会替你创建一个 GitHub App。选择 App 属于你的账号还是某个组织（GitHub Enterprise Server 需要填写服务器地址），在 GitHub 上确认创建，再把 App 安装到需要的仓库或整个组织。
   - **GitLab**：填写实例地址（默认 gitlab.com）和一个群组访问令牌，令牌需要 `api` 权限，角色建议为 Developer。
3. 确认「Webhooks」设置。GitHub 或 GitLab 能访问到你的 Studio 时保持开启；Studio 只在内网时关掉，Studio 会每 60 秒轮询一次。

### 你自己的 Git 账号

打开「账号设置 › Git」，连接你自己的 GitHub 或 GitLab 账号。连接后，Agent 为你开的 PR、你在 Studio 里的合并都以你的身份进行；没有连接时，使用工作区的连接。团队里的每位成员都建议连接自己的账号。

> [!NOTE] 记得保护默认分支
> Studio 不替你保护分支。请在 GitHub 或 GitLab 上为仓库的默认分支开启保护规则。

**完成的标志**：「设置 › 集成 › Git」里的连接显示已连接；「账号设置 › Git」显示你的账号。

## 创建项目

1. 打开「开发 › 项目」，点「新建项目」。
2. **基本信息**：填写项目名称和描述，例如“供应商管理”。
3. **代码**：选择「新建仓库」，选择 Git 连接和所有者，填写仓库名称；初始化方式选择「NocoBase 应用默认模板」，按提示选择由哪个 Agent 负责初始化（「初始化 Agent」）。
4. **预览**：这一步属于发布与部署模块，先点「跳过」。
5. 点「创建项目」。

Studio 会在代码托管平台上创建仓库，并生成一个“初始化项目”任务：负责初始化的 Agent 在运行环境上用 NocoBase 应用模板创建应用，作为首次提交推送到默认分支。项目里之后的任务都会等这个任务完成。

> [!NOTE] 初始化需要运行环境
> 用 NocoBase 应用模板初始化，需要一台装有 Node.js 24 和 pnpm 11 的运行环境在线。当前没有在线的运行环境时，项目会先创建，初始化等运行环境上线后再开始。

**完成的标志**：“初始化项目”任务变为「已完成」，仓库里有了应用代码。

> [!PENDING] CI 与预览
> 让 PR 自动生成预览环境、在 Studio 中查看构建结果，属于发布与部署模块，模块完善后补充。

## 交出第一个任务

1. 在项目里点「新建任务」。Studio 会打开 Agent 面板，开始一段新会话。你还没有连接自己的电脑，所以由 Agent 团队回复。
2. 描述第一个任务。可以简单些，例如：

   ```text
   在应用里新建“供应商”数据表，字段包括名称、联系人、电话、状态（合作中/暂停），并在导航中加入“供应商”页面，可以新增、编辑和查看供应商。
   验收：登录后能从导航打开“供应商”页面，新增一条供应商并在列表中看到它。
   ```

3. Agent 建好任务后，在会话里点「开始执行」。

想直接填表，点面板里的「手动填写」，填写标题和描述，「什么时候开始」选择「立即开始」，再点「创建并开始」。

任务进入「进行中」，执行者变为调度 Agent。打开任务，可以看到：

- 顶部的「现在」一行写着任务正在等什么，例如哪个 Agent 正在工作、在哪台机器上；
- 「动态」里是调度 Agent 的交接和执行 Agent 的回复；
- 「运行记录」里是每次运行的过程。

::figure req-now | 进行中的任务

## 验收

开发、检查和评审完成后，任务会进入「待验收」，你会在「我的任务」的“等你处理”里看到它。

1. 打开任务。顶部的“需要你”卡片写明要你做什么，下面是交付报告：改动前的情况、约定的方案、改了什么、怎么验证的，以及验收标准和截图。
2. 点「看改动」查看 PR。
3. 结果符合预期，点「合并」并确认。PR 合并后，任务变为「已完成」。
4. 有地方不对，点「退回修改」，写清哪里需要改，再点「发送并退回进行中」。调度 Agent 会安排修改，改完后再交给你。

::figure req-accept | 待验收的任务

**完成的标志**：任务「已完成」，仓库的默认分支上有了这次改动。

## 常见问题

**运行环境不在线。** 检查 `nocobase-runner` 是否在运行，以及这台机器能否访问 Studio 的地址。运行环境 150 秒没有心跳就显示离线。

**Agent 页面没有出现新的 Agent。** 只有在「添加运行环境」时勾选的编码工具才会上报；工具还需要在运行环境上，用运行 `nocobase-runner` 的那个系统用户登录。登录后等一次心跳即可出现。

**任务一直在排队。** 看任务页的「现在」一行或「开发 › 任务」的「Agent 队列」，会写明原因：没有在线的运行环境、并发已满，或者这个 Agent 只在别人的个人运行环境上。排队超过 24 小时没有被领取，运行会失败，负责人会收到可以重试的卡片。

**“初始化项目”一直没开始。** 确认有在线的运行环境，且装有 Node.js 24 和 pnpm 11，能访问 npm。

**连接 GitHub 后跳转失败。** 检查 `APP_PUBLIC_ORIGIN` 是否是浏览器实际访问 Studio 的地址，见 [安装 Studio › 环境变量](install.md#环境变量)。
