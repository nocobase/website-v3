NocoBase Core 是开发和运行业务应用的基础。它提供应用框架，以及登录、用户、权限、文件、通知等通用能力，供你的应用直接使用。

无论开发任务管理、采购系统还是客户管理，都需要处理账号、数据、权限和界面交互。Core 提供这些共同的基础，让你和 Coding Agent 可以把精力放在具体业务上：需要保存哪些数据、谁能操作、操作后应该发生什么。

创建应用后，你会得到一个独立的应用项目。Core 作为项目依赖提供基础能力，页面、接口、数据结构和业务规则则写在你自己的应用中。

## Core 提供什么

- **应用模板与运行框架**：从一个可以启动的项目开始，具备客户端、服务端和运行配置，继续添加自己的功能。
- **通用能力**：通过插件和基础库使用认证、用户、权限、数据访问、文件存储和通知等能力，按应用需要组合。
- **UI 组件库**：复用表格、表单、弹窗等组件及业务区块。组件安装到应用源码后，可以按需要修改。
- **开发工具与 Skills**：命令行工具负责配置、迁移、插件管理和构建；Skills 为 Agent 提供与依赖版本配套的使用指引。

模板决定项目的起点，插件和库提供能力，应用把这些能力组织成业务。具体可用的能力取决于应用安装和注册了哪些包。

## 你需要开发什么

本教程会逐步完成一个任务应用。Core 提供基础机制，任务的内容和规则由应用定义：

| 场景 | Core 提供 | 应用实现 |
| --- | --- | --- |
| 用户登录 | 账号、登录和会话能力 | 哪些人可以使用任务应用 |
| 保存任务 | 数据访问和迁移机制 | 任务标题、完成状态、负责人及相关接口 |
| 展示任务 | 表格、表单、弹窗等 UI 组件 | 任务列表、新建弹窗、筛选和分页交互 |
| 控制权限 | 权限模型与服务端检查能力 | 谁能查看、新建或完成任务，以及能操作哪些记录 |

例如，用户点击“完成任务”时，应用调用 Core 的认证和权限能力检查这次操作，再按自己的业务规则更新任务状态，最后在页面上展示结果。

这些功能通常直接在应用项目中开发。需要将同一能力独立发布并复用到多个应用时，再考虑把它做成插件。

## 怎样开发和维护

**和 Agent 一起开发。** 你说明业务需求、使用者和验收标准，Agent 读取项目约定与 Skills，编写数据结构、接口、页面和测试。你通过实际试用检查结果，再继续调整需求。

**手动开发。** 你也可以直接编写代码，使用同一套框架、组件、接口和命令行工具。两种方式可以在同一个项目中配合使用，后面的教程会分别提供 使用 Agent 和 不使用 Agent 的步骤。

**代码由你管理。** 应用源码保存在自己的仓库中，可以评审、测试和按版本发布，也可以部署到自己的服务器。升级 NocoBase 时，对照新版模板合并变化，保留业务定制，并通过测试验证兼容性。

应用上线后，管理员可以在已配置的管理页面中调整用户、角色和数据权限；页面、数据结构或业务逻辑的变化则通过修改代码、验证和重新部署交付。

Core 可以独立使用。Studio 用来组织团队的开发、评审和发布；Solutions 则是基于 Core 构建的现成业务应用。学习本教程不需要先搭建 Studio。

## 开始创建应用

先通过 [创建应用](create-app.md) 创建并运行项目，再用 [项目结构](project-structure.md) 了解代码的位置。

随后从 [搭建第一个应用](../tutorials/build-your-first-feature.md) 开始，搭建完整的团队任务应用，再验证权限并部署。
