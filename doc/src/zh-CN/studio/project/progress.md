项目推进得怎样，不用一个个任务去问。项目负责人看两个地方：「仪表盘」看团队整体，项目的「概览」看单个项目。

## 仪表盘

「仪表盘」回答三个问题：交付进展如何，Agent 表现怎样，哪些工作卡住了。可以选择时间范围，每个数字都和上一周期对比，并画出本周期的走势。

仪表盘只统计你有权限看到的项目和任务。

### 关键数字

| 数字 | 怎样算 |
| --- | --- |
| 完成任务 | 本周期完成的任务数 |
| 周期时间中位数 | 从任务开始到完成的时间，取中位数 |
| Agent 完成占比 | 本周期完成的任务里，由 Agent 执行的占比 |
| 单任务成本 | 本周期 Agent 的用量按当前的模型价格算出费用，除以完成的任务数 |
| 运行成功率 | 已结束的运行里，成功完成的占比 |
| 返工率 | Agent 执行的任务被退回修改、或者完成后又被重新打开的比例 |
| 单任务运行次数 | Agent 完成的任务，平均每个运行了几次 |
| 人工介入率 | 运行中，Agent 把任务移到「阻塞中」来问负责人的占比 |
| 排队等待中位数 | 工作从排队到被运行环境领取的时间，取中位数 |

把鼠标移到数字上，可以看到它的计算方式。

几个数字放在一起看：返工率高，说明需求写得不够清楚，或者 Agent 的擅长什么、技能需要调整；人工介入率高，说明需求里缺少业务规则；排队等待长，说明运行环境不够用，见 [Agent 工作负荷与模型用量](usage.md)。

### Agent 表现

每天排队的运行，按结果分为完成、失败、取消和进行中，看 Agent 团队这段时间的工作情况。

### 需要关注

只列出当前卡住或逾期的事项：阻塞中的任务、逾期的任务、等待验收太久的任务、最近 24 小时失败的运行。一切正常时，这里是空的。

### 按项目

你能看到的每个项目：当前完成了多少，以及本周期交付了多少。

## 项目概览

打开一个项目，「概览」分区里有：

- **关键数字和状态分布**：全部任务、进行中、待验收、已完成各有多少。
- **接下来**：这个项目还需要完成的设置，例如添加代码仓库、完成项目初始化、接入预览 CI。都做完后，这一块就不再显示。
- **发布**：每个环境上正在运行的版本，见 [批准上线与回滚](release.md)。
- **已合并未发布**：已经完成、但改动还没有部署到生产环境的任务。
