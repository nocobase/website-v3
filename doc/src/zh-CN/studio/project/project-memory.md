description: 项目记忆保存 Agent 自主学到的经验。Agent 在一个项目里被人纠正过、踩过坑、确认过的事，会记下来，下次开工前先读，不再重复犯错。换一个 Agent 来做，也能接着用。
---

它和 Claude Code 的自动记忆是同一个思路，由 Agent 自己记、自己读，人不需要维护。区别在于项目记忆存在代码仓库里，团队里所有的 Agent 共用。

## Agent 记什么

只记以后的任务用得上、从代码里又读不出来的事，大多数任务一条也不写：

| 类型 | 例子 |
| --- | --- |
| 反馈 | 被人纠正过的做法、确认过的做法、踩过的坑，例如“C 级供应商的订单不论金额都要采购经理审批” |
| 项目 | 从代码和提交历史看不出来的决定、约束和背景，例如“迁移编号要按合并顺序” |
| 参考 | 仓库外的资料在哪里，例如“评分权重以知识库《采购审批制度》为准” |

能从代码、目录结构、提交历史推出来的东西，仓库的 `AGENTS.md`、README 里已经写了的内容，只和当前任务有关的进度，都不记。

> [!WARNING] 记忆里不能有敏感信息
> 记忆会进入代码仓库。密钥、令牌、密码、连接串和个人联系方式一律不能写，不管仓库是公开还是私有；公开仓库里的记忆是公开的。

## 存在哪里，怎样审查

记忆是代码仓库 `.nb-studio/memory/` 目录里的文件，一条记忆一个文件。Agent 在任务的分支上写记忆，随这次的 PR 一起提交，评审的 Agent 会和代码一起检查，你验收、合并后进入默认分支，之后的任务就能读到。

记忆用什么语言，按仓库自己的约定，例如 `AGENTS.md` 里的规定；仓库没有规定时用英文。

一个项目有几个代码仓库时，每个仓库的记忆只讲这个仓库，分开存放。

## 查看记忆

「开发 › 项目记忆」列出各个项目的记忆，项目页的「记忆」分区只看这个项目的。可以搜索，也可以按反馈、项目、参考筛选，每条写明来自哪个分支和提交。

记忆是写给 Agent 看的，你不需要读，也不需要整理。想看看 Agent 团队从项目里学到了什么，可以翻一翻。

## 让 Agent 记住一件事

想让 Agent 记住某条规则，在任务里直接告诉它，它会判断要不要记下来。需要人和 Agent 长期共同参考的资料，写进 [知识库](knowledge-base.md)。

## 记忆过时了怎么办

记忆写的是当时成立的事实。Agent 用一条记忆之前，会对照现在的代码核实；对不上时以代码为准，在当前的 PR 里修改或删除这条记忆。

每个仓库建议不超过 50 条记忆，单条不超过 4 KB。超过时会提示整理，不影响当前的任务。
