项目负责人管理项目的设置。新建项目的人默认是项目负责人；管理员可以管理所有项目。

打开项目，页面上方有六个分区：概览、任务、知识库、成员、发布、设置。这一页讲成员和设置；知识库见 [知识库](knowledge-base.md)，发布见 [批准上线与回滚](release.md)，概览见 [项目进展](progress.md)。

## 可见性、负责人和成员

- **可见性**：「所有人」时，工作区所有成员都能看到这个项目；「仅项目成员」时，只有项目成员和管理员能看到这个项目和它的任务。
- **负责人**：在「成员」分区，点某位成员的「设为负责人」。项目负责人必须是项目成员；要移除现在的负责人，先换一位负责人。
- **成员**：在「成员」分区按姓名搜索添加，或者移除。邀请还没加入 Studio 的同事，见 [邀请成员](../setup/invite.md)，邀请时可以直接选上这个项目。
- **状态、优先级和日期**：在项目的属性里设置，项目列表据此排序和筛选。项目状态有已规划、进行中、已暂停、已完成、已取消。

## 设置

「设置」分区有六节：

| 设置 | 做什么 |
| --- | --- |
| 常规 | 项目的名称和描述，以及 Agent 提交时的署名方式 |
| 代码仓库 | 项目用到的代码仓库。第一个是主仓库，工作从这里开始；可以添加、调整顺序、移除 |
| 部署 | 代码仓库的 CI 怎样构建预览、部署到 Studio，见 [连接 CI](../setup/ci.md) |
| 分支规则 | Agent 在哪个分支上工作，哪些 PR 关联到任务，以及检查的结果什么时候唤醒调度 Agent，见 [检查与评审](checks-and-review.md) |
| Agent 运行变量 | Agent 在这个项目里工作时拿到的变量与密钥，见下文 |
| 默认技能 | 项目或某个代码仓库中，每次运行默认带上的技能，见 [技能](skills.md) |

### 代码仓库

一个项目可以有几个代码仓库，例如应用和它的插件分开放。第一个是主仓库，任务默认从这里开始。移除一个代码仓库，只是任务不再在这里进行，仓库本身不受影响。

还没有代码仓库的项目，Agent 只能处理不涉及代码的任务。项目概览的「接下来」会提示「添加代码仓库」。

### 提交署名

Agent 以发起工作的人的身份提交代码。每个人可以在「个人设置 › 偏好设置」里选择，提交时是否同时把 Agent 署名为共同作者；这里设定的是没有自己选择的人用的默认值。

### Agent 运行变量

Agent 运行时需要的环境变量，例如测试用的接口地址、访问第三方服务的密钥，在这里设置：

- 可以设在整个项目上，也可以只设在某个代码仓库上。代码仓库的变量会覆盖项目里的同名变量，Agent 自己的变量又会覆盖两者。
- 保存后不再显示值，运行记录里也会脱敏。确实要查看时，点「查看值」，这次查看会连同你的名字和时间记入访问记录。
- 「从运行环境取」：这里不保存值，由接活的运行环境从它所在的机器提供，在那台机器上用 `nocobase-runner env set NAME` 设置。不提供这个变量的运行环境，运行会在开始前失败。
- 高风险的密钥，勾选「仅限共享运行环境」：带这个变量的运行只由共享运行环境执行，不会发到成员自己的个人运行环境。

部署出来的应用（包括预览）读取的变量，不在这里设置，而是在发布管理里按环境或按应用设置。

## 删除项目

「更多项目操作」里可以删除项目，需要管理员权限。项目、它的成员和代码仓库的关联会被删除；项目里的任务保留，不再属于任何项目。代码托管平台上的仓库不受影响。
