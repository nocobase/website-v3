---
title: 技能
description: 技能保存团队做事的方法。开发规范、评审要点、测试步骤写成技能，挂在全局、项目或代码仓库上，Agent 每次运行都按它做事；换人、换 Agent，做法也不会变。
---

一个技能就是一份 `SKILL.md`，可以附带几个文件，和 Claude Code、Codex 使用的技能格式相同。文件开头的 `name` 是技能的名字，`description` 告诉 Agent 什么时候读它。

## 内置的技能

Studio 内置了五个技能，规定 Agent 团队的做法：

| 技能 | 规定什么 | 默认挂在 |
| --- | --- | --- |
| studio-workflow | 调度 Agent 怎样拆分步骤、交给谁、什么时候先写方案、评审怎样进行、什么时候可以交付 | 新项目 |
| studio-development | 执行 Agent 怎样做一步：设计、验证、处理 CI 失败、交付 | 新项目 |
| studio-approach | 怎样写方案 | 新项目 |
| studio-review | 怎样评审 PR：看什么、问题怎样分级、什么会阻止合并 | 新项目 |
| studio-comment-style | 评论和交付报告怎样写：交付报告的各节就是它规定的 | 全局 |

内置技能可以按团队的习惯修改，修改保存在 Studio 里，升级 Studio 不会覆盖。

用 NocoBase 应用模板初始化的代码仓库，还自带 Core 的开发规范，Agent 在仓库里工作时会读到。

## 新建和修改技能

在「Agent 管理 › 技能」里：

- **新建技能**：写好 `SKILL.md`，文件可以现在或之后添加。也可以「导入」一个 zip 包，按 Agent Skills 的目录格式组织。
- **修改**：点「编辑」，改完点「保存新版本」，可以写一句这一版改了什么。每次保存都是一个新版本，旧版本可以查看和导出。
- **导出**：把某个版本导出为 zip，带到别的地方用。

新建技能需要能管理 Agent 的权限，通常是管理员；技能的创建者和管理员可以修改它。项目负责人可以把已有的技能挂到自己的项目上。删除一个技能，所有挂着它的地方都会移除它。

## 挂在哪里

技能挂上之后，在那里工作的每次运行都会带上它。挂载有三个范围：

| 范围 | 在哪里设置 | 用在 |
| --- | --- | --- |
| 全局 | 技能详情里的「全局挂载」 | 所有项目 |
| 项目 | 「项目设置 › 默认技能」，选「整个项目」 | 这个项目的所有运行 |
| 代码仓库 | 「项目设置 › 默认技能」，选某个代码仓库 | 在这个仓库里的运行 |

三个范围的技能会叠加；同名的技能，范围越具体越优先。

在技能详情里打开「新项目自动挂载」，之后新建的项目会自动挂上它；已有的项目不变。

## 写技能的建议

- 一个技能讲一件事，`description` 写清楚什么时候用，Agent 才知道何时读它。
- 写团队特有的约定，例如命名规则、必须跑的检查、不许改的目录；通用的编程知识不用写。
- 改动后，看看接下来几个任务的动态和交付报告，确认 Agent 照着做了。
