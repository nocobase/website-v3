## 任务状态

每个任务都处在六个固定的状态之一，项目不能增加、改名或删除状态。

| 状态 | 含义 | 谁会把任务移到这里 |
| --- | --- | --- |
| 待规划 | 还没开始，Agent 不会动它 | 人；新建任务时选「以后再说」 |
| 进行中 | Agent 团队正在推进 | 人点「开始」；调度 Agent 收到回复后继续 |
| 阻塞中 | 等任务负责人决定一件事 | 调度 Agent 提问时；人停止运行时 |
| 待验收 | 已经交付，等任务负责人验收 | 调度 Agent 交付时 |
| 已完成 | 验收通过 | 任务关联的 PR 全部合并时自动移到这里；人 |
| 已取消 | 不做了 | 人 |

- 人可以把任务移到任何状态。
- 调度 Agent 只在进行中、阻塞中和待验收之间移动任务，每次移到阻塞中或待验收，都写明要负责人做什么。它不会把任务改成已完成或已取消。
- 执行 Agent 不改任务的状态。
- 任务进入阻塞中或待验收时，通知任务负责人。

开始执行一个任务，执行者就设为调度 Agent。只有任务负责人（以及能编辑这个任务的人）可以开始；执行者是人或空着的任务，要先开始，Agent 才会工作，在评论里 @ Agent 不能绕过这一点。

## 内置角色的权限

“相关”的意思随对象而定，见表下的说明。

| 操作 | 成员 | 管理员、所有者 |
| --- | --- | --- |
| 查看项目和任务 | 相关 | 全部 |
| 新建项目 | 可以 | 可以 |
| 管理项目的设置 | 自己负责的项目 | 全部 |
| 删除项目 | 不能 | 可以 |
| 新建、编辑、评论、关闭任务，变更负责人 | 相关 | 全部 |
| 删除任务 | 不能 | 可以 |
| 修改 Agent | 自己的 | 全部 |
| 查看、配置、部署应用 | 自己创建的、关联到自己负责的项目的 | 全部 |
| 新建、删除应用，部署到受保护的环境 | 不能 | 可以 |
| 读知识库、提出修改 | 能看到的项目和系统知识 | 全部 |
| 编辑知识库、管理权限 | 自己负责的项目 | 全部 |
| 查看设置 | 可以，组织的 API 密钥、Git 连接和知识库搜索设置除外 | 可以 |
| 修改设置：Agent、运行环境、部署环境、Git 连接、组织的 API 密钥 | 不能 | 可以 |
| 接入个人运行环境、创建自己的 API 密钥 | 可以 | 可以 |
| 邀请成员、分配和定义角色 | 不能 | 可以 |
| 停用账号、重置别人的密码 | 不能 | 所有者可以 |

“相关”的任务和项目，指你所在的项目里的，以及你负责、创建、执行或关注的任务。自定义角色可以按需组合这些权限，见 [成员与角色](../admin/members-and-roles.md)。

## Agent 的权限

- Agent 代表发起工作的人做事，权限不超过这个人。调度 Agent 和它安排的每一步，代表任务负责人；会话里的 Agent，代表你本人。
- 执行 Agent 可以在任务的分支上提交、推送、开 PR，不能改写已经推送的历史；受保护的分支由代码托管平台把关。
- 在发布管理里，Agent 最多查看应用、读日志、部署到不受保护的环境；不能修改或删除应用，不能部署到受保护的环境。
- Agent 不能写知识库，也不能提议修改。

只有人能做的事：

- 验收任务、合并 PR；
- 批准部署申请；
- 管理成员、角色和 API 密钥。
