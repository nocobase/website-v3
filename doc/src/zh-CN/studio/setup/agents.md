运行环境上报它装好并登录了的编码工具和模型，每个“编码工具 · 模型”组合就是一个 Agent，例如 Claude · Opus 5.5、Codex · GPT-6.1 Sol。启用后，它就成为 Agent 团队的一员。调度 Agent 按每个 Agent「擅长什么」分派工作，这段话写得好不好，直接决定活派得对不对。

启用 Agent、设置调度 Agent，需要能管理 Agent 的权限，通常是管理员。

## 检查自动启用的 Agent

打开「Agent 管理 › Agent」。运行环境上报后，常用的“编码工具 · 模型”组合会自动加入列表并启用，「擅长什么」已经预填好一段建议。

逐个看一遍「擅长什么」，按团队的实际用法修改：点「编辑」，改好后保存。写清楚它适合做什么、不适合做什么，例如：

| Agent | 擅长什么（示例） |
| --- | --- |
| Claude · Opus 5.5 | 方案设计、疑难排查和代码评审 |
| Codex · GPT-6.1 Sol | 常规功能开发、跨模块的改动和重构 |
| Codex · GPT-6 Luna | 小改动、补测试、查 CI 失败的原因，速度快、成本低 |

在「编辑」里还可以设置推理强度。调度 Agent 派活时不能调整它，所以按这个 Agent 平时承担的工作来定。

## 添加其他模型

不在常用清单里的模型，要手动添加：

1. 点「添加 Agent」。「可用模型」里按编码工具分组，列出运行环境上报的每个模型；常用清单里的标着「上报后自动启用」，已经加过的标着「已添加」。
2. 选中要用的模型，为每个写好擅长什么。
3. 点「添加」。添加后立即启用。

模型显示「需要设置」或「版本过低」时，按提示在运行环境上设置或升级这个编码工具，再刷新检测。

只在个人运行环境上有的 Agent，会标明「仅个人执行机」：只有那台运行环境的主人自己发起的任务，调度 Agent 才会派给它。

至少启用两家厂商的 Agent。评审时，调度 Agent 会把代码交给另一家厂商的 Agent；只有一家时，换同一家的另一个模型。

## 设置调度 Agent

调度 Agent 是 Studio 内置的，全局只有一个，所有项目的任务都由它安排。它自己也要用一个已启用的 Agent 来运行。在 Agent 列表上方，「调度 Agent」一栏点「设置」：

1. 「首选」选一个擅长推理的 Agent，例如 Claude · Opus 5.5。
2. 「备选」再选一个。首选排队超过「备选等待时间」（默认 120 秒），由空闲的备选接手；没有能运行首选的运行环境时，立即用备选。
3. 保存。

::figure qs-coordinator | 调度 Agent 的设置

其他设置先保留默认值：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 分配原则 | 内置 | 调度 Agent 怎样分派和流转工作。可以改，也可以「恢复内置」，见 [Agent 团队怎样工作](../intro/agent-team.md) |
| 运行上限 | 每个任务每 24 小时 20 次 | Agent 之间触发的运行次数，超过后暂停，通知任务负责人 |
| 委派排队超时 | 600 秒 | 调度 Agent 派出的一步一直没有运行环境领取时，撤回这一步，由它重新安排 |

**完成的标志**：Agent 列表里有两个以上已启用的 Agent，「在哪跑」一栏显示你的运行环境；「调度 Agent」一栏显示首选和备选。

## 停用

- 不再使用的 Agent，在「编辑」里关掉「启用」。已停用的 Agent 默认不显示，勾选「显示已停用」可以看到，需要时再打开。
- 运行环境 14 天没有上报某个 Agent，它会显示没有运行环境，调度 Agent 也不再派活给它。
