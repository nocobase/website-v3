团队里的成员都可以新建项目，新建项目的人默认是项目负责人。

## 新建项目

1. 打开「开发 › 项目」，点「新建项目」。
2. 填写项目名称和描述，例如“供应商管理”。
3. 「代码位置」选一种：

   | 代码位置 | 适合 |
   | --- | --- |
   | 新建仓库 | 新的业务系统。Studio 通过 Git 连接创建仓库，再完成初始化 |
   | 已有仓库 | 团队已有的代码仓库 |
   | 稍后添加 | 先建项目，之后在「项目设置 › 代码仓库」里添加。没有代码仓库时，Agent 只能处理不涉及代码的任务 |

4. 选「新建仓库」时，选择 Git 连接，填写仓库名称，一般保持「私有仓库」。所有者由 Git 连接决定，要建到别的账号或组织下，换一个 Git 连接。选「已有仓库」时，从 Git 连接能访问的仓库里选一个。
5. 选择初始化方式，见下一节。
6. 点「创建项目」。

## 选择初始化方式

新建仓库时：

| 初始化方式 | 结果 |
| --- | --- |
| NocoBase 应用 | 默认。Agent 在运行环境上用 NocoBase 应用模板创建应用，作为首次提交推送到默认分支。之后的开发都在这个应用上进行 |
| 根据提示词 | Agent 按你写的提示词完成首次提交，推送到默认分支 |
| 空仓库 | 只有代码托管平台的初始提交，不做初始化 |

选已有仓库时，默认「不初始化」，直接使用这个仓库。也可以选：

- **NocoBase 应用**：Agent 按所选的模板创建应用，保留仓库里已有的文件，改动通过分支和 PR 提交；
- **根据提示词**：例如“阅读代码，添加 AGENTS.md”，改动同样通过分支和 PR 提交。

用 NocoBase 应用初始化，需要一台在线的运行环境，装有 Node.js 24 和 pnpm。当前没有在线的运行环境时，项目会先建好，初始化等运行环境上线后再开始。

## 初始化项目

需要初始化时，Studio 会建一个“初始化项目”任务，交给调度 Agent 安排：它把这一步交给合适的 Agent，写清做什么、做到什么程度算完成。项目里之后新建的任务，都会等这个任务完成后再开始。

用 NocoBase 应用初始化要安装依赖，通常需要十几到二十分钟。期间可以在任务页看到哪个 Agent 在做、做了多久、在哪台运行环境上。

- 新建的仓库：首次提交推送到默认分支，它的检查通过（或者仓库没有检查）后，任务自动完成。
- 已有的仓库：初始化的改动通过 PR 提交，你验收、合并后，任务完成。

**完成的标志**：“初始化项目”任务变为「已完成」，代码仓库的默认分支上有了应用代码。项目概览的「接下来」里，“完成项目初始化”一项消失。

## 之后

- 要让每个 PR 都有预览、合并后自动部署，[连接 CI](ci.md)。项目概览的「接下来」里会提示这一项。
- 项目负责人、成员、代码仓库、变量与密钥、默认技能，在项目设置里调整，见 [项目设置](../project/settings.md)。

> [!NOTE] 新建仓库时提示“尚未确认 App 的访问权限”
> GitHub App 安装时只允许访问部分仓库，Studio 新建的仓库它访问不到。到 GitHub 上 App 的安装设置里加上这个仓库，再新建项目，选「已有仓库」。见 [连接 Git](git.md)。

接着 [连接 CI](ci.md)，或者直接 [走完第一个需求](first-request.md)。
