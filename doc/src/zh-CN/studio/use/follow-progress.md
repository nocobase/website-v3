Agent 团队推进任务时，你不用守着，也不用一个个去问。每个任务做到哪里、下一步做什么，打开任务页就能看到；有补充时，直接在任务里说。

## 任务页

不论从列表、看板还是链接打开，任务页都是同一个样子。

::figure req-now | 任务页的摘要：「现在」「接下来」、属性和关联的 PR

**顶部一行**：任务在列表里的位置、编号（点击复制链接）、所属项目；右边是状态、关注星标、「问 Agent」和更多操作。

**摘要**：

- **现在**：系统根据实际情况写出任务正在等什么，例如“Codex · GPT-6.1 Sol 工作中 · 8 分钟 · server-01”“等待运行环境领取”“等 PR 的检查结果”“等周航验收”。这一行由系统生成，不来自任何人写的文字。
- **接下来**：调度 Agent 写下的下一步计划。
- **需要你**：任务在阻塞中或待验收、等你决定时出现，写明要你做什么，旁边就是处理按钮。见 [回答提问](answer.md) 和 [验收](accept.md)。
- **交付报告**：调度 Agent 交付验收时提交，之后一直保留，直到下一次交付替换它。

**属性**：优先级、负责人、执行者，以及「更多属性」里的标签、项目、开始和截止日期、订阅通知等。

**页签**：

| 页签 | 内容 |
| --- | --- |
| 动态 | 评论、交接、状态变化。默认「只看对话」，切到「全部」可以看到系统记录。 |
| 说明 | 任务描述。 |
| 子任务 | 子任务及其状态。 |
| 代码与部署 | 关联的 PR、检查结果和改动。 |
| 运行记录 | Agent 在这个任务上的每一次运行。 |

## 用评论和 Agent 沟通

在任务底部的输入框写评论。评论有两种：

- **评论**：所有人都能看到。它会唤醒你 @ 到的 Agent、你回复的那条评论的 Agent，以及任务的执行者（通常是调度 Agent）。有 Agent 正在运行时，评论会直接送到它那里。
- **备注**：只是给人看的记录，不会唤醒任何 Agent。

::figure composer | 评论会唤醒 Agent，备注只给人看

几个常见用法：

- 补充或修改要求：直接写评论，调度 Agent 会据此调整安排。
- 问某个 Agent 一个具体问题：在评论里 @ 它。它只回答你问的事，不会改任务状态。
- 回复某条评论：在那条评论下回复，讨论会留在同一个线程里。

## 问 Agent

任务页右上角的「问 Agent」会打开 Agent 面板，开始一段带着这个任务的会话。适合问“这个任务卡在哪”“这个 PR 改了哪些地方”这类问题。会话里的 Agent 以你的身份和权限工作，只做你让它做的事。见 [我的会话](sessions.md)。

## 运行记录

「运行记录」页签列出这个任务上的每一次运行：哪个 Agent、在哪台运行环境上、第几次尝试、结果和用量。

::figure runs | 运行记录：可以查看过程和提示词，也可以停止正在进行的运行

- 「查看执行过程」：Agent 这次运行的完整过程。
- 「查看完整提示词」：Agent 这次收到的全部内容，便于判断它为什么这样做。
- 「停止」：停止正在进行的运行，已经做出的修改会保留。停止后，任务进入「阻塞中」，Agent 的工作暂停，等你在评论里说明怎样继续。
- 「重试」：重新排队一次失败的运行。

## 接手任务

想自己来做，把执行者改成自己即可。已经排队的 Agent 工作会被撤回，正在进行的会被要求停止。之后想再交给 Agent 团队，点「交给调度 Agent 开始」。
