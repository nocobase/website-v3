## 写作原则

1. **先讲清 Studio 是什么，再讲怎么装。** 开篇说明它提供什么、团队里谁做什么、和 Core 是什么关系。读者先知道为什么用，再学怎么用。
2. **用一个需求从提出到上线作为主线。** 概念都挂在这条线上讲：任务、调度 Agent、执行 Agent、运行环境、检查与评审、验收、项目记忆。读者看到的是一件事怎样完成，而不是一串配置页面。
3. **按读者分册。** 业务负责人和成员读“日常使用”，管理员读“快速开始”和“管理员手册”，技术负责人再加上“技术负责人手册”。每个人只读和自己有关的部分。
4. **人和 Agent 一眼可分。** 按 [命名方案](03-命名方案.md) 用词；流程和分工的图里，人用琥珀色，Agent 用紫色。
5. **每个操作写清四件事：** 为什么做；怎么做；做完后系统会发生什么；做完的标志和出错时怎么办。
6. **配图只画正在讲的那一部分。** 用 HTML 画出界面的局部，而不是整页截图（见 [写作规范与术语](04-写作规范与术语.md#配图)）。
7. **以代码为准。** 每个行为描述都对照 Studio 仓库和框架插件的代码或设计文档核实；产品还没定的地方写进“待确认事项”，不在文档里猜。

左侧菜单列出完整的 Studio 文档。分组的顺序：先“入门”和“日常使用”，这是所有人都会读的；后面的功能分组按 Studio 侧边栏的顺序排（开发 → 质量 → 发布 → Agent 团队 → 设置），读者在产品里看到哪个入口，就能在文档里找到对应的分组；最后是“参考”。

还没写好的页面已经生成占位页：菜单里颜色较浅，页面上写明“本页待编写”和计划包含的内容；质量管理、发布与部署的占位页只写“模块开发中”。上一页 / 下一页只在写好的页面之间跳转。

几处取舍：

- “快速开始”放进“入门”，不单独成组；它是管理员入门的最后一步。
- “日常使用”里先放两种跟进方式（我的任务、我的会话），再按一个需求的顺序排：提出、跟进、回答、验收。
- 成员读的“知识库与项目记忆”放在日常使用；技术负责人维护知识库、技能的内容放在“项目与代码”。
- 原计划的“管理员手册”“技术负责人手册”按功能拆进“项目与代码”“Agent 团队”“系统管理”，和产品的入口一一对应，比按角色分册更容易查找。

### 入门

按陌生读者理解一个新产品的顺序排列：它是什么 → 一件事怎样做完 → 背后的概念 → 在界面上哪里。

- **Studio 是什么**：Studio 从组织、制度、流程、记录、决策五个方面治理 Agent；团队里的分工（人做决定、Agent 做执行，分两栏列出）；人出现的三个时刻；与 Core 的关系，重点是“应用上线后独立运行，不经过 Studio”。
- **一个需求怎样完成**：以“供应商分级”为例，先用一条流程线给出全貌，再逐步展开。每一步配一张局部界面图：会话里建任务、调度 Agent 交接、「现在」一行、检查与评审、“需要你”卡片、交付报告。发布上线一步留空；最后说明项目记忆让 Agent 下次接着做（不配图，人不需要看记忆）。
- **核心概念**：从第一性原理组织，先给一张图，再按图从上到下讲八个概念：人和 Agent → 任务 → 交付流程 → 两种跟进方式（任务和会话）→ Agent 团队怎样组建 → 项目与代码仓库 → 团队积累（技能、知识库、项目记忆）→ 权限。Agent 的分类只在第一节讲一次（Agent 只有一种，分调度 Agent、执行 Agent、我的 Agent 三种角色），后面各节只引用，不再引入新的叫法。
- **界面导览**：侧边栏的局部图加编号说明，按“每个人常用”“管理员和技术负责人常用”分两张表。原来放在“Studio 是什么”里的功能地图移到这里。

### 快速开始

一位管理员约 30 分钟完成：部署 Studio → 添加运行环境 → 启用 Agent → 设置调度 Agent → 连接代码托管 → 创建项目 → 交出第一个任务 → 验收。结尾列出下一步和常见问题。

和现有文档相比：部署部分说明镜像的关键参数，再给出交给 Agent 部署的提示词；CI 与预览属于发布与部署模块，这一版跳过；补上“擅长什么”、两家厂商、团队与个人运行环境等关键说明；新建任务按现在的界面，从一段会话开始。

### 日常使用

按一个成员一天里会做的事排列：

1. 我的任务：按任务跟进，每天从这里开始。
2. 提出需求：点「新建任务」开始一段会话，或手动填写。
3. 跟进进展：任务页的结构、评论与备注、运行记录、Agent 队列、仪表盘。
4. 回答提问：阻塞中的任务、运行失败、运行上限、接手任务。
5. 验收：交付报告、看改动、合并或验收通过、退回修改。
6. 我的会话：按会话跟进，会话下的任务进度条；我的 Agent 和 Agent 团队两种模式；连接自己的电脑。
7. 知识库、项目记忆与技能：只有知识库需要人维护；项目记忆由 Agent 自己读写；技能已内置最佳实践。
8. 收件箱与提醒。
9. 在终端里使用 Studio（`nb-studio`）。

## 页面模板

操作类页面按这个顺序写，不需要的部分可以省略：

1. **开头一两句**：这一页解决什么问题，适合谁。
2. **前提**：需要什么权限、要先完成什么。
3. **步骤**：编号列表，每步一个动作；界面位置写成「A › B」。
4. **配图**：画出这一步涉及的那一块界面。
5. **之后会发生什么**：系统和 Agent 接下来做什么，人什么时候会再被找到。
6. **完成的标志**。
7. **常见问题**：只写真实会遇到的情况，每条给出原因和处理方法。

概念类页面以解释为主，配结构图或流程图。

## 发布形式

正文用 Markdown 写在 `Doc/src/`，局部配图是 `Doc/src/figures/` 里的 HTML 片段，`node Doc/build.mjs` 生成 HTML 文档站到 `Doc/site/`。

- **文档站外壳**是普通的文档站：顶栏，左侧菜单，中间正文，宽屏时最右侧列出本页的小节（“本页内容”，随阅读位置高亮）。左侧菜单只列已经写好的页面，按“认识 Studio”“快速开始”“日常使用”分组，不加编号；还在编写的部分在文档首页说明。只做浅色，配色和字体与官网一致。
- **界面配图**按官网 `studio-ui.css` 的写法画，这套样式是对照真实 Studio 截图做的：状态图标、编码工具缩写的 Agent 标识、胶囊、按钮、分组列表、任务详情、动态和评论框都与产品一致。图标用 lucide，与产品相同。
