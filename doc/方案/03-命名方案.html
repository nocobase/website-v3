文档方案 · Studio 文档

命名方案

统一 Studio 里人、Agent 和几个核心入口的叫法，让用户一眼分清谁是人、谁是 Agent，每个入口是做什么的。

为什么要改

现在的几个名字，向第一次接触 Studio 的人解释时都要多说一句：

现在的名字 问题
项目经理 这是企业里真人的职位。读到“项目经理拆分步骤、向负责人提问”，读者第一反应是一个人，要停下来想一想才知道说的是 Agent。项目成员里还有“负责人”这个角色，两者更容易混。
我的 Agent（导航） 作为页面名，读者会以为是自己配置的一组 Agent。实际上这个页面是会话列表，是按会话跟进工作的入口。
Runner Agent 中文界面里夹着英文术语 Runner，用户不知道 Runner 是什么。
运行环境 / 执行机 / 运行器 / Runner 同一个东西在不同页面有四种叫法。
负责人 任务的负责人和项目的负责人用的是同一个词；单独说“负责人”，也容易和技术负责人、业务负责人混在一起。
Agent / agent / 智能体 界面里混用，例如“还没有智能体说明交付了什么”。

命名原则

  1. 人和 Agent 一眼可分。 名字里带“Agent”的一定是 AI，人的角色名里不出现“Agent”。
  2. Agent 按它做的事或它在哪里运行来命名， 不借用人的职位名。
  3. 入口按用户跟进工作的方式命名。 「我的任务」按任务跟进，与之对应的入口按会话跟进。
  4. 一个东西只有一个名字。 界面、文档、官网、CLI 的说明保持一致；英文术语只留在程序名和命令里。

Agent 的分类

先把 Agent 的分类定下来，名字才不会越起越多。

Agent 只有一种：一个编码工具加一个模型，例如“Claude · Opus 5.5”。按它在哪里、为谁工作，只分三种角色：

角色 属于 做什么
调度 Agent Agent 团队 Studio 内置的角色，全局一个，用管理员指定的 Agent 运行。拆分步骤、分派、需要决定时找任务负责人、交付验收。
执行 Agent Agent 团队 团队启用的 Agent。完成调度 Agent 交给它的一步：开发、测试、评审、调查。
我的 Agent 你自己 你电脑上的编码工具，连接到 Studio 后在会话里陪你讨论、看代码、拆任务；不领取团队的任务。

文档里不再出现其他 Agent 的叫法：评审、开发、初始化都是执行 Agent 做的一步；“Coding Agent”一律写作“编码工具”；会话里的两种选择是“我的 Agent”和“Agent 团队里的 Agent”，不是新的类型。

建议的名称

现在 建议 英文 说明
项目经理 调度 Agent Coordinator 拆分步骤、分派给合适的 Agent、需要决定时找负责人、交付验收。它做的都是调度，不写代码。
（无统一叫法） 执行 Agent Agent 完成调度 Agent 交给它的一步：开发、测试、评审、调查。界面上的「Agent 团队 › Agent」页面名不变。
「我的 Agent」页面 我的会话 My sessions 和「我的任务」并列：一个按任务跟进，一个按会话跟进。会话里有讨论、由它创建的任务和这些任务的进展。两种模式的会话都列在这里。
会话模式「我的 Agent」 我的 Agent（不变） My agent 你连接到 Studio、自己直接驱动的 Coding Agent：选电脑、选目录，实时对话。作为会话模式，“我的”说的正是“由我直接驱动”。
会话模式「Runner Agent」 Agent 团队 Agent team 和 Agent 团队里的某个 Agent 对话，由运行环境领取执行。和导航里的「Agent 团队」是同一个概念。
运行环境 / 执行机 / 运行器 / Runner 运行环境 Runtime 只保留一个叫法；nocobase-runner 只作为程序名出现。
任务的「负责人」（作为角色） 任务负责人 Task owner 文档和官网讲角色时用全称；任务页上的属性名仍可以叫「负责人」，在任务里不会有歧义。
项目成员角色「负责人」 项目负责人 Project lead 与任务负责人区分开。
agent / 智能体 Agent Agent 统一大写的 Agent。

改名之后，几个核心概念的关系可以这样一句话讲清：

每个任务由一位任务负责人（人）负责，由 Agent 团队完成：调度 Agent 安排，执行 Agent 在运行环境上做每一步。你在「我的任务」里按任务跟进，在「我的会话」里和我的 Agent 或 Agent 团队里的 Agent 讨论、建任务。

保留不改的名称

名称 理由
执行者（任务属性） 绝大多数时候显示为“调度 Agent”，含义清楚。
Agent 团队（导航分组） 团队启用的全部 Agent，不论它们跑在团队服务器上，还是成员电脑上的个人运行环境里。会话模式也用这个名字。
我的任务、仪表盘、收件箱 含义清楚。
技能、知识库、项目记忆 三者分工清楚：技能是方法，知识库是人写的资料，项目记忆是 Agent 自动记下的经验。

考虑过的其他名字

对象 备选 没有采用的原因
调度 Agent 编排 Agent “编排”偏技术，业务用户不熟悉。
统筹 Agent、协调 Agent 意思对，但不如“调度”直接；“协调”听起来像只负责沟通。
主管 Agent、经理 Agent 仍然借用了人的职位，和原来的问题一样。
我的会话 我的对话 “会话”与界面上会话列表、会话面板的用词一致。
保留“我的 Agent” 读者会理解成“我的一组 Agent”，看不出这是一个跟进工作的入口。
会话的两种模式 本机 Agent / 团队 Agent 区分的不是“在不在本机”：成员电脑也可以作为个人运行环境加入 Agent 团队，Agent 团队的会话同样可能跑在你自己的电脑上。真正的区别是由谁驱动：我直接驱动，还是交给 Agent 团队。
Runner Agent 中文界面里的英文术语，用户不知道 Runner 是什么。

需要同步修改的地方

  • Studio 界面：中英文案、侧边栏、会话面板的模式切换、Agent 页面、新建项目向导、任务页。「我的会话」页面要同时列出两种模式的会话（已确认；现在 Agent 团队的会话只在面板的历史里）。
  • CLI：命令名可以保留（如 nb-studio project-manager），帮助文字和输出里的名称同步修改。
  • 官网：Studio 页面里的“项目经理 Agent”“我的 Agent”等。
  • 定位文档：NocoBase 3 定位与产品结构.md 中的相关叫法。

文档的处理

文档草稿已经按建议的名称编写，便于评估读起来的效果。界面完成改名之前，文档不发布；如果最终的名称有调整，在 doc/src/ 里统一替换即可。
