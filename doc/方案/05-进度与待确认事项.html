这一版完成了什么

文档站的“入门”“安装与上手”“日常使用”三组已经写成草稿，共 16 页（另有 26 个占位页），配有 22 张 HTML 局部配图。中文正文在 doc/src/zh-CN/，运行 node doc/build.mjs 生成 doc/dist/，再运行 node doc/serve.mjs 预览。

所有行为描述都对照了 Studio 仓库 dev 分支（19a3e83，包含 #164 项目记忆和 #170 统一 Agent 面板）和 NocoBase 框架 v3-develop 分支的代码、中文界面文案和设计文档（2026-10-22）。

第七轮修改（2026-10-23，文案）

  • 「Studio 是什么」和首页的定义与官网一致：“人与 Agent 协同开发的治理平台”（官网首页导航），配上官网 Studio 页的“Agent 完成执行，人只拍板”“每个人都能带领一支 Agent 团队，同时推进更多任务和项目”。NocoBase 的用户是有一定规模的企业，不写“一个人”。
  • 「Studio 是什么」开头合并为两段：副标题讲定位和价值；正文一段讲 Studio 统一调度团队的 Agent，并且像管理员工一样管理这支 Agent 团队（分好工，定好规范和流程，每一步都有记录，关键的决定由人来做），对应下面的组织、制度、流程、记录、决策。去掉“Agent 正在成为团队里新的执行力量”这类空泛的句子。
  • “与 Core 的关系”保留官网首页的主张句，补上“通用能力已经内置，Agent 只写业务”。
  • 核心概念、知识库页说明技能、知识库和项目记忆的作用：把团队的方法和业务认知留在团队里，换人、换 Agent 都能接着做。
  • 去掉讲文档自身的话：“一张图看懂”“用一句话说”“下面按这张图逐个说明”“这一页说明……”“这篇只讲……”。

第六轮修改（2026-10-23）

  • 部署从快速开始里拆出，成为「安装 Studio」，和快速开始组成“安装与上手”分组，放在“入门”之后。“系统管理”的“生产环境部署”并入这一页。
  • 「安装 Studio」改为 compose 文件加逐步命令，补上环境变量、数据与备份、PostgreSQL、升级和常见问题。按 Studio 仓库的 Dockerfile、config.example.yml、server/config/database.ts 和 server/config.ts 核实：默认 SQLite 文件是 /app/storage/database.sqlite；镜像设置了 APP_CONFIG_FILE，config.yml 必须存在；容器以 UID 1000 运行；没有 SECRETS_KEYS 时模板里的占位密钥会被拒绝；内置的数据库驱动只有 SQLite 和 PostgreSQL。
  • 快速开始从添加运行环境讲起；管理员的阅读路径加上「安装 Studio」。

第五轮修改（根据评审意见）

  • 文档站改为普通的样式：顶栏、左侧菜单、中间正文、右侧“本页内容”。
  • 左侧菜单列出完整的 Studio 文档：入门、日常使用、项目与代码、质量管理、发布与部署、Agent 团队、系统管理、参考。功能分组按 Studio 侧边栏的顺序排列；还没写好的 27 页生成了占位页。

第四轮修改（根据评审意见）

  • 理顺 Agent 的分类：Agent 只有一种（编码工具 · 模型），只分调度 Agent、执行 Agent、我的 Agent 三种角色，在“核心概念”第一节一次讲清；会话一节不再引入新类型，只说“和我的 Agent，或 Agent 团队里的某个 Agent 对话”。
  • 分工图把我的 Agent 也画进 Agent 一栏；“评审 Agent”“开发 Agent”“初始化 Agent”“Coding Agent”等叫法从正文中去掉。
  • “Agent 团队与运行环境”改为“Agent 团队怎样组建”，按“运行环境上报 → 启用执行 Agent → 指定调度 Agent”的顺序讲。

第三轮修改（根据评审意见）

  • 会话的两种模式改为「我的 Agent」和「Agent 团队」，不再用“本机 Agent / 团队 Agent”：成员电脑也能作为个人运行环境加入 Agent 团队，区别在于由谁驱动，而不是在不在本机。
  • 角色名“负责人”改为“任务负责人”。
  • 「我的会话」按两种模式合并展示来写；会话列表的配图加上产品里的任务进度条。
  • 项目记忆改为“写给 Agent 看的，人不需要阅读和整理”：去掉了项目记忆页面的配图和“在哪里看”，界面导览里也不再推荐查看。
  • 快速开始的“接下来”去掉“把团队规范写成技能、把业务资料放进知识库”和“配置 CI”两条；技能一节改为说明最佳实践已经内置。

第二轮修改（根据评审意见）

  • 提出 命名方案：项目经理 → 调度 Agent，「我的 Agent」页面 → 我的会话，等等。草稿已按新名称编写。
  • “Studio 是什么”改为从组织、制度、流程、记录、决策五个方面说明 Studio 的价值，补上流程治理；分工改为“人做决定、Agent 做执行”两栏；与 Core 的关系只保留“应用上线后独立运行，不经过 Studio”这个重点；功能地图移到新的“界面导览”。
  • “核心概念”重新组织：一张图加八个概念，增加“两种跟进方式：任务和会话”；执行者改为“几乎总是调度 Agent”。
  • 加入项目记忆（#164）：在“Studio 是什么”“一个需求怎样完成”“核心概念”中说明，并在日常使用中排到知识库之前。
  • 按 #170 修改新建任务的说明：「新建任务」现在开始一段会话，表单改为「手动填写」，原来的“AI 整理”页签不再出现。
  • 所有截图占位换成 HTML 局部配图；快速开始改为 30 分钟。

关于预览的归属

这一版把 PR 预览、项目设置里的「部署」、新建项目向导的「预览」一步都归入发布与部署模块，所以快速开始让读者在向导里「跳过」预览，验收以交付报告、截图和改动为准。

需要产品和研发确认的问题

  1. 命名方案。 确认 命名方案 里的名称；确认后 Studio 界面、CLI 帮助文字、官网和定位文档需要同步修改。界面改名之前文档不能发布。
  2. 「我的会话」合并两种模式的会话（已确认要做）。 现在页面只列「我的 Agent」的会话，Agent 团队的会话只在面板历史里。文档已按合并后的样子写，产品需要实现。
  3. 官网 Studio 页要改（已确认）。 官网写“Agent 在开发中自动提议更新知识库，人审阅后合入”，并有“来自 CRM-137 的知识库更新建议”的界面示意；#164 之后 Agent 对知识库只读，经验记进项目记忆。官网的叫法已按命名方案改好（2026-10-23）：Studio 页、首页、价格页和它们的源文件、界面示意图里，“项目经理”改为“调度 Agent”（英文 Coordinator），作为页面的「我的 Agent」改为「我的会话」，“执行人”改为“执行者”，“Runner”改为“运行环境”；连接自己电脑的「我的 Agent」按命名方案保留。知识库更新建议的说法还没改。
  4. 项目记忆存放在哪里（已确认）。 按代码：记忆是代码仓库 .nb-studio/memory/ 下的文件，随任务的 PR 提交、评审、合并。文档已按此描述。
  5. 标准部署方式。 「安装 Studio」里的 compose 文件是按镜像的 Dockerfile 写的，需要研发确认后作为官方写法，并确认：镜像仓库账号怎样发放；生产环境用 latest 还是固定版本号；团队正式使用时是否推荐 PostgreSQL；APP_BASE_PATH 能否设为根路径。
  6. 新建项目向导里的“初始化 Agent”。 向导的说明文字还写着“之后的任务由谁接手，取决于流程的状态规则”，而流程和状态规则已经被固定状态和调度 Agent 取代。建议更新这句说明，并确认初始化 Agent 是否仍需要手动选择。
  7. “擅长什么”的预填和自动启用。 框架支持“应用常用清单里的组合在上报时自动创建并启用”，需要确认 Studio 是否配置了这个清单；如果有，快速开始的“启用 Agent”一节要说明哪些 Agent 会自动启用。
  8. 会话里建好的任务从哪个状态开始。 文档写的是 Agent 建好任务后，在会话里点「开始执行」；需要确认 Agent 团队模式的会话里是否也有这个按钮，还是 Agent 直接按你的要求开始。
  9. 运行环境的系统支持。 nocobase-runner 暂不支持 Windows（要用 WSL），而「我的 Agent」的连接程序支持 Windows。文档已分别写明，需要确认这个差异会保持多久。

HTML 局部配图按中文界面文案和设计文档画出，没有逐张对照运行中的界面。正式发布前，请在测试环境里对照以下几张，确认布局和文字没有偏差：

配图 对照的界面

req-now、req-accept、req-blocked 任务页的摘要、“需要你”卡片和交付报告
qs-add-runtime、qs-agents、qs-coordinator 添加运行环境、Agent 列表、调度 Agent 设置
agent-queue、runs Agent 队列、运行记录
sessions-list 会话列表和任务进度条
