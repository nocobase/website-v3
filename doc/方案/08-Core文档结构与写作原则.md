## 内容基准

按用户确认，Core 全部采用 `nocobase/app-docs` 的现有内容，替换原 Core 草稿、采购教程和占位页面。迁入基线为 `5d8bdbe93bf63c6066013b121b189b3f8fdcad33`，中英文各 22 篇。开始与 Studio 保留原结构，仅调整失效的 Core 链接及全站共用的示例说明。

## 文档结构

- 开始使用：Core 是什么、创建应用、项目结构、搭建第一个应用。
- 开发应用：应用开发概览、和 Agent 一起开发、数据模型与迁移、查询与操作数据、业务服务与 HTTP 接口、页面路由与导航、UI 组件与交互、应用配置与系统设置、多语言与主题、管理插件、测试与验收。
- 扩展开发：什么时候写插件、创建插件、插件的结构、发布插件、给插件写技能、向 UI 组件库贡献。6 项均标记为不可点击的待编写条目，不恢复原占位文章。
- 能力：能力总览、数据库、认证与用户、权限控制、文件管理、工作流、审批、定时任务、消息通知、邮件、Agents、知识库、模板打印、外部集成、多语言、主题定制。全部条目为待编写；能力总览、数据库、认证与用户、权限控制、文件管理的首版已按用户要求下线，后续重新编写，不恢复原草稿。
- 部署与运维：选择部署方式、使用 Docker 部署、使用 app-installer 部署、部署到 Studio、发布应用新版本、升级 NocoBase Core；运行配置、备份与恢复、日志与故障排查仍为待编写项。
- 参考：插件总览已编写；命令行、配置项、常见问题仍为待编写项。

没有单独的快速实战栏目。“搭建第一个应用”在开始使用里，末尾链接选择部署方式。部署应用业务代码和升级 NocoBase Core 分开说明。

## 写作原则

中文是写作基准，文章有对应英文翻译；示例代码、应用界面和截图使用英文。团队任务应用是入门示例，保留已有开发专题各自的示例和版本边界，不把它们强行改写为采购故事。

使用 Agent 的提示词从读者的业务需要出发，简短、自然、易懂；项目的 AGENTS.md 与 Skills 提供实现规范。不使用 Agent 的内容解释背后的实现过程：数据表、后端、前端、权限和测试，每一步展示关键代码，较长内容保留必要的折叠或链接固定 GitHub 修订。完整代码的下载和运行放在实现步骤之后。

真实截图展示已经运行过的应用。原有验证说明、版本差异和历史示例链接继续保留。依赖使用 npmjs.org 已发布版本，不要求 unreleased 注册表或 NocoBase 源码环境。

## 能力

扩展开发、能力和未编写的参考主题保留已确认的规划条目，使用不可点击的“待编写”菜单，不生成空页面。写好一篇后再同时添加两种语言的源文件及菜单链接；不自动恢复被替换的原 Core 草稿。

## 页面与资源

正文放在 `src/core/` 和 `src/zh-CN/core/`，目录结构一致。原文章路径加 `core/` 前缀，保留 `tutorials/` 下既有文章文件名，但在菜单中归入开始使用或部署与运维。内部链接写相对 `.md` 路径。

截图与文章引用的下载包放在 `assets/core/`，不复制旧站的 Next.js、Fumadocs、运行配置、日志或测试账号。菜单在 build.mjs 中登记，页面增删和移动同步修正引用并运行构建检查。
