## 需要确认的问题

### 读者与内容

1. **读者的真实问题。** [读者与需求](06-读者与需求.md) 里除了用户反馈的两个问题，其余是推断。建议从社区论坛、客户支持和售前记录里收集一轮，修正问题清单和阅读路径。
2. **能力改为 13 类。** 与「应用底座」和定位文档一致，现有“能力”一章的 14 组要重组（见 [结构](08-Core文档结构与写作原则.md#能力)）。模板首页的“内置能力”代码注释写明按文档的顺序排列，需要同步调整。
3. **统一故事。** 建议全站用采购应用，Core 现有的 Northstar 物流例子逐步改写，77 张英文截图同步替换为中文界面或 HTML 局部图。
4. **Agent 按需求做出的页面怎样配图。** 建议：模板和插件自带的界面用 HTML 局部图；Agent 做出的页面需要时用中文界面的真实截图，标明“示例效果”。

### 用词

5. **业务 Agent 与 AI 员工。** 建议文档统一用“业务 Agent”，第一次出现时注明 NocoBase 2 的叫法。
6. **工作流。** 能力分类沿用「应用底座」的“工作流与审批”，机制叫“记录生命周期”。需要确认模板首页“内置能力”里的“工作流”是否改名。
7. **技能。** Core 文档现在写“Skills”，Studio 写“技能”。建议全站正文用“技能”，文件名和命令里保留 `SKILL.md`、`skills sync`。
8. **“开发 Agent”。** 定位文档用“开发 Agent / 业务 Agent”，Studio 的命名方案规定不再引入新的 Agent 叫法。建议只在需要和业务 Agent 对比时使用“开发 Agent”。

### 产品现状

9. **开源许可证。** `v3-develop` 分支根目录没有 LICENSE 文件，只有 5 个包在 `package.json` 里声明了 Apache-2.0。评估者一定会问，文档需要明确的说法。
10. **操作审计。** 「应用底座」的操作审计一项显示“尚未识别到支持的提供方”，定位文档和官网把“操作记录”列为底座能力。需要确认现状和计划。
11. **企业身份登录。** 认证插件基于 Better Auth，OIDC、社交登录可以配置；定位文档写商业版增加“企业身份”。需要确认 LDAP、SAML、钉钉、企业微信在 3 里的计划。
12. **可视化流程设计。** 应用开发技能提到“管理员在界面上画流程时，使用 DAG 流程插件（安装时）”，仓库里没有这个插件。需要确认是否有计划，文档才能回答 NocoBase 2 用户最关心的问题。
13. **信创数据库。** 商业仓库有达梦、人大金仓、OceanBase 方言，需要确认发布状态和授权方式。
14. **默认模板里“已安装、未注册”的 Agents 和知识库。** 需要确认是有意为之，以及推荐的启用方式。
15. **研发协作插件。** 项目、发布、Agent 会话插件是否推荐在业务应用里使用，还是主要给 Studio 用。
16. **通知插件的投递记录页面。** 通知插件 `logs-ui` 组件的说明写着“插件默认提供 `/settings/notifications/logs`”，代码里只找到接口，没有页面路由。需要核实。
17. **NocoBase 2 的迁移。** 有客户项目在做 2 到 3 的迁移，需要官方的迁移路径和 2 的维护计划。

### 正式站点

18. **地址。** 现有 `/capabilities/...` 已经发布，站点规则要求地址不变。新结构是做重定向，还是让能力页保留原路径，需要文档站维护者确定。
19. **插件档案的生成脚本。** 需要在 NocoBase 仓库里加一个导出脚本，在文档构建时运行。需要确定由谁负责。
