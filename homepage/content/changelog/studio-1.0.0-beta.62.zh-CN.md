### 🎉 新特性

- **[Git]**
  - 支持连接 gitee.com 账号和仓库，跟踪 PR 与 CI 检查，并在 Studio 中合并。
  - 使用项目现有仓库连接查询没有拉取请求的提交的 CI 检查结果。
- **[Studio]** 新增独立 Studio 演示模式，支持账号切换、只读浏览、完整 Agent 执行历史和演示数据重置。

### 🚀 优化

- **[Agent]**
  - 明确共享运行环境用词，提供完整 WSL 安装和 PATH 修复引导，新增环境默认最多并发运行三个任务。
  - 执行机对话逐步显示回复，并在生成时显示思考摘要。
- **[我的会话]** 将“我的 Agent”入口改为“我的会话”，并将聊天中的 conversation 统一称为“对话”。
- **[项目]**
  - 在单页弹窗中选择新建仓库、已有仓库或稍后添加，统一以代码仓库管理项目代码，并保留已有执行机目录的使用能力。
  - 统一仓库初始化选择，新仓库首次提交检查通过或确认无检查后自动完成，已有仓库在 PR 合并后完成；调用方需替换已移除的 initAgentId 和 existingRepo.initPrompt 参数。
- **[质量]** {{edition:enterprise}} 集中查看跨计划的质量缺陷，并跟踪原生修复任务从待规划到待验收的进度。

### 🐛 修复

- **[任务]** 在单行的任务处理标题下方并排显示撤销和下一个操作。
- **[Studio]** 修复普通 HTTP 下新建任务、Agent 草稿和复制操作失败的问题，并在浏览器拒绝复制时提供手动复制提示。
- **[质量]** {{edition:enterprise}} 按用户明确决定结束质量计划，保存已验收结果时不再重复扫描项目内无关任务。
- **[Agent]** 执行机 Agent 仅保留启用和停用，让可用模型与 Agent 列表保持一致。
- **[收件箱]** 收件箱通知、任务待办和会话待办分别计数与处理，知识库由有权限的人直接编辑。
