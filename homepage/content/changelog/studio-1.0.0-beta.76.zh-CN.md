### 🎉 新特性

- **[质量]** {{edition:enterprise}}
  - 质量指标可点击进入对应的测试报告，新增「跟进任务」页集中列出质量测试登记的跟进任务，测试任务标题以项目名开头，各维度卡片以本维度的指标为主数字。
  - 项目质量设置可选择核心场景清单的编写语言，未设置时跟随实例默认语言。
  - 质量概览和指标页在测试进行中显示整体进度和各维度状态，可切换到同类型之前的任意一次测试，并可取消进行中的测试。
  - 「选择任务测试」改名为「自定义测试」，可选择测试整个项目代码；质量页面在手机和平板上不再溢出。
  - 质量测试为每个维度生成独立报告、交付报告只保留一屏摘要，检查点都有名称，标明哪些场景由自动化用例证明，并能按维度列出每个问题及其跟进任务状态。
- **[授权]** {{edition:professional}}
  - Studio EE 只接受企业版密钥；客户中心报告公司没有对应版本授权时，Studio 会锁定
  - 可在 设置 › 授权 填写 NocoBase 私有源 Token，项目需要时执行机即可安装商业插件。
- **[Studio]** 提供独立的 Studio 和 Studio EE 镜像，质量功能由 Studio EE 提供
- **[账户]** 在「个人设置 › Agent」中可选择任务优先交给个人执行机还是共享执行机；提醒和手机推送移到新的「通知」分类。

### 🚀 优化

- **[登录]** Studio 找回密码改用 auth.passwordReset.mailer，原 auth.email.mailer 引用需直接改到新字段。
- **[质量]** {{edition:enterprise}}
  - 完善项目测试场景、维度并行提交、按包追踪漏洞，并将测试证据展示在任务动态中。
  - 手机上发布页和质量页改为从底部抽屉选择项目，不再显示长列表；质量页把正在测试的项目排在最前。
  - 质量场景详情中的证据文件改为在当前页预览，可缩放并在文件间切换，不再打开新窗口。
  - 质量测试的自动化失败用例每次测试合成一条跟进任务，依赖漏洞每个项目只保留一条未完成任务，项目测试分别显示 Vitest 和 Playwright 的结果。
  - 质量测试为中、低等级问题也登记对应优先级的跟进任务，跟进任务标题带项目和测试日期，指标表每个指标一行，较长的交付报告在区域内滚动。
  - 质量测试可以把与某个维度无关的场景标为「不适用」，显示每个检查项是由自动化用例还是 Agent 实测证明的，项目测试的各个维度都按同一份场景清单执行。
  - 每日测试改为只按计划自动运行，首次只统计最近 3 天完成的任务；质量页显示下次运行时间和已累积任务数。
  - 质量卡片按问题总数显示，点卡片或任意数字都打开同一个维度详情，可查看问题、维度报告和审查范围；检查点显示名称和证明它的用例。
  - 质量测试通过项保留简短文字证据，不再截图；失败和未验证项继续保留诊断证据。
  - 开发任务使用轻量代码检查，每日、发布和项目测试提供页面性能报告，并支持扩展和冻结版本化质量方法。
  - 质量页上「测试中」的图标恢复旋转，系统开启减少动态效果时保持静止。
  - 功能场景清单定稿前，质量卡片显示「等待场景清单定稿」和问题数；问题详情按来源分行显示字段并链接漏洞公告；维度报告须按四段精简撰写。
  - 性能和代码质量问题显示问题、影响、怎么修和相关场景，中风险及以上的问题须先关联跟进任务才能提交结果。
  - 质量页中待验收或受阻的测试按实际状态显示，不再显示为「测试中」。

### 🐛 修复

- **[质量]** {{edition:enterprise}}
  - 修复普通项目成员可在没有项目管理权限时修改质量测试设置的问题。
  - 质量命令现可从 JSON 文件读取请求体。
- **[授权]** {{edition:professional}} 部署时不再要求填写授权检查地址，默认使用 NocoBase 客户中心。
- **[任务]**
  - 较长的交付报告恢复为「展开 / 收起」，展开后随页面一起滚动，不再在独立的区域内滚动。
  - 手机上在任务中评论或退回修改时，输入框会停在键盘上方，不再被遮挡。
- **[Agent]** 评审者开始代码评审前必须确认使用独立会话。 请将现有 `jobs.<name>` 和 `queue.<name>` 配置项分别移到 `jobs.backends` 和 `queue.backends` 下，旧格式会在启动时被拒绝。
