# 首页的其他语言

首页的中文、英文直接写在 `homepage.html` 里（`<t-zh>` / `<t-en>`、脚本里的 `L()` / `M()`）。西班牙语、法语、德语、葡萄牙语（巴西）、俄语、印尼语、越南语、繁体中文、日语、韩语的译文在这里，以英文原文为键，页面切换到这些语言时按需加载。

## 文件

- `keys.json`：要翻译的条目，按页面顺序编号，每条有英文原文、中文原文和所在位置。首页文案变了，在 `_src` 下运行 `python3 i18n/extract.py ..` 重新抽取：已有编号不变，新文案追加在末尾，页面上已删掉的标记为不再使用。
- `home.<语言>.txt`：译文，每行 `编号: 译文`，另有 `title`、`description` 两行。文件开头写着这种语言的固定用语。
- `build.py`：检查译文（漏条、多条、标记和占位符是否和原文一致），生成 `assets/i18n/home.<语言>.js`。在 `_src` 下运行 `python3 i18n/build.py ..`。

缺某条译文时页面显示英文，不会出错。

## 哪些翻译，哪些不翻译

- **翻译**：营销文案、导航、页脚，以及结构图上的说明（Core 图、Hero 下方的 Core 能力条、Hero 收尾卡片、Solution 左侧的应用说明）。
- **不翻译**：产品界面示意图（我的 Agent、Studio、NocoCRM 等）。产品界面只有中文和英文，中文以外的语言都显示英文界面，不展示不存在的界面语言。脚本里界面文字用 `L(zh, en)`，要翻译的用 `M(zh, en)`。

## 写作标准

和英文版《NocoBase Product Definition and Messaging》同一个标准：

- 按这门语言里同类产品的习惯来写，不逐字翻译，也不改原意。繁体中文从简体中文原文改写成台湾用语，不从英文转译。
- 一个概念在全页只用一种说法，见各文件开头的用语表。比如 foundation（底座）：法语 socle、德语 Fundament、越南语 nền móng（与表示"平台"的 nền tảng 区分）、日语 基盤。
- 按位置控制长度。Hero 大标题不换行显示，要短；Hero 下方 Core 能力条每格约 72px，西文约 11 个字母、中日韩约 5 个字；卡片标题控制在一行半以内。
- "AI + NocoBase" 是品牌组合，各语言都不翻译；正文里的 AI 用当地习惯（德语 KI、法语和西语 IA、俄语 ИИ）。
- 法文 `? ! : ;` 前的不换行空格、数字和 `%` 之间的不换行空格由 `build.py` 自动加。

改完运行 `build.py`，再用浏览器在 1440、1180、768、390 几个宽度看一遍：标题和能力条不能溢出。

## 解决方案页（NocoCRM、NocoITAM）

`solution-crm.html`、`solution-itam.html` 的其他语言用 `pages.py`，写法和首页相同，用法见它开头的说明。产品界面上的名称照 `ui-terms.md` 写。
