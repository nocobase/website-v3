接入多台机器上的 AgentAgents on many machines

个人电脑和团队服务器上的 Claude Code、Codex 等接入后，Studio 自动识别已登录的编码工具和模型。写明每个 Agent 擅长什么并启用，它就加入 Agent 团队。Connect Claude Code, Codex, and other agents on your team’s computers and servers, and Studio finds the coding tools and models signed in there. Say what each agent is good at, enable it, and it joins the agent team.

调度 Agent 分派工作A coordinator assigns the work

调度 Agent 按每个 Agent 的专长分派设计、开发、测试、评审工作。它不写代码、不合并代码，验收始终由人来做。A coordinator agent assigns design, development, testing, and review by what each agent is good at. It writes no code and merges nothing; a person always accepts the work.

多个任务同时推进Many tasks at once

每个任务在自己的分支上开发，每次运行使用独立的 worktree，多个任务同时推进、互不干扰。机器越多，能同时推进的任务越多。Each task has its own branch, and every run works in a separate worktree, so many tasks move at once without colliding. Add machines to run more in parallel.

我的会话My sessions

在 Studio 里和自己电脑上的 Agent 对话，讨论和澄清需求、记录任务、跟进进展。任务开始后，由调度 Agent 安排 Agent 团队开发。In Studio, talk with the agent on your own computer to discuss and clarify requests, record tasks, and follow their progress. Once a task starts, the coordinator agent puts the agent team to work.

交到人手上之前，Studio 组织检查和评审。Before work reaches a person, Studio coordinates checks and reviews.

每次改动走同样的流程：测试和代码评审都通过，才交给人验收；经人批准，才发布到生产，出了问题可以回滚。Every change follows the same path. It reaches a person only after its tests and code review pass, and reaches production only after a person approves. If something goes wrong, roll it back.

  1. 1

    分支与 worktreeBranch and worktree

    每个任务有自己的分支，每次运行在独立的 worktree 里进行；分支上的 PR 自动关联到任务。Each task has its own branch, and every run works in a separate worktree. Pull requests from that branch link to the task.

  2. 2

    测试与评审Test and review

    CI 跑检查和测试，再换一个模型评审代码，优先用另一家厂商的模型。CI runs checks and tests, then a different model reviews the code, from another vendor when one is available.

  3. 3

    预览验收Preview

    需要时为 PR 启动独立的预览环境，供人试用验收。When needed, a pull request gets its own preview environment for a person to try and sign off.

  4. 4

    合并发布Merge and release

    验收通过后合并，任务的 PR 全部合并后任务自动完成；发布到生产由人批准。Merged after sign-off, and the task is done once all its pull requests merge. Releases to production need a person’s approval.

  5. 5

    回滚Roll back

    出了问题，退回上一个版本。If anything breaks, go back to the last release.
