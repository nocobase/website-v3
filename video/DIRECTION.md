# AI + NocoBase · 品牌片 · 规范与镜头表（v3.1 · 压到 120 秒以内）

118 秒，16:9，1920×1080，60 fps，中文版，无旁白（配乐 + 音效）。先出 HTML 审片版（`preview.html`），画面认可后再写配乐、渲染。上一版（v2，一个业务系统的一年）在 git 历史里（提交 6b00819）。

**v3.1 改了什么**（2026-10-24）：
- Studio 的品牌表达按标准文稿换成「Agent 自主推进，团队掌控全局。」（英文 “Agents keep the work moving. Your team stays in control.”）。
- 片长从 146 秒压到 118 秒。镜头一个不少，靠缩短停留：动作提前、间隔收紧、最后的停顿收短；去掉收束里重复的三个标签（落版上还有）。各段怎么压见第 2 节的对照表。
- 结尾不再渐隐成黑场：积木落定后停 6 秒，片子停在落版画面上结束。

## 1. 简报

| 项目 | 内容 |
|---|---|
| 讲什么 | NocoBase 是什么、为什么需要它：按《NocoBase 产品定义与标准表述》的主线，AI 写代码很快 → 但构建可靠的业务系统依然不简单（四个问题）→ NocoBase → Core 解决前两个 → Studio 解决后两个 → 系统长期稳定迭代 |
| 给谁看 | 已经在用 Claude Code、Codex、Cursor 开发的技术负责人、IT 负责人，和懂业务的负责人 |
| 用在哪 | 官网首页「观看演示」、发布会、销售演示 |
| 时长与画幅 | 118 秒（要求 120 秒以内）；16:9 |
| 语言 | 中文 |
| 声音 | 配乐 + 音效，无旁白 |
| 不讲 | Solution（另做方案片）、价格、Launch；不出现标准文稿和产品里都没有的能力（比如发布前自动备份） |

**看完要带走的**：
1. 用 AI 写代码很快，但构建可靠的业务系统依然不简单：底层能力要从零建设、架构随机漂移、并行任务人确认不过来、知识和经验难以沉淀。
2. NocoBase 是用 AI 持续开发和运行业务系统的开源平台：Agent 写代码、做执行，NocoBase 提供底座和治理能力，人来做决策。
3. Core 让 Agent 专心写业务，底座已经就绪；Studio 让 Agent 自主推进，团队掌控全局。

**故事**：采购部的供应商管理系统。一个有规模的业务系统，四个问题都会在它身上自然发生。人物：周航（采购主管，业务负责人，不写代码）、王磊（技术负责人）、陈宇（IT）、林悦（新接手的同事）。

**画面规则**：
- 开场到品牌之前是“单独使用 Coding Agent”，左上角 01 角标一直标着，环境光是中性冷灰；品牌出场后换成淡蓝，角标收起。
- 屏幕上的产品说法都取自标准文稿（原句或缩写，不改用词）。
- 故事段每个场景用同一套页头（段落名 + 一句标题 + 一行灰字），Agent 在做事时右上角用 Agent 状态标签写明是谁、在做什么。
- 人只通过光标出场；Agent 做的事带 Agent 标识（CC、CX、OC、调）。蓝色只标 NocoBase 提供的部分。

## 4. 配乐（`score.mjs`；审片音轨 `AUDIO_ONLY=1 ./make.sh`）

沿用上一版的音色和 score-kit 规则：120 BPM，调性中心 D，每个章节从前一小节引入、在强拍落下。开场和四个问题走干声总线，问题一个比一个紧；24 秒整句出现时减薄，29 秒停机；30 秒积木落定时 D 大调进来。Core、Studio 两章各一层律动，回到 2×2 打勾时每个勾一声钟；收束铺底变宽；落版 Dmaj9，三声钟，长尾。

v3.1 的和弦表按新的段落长度重排：开场 Dm · B♭ · C（3 小节）；四个问题 9 小节，最后一小节 B♭ 进整句的 A；Core 章节 D · A/C# · G；两个能力证明合起来 5 小节 Bm · G · D · Bm · A（工作流与审批从第 49 秒、小节中间进来，加一层鼓）；能力看板 G · Em，57 秒整屏拉远时落在 D 上，59 秒 G，61 秒 A；控制台每页 3 小节 D · G · A，换页都在小节线上；收束 G · D · A，低音在最后一小节走回 D。

## 5. 界面与数据

- **开场终端**：`~/supplier-app — coding agent`，七行 Write，共 28,400 行。
- **问题卡片**：四张，按标准文稿的问题标题和缩写后的说明。卡片放大时 760 × 330，收进 2×2 时缩到 0.75 倍；解决标签用标准文稿方案句的缩写。
- **Core**：业务代码 4,860 行（示意）；权限控制和工作流与审批沿用上一版的供应商列表和准入流程；权限控制没有需求气泡，所以窗口不用引擎 `.pf3` 给气泡留位置的 268 px，而是放在 240 px，推近到 1.03 倍时离页头和画面底边一样远（各约 88 px）；能力看板 24 张，名称按官网 Core 页（含处理记录、知识库）；底座上点亮的能力用官网名称：权限控制、工作流与审批、消息通知、外部集成，“等 20+ 项基础能力”。统一架构的项目树：`server/tiering`、`server/erp`、`server/qualifications`，每个模块都是 collections · routes · workflows；技能 `nocobase-app-development` 等。
- **Studio 控制台**：沿用上一版的控制台（NocoBase 3 shadcn 风格，1.0 倍，按页滑动），菜单按 Studio 现在的叫法（我的会话、调度 Agent、项目记忆）。任务 PUR-23/24/25；测试 46/46；版本 v1.1。
